# BuilderGate v0.10.7

## English

### Fixed

- **Server memory regression from v0.10.6.** v0.10.6 started trimming the output kept since the
  last snapshot less often, to save CPU. Its size limit was checked in characters instead of
  bytes, so output made of box-drawing characters or Hangul could be kept at up to about 3.7
  times the intended size per session. Each trimmed copy also kept the previous, longer string
  alive. A heap snapshot with 24 busy sessions showed 42 strings of 5.24 MB each.
  - The limit is checked in UTF-8 bytes again, tracked as output arrives so it stays cheap.
  - After each trim the kept text is copied, so the previous string can be freed.
  - The CPU improvement from v0.10.6 is unchanged.

### Added

- **Memory breakdown in the server status log.** The `[TerminalObs]` line written every 60
  seconds, and `/api/sessions/telemetry`, now include a `memory` section:
  - `process`: RSS, V8 heap used/total, external and ArrayBuffer memory (MB).
  - `sessions`: totals for terminal buffers, output kept since the last snapshot, snapshot
    caches and degraded-replay buffers (MB), plus retained record and fact counts.
  - `largestSessions`: the five largest sessions with columns, buffer lines and estimated MB.

  The figures come from sizes only (string lengths and buffer dimensions), so collecting them
  does not read terminal content and costs almost nothing. They make it possible to see where
  an installed server's memory goes, since the installed executable cannot attach a debugger.

### Tests

- Added a measurement test for browser and server CPU and memory with many busy sessions
  (`perf-memory-probe.spec.ts`).

## 한국어

### 수정

- **v0.10.6 의 서버 메모리 회귀를 고쳤습니다.** v0.10.6 은 CPU 를 아끼려고, 마지막 스냅샷 이후의 출력을
  보관하는 문자열을 덜 자주 자르도록 바꿨습니다. 그런데 크기 상한을 바이트가 아니라 글자 수로 비교해서,
  박스 문자나 한글이 많은 출력은 세션마다 의도한 크기의 최대 약 3.7배까지 보관될 수 있었습니다. 잘라낸
  뒤에도 이전의 더 긴 문자열이 메모리에 함께 남았습니다. 바쁜 세션 24개로 찍은 힙 스냅샷에서 5.24MB 짜리
  문자열 42개가 확인됐습니다.
  - 상한을 다시 UTF-8 바이트로 비교합니다. 바이트 수는 출력이 올 때마다 누적해 계산 비용이 적습니다.
  - 자를 때마다 남길 부분을 복사해, 이전 문자열이 해제되도록 했습니다.
  - v0.10.6 의 CPU 개선 효과는 그대로입니다.

### 추가

- **서버 상태 로그에 메모리 내역을 추가했습니다.** 60초마다 남는 `[TerminalObs]` 로그와
  `/api/sessions/telemetry` 에 `memory` 항목이 생겼습니다.
  - `process`: RSS, V8 힙 사용량·전체, external, ArrayBuffer 메모리(MB)
  - `sessions`: 세션 합계. 터미널 버퍼, 마지막 스냅샷 이후 보관 출력, 스냅샷 캐시, 장애 대비 재생 버퍼(MB),
    보관 중인 레코드·팩트 개수
  - `largestSessions`: 가장 큰 세션 5개의 칸 수, 버퍼 줄 수, 추정 MB

  문자열 길이와 버퍼 크기만 읽고 터미널 내용은 읽지 않으므로 비용이 거의 없습니다. 설치된 실행 파일에는
  디버거를 붙일 수 없어서, 설치본의 메모리가 어디에 쓰이는지는 이 로그로 확인할 수 있습니다.

### 테스트

- 바쁜 세션이 많을 때 브라우저와 서버의 CPU·메모리를 재는 측정 테스트를 추가했습니다
  (`perf-memory-probe.spec.ts`).
