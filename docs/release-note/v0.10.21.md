# BuilderGate v0.10.21

## English

### Added

- **Git viewer (read-only).** A session whose folder is a git repository shows a branch chip
  in its bottom bar: the branch, the number of changed paths, and ahead/behind. (#164,
  FR-GIT-001..011)
  - The chip gets shorter in seven steps as the bar gets narrower. The full name stays in
    its label. While the first answer is slow, a "checking" mark holds its place.
  - Click the chip to open the Git window: the commit graph (current branch, all branches,
    or the comparison with the base branch), the commit detail, its files, and the diff.
  - The diff can be unified or split. It can expand hidden context, ignore whitespace, wrap
    lines, and open a working-tree file in the editor. Binary, large, mode-only,
    line-ending-only, symbolic link, LFS, submodule and non-UTF-8 files show a notice.
  - The window keeps itself up to date: an auto-refresh switch, a badge when the list or
    the shown file changed, and a move to the new HEAD after a commit.
  - On a phone (narrower than 900 px) the window is full screen, in three steps: list,
    commit and diff. The browser's back button steps out.
  - A WSL session in a Windows drive (`/mnt/c/...`) uses Windows git. Linux git took about
    35 s for one status there.

### Fixed

- **The server ran out of memory after about 34 hours.** Its terminal emulator kept a record
  of about 3 KB for every hyperlink (OSC 8) that a program redrew in place, and never freed
  it. The heap grew about 106 MB an hour until the V8 limit stopped the server. The server's
  terminal now ignores hyperlinks; browsers still get them and can click them. The status log
  reports what is left (`oscLinkEntries`). (REL-BGSTAB-051)
- **A browser tab left open for days used more and more memory.** (REL-BGSTAB-052)
  - Each terminal reset (showing a tab again, reconnecting) kept the old screen buffer
    in memory, about 20 MB when a hyperlink was on screen. It is now released.
  - A hyperlink redrawn in place added a record every time. It now reuses one, and the
    link still opens.
  - In a hidden browser tab, the Git chip stops asking the server and starts again when
    you come back. An unchanged answer no longer redraws the Git window or the whole app.
- **Other server records that grew without a limit.** Fair-delivery latency samples (past
  about 150,000 a snapshot threw an error), MCP audit events and message assignments, and the
  binary channel group of a closed connection. (REL-BGSTAB-051)
- **Fewer and faster git calls.** The status of a repository whose index another git wrote
  (WSL git, for example) took 3.6 s every time. It is refreshed once, and then takes about
  0.2 s. (PERF-GIT-001)

## 한국어

### 추가

- **Git 보기(읽기 전용).** 세션의 폴더가 git 저장소이면 하단바에 브랜치 칩이 나옵니다. 칩에는
  브랜치, 바뀐 경로 수, 앞섬·뒤처짐이 보입니다. (#164, FR-GIT-001~011)
  - 하단바가 좁아지면 칩이 7단계로 줄어들고, 전체 이름은 칩의 설명에 그대로 남습니다. 첫 응답이
    늦으면 그 자리에 "확인 중" 표시가 먼저 뜹니다.
  - 칩을 누르면 Git 창이 열립니다. 커밋 그래프(현재 브랜치, 모든 브랜치, 기준 브랜치와 비교),
    커밋 상세, 바뀐 파일, diff 를 보여 줍니다.
  - diff 는 한 줄 보기와 좌우 보기를 고를 수 있습니다. 숨은 문맥 펼치기, 공백 무시, 줄바꿈,
    작업 트리 파일을 편집기로 열기도 됩니다. 바이너리, 큰 파일, 권한만 바뀐 파일, 줄 끝만 바뀐
    파일, 심볼릭 링크, LFS, 서브모듈, UTF-8 이 아닌 파일은 안내를 보여 줍니다.
  - 창은 스스로 갱신됩니다. 자동 새로고침을 켜고 끌 수 있고, 목록이나 보고 있는 파일이 바뀌면
    배지가 뜨며, 커밋하면 새 HEAD 로 옮겨 갑니다.
  - 휴대폰(폭 900px 미만)에서는 목록 → 커밋 → diff 세 단계의 전체 화면으로 열립니다. 브라우저의
    뒤로 가기로 한 단계씩 나옵니다.
  - Windows 드라이브(`/mnt/c/...`) 안의 WSL 세션은 Windows git 을 씁니다. 그 경로에서 Linux git
    으로 상태를 한 번 확인하면 약 35초가 걸렸습니다.

### 수정

- **서버가 약 34시간 만에 메모리 부족으로 멈추던 문제.** 서버의 터미널 에뮬레이터가, 프로그램이
  제자리에서 다시 그리는 하이퍼링크(OSC 8)마다 약 3KB 의 기록을 남기고 지우지 않았습니다. 힙이
  시간당 약 106MB 씩 늘어 V8 한도에서 서버가 멈췄습니다. 이제 서버 쪽 터미널은 하이퍼링크를
  무시합니다. 브라우저에는 그대로 전달되어 계속 누를 수 있습니다. 남은 기록 수는 상태 로그
  (`oscLinkEntries`)에 나옵니다. (REL-BGSTAB-051)
- **며칠 동안 열어 둔 브라우저 탭이 메모리를 점점 더 쓰던 문제.** (REL-BGSTAB-052)
  - 터미널을 다시 그릴 때마다(탭을 다시 보거나 다시 연결할 때) 이전 화면 버퍼가 메모리에
    남았습니다. 화면에 하이퍼링크가 있으면 약 20MB 씩입니다. 이제 해제합니다.
  - 제자리에서 다시 그리는 하이퍼링크가 그릴 때마다 기록을 하나씩 더 남겼습니다. 이제 기록
    하나를 다시 쓰고, 링크도 그대로 열립니다.
  - 브라우저 탭이 가려지면 Git 칩이 서버에 묻지 않고, 돌아오면 다시 묻습니다. 응답이 그대로면
    Git 창과 앱 전체를 다시 그리지 않습니다.
- **서버에서 한없이 늘던 다른 기록들.** 공정 전달 지연 표본(약 15만 개를 넘으면 상태 조회가
  오류를 냈습니다), MCP 감사 기록과 메시지 전달 기록, 닫힌 연결의 바이너리 채널 그룹을 정리합니다.
  (REL-BGSTAB-051)
- **git 호출을 줄이고 빠르게 했습니다.** 다른 git(예: WSL 의 git)이 index 를 쓴 저장소는 상태
  확인에 매번 3.6초가 걸렸습니다. 이제 한 번 갱신한 뒤로는 약 0.2초가 걸립니다. (PERF-GIT-001)
