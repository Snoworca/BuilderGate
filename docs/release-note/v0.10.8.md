# BuilderGate v0.10.8

## English

### Fixed

- **A terminal could stay frozen after switching back to its workspace, until the page was
  reloaded.** This happened in tab and grid mode. The terminal kept showing an old screen
  (for example 80 columns wide in a 151-column view) while the program in it kept drawing.
  - Cause: output that arrives while a terminal is hidden is skipped. When the terminal is
    shown again, the browser restores the screen it saved locally. If that copy was missing,
    from another session generation, or a different size, the restore failed. The fallback
    then asked the server for a fresh screen through a screen repair. But the screen repair
    is refused while the terminal waits for its restore, and that wait only ends when a fresh
    screen arrives. So nothing came, and live output kept being skipped while visible.
  - Fix: when the local restore fails, the browser asks the server for the current screen
    directly. If that request cannot be sent, the wait ends so live output is shown again.
  - Found with the diagnostic capture from the in-app debug tools. A new end-to-end test
    hides busy workspaces, removes their saved screens and shows them again. It froze every
    time in grid mode before the fix and passes in both modes after it.

- **The "restored after restart" banner came back on every reload after it was closed.**
  Closing it, or letting it disappear after 5 seconds, was remembered only until the page
  reloaded, while the server keeps the same restore result until the next restart.
  - Each automatic restore now has its own id. The browser remembers the id of the result
    you closed and does not show it again. The next restart has a new id, so its result
    shows as before.

### Tests

- Three frontend unit tests failed or hung on Windows; they now pass on Windows and Linux.
  - `tscBuildLock.test.ts` waited forever: its child processes imported a `C:\...` path,
    which Node's ES module loader rejects.
  - `terminalWidthProviderRollback.test.ts` and `terminalWidthPolicyParity.test.ts` scanned
    `C:\C:\...`, because the directory came from a URL's `pathname`.
- `tools/with-tsc-build-lock.mjs` (used by `npm run build` and `npm run typecheck`) passed
  arguments to the Windows shell without quotes. A path with a space, such as
  `C:\Program Files\nodejs\node.exe`, was split and the exit code was lost. Such arguments
  are now quoted.
- `perf-memory-probe.spec.ts` deleted its workspaces without the ownership check the test
  suite requires; it now uses the owner-checked helper.

## 한국어

### 수정

- **워크스페이스를 옮겨 다니다 돌아오면 터미널이 멈춘 채로 남던 문제를 고쳤습니다.** 새로고침해야만
  풀렸고, 탭 모드와 그리드 모드 모두에서 생겼습니다. 터미널은 예전 화면(예: 151칸 화면에 80칸 폭 내용)을
  계속 보여 주고, 안의 프로그램이 새로 그리는 내용은 나오지 않았습니다.
  - 원인: 숨겨진 터미널에 온 출력은 건너뜁니다. 다시 보일 때 브라우저가 저장해 둔 화면으로 복원하는데,
    저장본이 없거나 세션 세대가 다르거나 크기가 다르면 복원에 실패합니다. 실패하면 화면 수리로 서버에
    현재 화면을 요청하는데, 화면 수리는 복원을 기다리는 동안 거절됩니다. 그 기다림은 서버 화면이 와야
    끝나므로 서로를 기다리며 아무 일도 일어나지 않았고, 보이는 상태에서도 출력이 계속 버려졌습니다.
  - 해결: 로컬 복원이 실패하면 서버에 현재 화면을 바로 요청합니다. 요청을 보내지 못하면 기다림을 끝내
    출력이 다시 화면에 쓰이게 합니다.
  - 앱의 디버그 도구로 받은 진단 파일로 원인을 찾았습니다. 바쁜 워크스페이스를 숨기고 저장된 화면을 지운
    뒤 다시 여는 E2E 테스트를 추가했습니다. 수정 전에는 그리드 모드에서 매번 멈췄고, 수정 후에는 두
    모드 모두 통과합니다.

- **"재시작 후 복구 완료" 배너가 닫은 뒤에도 새로고침할 때마다 다시 나오던 문제를 고쳤습니다.** 닫거나
  5초 뒤 사라진 상태를 새로고침 전까지만 기억했고, 서버는 다음 재시작 전까지 같은 복구 결과를 계속
  돌려줍니다.
  - 이제 자동 복구마다 고유 ID 가 붙습니다. 브라우저는 닫은 결과의 ID 를 기억해 다시 띄우지 않습니다.
    다음 재시작은 새 ID 이므로 그 결과는 이전처럼 표시됩니다.

### 테스트

- Windows 에서 실패하거나 끝나지 않던 프런트엔드 단위 테스트 3개를 고쳤습니다. 이제 Windows 와 Linux
  모두에서 통과합니다.
  - `tscBuildLock.test.ts` 가 끝나지 않았습니다. 자식 프로세스가 `C:\...` 경로를 import 했는데, Node 의
    ES 모듈 로더가 이를 거부합니다.
  - `terminalWidthProviderRollback.test.ts`, `terminalWidthPolicyParity.test.ts` 는 디렉터리를 URL 의
    `pathname` 으로 만들어 `C:\C:\...` 를 읽으려 했습니다.
- `npm run build`·`npm run typecheck` 가 쓰는 `tools/with-tsc-build-lock.mjs` 가 Windows 셸에 인자를 따옴표
  없이 넘겼습니다. `C:\Program Files\nodejs\node.exe` 처럼 공백이 있는 경로가 잘려 종료 코드가 사라졌습니다.
  이런 인자는 이제 따옴표로 감쌉니다.
- `perf-memory-probe.spec.ts` 가 테스트 스위트가 요구하는 소유 확인 없이 워크스페이스를 지웠습니다. 소유를
  확인하는 헬퍼를 쓰도록 바꿨습니다.
