# BuilderGate v0.10.13

## English

### Fixed

- **Input typed right after opening the page was lost.** With many terminals open, text and Enter
  typed in the first seconds after the page opened were never sent, and a reload did not show them.
  - Cause: each new connection made the server validate the published fair-delivery evidence from
    disk again. This work is synchronous and stopped the whole server for it: about 150 ms on
    Windows and about 4 seconds on WSL over /mnt/c. The visible terminal restored late, and input
    that waited longer than the 1.5-second input queue limit was dropped.
  - Fix: an accepted validation result is reused while the evidence on disk is unchanged. Any
    change to the evidence pointer or to a file of the current evidence generation validates from
    disk again, so tampered evidence is still refused. The server also validates once at start-up,
    before it accepts connections.
  - Measured per connection: Windows about 150 ms → 1.5 ms, WSL about 4 s → 180 ms. With 40
    terminals the visible terminal was ready after 0.56–0.73 s instead of 4.35–4.95 s, and no input
    was dropped (13 before). (PERF-BGSTAB-010)

### Changed

- **The installer stops a running BuilderGate on port 2002 before it installs.** Before, the MSI
  stopped an earlier version only on an upgrade, ignored whether that stop worked, and did nothing
  about a portable or source copy that held port 2002.
  - On every install and upgrade, before the installer checks files, it finds what listens on
    ports 2002 and 2001.
  - It stops only a process it recognises as BuilderGate. The sentinel of that BuilderGate is
    stopped first, so it cannot start the app again. Each process is stopped by its own process ID.
  - A program that is not BuilderGate is not stopped, and the install continues.
  - If a BuilderGate is still running after 20 seconds, the install stops with an error.
  (OPS-BGSTAB-021)

- **Starting BuilderGate again while it runs prints one line and exits.** The message is
  `BuilderGate is already running at https://localhost:<port>.` Before, it printed the process IDs
  and then the start-up banner, so it looked as if a second instance had started. A BuilderGate
  from another location on the same port is recognised too. With `--open` (the Start Menu
  shortcut), the running instance still opens in the browser. (FR-BGSTAB-033)

### Added

- **Tab mode shows which tab is working.** While a tab's session is running, a brighter band about
  a tenth of the tab wide moves left and right along the tab's colour bar. It disappears when the
  session becomes idle. If the system asks for reduced motion, the band does not move and the
  colour bar is shown brighter instead. (FR-UIDS-009)

## 한국어

### 수정

- **페이지를 연 직후 입력한 글자가 사라지던 문제를 고쳤습니다.** 터미널을 많이 연 상태에서
  페이지를 열고 처음 몇 초 안에 글자를 치고 Enter 를 누르면, 그 입력이 서버로 가지 않았고
  새로고침해도 보이지 않았습니다.
  - 원인: 새로 연결할 때마다 서버가 공개된 fair-delivery 증거 파일을 디스크에서 처음부터 다시
    검증했습니다. 이 작업은 동기로 돌아서 그동안 서버 전체가 멈췄습니다. Windows 에서는 약
    150ms, WSL 의 /mnt/c 에서는 약 4초였습니다. 그래서 보이는 터미널의 복원이 늦었고, 입력 큐의
    1.5초 제한을 넘긴 입력은 버려졌습니다.
  - 해결: 디스크의 증거가 바뀌지 않았으면 이전에 통과한 검증 결과를 다시 씁니다. 증거 포인터나
    현재 증거 세대의 파일이 하나라도 바뀌면 디스크에서 다시 검증하므로, 변조된 증거는 여전히
    거부합니다. 또 서버가 시작할 때 연결을 받기 전에 한 번 미리 검증합니다.
  - 연결 한 번당 측정: Windows 약 150ms → 1.5ms, WSL 약 4초 → 180ms. 터미널 40개에서 보이는
    터미널이 준비되기까지 4.35~4.95초 걸리던 것이 0.56~0.73초가 되었고, 버려진 입력은 13개에서
    0개가 되었습니다. (PERF-BGSTAB-010)

### 변경

- **설치할 때 2002 포트에서 실행 중인 BuilderGate 를 확실히 종료한 뒤 설치합니다.** 이전에는
  업그레이드할 때만 이전 버전을 종료했고, 종료에 성공했는지 확인하지 않았습니다. 또 포터블이나
  소스 실행본이 2002 포트를 잡고 있으면 아무것도 하지 않았습니다.
  - 설치와 업그레이드 때마다, 파일을 확인하기 전에 2002·2001 포트를 쓰는 프로세스를 찾습니다.
  - BuilderGate 로 확인된 프로세스만 종료합니다. 앱을 다시 띄우지 못하도록 그 BuilderGate 의
    감시 프로세스(sentinel)를 먼저 종료하고, 프로세스마다 자기 PID 로 종료합니다.
  - BuilderGate 가 아닌 프로그램은 종료하지 않고 설치를 계속합니다.
  - 20초가 지나도 BuilderGate 가 남아 있으면 오류를 내고 설치를 멈춥니다.
  (OPS-BGSTAB-021)

- **이미 실행 중일 때 다시 실행하면 한 줄만 출력하고 끝납니다.** 출력은
  `BuilderGate is already running at https://localhost:<port>.` 입니다. 이전에는 프로세스 ID 와
  시작 안내까지 출력해서, 두 번째 인스턴스가 시작된 것처럼 보였습니다. 같은 포트를 다른 위치의
  BuilderGate 가 쓰고 있어도 알아봅니다. `--open`(시작 메뉴 바로가기)으로 실행하면 지금처럼
  실행 중인 BuilderGate 를 브라우저로 엽니다. (FR-BGSTAB-033)

### 추가

- **탭 모드에서 지금 일하고 있는 탭이 보입니다.** 탭의 세션이 동작하는 동안 탭 위쪽 색상 막대를
  따라 탭 너비의 10% 정도 되는 더 밝은 띠가 좌우로 움직입니다. 세션이 쉬면 띠는 사라집니다.
  시스템에서 움직임 줄이기를 켜 두었으면 띠는 움직이지 않고, 대신 색상 막대를 밝게 표시합니다.
  (FR-UIDS-009)
