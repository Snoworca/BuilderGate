# BuilderGate v0.10.26

## English

### Fixed

- **One terminal's screen recovery no longer interrupts the others.** (REL-BGSTAB-055)
  - Before, when the screen recovery of one terminal failed, the browser closed the WebSocket
    that every terminal shares. Then every terminal fetched its screen again at the same time,
    and typed input waited until they finished. With many sessions, this showed as broken
    screens and laggy typing.
  - Now the browser unsubscribes and subscribes again only that terminal, on the same
    connection. The other terminals keep their output and input.
  - The whole connection is opened again only on the third failed attempt in a row for the
    same terminal, or when the connection is already closed.

### Changed

- **The webhook key is sent as `Authorization: Bearer <key>`.** (FR-MCP-014)
  - The webhook header setting is removed from the MCP settings dialog.
  - **Action needed:** a webhook caller that sends the key in the `X-BuilderGate-Webhook-Key`
    header must change to `Authorization: Bearer <key>`. The old header is no longer read. The
    `?key=` query still works.
- **The MCP settings dialog shows the MCP address.** The address an MCP client connects to
  (for example `http://127.0.0.1:3333/mcp`) is shown above the tabs, with a copy button.
  (FR-MCP-014)

### Diagnostics

- The server log records why a connection closed: `[WS] Client disconnected: <id> code=<code>
  reason="<reason>"`. (REL-BGSTAB-054)
- The server log records each terminal recovery that subscribes again, with its reason and
  attempt: `[WS] Session resubscribe: ...`. These lines show which recovery fails most often.
  (REL-BGSTAB-056)

## 한국어

### 수정

- **터미널 하나의 화면 복구가 다른 터미널을 멈추지 않습니다.** (REL-BGSTAB-055)
  - 전에는 터미널 하나의 화면 복구가 실패하면, 모든 터미널이 함께 쓰는 WebSocket 을 브라우저가
    닫았습니다. 그러면 모든 터미널이 한꺼번에 화면을 다시 받고, 그동안 입력이 멈췄습니다.
    세션이 많으면 화면이 깨지고 키 입력이 버벅거리는 것으로 나타났습니다.
  - 이제는 같은 연결에서 그 터미널만 구독을 풀었다가 다시 구독합니다. 다른 터미널은 출력과
    입력이 끊기지 않습니다.
  - 같은 터미널이 세 번 연달아 실패하거나 연결이 이미 닫혀 있을 때만 연결 전체를 다시 엽니다.

### 변경

- **웹훅 키는 `Authorization: Bearer <키>` 로 보냅니다.** (FR-MCP-014)
  - MCP 설정 창에서 웹훅 헤더 설정을 없앴습니다.
  - **조치 필요:** 웹훅 키를 `X-BuilderGate-Webhook-Key` 헤더로 보내던 호출은
    `Authorization: Bearer <키>` 로 바꿔야 합니다. 예전 헤더는 더 이상 읽지 않습니다.
    `?key=` 쿼리 방식은 그대로 동작합니다.
- **MCP 설정 창에 MCP 연결 주소가 나옵니다.** MCP 클라이언트가 접속할 주소(예:
  `http://127.0.0.1:3333/mcp`)를 탭 위에 복사 버튼과 함께 보여 줍니다. (FR-MCP-014)

### 진단

- 서버 로그에 연결이 끊긴 이유를 남깁니다: `[WS] Client disconnected: <id> code=<코드>
  reason="<사유>"`. (REL-BGSTAB-054)
- 터미널 복구로 다시 구독할 때마다 사유와 시도 횟수를 서버 로그에 남깁니다:
  `[WS] Session resubscribe: ...`. 이 로그로 어떤 복구가 가장 자주 실패하는지 알 수 있습니다.
  (REL-BGSTAB-056)
