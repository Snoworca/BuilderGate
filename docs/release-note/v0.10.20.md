# BuilderGate v0.10.20

## English

### Added

- **Drop desktop files on a terminal session to upload them.** Drag files or folders from
  the desktop over a session: a yellow overlay at 15% opacity reads "Drop files here to
  upload". Release them, and they go into that session's current folder through the same
  upload job as the file explorer, with progress on the bottom file-job bar. (FR-FEX-031)
  - A name that is already in the folder is kept as well, as `name (2).ext`. Nothing is
    overwritten.
  - Desktop only. A touch screen or a window narrower than 768 px shows no overlay.

- **Sessions waiting for a GUI editor are announced and can be closed remotely.** When a
  session's shell starts an editor on the server PC (for example Claude Code's Ctrl+G opens
  Notepad), a notice above the terminal names it, with a **Close editor** button. The server
  checks at most every 20 s, only while sessions exist, and closes only the one process it
  confirmed by PID and start time. (#161, FR-ARCH-014)

- **"Redraw screen" in the terminal menu, and redraw in tab view.** The one-row shrink and
  restore that makes a program redraw at its real size now also runs when a terminal in tab
  view becomes visible (including after a reload), and from the new menu item. (#161,
  REL-BGSTAB-050)

### Changed

- **The server no longer stops while it resolves a WSL session's folder.** Every file API
  call of a WSL session ran `wsl.exe wslpath` synchronously, about 330 ms in which the whole
  server (terminal output included) stopped. The conversion now runs asynchronously, without
  a shell, and remembers each answer. A file check in a WSL session went from about 1.8 s to
  40–99 ms. Shell discovery, name-collision checks for upload and extract, the cwd watcher,
  session snapshots and agent-session lookup are asynchronous too. (PERF-BGSTAB-025)

- **"Files on screen" lists only files that can be opened.** The menu checks each path with
  the server before it lists it ("Checking…" while it does), so a file the output only
  mentioned no longer answers "file not found" when picked. The "Open {name}" item at the
  press point goes through the same check. (FR-ARCH-013)

### Fixed

- **Terminals drawn in their top 24 rows, or with wide lines folded over the text.** After
  a server restart, or when another view resized the shared terminal while this one was
  hidden, the server-side terminal kept a size the browser no longer showed (the default
  80×24, or a 270-column width behind a 68-column pane). The browser now sends its size again
  when the connection reopens and when a hidden terminal is shown again. (REL-BGSTAB-038)

- **Delete, move and copy failed in WSL sessions** with "sources must be absolute paths".
  The explorer sends the Linux path the terminal reports; a Windows server now places it
  under the session's WSL share before it checks it. (IR-FOP-001)

- **The terminal menu offered BuilderGate's own cwd file.** A WSL shell prints the line that
  sets up folder tracking, and its `buildergate-cwd-<id>.txt` was offered as "Open"; from a
  WSL home it answered PATH_TRAVERSAL. That file is no longer detected as a path. (#163,
  FR-ARCH-012)

## 한국어

### 추가

- **데스크톱 파일을 터미널 세션 위에 끌어 놓아 업로드합니다.** 데스크톱에서 파일이나 폴더를
  세션 위로 끌어오면 그 세션에 15% 노란 오버레이와 "이곳으로 파일 업로드" 문구가 뜹니다. 놓으면
  파일 탐색기와 같은 업로드 작업으로 그 세션의 현재 폴더에 올라가고, 진행은 하단 파일 작업
  막대에 보입니다. (FR-FEX-031)
  - 폴더에 같은 이름이 있으면 덮어쓰지 않고 `이름 (2).확장자` 로 둘 다 보관합니다.
  - 데스크톱 전용입니다. 터치 화면이나 폭 768px 미만 창에서는 오버레이가 뜨지 않습니다.

- **GUI 편집기를 기다리며 멈춘 세션을 알리고 원격에서 닫습니다.** 세션의 셸이 서버 PC 에
  편집기를 띄우면(예: Claude Code 의 Ctrl+G 가 메모장을 엶) 터미널 위에 편집기 이름과
  **편집기 닫기** 버튼이 나옵니다. 서버는 세션이 있을 때만 최대 20초에 한 번 확인하고, PID 와
  시작 시각으로 확인한 그 프로세스 하나만 닫습니다. (#161, FR-ARCH-014)

- **터미널 메뉴의 "화면 다시 그리기", 탭 보기에서도 다시 그리기.** 프로그램이 실제 크기로 다시
  그리게 하는 "한 줄 줄였다 복원" 을 탭 보기의 터미널이 보이게 될 때(새로고침 뒤 포함)와 새 메뉴
  항목에서도 실행합니다. (#161, REL-BGSTAB-050)

### 변경

- **WSL 세션의 폴더를 풀 때 서버가 멈추지 않습니다.** WSL 세션의 파일 요청마다 `wsl.exe wslpath`
  를 동기로 실행해, 약 330ms 동안 서버 전체(터미널 출력 포함)가 멈췄습니다. 이제 셸을 거치지
  않고 비동기로 실행하며 결과를 기억합니다. WSL 세션의 파일 확인이 약 1.8초에서 40~99ms 가
  됐습니다. 셸 확인, 업로드·압축 해제의 같은 이름 검사, cwd 감시, 세션 스냅샷, 에이전트 세션
  탐색도 비동기로 바꿨습니다. (PERF-BGSTAB-025)

- **"화면의 파일" 은 열 수 있는 파일만 보여 줍니다.** 메뉴가 각 경로를 서버에 먼저 확인하고
  나열합니다(확인하는 동안 "확인 중…"). 출력에 언급만 된 파일을 골라 "파일이 없다" 는 경고를
  받는 일이 없습니다. 누른 자리 근처의 "{이름} 열기" 항목도 같은 확인을 거칩니다. (FR-ARCH-013)

### 수정

- **터미널이 위 24줄에만 그려지거나, 넓은 줄이 글 사이에 접혀 끼던 문제.** 서버가 재시작됐거나,
  이 터미널이 가려진 동안 다른 화면이 같은 터미널의 크기를 바꾸면, 서버 쪽 터미널이 브라우저가
  보여 주지 않는 크기(기본 80×24, 또는 68열 칸 뒤의 270열)에 머물렀습니다. 이제 연결이 다시
  열리거나 가려졌던 터미널이 다시 보일 때 브라우저가 크기를 다시 보냅니다. (REL-BGSTAB-038)

- **WSL 세션에서 삭제·이동·복사가 "sources must be absolute paths" 로 실패하던 문제.** 탐색기는
  터미널이 알려 준 리눅스 경로를 보냅니다. 이제 Windows 서버가 그 경로를 세션의 WSL 공유 아래로
  바꾼 뒤 검사합니다. (IR-FOP-001)

- **터미널 메뉴가 BuilderGate 내부 cwd 파일을 열자고 하던 문제.** WSL 셸은 폴더 추적을 설정하는
  줄을 화면에 찍는데, 그 안의 `buildergate-cwd-<id>.txt` 가 "열기" 로 나왔고 WSL 홈에서는
  PATH_TRAVERSAL 경고가 났습니다. 이제 이 파일은 경로로 인식하지 않습니다. (#163, FR-ARCH-012)
