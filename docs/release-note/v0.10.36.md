# BuilderGate v0.10.36

## English

### Fixed

- **Usage monitoring no longer wakes a stopped WSL and takes the keyboard focus.**
  (FR-USAGE-008, #229)
  - On Windows with no WSL window open, the focus left the app being typed in about twice a
    minute. Usage monitoring read the WSL user's `.claude` and `.codex` over `\\wsl.localhost`
    every minute, both for the server refresh and for the browser panel. Each read started the
    stopped WSL distribution, and each start launched WSLg, whose window took the focus.
  - The WSL folders are now read only while their distribution already runs. While it is
    stopped, the last WSL usage stays on screen. Affected 0.10.32 to 0.10.35.
- **Tabs opened by session restore appear at once.** (FR-AITUI-022, #226)
  - Restore said it was done, but its new tabs showed only after a reload, and restoring again
    opened the same tabs twice. Every open browser now gets the new tabs right away.
- **The session save button names the selection.** (FR-AITUI-023, #227)
  - It read **Save all (0)** with nothing selected. It now reads **Save N selected**, as the
    restore tab's **Restore N selected** does.

## 한국어

### 수정

- **사용량 감시가 멈춘 WSL을 깨워 포커스를 빼앗지 않습니다.** (FR-USAGE-008, #229)
  - Windows에서 WSL 창을 열지 않은 채로 쓰면, 타이핑하던 프로그램의 포커스가 1분에 두 번쯤
    빠져나갔습니다. 사용량 감시가 서버 갱신과 브라우저 패널 요청 때마다 WSL 홈의 `.claude`와
    `.codex`를 `\\wsl.localhost` 경로로 읽었기 때문입니다. 읽을 때마다 멈춰 있던 WSL이 다시
    켜졌고, 그때마다 WSLg 창이 떠서 포커스를 가져갔습니다.
  - 이제 WSL 폴더는 그 배포판이 이미 실행 중일 때만 읽습니다. 멈춰 있는 동안에는 마지막으로 읽은
    WSL 사용량을 그대로 보여 줍니다. 0.10.32~0.10.35에 있던 문제입니다.
- **세션 복구로 연 탭이 바로 보입니다.** (FR-AITUI-022, #226)
  - 복구가 끝났다고 표시되어도 새 탭이 새로고침해야 보였고, 다시 복구하면 같은 탭이 두 벌
    열렸습니다. 이제 열려 있는 모든 브라우저에 새 탭이 바로 나타납니다.
- **세션 저장 버튼이 선택한 개수를 보여 줍니다.** (FR-AITUI-023, #227)
  - 아무것도 고르지 않아도 **모두 저장 (0)**으로 보였습니다. 이제 복구 탭의 **선택한 N개 복구**처럼
    **선택한 N개 저장**으로 보입니다.
