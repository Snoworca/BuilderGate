# BuilderGate v0.10.22

## English

### Changed

- **The Git chip and window start far fewer git processes.** On Windows each git process costs
  tens to hundreds of milliseconds to start, and WSL sessions also started a new `wsl.exe` each
  time. (PERF-GIT-001)
  - The chip's check runs one git process. HEAD and the base branch are read from the
    repository's ref files.
  - The first diff after a click uses at most four git processes. It reuses the chip's last
    check.
  - A Windows repository where nothing changed answers from a file watch, without git, for up
    to 30 s. Any change, or a failed watch, asks git again.
  - A WSL session keeps one helper per distribution, so `wsl.exe` starts once. In the measured
    repository, a WSL check took 38 ms instead of 553 ms, and the first diff 60 ms instead of
    3.1 s.
  - git starts from worker threads, so starting it no longer holds up terminal output.
  - The index is refreshed after a check slower than 150 ms (it was 1 s).
- **MCP messages name the real sending session.** When a message names its sender, the
  receiving session sees `[from: <alias> · sessionKey <key> · sessionId <id>]` and knows where
  to reply. Before, it saw `[from: external MCP client]`. A message that names no sender gets
  no tag. (FR-MCP-011)
- **README.** The README now describes the Git viewer, file drop upload, the file explorer and
  session saves, with new screenshots.

## 한국어

### 변경

- **Git 칩과 Git 창이 띄우는 git 프로세스가 크게 줄었습니다.** Windows 에서는 git 프로세스를
  하나 띄울 때마다 수십~수백 ms 가 걸리고, WSL 세션은 그때마다 `wsl.exe` 도 새로 띄웠습니다.
  (PERF-GIT-001)
  - 칩의 상태 확인은 git 프로세스 하나만 씁니다. HEAD 와 기준 브랜치는 저장소의 ref 파일에서
    읽습니다.
  - 칩을 누른 뒤 첫 diff 까지는 git 프로세스를 최대 4개 씁니다. 칩이 직전에 확인한 결과를 다시
    씁니다.
  - Windows 저장소에서 바뀐 것이 없으면, 파일 감시로 확인하고 git 없이 최대 30초 동안
    답합니다. 무엇이든 바뀌거나 감시가 실패하면 git 으로 다시 확인합니다.
  - WSL 세션은 배포판마다 헬퍼 하나를 띄워 두므로 `wsl.exe` 를 한 번만 띄웁니다. 측정한
    저장소에서 WSL 상태 확인이 553ms 에서 38ms 로, 첫 diff 가 3.1초에서 60ms 로 줄었습니다.
  - git 은 worker thread 에서 띄웁니다. git 을 띄우는 동안 터미널 출력이 멈추지 않습니다.
  - 상태 확인이 150ms 를 넘으면 index 를 갱신합니다(전에는 1초).
- **MCP 메시지에 실제로 보낸 세션이 표시됩니다.** 보낸 세션을 지정한 메시지에는
  `[from: <별칭> · sessionKey <키> · sessionId <ID>]` 가 붙습니다. 받은 세션이 어디로 답할지
  알 수 있습니다. 전에는 `[from: external MCP client]` 만 붙었습니다. 보낸 세션을 지정하지
  않은 메시지에는 아무것도 붙지 않습니다. (FR-MCP-011)
- **README.** Git 보기, 파일 끌어다 놓기 업로드, 파일 탐색기, 세션 저장을 설명하고 새
  스크린샷을 넣었습니다.
