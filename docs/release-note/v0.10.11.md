# BuilderGate v0.10.11

## English

### Added

- **Session auto save.** BuilderGate now saves every terminal at a fixed interval, so the sessions
  can come back after the server is killed (for example when the machine runs out of memory with
  dozens of sessions open).
  - On by default, every 5 minutes. In Settings you can turn it off or change the interval
    (5 minutes or more).
  - The save runs without blocking the server, so terminals do not stall or stutter while it runs.
  - Session ids that cannot be found for certain are saved anyway, marked as estimated.
  - The auto save has one slot and each run overwrites it.
  (FR-AITUI-016, FR-AITUI-019, NFR-AITUI-001)

- **A list of manual saves.** Each press of the session save button adds one save to a list. In
  Settings you choose how many recent saves to keep (10 by default); older ones are deleted.
  (FR-AITUI-017)

- **The restore tab and a header restore button.** The session save window has a **Restore** tab.
  It shows the auto save at the top and the manual saves by date below. Pick a save, pick its
  terminals, and restore them by hand. A new **Restore sessions** button in the header opens this
  tab directly. It works even when the save button is disabled because no AI session is running,
  for example right after a reboot. (FR-AITUI-018)

### Changed

- **Every start restores the newest save.** When BuilderGate starts, it restores the newer of the
  newest manual save and the auto save, even if an earlier start already used that save.
  (FR-AITUI-018 AC-1)
- **The "restored after restart" banner is shown once.** The server records that the notice was
  shown. A reload, a reconnect or another browser does not show it again; the next restart shows
  its own. (FR-AITUI-018 AC-3)

### Upgrading

- The old single file `data/session-snapshot.json` moves into the manual save list.
- If every entry in it was already restored by an earlier start, the first start after the
  upgrade does not type it again. It is still in the list: open **Restore sessions** and restore
  it by hand.
- New data files: `data/session-autosave.json`, `data/session-snapshots/` and
  `data/session-restore-state.json`.

## 한국어

### 추가

- **세션 자동 저장.** 정해진 간격마다 모든 터미널을 저장합니다. 세션을 수십 개 띄워 쓰다 메모리
  부족으로 서버가 강제 종료되어도 세션을 되살릴 수 있습니다.
  - 기본으로 켜져 있고 5분마다 저장합니다. 설정에서 끄거나 간격을 바꿀 수 있습니다(5분 이상).
  - 저장은 서버를 막지 않고 진행되므로, 저장하는 동안에도 터미널이 멈추거나 끊기지 않습니다.
  - 확실히 찾지 못한 세션 id 도 "추정" 으로 표시해 일단 저장합니다.
  - 자동 저장본은 한 칸에만 저장하며, 저장할 때마다 덮어씁니다.
  (FR-AITUI-016, FR-AITUI-019, NFR-AITUI-001)

- **직접 저장본 목록.** 세션 저장 버튼을 누를 때마다 저장본이 목록에 하나씩 쌓입니다. 최근 몇 개까지
  보관할지는 설정에서 정합니다(기본 10개). 오래된 것부터 지웁니다. (FR-AITUI-017)

- **복구 탭과 헤더의 복구 버튼.** 세션 저장 창에 **복구** 탭이 생겼습니다. 맨 위에 자동 저장본을,
  그 아래에 직접 저장본을 날짜별로 보여 줍니다. 저장본과 터미널을 골라 직접 복구할 수 있습니다.
  헤더에 새로 생긴 **세션 복구** 버튼을 누르면 이 탭이 바로 열립니다. 재부팅 직후처럼 실행 중인 AI
  세션이 없어 세션 저장 버튼이 비활성일 때도 이 버튼은 쓸 수 있습니다. (FR-AITUI-018)

### 변경

- **시작할 때마다 가장 최근 저장본을 복구합니다.** BuilderGate 가 시작되면 가장 최근 직접 저장본과
  자동 저장본 중 더 최근 것을 복구합니다. 이전 시작에서 이미 쓴 저장본이라도 다시 씁니다.
  (FR-AITUI-018 AC-1)
- **"재시작 뒤 복구됨" 배너는 한 번만 뜹니다.** 배너를 띄웠다는 사실을 서버가 기록합니다. 새로고침,
  재접속, 다른 브라우저에서는 다시 뜨지 않고, 다음 재시작의 복구 결과는 새로 뜹니다.
  (FR-AITUI-018 AC-3)

### 업그레이드할 때

- 예전의 단일 파일 `data/session-snapshot.json` 은 직접 저장본 목록으로 옮겨집니다.
- 그 파일의 항목이 모두 이전 시작에서 이미 복구된 것이면, 업그레이드 뒤 첫 시작은 그것을 다시
  입력하지 않습니다. 목록에는 남아 있으니 **세션 복구** 버튼을 눌러 직접 복구하세요.
- 새 데이터 파일: `data/session-autosave.json`, `data/session-snapshots/`,
  `data/session-restore-state.json`.
