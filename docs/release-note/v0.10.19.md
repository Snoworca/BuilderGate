# BuilderGate v0.10.19

## English

### Added

- **Install the macOS runtime with Homebrew.** `brew install snoworca/tap/buildergate`
  installs the arm64 command-line runtime from the release ZIP. (FR-BGSTAB-035)
  - Config, certificates and state live in `var/buildergate`, so they survive an upgrade.
    The default config is copied once; a later install keeps your file.
  - `brew services` runs the daemon in the foreground.
  - Homebrew-core needs a source build and homebrew-cask needs a notarized app, so the
    runtime is published through a tap with a command-line formula.

- **Open context menus with a double tap on touch screens.** Two quick taps (within 300 ms
  and 24 px) open the same menu a long press opens, everywhere a long press works: the
  terminal, grid tiles, explorer rows, workspace and editor tabs, the editor title bar and
  body, the sidebar and the status bar path. (#157, FR-UIDS-013)
  - On Android a long press also summons the assistant, which is why the double tap was
    added. Long press still works, and mouse double click is unchanged.
  - The second tap raises no click: it does not select, open a file, start a rename or zoom.
    On the terminal and grid tiles it also puts the on-screen keyboard away first.
  - Folders in the file explorer now have an **Open** entry, so entering a folder no longer
    needs a double tap.

### Changed

- **Mobile: the file explorer and the editor cover the whole screen.** They filled only the
  terminal area, leaving the header and the tab bar above them; they now take the whole app
  area. With the on-screen keyboard open they end where the keyboard begins. Desktop windows
  are unchanged. (#159, FR-UIDS-014)

- **MCP: a submit delivery waits 1000 ms before its Enter.** The default base wait goes from
  150 ms to 1000 ms, so a short prompt now waits 1050 ms. The per-KB wait (50 ms per started
  1024 characters), the 0–5000 ms range and the 10 s cap are unchanged. A value already saved
  stays as it was and can be changed in **Tools > MCP settings**. (FR-MCP-002)

- **Mobile: Ctrl, Alt and Shift lock after a shorter hold.** The hold that locks a modifier
  from the key bar goes from 1500 ms to 750 ms, and the fill on the key rises over the same
  750 ms. A release before 750 ms is still a single-use tap. (FR-MKB-002)

### Fixed

- **A revealed tab could stay blank until you switched away and back (Android).** The reveal
  fitted the terminal once, in the next frame, and repainted only from that fit. A frame
  without a size — the layout moves as the keyboard closes — or a fit the write coordinator
  held dropped the repaint, and the next convergence check refits only when the size differs,
  so the freshly attached renderer never painted. (#155, REL-BGSTAB-049)
  - The reveal now re-checks at 0, 120, 400 and 1000 ms, submits the fit at the first check
    with a size, and schedules a full repaint either way. Hiding the tab cancels the rest.
  - The terminal host re-measures on the same schedule when it becomes visible, so a box that
    moved while the keyboard closed cannot leave the terminal parked off screen.
  - The regression spec counts the light pixels of printed text in a screenshot, so a blank
    canvas fails whatever the DOM reports.

- **Mobile: a tab or view-mode switch could look ignored.** The screen changed only after the
  PATCH round trip, so mobile latency, a token refresh or a queued connection made the tap
  look lost and it got tapped again; a failed PATCH never switched at all. (#156,
  PERF-BGSTAB-024)
  - The switch now shows at once and saves behind. One request runs at a time per workspace
    and field, and values set meanwhile collapse to the latest, so the server ends on the last
    selection whatever order the responses arrive in. A failed save keeps the selection on
    screen and reports the error.
  - A selection is held as pending until its save finishes, so refreshed server data and a
    `workspace:updated` broadcast can no longer revert a tab tapped just after loading.

- **A selection inside one line showed no highlight in the code editor.** Code mode painted
  the active line with an opaque panel colour, which covered the selection drawn beneath it —
  all of a one-line selection, and the cursor's line of a multi-line one. The active line is
  now translucent, and code mode paints the selection with the accent at 30% instead of the
  reader's faint tint. Affects code files, the raw Markdown view and the read-only code view.
  (#158, FR-MDE-029)

- **Mobile: Ctrl locked from the key bar + v did not paste.** The latch re-encoded the typed
  v into `^V` and sent it to the program, which is what the key bar does for every letter,
  while on a desktop Ctrl+V is the paste shortcut. Ctrl (or a single-use Ctrl) with v or V and
  Alt off now pastes the clipboard through the same path the menus use, and sends nothing
  else. Any other character, and Ctrl+Alt+v, keep the old re-encoding. (FR-MKB-014)

## 한국어

### 추가

- **macOS 런타임을 Homebrew 로 설치합니다.** `brew install snoworca/tap/buildergate` 로 릴리즈
  ZIP 의 arm64 명령줄 런타임을 설치합니다. (FR-BGSTAB-035)
  - 설정·인증서·상태는 `var/buildergate` 에 두므로 업그레이드해도 남습니다. 기본 설정은 처음
    한 번만 복사하고, 다시 설치해도 쓰던 파일을 그대로 둡니다.
  - `brew services` 로 데몬을 띄울 수 있습니다.
  - homebrew-core 는 소스 빌드를, homebrew-cask 는 공증된 앱을 요구해서 명령줄 formula 를 담은
    tap 으로 배포합니다.

- **터치 화면에서 두 번 탭으로 컨텍스트 메뉴를 엽니다.** 300ms·24px 안에 두 번 탭하면 길게 누를
  때와 같은 메뉴가 열립니다. 길게 누르기가 되는 곳이면 모두 됩니다. 터미널, 그리드 타일, 탐색기
  행, 워크스페이스·편집기 탭, 편집기 제목 표시줄과 본문, 사이드바, 상태 표시줄 경로. (#157,
  FR-UIDS-013)
  - 안드로이드에서는 길게 누르면 어시스턴트도 함께 떠서 두 번 탭을 넣었습니다. 길게 누르기는
    그대로 되고, 마우스 더블클릭도 전과 같습니다.
  - 두 번째 탭은 클릭을 일으키지 않습니다. 선택·파일 열기·이름 바꾸기·확대가 일어나지 않습니다.
    터미널과 그리드 타일에서는 화면 키보드를 먼저 내립니다.
  - 파일 탐색기의 폴더에 **열기** 항목이 생겨서, 폴더로 들어갈 때 두 번 탭하지 않아도 됩니다.

### 변경

- **모바일: 파일 탐색기와 편집기가 화면 전체를 덮습니다.** 터미널 영역만 채워서 헤더와 탭 바가
  위에 남아 있었습니다. 이제 앱 영역 전체를 차지합니다. 화면 키보드가 올라오면 키보드가 시작하는
  곳에서 끝납니다. 데스크톱 창은 그대로입니다. (#159, FR-UIDS-014)

- **MCP: submit 전달이 Enter 전에 1000ms 기다립니다.** 기본 대기가 150ms 에서 1000ms 로
  바뀌어서, 짧은 프롬프트는 이제 1050ms 를 기다립니다. KB 당 대기(1024자마다 50ms), 0–5000ms
  범위, 10초 상한은 그대로입니다. 이미 저장한 값은 바뀌지 않으며 **도구 > MCP 설정**에서 바꿀 수
  있습니다. (FR-MCP-002)

- **모바일: Ctrl·Alt·Shift 가 더 짧게 눌러도 잠깁니다.** 키 바에서 수식키를 잠그는 누름이
  1500ms 에서 750ms 로 줄었고, 키에 차오르는 표시도 같은 750ms 동안 찹니다. 750ms 전에 떼면
  전처럼 한 번만 쓰는 탭입니다. (FR-MKB-002)

### 수정

- **탭을 전환하면 터미널이 비어 보이고, 다른 탭에 갔다 와야 보이던 문제 (안드로이드).** 탭이
  드러날 때 다음 프레임에서 한 번만 크기를 맞추고 그 결과로만 다시 그렸습니다. 크기가 없는
  프레임(키보드가 닫히면서 배치가 움직입니다)이거나 쓰기 조정자가 그 맞춤을 붙잡으면 다시 그리기가
  사라졌고, 다음 수렴 검사는 크기가 달라야만 다시 맞추므로 새로 붙은 렌더러는 끝내 그려지지
  않았습니다. (#155, REL-BGSTAB-049)
  - 이제 0·120·400·1000ms 에 다시 확인해서, 크기가 있는 첫 확인에서 맞춤을 넣고 어느 쪽이든 전체
    다시 그리기를 겁니다. 탭을 숨기면 남은 확인을 취소합니다.
  - 터미널 호스트도 보이게 될 때 같은 간격으로 다시 잽니다. 키보드가 닫히며 상자가 움직여도
    터미널이 화면 밖에 남지 않습니다.
  - 회귀 테스트는 화면을 찍어 출력된 글자의 밝은 픽셀을 세므로, DOM 이 뭐라 하든 빈 캔버스는
    실패합니다.

- **모바일: 탭이나 보기 모드를 바꿔도 반응이 없어 보이던 문제.** PATCH 왕복이 끝나야 화면이
  바뀌어서, 모바일 지연·토큰 갱신·줄 선 연결 때문에 탭이 무시된 것처럼 보이고 다시 탭하게
  됐습니다. PATCH 가 실패하면 아예 바뀌지 않았습니다. (#156, PERF-BGSTAB-024)
  - 이제 화면을 먼저 바꾸고 뒤에서 저장합니다. 워크스페이스와 항목마다 요청을 하나씩 보내고 그
    사이에 바뀐 값은 마지막 것으로 모이므로, 응답이 어떤 순서로 오든 서버는 마지막 선택으로
    끝납니다. 저장이 실패하면 화면의 선택은 그대로 두고 오류를 알립니다.
  - 선택은 그 저장이 끝날 때까지 대기 상태로 남습니다. 새로 읽은 서버 데이터나 `workspace:updated`
    알림이 방금 탭한 탭을 되돌리지 않습니다.

- **코드 편집기에서 한 줄 안의 선택이 보이지 않던 문제.** 코드 모드가 커서가 있는 줄을 불투명한
  패널 색으로 칠해서, 그 아래에 그려지는 선택을 덮었습니다. 한 줄 선택은 전부, 여러 줄 선택은
  커서가 있는 줄이 보이지 않았습니다. 이제 그 줄을 반투명하게 칠하고, 코드 모드는 선택을 흐린
  읽기 모드 색 대신 강조색 30% 로 칠합니다. 코드 파일, 마크다운 원본 보기, 읽기 전용 코드 보기에
  적용됩니다. (#158, FR-MDE-029)

- **모바일: 키 바에서 Ctrl 을 잠그고 v 를 눌러도 붙여넣지 않던 문제.** 키 바가 모든 글자에 하는
  대로 v 를 `^V` 로 바꿔 프로그램에 보냈는데, 데스크톱에서는 Ctrl+V 가 붙여넣기입니다. 이제 Ctrl
  (한 번 쓰기든 잠금이든)에 Alt 가 꺼진 상태로 v 나 V 를 누르면 메뉴와 같은 경로로 클립보드를
  붙여넣고 다른 것은 보내지 않습니다. 다른 글자와 Ctrl+Alt+v 는 전처럼 바꿔 보냅니다.
  (FR-MKB-014)
