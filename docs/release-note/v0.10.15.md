# BuilderGate v0.10.15

## English

### Added

- **Mobile terminal keyboard.** A phone's system keyboard has no arrow keys, Esc, Ctrl or F keys.
  BuilderGate now adds them in mobile mode. (#133, FR-MKB-001…011)
  - **Key bar:** when the terminal has focus, a bar sits directly above the system keyboard with
    Esc, Tab, Ctrl, Alt, the arrow keys, Home, End, PgUp and PgDn. It scrolls sideways when it does
    not fit. The terminal area shrinks so the prompt line stays visible.
  - **Lockable Ctrl, Alt and Shift:** a short tap applies the modifier to the next key only (blue
    text and underline). A 1.5-second press locks it (orange light and a short vibration on
    Android); tap again to release. The modifier also applies to letters typed on the system
    keyboard, for example Ctrl then `c` sends Ctrl+C. Only these three keys lock, and each shows a
    dot in its corner.
  - **Special keyboard:** the keyboard button swaps the system keyboard for a panel with F1–F12,
    an edit and symbol block, and a cross of arrow keys with Home, End, PgUp, PgDn, Ins and Del.
    Tapping the terminal while the panel is open does not bring the system keyboard back. The
    panel's right block switches to a numpad, and the choice is remembered on that device.
  - Arrow keys follow the program's cursor mode, so they work in vim and less. Desktop is
    unchanged.

- **MCP: open files in the editor.** New tools `buildergate.editor.open_markdown` (a file, or
  text saved to `.buildergate/mcp-docs/`), `open_code` and `open_image` open a file in the
  browser's editor window, switching to its workspace first. Paths are checked the same way as the
  file API. Scope `mcp:editor.open`; a session agent can open only for its own terminal.
  (FR-MCP-012)

- **Image viewer: previous and next.** `‹ n / m ›` and the ←/→ keys move through the images in the
  same folder in the same tab. (FR-MDE-027)

- **Download a file.** The file explorer's context menu and the mobile action bar can download a
  single file. The server checks the path and hands out a one-time token valid for 60 seconds.
  (FR-FEX-021)

- **Mobile file explorer:** pressing an entry for 1.5 seconds opens it like a double tap. The
  0.5-second menu is unchanged. (FR-FEX-020)

### Fixed

- **Terminal text was huge and cut off in browser device emulation.** With a device pixel ratio
  above 1 in Chrome's device mode, the terminal drew its glyphs 2–3 times too large.
  - Cause: under that emulation the browser reports the canvas size in CSS pixels, and the WebGL
    renderer sized its canvas from that value while drawing at the device pixel ratio.
  - Fix: after attaching WebGL, and after a resize, a reveal or a change of device pixel ratio,
    the terminal compares the canvas with CSS size × device pixel ratio. If they differ by more
    than 1 pixel, it switches to the DOM renderer. Real devices report matching sizes and keep
    WebGL. (REL-BGSTAB-046)

- **The scroll position jumped back to the bottom** in programs that redraw continuously, such as
  Claude Code, right after you scrolled up. A large write now scrolls to the bottom only when the
  view was already at the bottom. (FR-ARCH-009)

- **Mobile: window close buttons did not respond to a tap**, because the title bar's drag handler
  swallowed the touch. (#127, FR-UIDS-010)

- **Mobile: a one-finger drag in a full-screen program** (vim, less, an agent TUI) now scrolls the
  same way as the mouse wheel on desktop. (FR-ARCH-008)

## 한국어

### 추가

- **모바일 터미널 키보드.** 휴대폰의 시스템 키보드에는 방향키, Esc, Ctrl, F 키가 없습니다.
  이제 모바일 모드에서 BuilderGate 가 이 키들을 제공합니다. (#133, FR-MKB-001~011)
  - **키 줄:** 터미널에 포커스가 있으면 시스템 키보드 바로 위에 Esc, Tab, Ctrl, Alt, 방향키,
    Home, End, PgUp, PgDn 줄이 붙습니다. 화면보다 길면 옆으로 밀어서 봅니다. 터미널 영역이 그만큼
    줄어들어 프롬프트 줄이 가려지지 않습니다.
  - **잠글 수 있는 Ctrl·Alt·Shift:** 짧게 누르면 다음 한 키에만 적용됩니다(파란 글자와 밑줄).
    1.5초 누르면 잠기고, 주황 불이 켜지며 Android 에서는 짧게 진동합니다. 다시 누르면 풀립니다.
    시스템 키보드로 친 글자에도 적용되어, 예를 들어 Ctrl 을 누른 뒤 `c` 를 치면 Ctrl+C 가 갑니다.
    잠글 수 있는 키는 이 셋뿐이며 오른쪽 위의 점으로 구분합니다.
  - **특수 키보드:** 키보드 버튼을 누르면 시스템 키보드 대신 F1~F12, 편집·기호 블록, 십자형
    방향키와 Home·End·PgUp·PgDn·Ins·Del 이 있는 패널이 뜹니다. 패널이 열린 동안 터미널을 눌러도
    시스템 키보드가 다시 올라오지 않습니다. 패널 오른쪽 블록은 숫자패드로 바꿀 수 있고, 그
    선택을 기기마다 기억합니다.
  - 방향키는 프로그램의 커서 모드를 따라가므로 vim·less 에서도 동작합니다. 데스크톱 동작은
    바뀌지 않습니다.

- **MCP: 편집기에서 파일 열기.** 새 도구 `buildergate.editor.open_markdown`(파일, 또는
  `.buildergate/mcp-docs/` 에 저장되는 텍스트), `open_code`, `open_image` 가 브라우저의 편집기
  창에서 파일을 엽니다. 필요하면 그 워크스페이스로 먼저 전환합니다. 경로 검사는 파일 API 와
  같습니다. 권한은 `mcp:editor.open` 이며, 세션 에이전트는 자기 터미널 기준으로만 열 수
  있습니다. (FR-MCP-012)

- **이미지 뷰어 이전·다음.** `‹ n / m ›` 와 ←/→ 키로 같은 폴더의 이미지를 같은 탭에서 넘겨
  봅니다. (FR-MDE-027)

- **파일 다운로드.** 파일 탐색기의 오른쪽 버튼 메뉴와 모바일 버튼 줄에서 파일 하나를 내려받을
  수 있습니다. 서버가 경로를 검사한 뒤 60초 동안 한 번만 쓸 수 있는 토큰을 줍니다. (FR-FEX-021)

- **모바일 파일 탐색기:** 항목을 1.5초 누르고 있으면 두 번 탭한 것처럼 열립니다. 0.5초 메뉴는
  그대로입니다. (FR-FEX-020)

### 수정

- **브라우저 기기 에뮬레이션에서 터미널 글자가 크게 잘려 보이던 문제를 고쳤습니다.** Chrome
  기기 모드에서 화면 배율(DPR)이 1보다 크면 터미널 글자가 2~3배로 커져 그려졌습니다.
  - 원인: 그 에뮬레이션에서는 브라우저가 캔버스 크기를 CSS 픽셀로 알려 주는데, WebGL 렌더러는
    그 값으로 캔버스 크기를 정하고 글자는 화면 배율만큼 키워 그렸습니다.
  - 해결: WebGL 을 붙인 뒤, 그리고 크기가 바뀌거나 다시 보이거나 화면 배율이 바뀐 뒤 캔버스
    크기를 `CSS 크기 × 화면 배율` 과 비교합니다. 1 px 넘게 다르면 DOM 렌더러로 바꿉니다. 실제
    기기에서는 두 값이 맞으므로 WebGL 을 그대로 씁니다. (REL-BGSTAB-046)

- **스크롤 위치가 맨 아래로 되돌아가던 문제를 고쳤습니다.** Claude Code 처럼 화면을 계속 다시
  그리는 프로그램에서 위로 올리면 곧바로 맨 아래로 돌아갔습니다. 이제 큰 출력이 와도 이미 맨
  아래를 보고 있을 때만 맨 아래로 맞춥니다. (FR-ARCH-009)

- **모바일: 창 닫기 버튼이 탭에 반응하지 않던 문제를 고쳤습니다.** 제목 표시줄의 드래그
  처리기가 터치를 가로챘기 때문입니다. (#127, FR-UIDS-010)

- **모바일: 전체 화면 프로그램(vim, less, 에이전트 TUI)에서 한 손가락으로 끌면** 데스크톱의
  마우스 휠과 같은 방식으로 스크롤됩니다. (FR-ARCH-008)
