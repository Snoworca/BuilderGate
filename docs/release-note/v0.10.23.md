# BuilderGate v0.10.23

## English

### Fixed

- **Codex 0.164 sessions are found again for saving and resuming.** (FR-AITUI-006)
  - A tab opened with `codex resume <id>` and left idle got no session id. Codex 0.164
    takes a reopened thread's lock only when the thread writes again. The id now comes from
    the tab's own `codex resume <id>` command.
  - Two Codex tabs in one folder could get the same id, which belonged to another tab. Since
    0.157, Codex records its terminal threads as if an editor started them. Terminal threads
    are now told apart by their originator.
  - When you start another thread inside the tab (`/new`, `/resume`), the tab follows it.
  - A session id that another tab holds is not given to a second tab.

## 한국어

### 수정

- **Codex 0.164 세션을 다시 찾아 저장하고 이어 열 수 있습니다.** (FR-AITUI-006)
  - `codex resume <id>` 로 연 뒤 쉬고 있는 탭에서 세션 ID 를 찾지 못했습니다. Codex 0.164 는
    다시 연 스레드를 다시 쓸 때에만 잠그기 때문입니다. 이제 그 탭의 `codex resume <id>`
    명령에서 ID 를 읽습니다.
  - 같은 폴더의 Codex 탭 두 개가 같은 ID 를 받을 수 있었고, 그 ID 는 다른 탭의 것이었습니다.
    0.157 부터 Codex 가 터미널 스레드를 편집기에서 띄운 것처럼 기록하기 때문입니다. 이제
    originator 로 터미널 스레드를 구분합니다.
  - 탭 안에서 다른 스레드를 열면(`/new`, `/resume`) 그 스레드를 따라갑니다.
  - 다른 탭이 가진 세션 ID 를 다시 주지 않습니다.
