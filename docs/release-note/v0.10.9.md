# BuilderGate v0.10.9

## English

### Fixed

- **On macOS, adding a terminal did not create a session.** Every attempt failed with
  `posix_spawnp failed.`, both in the packaged app and when running from source. Windows and
  Linux were not affected.
  - Cause: on macOS, node-pty starts every terminal through a small helper program,
    `spawn-helper`, that ships with it. node-pty 1.1.0 publishes that file without the execute
    permission, so it cannot be run. In the packaged app the helper is also inside the
    executable's built-in file system, which macOS cannot run programs from at all. Windows and
    Linux start terminals without this helper.
  - Fix: on macOS, BuilderGate now makes sure the helper can be run before a terminal starts. If
    the file only lacks the permission, the permission is added. If that is not possible (a
    read-only install) or the file is inside the packaged app, an executable copy is placed in
    the system temp folder and used instead. Nothing changes on Windows or Linux.
  - Checked in a real browser on macOS, from source and with the packaged app: log in, add a
    terminal, run a command, and the output appears.

### Tests

- Three checks failed on macOS for reasons unrelated to the product; they now pass on macOS
  as well.
  - `build-portable-runtime-evidence.test.mjs` created its files in the temp folder, which on
    macOS is reached through a symbolic link (`/var` → `/private/var`). The check that rejects
    symbolic links refused every case. The test now uses the real path.
  - A shell fallback test assumed zsh was missing but asked the real machine, and macOS always
    has zsh. The test now states that assumption itself.
  - The consumer manifest check read test output in a format that Node 22 does not print by
    default. The output format is now set explicitly.

## 한국어

### 수정

- **macOS 에서 터미널을 추가해도 세션이 만들어지지 않던 문제를 고쳤습니다.** 패키지 앱과 소스 실행
  모두에서 매번 `posix_spawnp failed.` 로 실패했습니다. Windows 와 Linux 에는 영향이 없었습니다.
  - 원인: macOS 의 node-pty 는 함께 들어 있는 작은 도우미 프로그램 `spawn-helper` 를 거쳐 터미널을
    시작합니다. node-pty 1.1.0 이 이 파일을 실행 권한 없이 배포해 실행할 수 없었습니다. 패키지 앱에서는
    이 파일이 실행파일 내부의 파일 시스템에 있어서, 권한과 상관없이 macOS 가 실행할 수 없었습니다.
    Windows 와 Linux 는 이 도우미 없이 터미널을 시작합니다.
  - 해결: macOS 에서는 터미널을 시작하기 전에 도우미를 실행할 수 있는지 확인합니다. 권한만 없으면 권한을
    줍니다. 그럴 수 없거나(읽기 전용 설치) 패키지 앱 내부의 파일이면, 실행할 수 있는 사본을 시스템 임시
    폴더에 만들어 그것을 씁니다. Windows 와 Linux 의 동작은 바뀌지 않습니다.
  - macOS 에서 소스 실행과 패키지 앱 모두 실제 브라우저로 확인했습니다. 로그인하고 터미널을 추가해
    명령을 실행하면 결과가 나옵니다.

### 테스트

- 제품과 무관한 이유로 macOS 에서만 실패하던 검사 3개를 고쳤습니다. 이제 macOS 에서도 통과합니다.
  - `build-portable-runtime-evidence.test.mjs` 는 임시 폴더에 파일을 만드는데, macOS 의 임시 폴더는
    심볼릭 링크(`/var` → `/private/var`)를 거칩니다. 심볼릭 링크를 거부하는 검사가 모든 경우를
    거절했습니다. 이제 실제 경로를 씁니다.
  - 대체 셸 테스트가 zsh 가 없다고 가정하면서 실제 기기에 물었는데, macOS 에는 항상 zsh 가 있습니다.
    이제 테스트가 그 가정을 직접 정합니다.
  - 소비자 매니페스트 검사가 Node 22 가 기본으로 출력하지 않는 형식으로 테스트 결과를 읽었습니다. 이제
    출력 형식을 명시합니다.
