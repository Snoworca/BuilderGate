# BuilderGate v0.11.2

## English

### Changed

- **Agents started in a BuilderGate terminal join their session by themselves.** (FR-MCP-026)
  - Type `claude`, `claude --resume <id>` or `codex` in any BuilderGate terminal; the agent is
    bound to that terminal's session with no claim code and no MCP config change.
    `buildergate.session.whoami` and the room tools (`buildergate.room.*`) work at once.
  - The server finds the process behind a local MCP connection and walks up to the terminal it was
    started in.
  - Regenerating the MCP key no longer cuts terminal agents off: an agent in a terminal keeps its
    session even with an old key (or none). Clients outside BuilderGate terminals still need the
    current key.
  - After BuilderGate restarts, agents carry on with the connection they had; no `/mcp` reconnect.
  - Without a valid key only an agent CLI itself (Claude Code, Codex, OpenCode, Hermes) is let in.
    A tunnel or proxy started in a terminal (`ssh -R`, ngrok, cloudflared) gets nothing.
- **`session.claim` works over the MCP key.** (FR-MCP-025)
  - An agent connected with the MCP key can call `buildergate.session.claim` with the one-time code
    from MCP settings; that same connection is then bound. Nothing else to configure.

## 한국어

### 변경

- **BuilderGate 터미널에서 띄운 에이전트는 알아서 자기 세션에 붙습니다.** (FR-MCP-026)
  - BuilderGate 터미널에서 `claude`, `claude --resume <id>`, `codex` 를 직접 입력해도 그 터미널의
    세션으로 붙습니다. 연결 코드도, MCP 설정 변경도 필요 없습니다.
    `buildergate.session.whoami` 와 대화방 도구(`buildergate.room.*`)가 바로 동작합니다.
  - 서버가 로컬 MCP 연결을 보낸 프로세스를 찾고, 그 프로세스가 어느 터미널에서 실행됐는지
    따라 올라가 확인합니다.
  - MCP 키를 재생성해도 터미널 안 에이전트는 끊기지 않습니다. 이전 키를 쓰거나 키가 없어도
    자기 세션으로 계속 동작합니다. BuilderGate 터미널 밖의 클라이언트는 지금처럼 현재 키가
    필요합니다.
  - BuilderGate 를 다시 시작해도 에이전트는 쓰던 연결로 계속 동작합니다. `/mcp` 재연결이 필요
    없습니다.
  - 유효한 키 없이 붙을 수 있는 것은 에이전트 CLI(Claude Code, Codex, OpenCode, Hermes)
    자신뿐입니다. 터미널에서 띄운 터널이나 프록시(`ssh -R`, ngrok, cloudflared)는 아무 권한도
    얻지 못합니다.
- **MCP 키 연결에서도 `session.claim` 이 동작합니다.** (FR-MCP-025)
  - MCP 키로 연결한 에이전트가 MCP 설정 창에서 발급한 일회성 코드로
    `buildergate.session.claim` 을 부르면, 그 연결이 바로 세션에 묶입니다. 따로 설정할 것이
    없습니다.
