# BuilderGate v0.10.14

## English

### Fixed

- **The login kept dropping around a token refresh.** The page was disconnected and the login
  screen came back, often while the browser was in use.
  - Cause: a refresh revoked the old token at once. A request that still carried the old token,
    sent while the refresh was in progress, got 401 before the browser had stored the new token,
    and the browser treated that 401 as a logout.
  - Fix: a refreshed token stays valid for a grace period and is revoked after it. A second
    refresh of the same token keeps the first deadline. Logout still revokes the token at once.
  - In the browser, a request that gets 401 while this page's refresh is in progress waits for
    the refresh and tries once more with the new token. It logs out only if that also fails.
  - New setting `auth.refreshGraceSeconds`: default 180 seconds, 0 to 3600, shown in the
    Authentication section of Settings. A saved value applies to the next refresh without a
    restart. With 0 the old token is revoked at once, as before. (REL-BGSTAB-045)

### Added

- **Skip the login screen on this computer.** New setting `auth.localhostNoAuth` (default off,
  in the Authentication section of Settings). When it is on, a browser on this computer opens the
  app without the login screen. A connection from another computer still needs the password and
  any second factor.
  - The server gives the token only when all of these are true: the connection comes from
    loopback, the Host is localhost, 127.0.0.1 or [::1], the Origin is absent or one of those,
    and no proxy header (X-Forwarded-For, Forwarded, X-Real-IP) is present. Otherwise it refuses
    and logs why.
  - A saved change applies at once, without a restart. (FR-BGSTAB-034)

- **MCP: read a terminal without typing into it.** New tool `buildergate.terminal.read` returns
  the last lines of a terminal (screen and scrollback, default 40, 1 to 200) and writes nothing to
  the terminal. The terminal is chosen the same way as for `buildergate.terminal.exec`. It needs
  the same permission as exec (`mcp:terminals.exec`). (FR-MCP-009)

- **MCP: agents learn your agent launch commands.** The server instructions and the
  `buildergate.terminal.exec` description now list your registered agent aliases and the agent
  each one starts, for example `claudep (Claude Code), codexp (Codex)`. An orchestrating agent
  runs them as given instead of first investigating them. A changed alias applies from the next
  connection. (FR-MCP-010)

- **MCP: messages between sessions can say who sent them.** `buildergate.message.send` (default
  off) and `buildergate.message.reply_to_leader` (default on) accept `includeSender`. When it is
  on, the server puts a one-line tag in front of the text, built from the authenticated caller:
  `[from: <alias> · sessionKey <key>]`, or `[from: external MCP client]` for a fixed access key.
  A text that itself starts with `[from:` is changed to `(from:` so that it cannot pose as a
  tag. (FR-MCP-011)

## 한국어

### 수정

- **토큰 갱신 즈음에 로그인이 자꾸 풀리던 문제를 고쳤습니다.** 사용하는 중에 페이지 연결이
  끊기고 로그인 화면이 다시 나타나곤 했습니다.
  - 원인: 토큰을 갱신하면 이전 토큰을 바로 폐기했습니다. 갱신이 진행되는 동안 이전 토큰으로
    보낸 요청은 브라우저가 새 토큰을 저장하기 전에 401 을 받았고, 브라우저는 이 401 을
    로그아웃으로 처리했습니다.
  - 해결: 갱신된 토큰을 유예 시간 동안 계속 받아 주고, 그 뒤에 폐기합니다. 같은 토큰을 두 번
    갱신해도 처음 정한 기한을 유지합니다. 로그아웃하면 지금처럼 바로 폐기합니다.
  - 브라우저는 이 페이지의 갱신이 진행 중일 때 받은 401 이면 갱신이 끝나기를 기다렸다가 새
    토큰으로 한 번 더 시도합니다. 그것마저 실패할 때만 로그아웃합니다.
  - 새 설정 `auth.refreshGraceSeconds`: 기본 180초, 0~3600초이며 설정 화면의 인증 섹션에
    있습니다. 저장한 값은 재시작 없이 다음 갱신부터 적용됩니다. 0 이면 이전처럼 바로
    폐기합니다. (REL-BGSTAB-045)

### 추가

- **이 컴퓨터에서는 로그인 화면을 건너뜁니다.** 새 설정 `auth.localhostNoAuth`(기본 꺼짐,
  설정 화면의 인증 섹션)를 켜면, 이 컴퓨터의 브라우저는 로그인 화면 없이 앱을 엽니다. 다른
  컴퓨터에서 접속하면 지금처럼 비밀번호와 2단계 인증이 필요합니다.
  - 서버는 다음을 모두 만족할 때만 토큰을 줍니다. 연결이 loopback 에서 오고, Host 가
    localhost·127.0.0.1·[::1] 중 하나이고, Origin 이 없거나 그 셋 중 하나이며, 프록시 헤더
    (X-Forwarded-For, Forwarded, X-Real-IP)가 없어야 합니다. 그렇지 않으면 거절하고 이유를
    로그에 남깁니다.
  - 저장하면 재시작 없이 바로 적용됩니다. (FR-BGSTAB-034)

- **MCP: 입력 없이 터미널 내용을 읽습니다.** 새 도구 `buildergate.terminal.read` 는 터미널의
  마지막 줄들(화면과 스크롤백, 기본 40줄, 1~200줄)을 돌려주고 터미널에는 아무것도 쓰지
  않습니다. 터미널을 고르는 방법은 `buildergate.terminal.exec` 와 같고, 권한도 exec 와 같은
  `mcp:terminals.exec` 가 필요합니다. (FR-MCP-009)

- **MCP: 에이전트가 사용자의 에이전트 실행 명령을 압니다.** 서버 지침과
  `buildergate.terminal.exec` 설명에 등록한 에이전트 별칭과 각각이 실행하는 에이전트가
  들어갑니다(예: `claudep (Claude Code), codexp (Codex)`). 그래서 오케스트레이션하는 에이전트가
  미리 조사하지 않고 그대로 실행합니다. 별칭을 바꾸면 다음 연결부터 반영됩니다. (FR-MCP-010)

- **MCP: 세션 사이 메시지에 보낸 쪽을 표시할 수 있습니다.** `buildergate.message.send`(기본
  꺼짐)와 `buildergate.message.reply_to_leader`(기본 켜짐)에 `includeSender` 를 넣을 수
  있습니다. 켜면 서버가 인증된 호출자를 바탕으로 본문 앞에 한 줄 태그를 붙입니다:
  `[from: <별칭> · sessionKey <키>]`, 고정 액세스 키면 `[from: external MCP client]`. 본문이
  `[from:` 으로 시작하면 `(from:` 으로 바꿔서 태그로 위장하지 못하게 합니다. (FR-MCP-011)
