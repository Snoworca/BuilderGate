> **관측된 drift (승급·수정 없이 기록만 함)**: FR-BGSTAB-008 AC-6 은 Wave 0 완료 시점에 frontend runtime residency 가 "legacy/observe/direct default switches" 를 넘어 활성화되지 않는다고 규정한다. 그러나 resolved 값은 `frontendRuntimeResidency = bounded` 로, 그 문면의 기본 스위치 집합에 속하지 않는다. 사실만 기록하고 AC·Status·Stability 를 변경하지 않는다.

### 4.4 신규 결함 — 고정 포트 2222 경로의 프로세스 내 재사용 실패

### 4.7 guard 의 거부 규칙은 "TCP 여부" 가 아니라 "이름 접두" 다

`frontend/playwright.config.ts`:

| 행 | 값 |
| --- | --- |
| `:3` | `baseURL = process.env.PLAYWRIGHT_BASE_URL ?? 'https://localhost:2222'` |
| `:46` | `webServer.command = 'cd .. && start.bat --port 2222'` |
| `:48` | `reuseExistingServer: **true**` |

**결정**: `npx playwright test` 는 2222 가 비어 있으면 **`start.bat` 으로 실서버를 띄운다.**

`tools/start-runtime.js` 의 "A different BuilderGate daemon is already running" 거부(`tools/daemon/launcher.js:603`)는 `inspectExistingDaemonState`(`:491-494`)가 **해석된 root 의 state file 만** 보고 판정한다. §2 에서 확인했듯 root 는 `BUILDERGATE_ROOT` → packaged → source root 순이고 이 세션의 상속 `BUILDERGATE_*` 는 0개이므로 root 는 이 worktree 다. 따라서 **§1 의 production PID 30596(별도 root, 별도 state file)은 이 거부를 유발하지 않는다.** CLAUDE.md 가 기록한 거부 사례는 daemon state 가 이 root 에 남아 있을 때의 이야기다.

그럼에도 이 경로를 쓰지 않는 이유는 다르다 — `start.bat` 은 daemon 을 기동하며 이 checkout 의 daemon state·로그·인증서를 생성/변경하고, 종료 소유권이 Playwright 가 아니라 daemon 에 넘어간다. **소유권을 명시적으로 유지하기 위해** E2E 레인은 반드시 **이 checkout 의 `server/dist/index.js` 를 `NODE_ENV=production PORT=2222` 로 직접 띄운 뒤** `reuseExistingServer` 가 그것을 재사용하게 해야 한다.
