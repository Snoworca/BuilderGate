## 0. 이 문서가 주장하는 것과 주장하지 않는 것

**주장한다**

- 서버 회귀의 **전체 수집이 실제로 nonempty** 이며, 실행 계층을 나누어도 **`server/src/**/*.test.ts` 커버리지 손실이 0** 이다(§2).
- 각 실행 계층의 **정직한 특성화** — 명령·cwd·수집 수·counts·실패 이름(§3, §4).
- guard 의 **이름 접두 false positive 3건을 실제로 제거**했고, 그 수정이 RED→GREEN 과 mutation battery 로 입증된다(§5).

**주장하지 않는다**

- **어떤 계층도 green 이 아니다.** 이 호스트에서 green 은 달성 대상이 아니다(§6).
- 어떤 Requirement 의 Status·Stability·AC 도 승급하지 않는다.
- 이슈 본문은 `REL-BGSTAB-001 AC-1..3` 을 지목하지만 **AC-2·AC-3 은 frontend 범위**(focused frontend unit / frontend production build)이며 RG-07 이 담당한다. 이 작업은 **AC-1 만** 다룬다. 불일치를 재해석하지 않고 그대로 기록한다.
- `WsRouterSplitHandshake.test.ts` 의 todo 13건은 #3 이 **0B(deferred/superseded, `REL-BGSTAB-024`)** 로 닫은 계약이다. 관측만 하고 green 으로 만들지 않았다(§4.4).
- Playwright·E2E·`authority-promotion-evidence`(계층 B 의 두 번째 항목)는 server 범위 밖이므로 실행하지 않았다(§6.5).
- `tools/daemon`·`tools/wave1`·`tools/wave3` 스위트는 RG-06 의 §9.1·§9.4 범위 밖이므로 실행하지 않았다.
- **종료한 프로세스가 0개라는 것은 이 번들로 재현할 수 없는 부정 주장이다.** 같은 요구사항의 RG-04 증거(VE-10)가 같은 한계를 명시했다. 이 작업은 어떤 kill 도 수행하지 않았고 외부 서버를 기동하지 않았으나, 그 사실을 증명하는 아티팩트는 존재하지 않는다 — 번들이 실제로 보이는 것은 §1 의 보호 포트 관측뿐이다.

## 0.1 측정 대상 트리 — 실행마다 다르다

**단일 "측정 HEAD" 는 존재하지 않는다.** guard 수정 전후로 실행이 갈리므로 실행 단위마다 명시한다.

| T2b, T3, T4, T4b, T5, T5b, T6×3 | `a6c7edc` (불변) | 1차 수정본 | 1차 수정본 |

| T1c, T2e, T5d, T5-default×3, GREEN2, RED2 | `a6c7edc` (불변) | RED2 는 `a6c7edc` 사본, 나머지는 **최종 guard** | 3차본 |

`server/src/**` 는 이 작업 전 구간에서 `a6c7edc` 와 **바이트 동일**하다 — 변경된 추적 파일은 `server/tools/` 의 기존 두 파일, 신규 `server/tools/owned-http-test-pipe-guard.test.cjs`, `server/package.json`, 루트 `package.json`, 생성 파일 `kiwi/.status.json`, 그리고 `docs/` 아래다. 따라서 모든 실행의 **제품 코드 대상은 동일**하고, 갈리는 것은 guard 뿐이다.

### 0.1.1 T2 는 깨끗한 baseline 이 아니다 — T2c 가 대체한다

초판은 T2 를 "무변경 트리의 baseline" 으로 제시했다. **그 진술은 부정확했다.** T2 는 132.5초 동안 돌았고 그 구간 안에서 guard 자기검사 파일과 guard 구현이 편집되었으며, RED·GREEN 자기검사 프로세스 두 개가 동시에 돌았다. T2 가 **로드한** guard 는 수정 전 모듈이 맞지만, 트리와 프로세스 환경은 실행 중에 변했다.

그래서 **T2c 를 별도로 측정했다**: `server/src/**` 는 손대지 않은 채, `a6c7edc` 의 guard 사본을 스크래치패드에서 `--require` 로 주입하고 다른 측정 프로세스 없이 단독 실행했다. 실행 중 **측정 대상(`server/`)은 바뀌지 않았다** — 하네스가 자기 로그를 증거 디렉터리에 쓰는 것은 모든 실행에 공통이며 §6.4 가 명시적으로 예외로 둔다. **선재 판정의 근거는 T2 가 아니라 T2c 다.**

## 1. 보호 대상 프로세스 — 실행 전후 실측

### 1.1 관측 아티팩트

| 파일 | 시점 |
| --- | --- |
| `raw/netstat-before-R1-20260916T202951Z.txt` | 1차 라운드 모든 실행 이전 |
| `raw/netstat-before-T3-20260916T203908Z.txt` | 2222 를 점유한 실행의 직전 |
| `raw/netstat-after-T3-20260916T203908Z.txt` | 그 실행의 직후 |
| `raw/ports-after-tierC-20260916T203806Z.txt` | 19999–39999 을 점유한 실행의 직후 |
| `raw/env-and-ports-round2-before-*.txt` / `raw/env-and-ports-round2-after-*.txt` | 2차 라운드 전후 (환경 변수·HEAD 포함) |
| `raw/env-and-ports-round3-before-*.txt` / `raw/env-and-ports-round3-after-*.txt` | 3차 라운드 전후 (동일) |
| `raw/env-and-ports-round4-before-*.txt` / `raw/env-and-ports-round4-after-*.txt` | 4차 라운드 전후 (동일) |
| `raw/env-and-ports-round5-before-*.txt` / `raw/env-and-ports-round5-after-*.txt` | 5차 라운드 전후 (동일) |

열두 관측 모두에서 아래 네 행이 동일하다(아래는 **열을 줄인 요약**이며 원문은 foreign address 열과 CRLF 을 포함한다).

```
TCP  0.0.0.0:2001  LISTENING  30596
TCP  0.0.0.0:2002  LISTENING  30596
TCP  [::]:2001     LISTENING  30596
TCP  [::]:2002     LISTENING  30596
```

### 1.2 이 관측이 증명하는 것과 증명하지 않는 것

- **증명한다**: 보존된 열두 시점 전부에서 PID 30596 이 2001·2002 를 LISTENING 한다.
- **증명하지 않는다 — 2222 의 해제.** 1차 라운드의 `netstat-*.txt` 세 개는 `netstat.exe -ano | grep LISTENING` 을 `2001|2002|2222` 로 **필터해서 저장한 것**이다(필터는 이 문단이 유일한 기록이며 아티팩트 자체에는 남아 있지 않다. 2–5차 라운드 파일은 필터를 파일 안에 적는다). 따라서 그 출력에 2222 행이 없다는 것은 **그 시점 Windows 뷰에 2222 LISTENING 행이 없었다**는 뜻이지만, 이 문서가 §1.3 에서 인정하듯 **WSL 이 호스팅하는 리스너의 Windows 측 표기는 신뢰할 수 없다.** 그러므로 "2222 가 해제되었다" 는 이 번들로 강하게 입증되지 않는다. 강한 증거는 2–5차 라운드의 **필터하지 않은 WSL 측 `ss -ltn`** 이며, 거기에 2222 도 19999–39999 도 없다.
- **증명하지 않는다 — before/after 의 구분.** `netstat-before-T3` 와 `netstat-after-T3` 는 파일명이 같은 실행 시작 스탬프를 공유하고(두 파일 모두 실행 시작 시각으로 이름 붙었다) **바이트 동일**하다. 따라서 두 아티팩트만으로는 어느 쪽이 사후 관측인지 구분할 수 없다. 더 넓게 보면 1차 라운드의 `netstat-*.txt` **세 개가 모두 같은 해시**이므로, `netstat-before-R1` 의 "모든 실행 이전" 이라는 이름표도 파일 자체로는 구별되지 않는다 — 구별은 파일명과 이 문서의 서술에만 있다. RG-04 증거(VE-10)가 같은 성질을 명시한 것과 동일한 한계다.

### 1.3 포트 점유 요약

- 2222 는 계층 B 실행 중 **runner 프로세스 내부에서만** 바인드되었다(`test-runner.ts` 의 `invokeLoopbackLoginOverTcp` 와 direct-TLS 리스너). 외부 서버를 기동하지 않았고 `stop.bat` 을 호출하지 않았다.
- 19999–39999 은 계층 C 의 `terminalWireFormatBoot.test.ts` 가 스스로 인접 2포트를 확보·해제한다. 테스트가 포트 번호를 출력하지 않아 **점유한 정확한 번호는 기록되지 않았다.**
- 해제 확인은 WSL 측 `ss -ltn` 을 근거로 한다. `ports-after-tierC-*.txt` 의 Windows 구간에 보이는 22112·24282–24285·32847·34581 은 **이 checkout 과 무관한 Windows 프로세스**이며, WSL 리스너는 원리상 그 표에 자신의 WSL PID 로 나타나지 않는다.

### 5.1 문제

guard 의 허용 이름 패턴은 `buildergate-http-<pid>-<uuid>` 하나만 인정했다. 그런데 `WsRouterRestoreMetadata.test.ts` 의 `createLocalEndpoint` 는 동일한 pid+uuid 규율로 **`buildergate-ws-<pid>-<uuid>`** 라는 unix socket(또는 named pipe)을 만든다. ### 5.2 RED → GREEN (TDD)

자기검사 `server/tools/test-owned-http-test-pipe.cjs` 에 먼저 케이스를 추가했다. 허용되어야 할 것은 `buildergate-ws-<pid>-<uuid>` 의 전달이고, 계속 거부되어야 할 것은 닫힌 집합 밖의 종류·다른 프로세스 소유·uuid 형식 위반이다.

RED: `raw/RED-guard-selfcheck-20260916T203126Z.log` — `B0_FORBIDDEN_TCP_LISTEN` 이 **`ws` 전달 단언 지점에서** 발생한다. 그 로그의 스택은 `a6c7edc` 의 guard 바이트와 오류 문구까지 일치하므로 RED 가 수정 전 guard 에 대해 돈 것이 확인된다. corpus 가 바뀔 때마다 같은 성질을 다시 확인했고 **최종본의 RED 는 `raw/RED4-guard-selfcheck-vs-a6c7edc-*.log`** 다 — 최종 corpus 를 `a6c7edc` guard 사본 옆에서 돌려 `EXIT=1` 로 끝난다.

수정: 허용 이름을 `buildergate-<kind>-<pid>-<uuid>` 로 일반화하되 **kind 를 `['http','ws']` 닫힌 집합**으로 고정했다. pid 일치와 uuid 형식, tmpdir 직하위, `.sock` 접미(비-Windows), named pipe 접두(Windows) 검사는 전부 그대로다. 메시지는 원인을 정확히 말하도록 고쳤고, 오류 `code` 는 불변이다 — 다른 테스트가 `code` 로 판정한다.

GREEN: 최종본의 증거는 `raw/GREEN4-guard-selfcheck-final-*.log` 이며 `{"platform":"linux","rejected":36,"rejectedOutsideCorpus":7,"forwardedToCapturedOriginal":3,"openHandles":false}` 와 `EXIT=0` 을 담는다. **corpus 가 바뀔 때마다 이 아티팩트도 다시 캡처했다** — `GREEN-…log` 는 1차 corpus(`rejected:21`, 전달 2), `GREEN2-…log` 는 3차(36, 전달 2), `GREEN3-…log` 는 4차(36+5, 전달 3), `GREEN4-…log` 가 최종(36+7, 전달 3)이다. 넷 다 보존하되 **최종본의 증거는 GREEN4 하나**임을 여기서 고정한다.

출력 필드의 성질을 정확히 적는다. `rejected` 는 corpus 배열의 크기, `rejectedOutsideCorpus` 는 배열 밖에서 따로 단언하는 다섯 형태(무인자 `listen()`, 뒤쪽 인자에 opt-out 을 실은 두 형태, `http.Server` 두 건)의 수, `forwardedToCapturedOriginal` 은 치환된 원본에 도달한 호출 수로 셋 다 측정값이다. `openHandles` 는 소켓에서 읽어 오지만 **guard 에 대한 측정이 아니라 안전 난간**이다 — `listen` 이 guard 로드 이전에 치환되므로 어떤 경로로도 참이 될 수 없다. 초판이 출력하던 상수 `actualBinds: 0` 은 "바인드가 없었다" 를 증거처럼 보이게 했으므로 제거했고, 같은 비판이 `openHandles` 에도 부분적으로 적용된다는 사실을 소스 주석과 여기에 함께 적는다. guard 가 실제로 구동되었다는 증거는 별도 채널이다 — §5.4 의 wrapper 가 `BUILDERGATE_B0_GUARD_LOG` 를 켜고 **guard 자신이 남긴 이벤트 수**를 corpus 크기와 대조한다.

회귀: T2c(20 FAIL) → T2d·T2e(각 17 FAIL). 사라진 3건 전부가 `B0_FORBIDDEN_TCP_LISTEN` 이고 **새로 늘어난 실패 이름은 0건**이다. A1 은 T1·T1b·T1c 에서 실패 이름 집합이 동일하다.

### 5.3 kind 는 정규식에 보간되므로 리터럴임을 강제한다 — 그리고 그 강제의 한계

kind 문자열은 `RegExp` 에 그대로 들어간다. 메타문자가 섞이면 허용 이름이 조용히 넓어진다. 그래서 guard 는 로드 시점에 모든 kind 가 `/^[a-z0-9]+$/` 인지 검사하고 위반 시 `B0_INVALID_OWNED_ENDPOINT_KIND` 로 **모듈 로드를 실패시킨다.**

**이 검사가 덮는 것은 kind 배열뿐이다.** 그것을 둘러싼 패턴 템플릿 자체를 고쳐 대안을 넓히는 편집(`…join('|')}|zz)-`)이나 구분자를 선택적으로 만드는 편집(`})-?${'$'}{process.pid}`)은 이 검사를 지나간다. 그래서 자기검사 corpus 에 **닫힌 집합 밖의 kind 토큰 여섯 개**(`zz`·`htt`·`httpx`·`ws2`·`w`·`h`)와 **구분자 없는 형태**를 넣어, 그런 편집이 관측되게 했다. §5.5 의 `kind-template-widen`·`pid-separator-optional` mutant 가 그 두 편집이고, 둘 다 killed 다.

부수 효과도 적어 둔다. 이 파일은 `--require` preload 로 쓰이므로 **로드 실패는 그 프로세스 전체의 실패**다. `NODE_OPTIONS` 에 걸어 두었다면 무관한 node 프로세스까지 같이 죽는다. 안전 가드에 대해서는 조용한 통과보다 큰 소리로 실패하는 편이 옳다고 판단했으나, 그 대가를 모르고 겪지 않도록 기록한다.

### 5.4 자기검사를 실제로 수집되는 표면에 올렸다 — 그리고 그 표면을 실재하게 만들었다

기존 자기검사는 `*.test.*` 이름 규약 밖이어서 어떤 glob·npm 스크립트·워크플로도 수집하지 않았다 — **B0 guard 의 유일한 자기검사가 자동으로는 한 번도 돌지 않았다.**

신규 `server/tools/owned-http-test-pipe-guard.test.cjs` 가 자기검사를 자식 프로세스로 돌린다. 다만 `server/tools/*.test.*` 를 부르는 스크립트도 **원래 존재하지 않았다** — CLAUDE.md 가 그 칸에 "스크립트 없음" 이라고 적어 둔 그대로다. 그래서 두 단계로 실재하게 만들었다.

1. `server/package.json` 에 `test:tools` 추가: `node --test --test-concurrency=1 tools/*.test.*`. 동시성 1은 §4.5 의 실행 계약이므로 스크립트에 박아 둔다. 호출은 `npm --prefix server run test:tools` 이며 cwd 는 `server/` 다.
2. 루트의 `test:release-pipeline` 체인에 **wrapper 파일 하나를** 끼워 넣었다. **스크립트를 만들기만 하고 아무도 부르지 않으면 표면은 여전히 실재하지 않는다.**

   처음에는 `npm --prefix server run test:tools` 를 통째로 체인에 넣었다가 되돌렸다. 그 스크립트는 `server/tools/*.test.*` 전부를 돌리고 그중 `fair-scheduler-checkout-provenance.test.mjs` 는 **gitignore 된 `server/dist` 를 요구**한다. 그래서 체인에는 `server/dist` 를 요구하지 않는 `server/tools/owned-http-test-pipe-guard.test.cjs` 만 넣는다. 4차 라운드의 `release-pipeline-gate` 로그는 되돌리기 전 구성의 기록이다.

   **이 되돌리기가 게이트의 dist 의존을 없앤 것은 아니다.** 실측하면 `server/dist` 가 없는 트리에서 이 게이트는 여전히 실패한다 — 다만 실패 지점은 이 작업이 건드리지 않은 기존 단계 `test:authority-pin` 이고(`server build must emit the compiled canary`), 그 단계는 `a6c7edc` 이전부터 그랬다. 즉 **게이트는 원래 dist 를 전제하고 있었고**, 이 작업이 한 일은 거기에 두 번째 dist 의존을 더할 뻔한 것을 되돌린 것뿐이다. 기존 의존은 이 작업의 범위 밖이며 §7 에 결함으로 보고한다.

   게이트 전체를 돌려 3단계가 모두 통과하고 `docs/analysis/terminal-fairness-authority` 에 사후 `git status` 가 비어 있음을 확인했다(최신 `raw/release-pipeline-gate-*.log`). 그 실행은 `server/dist` 가 있는 트리에서 이루어졌다.

   **`test:tools` 자체는 여전히 자동으로 불리지 않는다.** 체인에 들어간 것은 wrapper 파일 하나이고, 그것은 루트 `node --test` 가 기본 동시성으로 돌린다(파일이 하나이므로 §4.5 의 경합은 일어나지 않는다). 동시성 1 계약을 강제하는 자동 실행은 없으며, 그것을 이 작업의 성과로 주장하지 않는다.

wrapper 의 케이스 넷:

| 케이스 | 무엇을 막는가 |
| --- | --- |
| corpus 크기·전달 수를 **정확히** 단언 | 부등호였다면 앵커·디렉터리 케이스를 지워도 통과한다 |
| `BUILDERGATE_B0_GUARD_LOG` 를 켜고 **guard 자신이 남긴 이벤트 수**를 대조 | 자기검사가 올바른 JSON 만 출력하고 아무것도 실행하지 않는 경우를 잡는다. 앞 케이스의 수치는 자식이 스스로 고른 값이므로 그것만으로는 구동을 증명하지 못한다 |
| `process.platform` 을 강제해 **이 레인이 타지 않는 분기**로 자기검사를 한 번 더 실행 | posix 레인은 named pipe 절을, win32 레인은 owned 디렉터리·`.sock` 절을 영원히 밟지 않는다 |
| guard 소스에 메타문자 kind 를 심어 로드가 거부되는지 확인 | §5.3 의 계약 |

자식 환경은 명시적으로 구성한다 — 운영자의 `BUILDERGATE_B0_GUARD_LOG` 를 상속해 그 파일에 이벤트를 흘리지 않고, `NODE_TEST_*` 를 제거해 재귀 가드로 인한 공허한 통과를 막는다.

계층 A0 #3 결과: 스크립트를 실제로 경유한 T5e·T5f 에서 5파일 **37/37, exit 0**.

### 5.5 mutation battery — 자기검사가 공허하지 않음의 증거

**재실행 가능한 스크립트로 커밋했다**: `guard-mutation-battery.mjs` (이 문서와 같은 디렉터리). guard 사본에 결함을 하나씩 심고 **두 표면**(자기검사, wrapper)을 각각 돌린다. 모든 작업은 새 임시 디렉터리에서 일어나고 저장소를 건드리지 않으며, 자기검사가 guard 로드 이전에 `listen` 을 치환하므로 소켓은 하나도 열리지 않는다.

```
node docs/analysis/2026-09-17.rg06-regression/guard-mutation-battery.mjs
```

판정 기준은 **"비동등 mutant 중 두 표면 모두에서 살아남은 것이 0건"** 이다. 한 표면에서만 죽는 것은 결함이 아니다 — 두 표면은 상보적이고, wrapper 는 자기검사가 원리상 닿을 수 없는 곳(다른 플랫폼 분기, 로드 시점 검증)을 덮는다.

현재 결과: 최신 `raw/guard-mutation-battery-current-*.log`, **`result=PASS`, exit 0**, mutant **28개**. exit code 는 세 값을 구분한다 — `0` PASS, `1` 검토 필요, `2` 잘못된 호출.

mutant 28개 중 다섯은 `ownedEndpoint` 술어가 아니라 **`allowed` 식 자체**를 공격하고(다른 subject 클래스 두 종류, 무인자 `listen()`, 환경 변수 backdoor, 뒤쪽 인자의 opt-out), 둘은 **guard 가 남기는 이벤트 로그의 내용**을 망가뜨린다. 술어만 공격하는 corpus 는 앞 부류에 구조적으로 눈이 멀기 때문에 자기검사가 `http.Server`·`https.Server` subject 와 무인자 호출과 뒤쪽 인자 형태를 직접 들고 있고, 로그 부류는 wrapper 가 `firstType`·`first` 페이로드를 단언해 잡는다.

**이 부류가 전부 열거된 것은 아니며, 원리상 열거될 수 없다.** 고정 corpus 는 한 프로세스의 정해진 호출 집합이므로, 호출 순번·시각·argv·환경 변수처럼 그 집합 밖에 방아쇠를 둔 guard 결함은 어떤 유한 corpus 로도 보이지 않는다. 독립 리뷰가 그런 mutant(`nth-call-escape`·`time-escape`·`argv-escape`)를 실제로 만들어 두 표면을 모두 통과시켰다. 이 문서는 그것을 **닫힌 계약이 아니라 표본**으로 선언한다 — 자기검사 파일 끝에도 같은 한계를 적어 두었다. battery 가 사는 이유는 "모든 결함을 잡는다" 가 아니라 **"덮는다고 적은 불변식 하나하나가 실제로 하중을 받는다"** 를 보이는 데 있다.

| 한 표면에서만 죽는 mutant | 이유 |
| --- | --- |
| `kind-validation-removed` | 자기검사는 로드 시점 검증을 볼 수 없다. wrapper 가 잡는다 |
| `win32-prefix-dropped`, `win32-allow-all` | posix 레인의 자기검사는 win32 분기를 밟지 않는다. wrapper 의 플랫폼 강제 케이스가 잡는다 |
| `log-first-field-nulled`, `log-firsttype-const` | 자기검사는 guard 의 이벤트 로그를 읽지 않는다. wrapper 가 페이로드를 단언해 잡는다 |
| `absolute-dropped` | **동등 mutant** — posix 에서 `dirname(value) === resolve(tmpdir())` 는 절대경로에서만 성립하고 win32 분기는 이 절을 평가하지 않는다. 관측 가능한 동작이 바뀌지 않으므로 생존이 결함이 아니다. 이 판정은 스크립트에 플래그로 박아 두었고, 28개 중 이 하나뿐이다 |

#### 5.5.1 과거 corpus 와의 대조 — 반사실이 아니라 실측

같은 battery 를 과거 자기검사 corpus 에 직접 돌렸다(`--self-check <과거본>`). wrapper 는 자기 subject 를 고정된 basename 으로 찾으므로, 과거 corpus 와 짝지으면 **어긋난 쌍**을 재는 셈이 된다. 그래서 과거 실행 전부에 항상 통과하는 placeholder wrapper 를 주었고 **자기검사 열만 의미가 있다.** (`a6c7edc`·`839db2a` 는 wrapper 이전이고, `9845ea7` 에는 당시 wrapper 가 있었으나 같은 이유로 측정하지 않았다.)

| corpus | 자기검사 단독 생존 mutant 수 (28 중) | 원시 |
| --- | --- | --- |
| `a6c7edc` (작업 전) | **20** | 최신 `raw/guard-mutation-battery-selfcheck-a6c7edc-*.log` |
| `839db2a` (`ws` 를 처음 허용한 판) | **18** | 최신 `raw/guard-mutation-battery-selfcheck-839db2a-*.log` |
| `9845ea7` (앵커·디렉터리·접미를 처음 덮은 판) | **14** | 최신 `raw/guard-mutation-battery-selfcheck-9845ea7-*.log` |
| 최종 | **6** (5건은 wrapper 가 잡고 1건은 동등 mutant) | 최신 `raw/guard-mutation-battery-current-*.log` |

"이전 판이 무엇을 놓쳤는가" 는 이제 추정이 아니라 위 네 실행의 관측이다. mutant 집합이 21 → 25 → 28 로 늘었으므로 **세대가 다른 로그의 수치를 섞어 읽으면 안 된다** — 세 세대의 로그가 모두 보존되어 있고 §8.3 이 구분한다. 위 표는 전부 28개 세대의 값이다.

### 5.6 왜 소켓 이름을 `http` 로 바꾸지 않았는가

`WsRouterRestoreMetadata` 하네스는 WebSocket 하네스이지 HTTP fixture 가 아니다. 이름을 `http` 로 맞추면 guard 는 통과하지만 규약이 거짓말을 하게 된다. guard 쪽을 닫힌 kind 집합으로 넓히는 편이 규약을 정직하게 유지하면서 거부 강도를 낮추지 않는다.

### 6.1 계층 C 는 guard 아래에서 돌릴 수 없다 — RG-01 대비 정정

RG-01 §6 은 계층 C 를 포트 범위로만 규정했고 guard 부착 여부를 명시하지 않았다. 실측(T4)에 따르면 `terminalWireFormatBoot.test.ts` 는 **자기 프로세스 안에서 후보 포트를 실제로 열어 가용성을 확인**하므로 guard 아래에서는 6/6 전건이 `B0_FORBIDDEN_TCP_LISTEN` 으로 실패한다. guard 를 떼면 6/6 통과한다(T4b). **계층 C 의 실행 계약에 "guard 미부착" 을 추가한다.**

### 6.2 두 monolithic 구성은 서로를 대체하지 않는다

A1 은 2222 를 건드리지 않는 대신 4개 테스트의 본체 단언에 도달하지 못한다. B 는 그 4개를 실제로 실행하지만 2222 배타 점유가 필요하고 재사용 결함 1건을 떠안는다. **두 구성을 모두 돌려야 541개 등록 테스트 전부가 한 번 이상 실제로 단언에 도달한다.**

### 6.3 이 호스트에서 절대 green 은 불가능하다

PLATFORM 실패(A0 의 11, monolithic 의 2)는 winpty/PowerShell 부재에서 오며 Linux/WSL2 레인에 내재한다. 원본 §10 갈래 A·C 가 요구하는 `§9.1 green` 은 **Windows 레인에서만** 판정 가능하다. 이 작업은 그 gate 를 충족했다고 주장하지 않는다.

### 6.4 실행 순서 불변식 (RG-01 §6 에 추가)

- A0 의 78파일 스윕과 A0 #3 의 `server/tools` 는 **같은 시간대에 돌리지 않는다** — 전자는 `process.cwd()` 하위에 임시 디렉터리를 만들고 후자는 추적 아티팩트를 일시 변조한다.
- A0 #3 은 **반드시 `--test-concurrency=1`**.
- 계층 C 는 **guard 미부착**.
- B 와 C 는 각각 단독이며 서로 병렬 금지.
- **측정 중에는 소스·guard 파일을 편집하지 않고 다른 측정 프로세스를 함께 돌리지 않는다.** T2 가 이 규칙을 어겨 baseline 자격을 잃었다(§0.1.1). 실행 하네스가 자기 로그를 증거 디렉터리에 쓰는 것은 여기에 해당하지 않는다 — 그것은 모든 실행에 공통이고 측정 대상(`server/`)을 건드리지 않는다. T5c·T5d 의 사후 `git status` 블록이 자기 로그 파일을 untracked 로 보여 주는 것이 그 예다.

### 6.5 실행하지 않은 것

- 계층 B 의 두 번째 항목(`authority-promotion-evidence.test.mjs` 및 Playwright E2E)은 외부 2222 서버 기동을 요구하며 frontend/E2E 범위다. RG-06 의 §9.1·§9.4 범위 밖이므로 실행하지 않았다.
- `tools/daemon`·`tools/wave1`·`tools/wave3` 스위트.

## 7. 관측된 신규·정정 결함 (보고만 하며 이 작업에서 수정하지 않음)

1. **`server/tools` 상호배제 결함** — 기본 동시성에서 3/3 재현되며(§4.5), 실패는 `write-fair-scheduler-evidence-bundle.mjs` 의 단일 publication lock 경합이다. 릴리즈 파이프라인 가드를 건드리는 수정이므로 별도 판단이 필요하다.
2. **고정 포트 2222 재사용 실패의 범위 정정** — 연속 3건 중 **두 번째만** 실패하고 세 번째는 통과한다(§4.3).
3. **monolithic 실행 로그가 TOTP 비밀을 평문으로 담는다** — `TOTPService` 의 최초 설정 경로가 manual entry key 와 **스캔 가능한 QR 블록**을 stdout 에 출력하며(그 출력의 존재 자체를 `test-runner.ts` 의 단언이 고정하고 있다), 그 결과 monolithic 실행 로그를 그대로 보존하면 자격증명 형태의 문자열이 추적 파일에 들어간다. 이번 증거는 §8.1 규칙으로 편집했다.
4. **비결정적 실패 1건** — §4.2.2. 단정하지 않고 관측만 기록한다.
5. **릴리즈 게이트가 `server/dist` 를 전제한다** — `npm run test:release-pipeline` 은 `server/dist` 가 없는 트리에서 `test:authority-pin` 단계에서 실패한다(`server build must emit the compiled canary`). 체인의 어느 단계도 build 를 수행하지 않으므로 갓 clone 한 트리에서는 통과할 수 없다. 이 작업이 만든 것이 아니라 선재하는 성질이며(해당 테스트는 `a6c7edc..` 구간에서 변경되지 않았다), 고치지 않았다.
6. **`speckiwi` 가 lock 스냅샷을 누수한다** — `sync-index` 는 lock 을 쥔 상태에서 `kiwi/.status.json` 을 쓰고 해제 후 다시 쓰지 않아, 만료된 lock 과 호스트명·pid 가 추적 파일에 남는다. 이 작업이 그것을 한 번 커밋했다가 해제 상태로 되돌렸다.

(초판이 여기에 적었던 "guard 자기검사가 어떤 수집에도 들어가지 않는다" 는 §5.4 에서 해소되었으므로 결함 목록에서 내렸다 — 자기검사를 `*.test.*` 표면에 올리고 그 표면을 부르는 `test:tools` 스크립트를 만들었다.)

## 8. 증거 색인

### 8.1 편집(redaction) 고지 — 적용 범위와 규칙

monolithic 실행 로그 **네 파일**(`T1-monolithic-guard-*.log`, `T1b-monolithic-guard-final-*.log`, `T1c-monolithic-guard-final-*.log`, `T3-tierB-monolithic-noguard-*.log`)에만 아래 두 치환을 적용했다. 다른 파일은 원시 그대로다 — `node:test` 로그(T2 계열·T4 계열·T5 계열·T6)에는 자격증명 형태 문자열이 애초에 0건이다.

| 규칙 | 치환 결과 | 적용 수 (**각 파일**) |
| --- | --- | --- |
| `Manual entry key: <base32>` | `Manual entry key: <redacted-ephemeral-totp-secret>` | **5회** |
| 블록 문자(U+2580–U+259F)만으로 이루어진 연속 행 = 스캔 가능한 QR | 연속 블록마다 한 줄짜리 `<redacted-totp-qr-block: …>` | **100행이 5줄로** (QR 5개 × 20행) |

편집 사유는 조직 규정(비밀·토큰·키를 추적 파일·증거 번들에 쓰지 않는다)이다. 값은 실행마다 새로 생성되는 fixture 전용 비밀이지만 형태가 자격증명이므로 예외를 두지 않았다. **편집 전 원본은 커밋하지 않고 세션 스크래치패드에 보존**했으며 그 사전 해시는 아래와 같다.

```
53dab001b865acfd979fc4fb93edd677f468fd158207220879ef9e4a2405e6b9  T1-monolithic-guard-20260916T202955Z.log  (pre-redaction)
5391259bc749f2e74df585e59eefd15714fe7dfa1812128851f9427253df4427  T3-tierB-monolithic-noguard-20260916T203908Z.log  (pre-redaction)
49fb9ed999675b43cd3e24ffc851266e52f8e969d9b864e298be44d1924b0496  T1b-monolithic-guard-final-20260916T222555Z.log  (pre-redaction)
a086167abb96eb9c83bd07da569b0f4e5abdd2ba919540b5207624d7fd73d7c5  T1c-monolithic-guard-final-20260916T225912Z.log  (pre-redaction)
```

**이 네 해시는 저장소 안의 어떤 것으로도 재계산할 수 없다** — 대상 바이트가 의도적으로 커밋되지 않았기 때문이다. 따라서 이것은 검증 가능한 증거가 아니라 **편집이 일어났다는 선언**이며, 그렇게만 읽어야 한다. 검증 가능한 것은 치환 흔적의 개수(네 파일 모두 5 + 5)와, 편집 후에도 `T1`·`T1b`·`T1c` 가 `PASS 535 / FAIL 6 / EXIT=1`, `T3` 이 `PASS 538 / FAIL 3 / EXIT=1` 을 그대로 담는다는 사실이다. 제거된 행은 전부 QR 블록 또는 비밀 문자열이고 테스트 결과 행은 하나도 제거되지 않았다.

### 8.2 해시 매니페스트

`SHA256SUMS.txt` 는 `raw/` 의 **모든 파일**(`raw/.gitignore` 포함)을 담으며, 경로는 이 문서가 있는 디렉터리 기준의 `raw/<파일>` 이다. 따라서 검증은 `docs/analysis/2026-09-17.rg06-regression/` 에서 `sha256sum -c SHA256SUMS.txt` 로 한다.

루트 `.gitignore` 가 `*.log` 를 제외하므로 `raw/.gitignore` 가 `!*.log` 로 되살린다. `guard-mutation-battery.mjs` 는 증거가 아니라 **증거를 만드는 스크립트**이므로 `raw/` 밖에 있고 매니페스트에 들어가지 않는다.
