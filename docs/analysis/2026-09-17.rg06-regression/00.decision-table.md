### 5.1 문제

guard 의 허용 이름 패턴은 `buildergate-http-<pid>-<uuid>` 하나만 인정했다. 그런데 `WsRouterRestoreMetadata.test.ts` 의 `createLocalEndpoint` 는 동일한 pid+uuid 규율로 **`buildergate-ws-<pid>-<uuid>`** 라는 unix socket(또는 named pipe)을 만든다. TCP 는 전혀 관여하지 않는데도 guard 가 이를 `B0_FORBIDDEN_TCP_LISTEN` 으로 거부했다. 오류 메시지 또한 `HTTP fixtures …` 여서 원인을 오도했다.

### 5.2 RED → GREEN (TDD)

자기검사 `server/tools/test-owned-http-test-pipe.cjs` 에 먼저 케이스를 추가했다.

- 허용되어야 함: `buildergate-ws-<pid>-<uuid>` 가 원본 `listen` 으로 전달된다
- 계속 거부되어야 함: 닫힌 집합 밖의 종류(`buildergate-agent-…`), 다른 프로세스 소유(`buildergate-ws-<pid+1>-…`), uuid 형식 위반(`buildergate-ws-<pid>-invalid`)

RED: `raw/RED-guard-selfcheck-20260916T203126Z.log` — exit 1, `B0_FORBIDDEN_TCP_LISTEN` 이 **`ws` 전달 단언 지점에서** 발생. 새로 추가한 세 거부 케이스는 이 시점에도 정상적으로 거부되었으므로, RED 는 의도한 한 지점에서만 발생한다.

수정: 허용 이름을 `buildergate-<kind>-<pid>-<uuid>` 로 일반화하되 **kind 를 `['http','ws']` 닫힌 집합**으로 고정했다. pid 일치와 uuid 형식, tmpdir 직하위, `.sock` 접미(비-Windows), named pipe 접두(Windows) 검사는 전부 그대로다. 메시지는 원인을 정확히 말하도록 고쳤다(오류 `code` 는 불변 — 다른 테스트가 `code` 로 판정한다).

GREEN: `raw/GREEN-guard-selfcheck-20260916T203144Z.log` — exit 0, `{"rejected":21,"validForwarded":2,"actualBinds":0}`. 실제 바인드는 0이다(자기검사는 원본 `listen` 을 스텁으로 치환한 상태에서 돈다).

회귀: T2(21 FAIL) → T2b(17 FAIL). 사라진 4건 중 3건이 `B0_FORBIDDEN_TCP_LISTEN` 이고 나머지 1건은 §4.2.2 의 부하 의존 항목이다. **counts 만으로 회귀를 주장하지 않는다** — 변경 범위가 guard 의 이름 패턴과 오류 문구 두 곳뿐이고, 사라진 3건의 증거 문자열이 정확히 그 거부 경로이며, 새로 늘어난 실패 이름은 0건이다.

### 5.3 왜 소켓 이름을 `http` 로 바꾸지 않았는가

`WsRouterRestoreMetadata` 하네스는 WebSocket 하네스이지 HTTP fixture 가 아니다. 이름을 `http` 로 맞추면 guard 는 통과하지만 규약이 거짓말을 하게 된다. guard 쪽을 **닫힌 kind 집합**으로 넓히는 편이 규약을 정직하게 유지하면서 거부 강도를 낮추지 않는다 — 새 kind 를 추가하려면 guard 를 명시적으로 고쳐야 한다.

## 6. "회귀 복구" 의 계층별 정의 — 이 작업이 주장하는 기준

green 이 아니라 **알려진 실패 예산이 이름 단위로 고정되어 있고, 그 예산 밖의 실패가 0건인 상태**를 복구로 정의한다. 계층마다 예산이 다르다.

| 계층 | 실행 구성 | 복구의 정의 | 현재 상태 |
| --- | --- | --- | --- |
| **A0** — 광역 `node:test` 78파일 | guard 부착, 포트 미점유, 병렬 안전 | 예산 = PLATFORM 11 + 선재 미해결 6 = **17**. 그 밖의 이름이 나오면 회귀 | **충족** (T2b: fail 17, 이름 전부 예산 안) |
| **A0 #3** — `server/tools` 4파일 | **`--test-concurrency=1` 필수** | 예산 = **0**, exit 0 | **충족** (T5b). 기본 동시성으로 돌리면 실패하므로 동시성 1이 이 계층의 실행 계약이다 |
| **A1** — monolithic 541 | guard 부착, 포트 미점유 | 예산 = PLATFORM 2 + GUARD 정당 거부 4 = **6** | **충족** (T1) |
| **B** — monolithic 541 | guard 미부착, **2222 배타·단독** | 예산 = PLATFORM 2 + 고정포트 재사용 결함 1 = **3** | **충족** (T3) |
| **C** — boot 1파일 | **guard 미부착**, 19999–39999 배타·단독 | 예산 = **0**, exit 0 | **충족** (T4b) |

### 6.1 계층 C 는 guard 아래에서 돌릴 수 없다 — RG-01 대비 정정

RG-01 §6 은 계층 C 를 포트 범위로만 규정했고 guard 부착 여부를 명시하지 않았다. 실측(T4)에 따르면 `terminalWireFormatBoot.test.ts` 는 **자기 프로세스 안에서 후보 포트를 실제로 열어 가용성을 확인**하므로 guard 아래에서는 6/6 전건이 `B0_FORBIDDEN_TCP_LISTEN` 으로 실패한다. guard 를 떼면 6/6 통과한다(T4b). **계층 C 의 실행 계약에 "guard 미부착" 을 추가한다.**

### 6.2 두 monolithic 구성은 서로를 대체하지 않는다

A1 은 2222 를 건드리지 않는 대신 4개 테스트의 본체 단언에 도달하지 못한다. B 는 그 4개를 실제로 실행하지만 2222 배타 점유가 필요하고 재사용 결함 1건을 떠안는다. **두 구성을 모두 돌려야 541개 등록 테스트 전부가 한 번 이상 실제로 단언에 도달한다.** 어느 한쪽만으로 "monolithic 회귀를 돌렸다" 고 말할 수 없다.

### 6.3 이 호스트에서 절대 green 은 불가능하다

PLATFORM 실패(A0 의 11, monolithic 의 2)는 winpty/PowerShell 부재에서 오며 Linux/WSL2 레인에 내재한다. 원본 §10 갈래 A·C 가 요구하는 `§9.1 green` 은 **Windows 레인에서만** 판정 가능하다. 이 작업은 그 gate 를 충족했다고 주장하지 않는다.

### 6.4 실행 순서 불변식 (RG-01 §6 에 추가)

- A0 의 78파일 스윕과 A0 #3 의 `server/tools` 는 **같은 시간대에 돌리지 않는다** — 전자는 `process.cwd()` 하위에 임시 디렉터리를 만들고 후자는 추적 아티팩트를 일시 변조한다.
- A0 #3 은 **반드시 `--test-concurrency=1`**.
- 계층 C 는 **guard 미부착**.
- B 와 C 는 각각 단독이며 서로 병렬 금지.

### 6.5 실행하지 않은 것

- 계층 B 의 두 번째 항목(`authority-promotion-evidence.test.mjs` 및 Playwright E2E)은 외부 2222 서버 기동을 요구하며 frontend/E2E 범위다. RG-06 의 §9.1·§9.4 범위 밖이므로 실행하지 않았다.
- `tools/daemon`·`tools/wave1`·`tools/wave3` 스위트.

## 7. 관측된 신규·정정 결함 (보고만 하며 이 작업에서 수정하지 않음)

1. **`server/tools` 상호배제 결함** — `canonical-authority-line-endings.test.mjs` 와 `write-fair-scheduler-evidence-bundle.test.mjs` 가 동일 publication lock 을 두고 경합해 기본 동시성에서 결정론적으로 실패한다(§4.5). 릴리즈 파이프라인 가드를 건드리는 수정이므로 별도 판단이 필요하다.
2. **guard 자기검사가 어떤 수집에도 들어가지 않는다** — `server/tools/test-owned-http-test-pipe.cjs` 는 `*.test.*` 이름 규약을 따르지 않아 `node --test server/tools/*.test.*` 에 잡히지 않고, npm 스크립트도 그것을 부르지 않는다. B0 guard 의 유일한 자기검사가 **어느 회귀 표면에서도 자동으로 돌지 않는다.** 이번 작업은 명시적으로 실행했다.
3. **고정 포트 2222 재사용 실패의 범위 정정** — 연속 3건 중 **두 번째만** 실패하고 세 번째는 통과한다(§4.3). "이후 전부 실패" 라는 기존 서술은 이번 관측과 다르다.
4. **monolithic 실행 로그가 TOTP 비밀을 평문으로 담는다** — `TOTPService` 의 최초 설정 경로가 manual entry key 와 스캔 가능한 QR 블록을 stdout 에 출력하며(그 출력의 존재 자체를 `test-runner.ts` 의 단언이 고정하고 있다), 그 결과 monolithic 실행 로그를 그대로 보존하면 자격증명 형태의 문자열이 추적 파일에 들어간다. 이번 증거는 §8.1 규칙으로 편집했다.
5. **부하 의존 1건** — §4.2.2. 단정하지 않고 관측만 기록한다.

## 8. 증거 색인

### 8.1 편집(redaction) 고지 — 적용 범위와 규칙

`T1-monolithic-guard-*.log` 와 `T3-tierB-monolithic-noguard-*.log` **두 파일에만** 아래 두 치환을 적용했다. 다른 파일은 원시 그대로다.

| 규칙 | 치환 결과 | 각 파일의 적용 수 |
| --- | --- | --- |
| `Manual entry key: <base32>` | `Manual entry key: <redacted-ephemeral-totp-secret>` | 5 |
| 블록 문자(U+2580–U+259F)만으로 이루어진 연속 행 = 스캔 가능한 QR | 한 줄짜리 `<redacted-totp-qr-block: …>` 로 축약 | 100행 → 5줄 |

편집 사유는 조직 규정(비밀·토큰·키를 추적 파일·증거 번들에 쓰지 않는다)이다. 값은 실행마다 새로 생성되는 fixture 전용 비밀이지만 형태가 자격증명이므로 예외를 두지 않았다. **편집 전 원본은 커밋하지 않고 세션 스크래치패드에 보존**했으며, 그 사전 해시는 아래와 같다. 이 해시는 편집 전 바이트에 대한 것이므로 커밋된 파일과는 일치하지 않는다 — 그 점이 편집이 일어났다는 감사 흔적이다.

```
53dab001b865acfd979fc4fb93edd677f468fd158207220879ef9e4a2405e6b9  T1-monolithic-guard-20260916T202955Z.log  (pre-redaction)
5391259bc749f2e74df585e59eefd15714fe7dfa1812128851f9427253df4427  T3-tierB-monolithic-noguard-20260916T203908Z.log  (pre-redaction)
```

편집이 증거를 훼손하지 않았음의 확인: 편집 후에도 `T1` 은 `PASS 535 / FAIL 6 / EXIT=1`, `T3` 은 `PASS 538 / FAIL 3 / EXIT=1` 을 그대로 담고 있으며, 제거된 행은 전부 QR 블록 또는 비밀 문자열이고 테스트 결과 행은 하나도 제거되지 않았다.
