## 0. 이 문서가 주장하는 것과 주장하지 않는 것

**주장한다**

- 서버 회귀의 **전체 수집이 실제로 nonempty** 이며, 실행 계층을 나누어도 **`server/src/**/*.test.ts` 커버리지 손실이 0** 이다(§2).
- 각 실행 계층의 **정직한 특성화** — 명령·cwd·수집 수·counts·실패 이름(§3, §4).
- guard 의 **이름 접두 false positive 3건을 실제로 제거**했고, 그 수정이 RED→GREEN 과 mutation battery 로 입증된다(§5).

**주장하지 않는다**

- **어떤 계층도 green 이 아니다.** 이 호스트에서 green 은 달성 대상이 아니다(§6).
- 어떤 Requirement 의 Status·Stability·AC 도 승급하지 않는다.
- 이슈 본문은 `REL-BGSTAB-001 AC-1..3` 을 지목하지만 **AC-2·AC-3 은 frontend 범위**(focused frontend unit / frontend production build)이며 RG-07 이 담당한다. 이 작업은 **AC-1 만** 다룬다. 불일치를 재해석하지 않고 그대로 기록한다.
- `WsRouterSplitHandshake.test.ts` 의 todo 13건은 #3 이 **0B(deferred/superseded, `REL-BGSTAB-024`)** 로 닫은 계약이다. 관측만 하고 green 으로 만들지 않았다(§4.4).
- Playwright·E2E·`authority-promotion-evidence`(계층 B 의 두 번째 항목)는 server 범위 밖이므로 실행하지 않았다(§6.5).
- `tools/daemon`·`tools/wave1`·`tools/wave3` 스위트는 RG-06 의 §9.1·§9.4 범위 밖이므로 실행하지 않았다.
- **종료한 프로세스가 0개라는 것은 이 번들로 재현할 수 없는 부정 주장이다.** 같은 요구사항의 RG-04 증거(VE-10)가 같은 한계를 명시했다. 이 작업은 어떤 kill 도 수행하지 않았고 외부 서버를 기동하지 않았으나, 그 사실을 증명하는 아티팩트는 존재하지 않는다 — 번들이 실제로 보이는 것은 §1 의 보호 포트 관측뿐이다.

## 0.1 측정 대상 트리 — 실행마다 다르다

**단일 "측정 HEAD" 는 존재하지 않는다.** guard 수정 전후로 실행이 갈리므로 실행 단위마다 명시한다.

| 실행 | `server/src/**` | guard 모듈 | `server/tools/**` |
| --- | --- | --- | --- |
| T1, T2 | `a6c7edc` | `a6c7edc` (프로세스 기동 시 로드) | `a6c7edc` |

`server/src/**` 는 이 작업 전 구간에서 `a6c7edc` 와 **바이트 동일**하다 — 변경은 `server/tools/` 두 파일과 신규 `server/tools/owned-http-test-pipe-guard.test.cjs`, 그리고 `docs/` 에 한정된다. 따라서 모든 실행의 **제품 코드 대상은 동일**하고, 갈리는 것은 guard 뿐이다.

### 0.1.1 T2 는 깨끗한 baseline 이 아니다 — T2c 가 대체한다

초판은 T2 를 "무변경 트리의 baseline" 으로 제시했다. **그 진술은 부정확했다.** T2 는 132.5초 동안 돌았고 그 구간 안에서 guard 자기검사 파일과 guard 구현이 편집되었으며, RED·GREEN 자기검사 프로세스 두 개가 동시에 돌았다. T2 가 **로드한** guard 는 수정 전 모듈이 맞지만, 트리와 프로세스 환경은 실행 중에 변했다.

그래서 **T2c 를 별도로 측정했다**: `server/src/**` 는 손대지 않은 채, `a6c7edc` 의 guard 사본을 스크래치패드에서 `--require` 로 주입하고 다른 프로세스 없이 단독 실행했다. 워크트리는 실행 중 전혀 바뀌지 않았다. **선재 판정의 근거는 T2 가 아니라 T2c 다.**

여섯 관측 모두에서 아래 네 행이 동일하다(아래는 **열을 줄인 요약**이며 원문은 foreign address 열과 CRLF 을 포함한다).

TCP  0.0.0.0:2001  LISTENING  30596
TCP  0.0.0.0:2002  LISTENING  30596
TCP  [::]:2001     LISTENING  30596

### 1.2 이 관측이 증명하는 것과 증명하지 않는 것

- **증명한다**: 보존된 여섯 시점 전부에서 PID 30596 이 2001·2002 를 LISTENING 한다.
- **증명하지 않는다 — 2222 의 해제.** 네 개의 `netstat-*.txt` 는 `netstat.exe -ano | grep LISTENING` 을 `2001|2002|2222` 로 **필터해서 저장한 것**이다(필터는 이 문단이 유일한 기록이며 아티팩트 자체에는 남아 있지 않다. 2차 라운드 파일은 필터를 파일 안에 적는다). 따라서 그 출력에 2222 행이 없다는 것은 **그 시점 Windows 뷰에 2222 LISTENING 행이 없었다**는 뜻이지만, 이 문서가 §1.3 에서 인정하듯 **WSL 이 호스팅하는 리스너의 Windows 측 표기는 신뢰할 수 없다.** 그러므로 "2222 가 해제되었다" 는 이 번들로 강하게 입증되지 않는다. 강한 증거는 2차 라운드의 **필터하지 않은 WSL 측 `ss -ltn`** 이며, 거기에 2222 도 19999–39999 도 없다.
- **증명하지 않는다 — before/after 의 구분.** `netstat-before-T3` 와 `netstat-after-T3` 는 파일명이 같은 실행 시작 스탬프를 공유하고(두 파일 모두 실행 시작 시각으로 이름 붙었다) **바이트 동일**하다. 따라서 두 아티팩트만으로는 어느 쪽이 사후 관측인지 구분할 수 없다. RG-04 증거(VE-10)가 같은 성질을 명시한 것과 동일한 한계다.

### 1.3 포트 점유 요약

- 2222 는 계층 B 실행 중 **runner 프로세스 내부에서만** 바인드되었다(`test-runner.ts` 의 `invokeLoopbackLoginOverTcp` 와 direct-TLS 리스너). 외부 서버를 기동하지 않았고 `stop.bat` 을 호출하지 않았다.
- 19999–39999 은 계층 C 의 `terminalWireFormatBoot.test.ts` 가 스스로 인접 2포트를 확보·해제한다. 테스트가 포트 번호를 출력하지 않아 **점유한 정확한 번호는 기록되지 않았다.**
- 해제 확인은 WSL 측 `ss -ltn` 을 근거로 한다. `ports-after-tierC-*.txt` 의 Windows 구간에 보이는 22112·24282–24285·32847·34581 은 **이 checkout 과 무관한 Windows 프로세스**이며, WSL 리스너는 원리상 그 표에 자신의 WSL PID 로 나타나지 않는다.

## 5. 실제 수정 — B0 guard 와 그 자기검사

**변경 파일**: `server/tools/require-owned-http-test-pipe.cjs`, `server/tools/test-owned-http-test-pipe.cjs`, 신규 `server/tools/owned-http-test-pipe-guard.test.cjs`

### 5.1 문제

guard 의 허용 이름 패턴은 `buildergate-http-<pid>-<uuid>` 하나만 인정했다. 그런데 `WsRouterRestoreMetadata.test.ts` 의 `createLocalEndpoint` 는 동일한 pid+uuid 규율로 **`buildergate-ws-<pid>-<uuid>`** 라는 unix socket(또는 named pipe)을 만든다. TCP 는 전혀 관여하지 않는데도 guard 가 이를 `B0_FORBIDDEN_TCP_LISTEN` 으로 거부했다. 오류 메시지 또한 `HTTP fixtures …` 여서 원인을 오도했다.

### 5.2 RED → GREEN (TDD)

자기검사 `server/tools/test-owned-http-test-pipe.cjs` 에 먼저 케이스를 추가했다. 허용되어야 할 것은 `buildergate-ws-<pid>-<uuid>` 의 전달이고, 계속 거부되어야 할 것은 닫힌 집합 밖의 종류·다른 프로세스 소유·uuid 형식 위반이다.

RED: `raw/RED-guard-selfcheck-20260916T203126Z.log` — `B0_FORBIDDEN_TCP_LISTEN` 이 **`ws` 전달 단언 지점에서** 발생. 새로 추가한 세 거부 케이스는 이 시점에도 정상적으로 거부되었으므로 RED 는 의도한 한 지점에서만 발생한다.

수정: 허용 이름을 `buildergate-<kind>-<pid>-<uuid>` 로 일반화하되 **kind 를 `['http','ws']` 닫힌 집합**으로 고정했다. pid 일치와 uuid 형식, tmpdir 직하위, `.sock` 접미(비-Windows), named pipe 접두(Windows) 검사는 전부 그대로다. 메시지는 원인을 정확히 말하도록 고쳤고, 오류 `code` 는 불변이다 — 다른 테스트가 `code` 로 판정한다.

GREEN: `raw/GREEN-guard-selfcheck-20260916T203144Z.log`. 최종본의 출력은 `{"platform":"linux","rejected":25,"forwardedToCapturedOriginal":2,"openHandles":false}` 이며 세 필드 모두 **측정값**이다(초판은 `actualBinds: 0` 이라는 상수를 출력해 "바인드가 없었다" 를 증거처럼 보이게 했다 — 그 필드는 제거했다. 바인드 부재의 실제 근거는 `server.listening` 단언이며, 그것이 `openHandles` 로 출력된다).

회귀: T2c(20 FAIL) → T2d(17 FAIL). 사라진 3건 전부가 `B0_FORBIDDEN_TCP_LISTEN` 이고 **새로 늘어난 실패 이름은 0건**이다. A1 은 T1 과 T1b 에서 실패 이름 집합이 동일하다.

### 5.3 kind 는 정규식에 보간되므로 리터럴임을 강제한다

kind 문자열은 `RegExp` 에 그대로 들어간다. 메타문자가 섞이면 허용 이름이 조용히 넓어진다. 그래서 guard 는 로드 시점에 모든 kind 가 `/^[a-z0-9]+$/` 인지 검사하고 위반 시 `B0_INVALID_OWNED_ENDPOINT_KIND` 로 **모듈 로드를 실패시킨다.** "닫힌 집합" 이 주석이 아니라 실행되는 계약이 된다.

### 5.4 자기검사를 실제로 수집되는 표면에 올렸다

기존 자기검사는 `*.test.*` 이름 규약 밖이어서 어떤 glob·npm 스크립트·워크플로도 수집하지 않았다 — **B0 guard 의 유일한 자기검사가 자동으로는 한 번도 돌지 않았다.** 신규 `server/tools/owned-http-test-pipe-guard.test.cjs` 가 자기검사를 자식 프로세스로 돌려 exit code 와 측정 필드를 단언하고, 별도 케이스로 §5.3 의 kind 검증을 고정한다. 이 파일은 `server/tools/*.test.*` 에 수집되므로 계층 A0 #3 에서 자동으로 실행된다(T5c: 5파일 35/35).

### 5.5 mutation battery — 자기검사가 공허하지 않음의 증거

`raw/guard-mutation-battery-*.log`. guard 사본에 결함을 하나씩 심고 자기검사를 돌려, 자기검사가 그 결함을 잡는지 본다. **살아남은 mutant 는 자기검사가 그 불변식을 덮지 않는다는 뜻이다.**

| mutant | 결과 |
| --- | --- |
| `^` 앵커 제거 | killed |
| `$` 앵커 제거 | killed |
| owned 디렉터리 검사 제거 | killed |
| `.sock` 접미 검사 제거 | killed |
| kind 집합에 메타문자 추가 | killed |
| kind 집합을 `.*` 로 개방 | killed |
| pid 결속 제거 | killed |
| uuid 형식을 `.+` 로 완화 | killed |
| kind 집합을 `http` 만으로 되돌림 | killed |
| **무변경 control** | **SURVIVED** (기대값) |

초판의 자기검사는 이 중 앵커 2개·디렉터리·접미·메타문자 kind 네 종류를 놓쳤다. `.sock` 케이스는 guard 가 접미 5글자를 잘라내므로 **대체 확장자도 5글자여야** 접미 절만 단독으로 시험된다 — 그렇지 않으면 이름 패턴에서 먼저 걸려 접미 검사를 검증하지 못한다.

### 5.6 왜 소켓 이름을 `http` 로 바꾸지 않았는가

`WsRouterRestoreMetadata` 하네스는 WebSocket 하네스이지 HTTP fixture 가 아니다. 이름을 `http` 로 맞추면 guard 는 통과하지만 규약이 거짓말을 하게 된다. guard 쪽을 닫힌 kind 집합으로 넓히는 편이 규약을 정직하게 유지하면서 거부 강도를 낮추지 않는다.

## 6. "회귀 복구" 의 계층별 정의 — 이 작업이 주장하는 기준

green 이 아니라 **알려진 실패 예산이 이름 단위로 고정되어 있고, 그 예산 밖의 실패가 0건인 상태**를 복구로 정의한다. 계층마다 예산이 다르다.

| 계층 | 실행 구성 | 복구의 정의 | 현재 상태 |
| --- | --- | --- | --- |
| **A0** — 광역 `node:test` 78파일 | guard 부착, 포트 미점유, 병렬 안전 | 예산 = PLATFORM 11 + 선재 미해결 6 = **17**, 여기에 §4.2.2 의 비결정적 항목 1건을 **알려진 비결정 엔트리로 포함**하므로 관측 범위는 **17–18**. 그 이름 집합 밖이 나오면 회귀 | **충족** (T2d: fail 17, 이름 전부 예산 안) |
| **A0 #3** — `server/tools` 5파일 | **`--test-concurrency=1` 필수** | 예산 = **0**, exit 0 | **충족** (T5c: 35/35). 기본 동시성으로 돌리면 실패하므로 동시성 1이 이 계층의 실행 계약이다 |
| **A1** — monolithic 541 | guard 부착, 포트 미점유 | 예산 = PLATFORM 2 + GUARD 정당 거부 4 = **6** | **충족** (T1b, 최종 guard 로 재측정) |
| **B** — monolithic 541 | guard 미부착, **2222 배타·단독** | 예산 = PLATFORM 2 + 고정포트 재사용 결함 1 = **3** | **충족** (T3) |
| **C** — boot 1파일 | **guard 미부착**, 19999–39999 배타·단독 | 예산 = **0**, exit 0 | **충족** (T4b) |

### 6.1 계층 C 는 guard 아래에서 돌릴 수 없다 — RG-01 대비 정정

RG-01 §6 은 계층 C 를 포트 범위로만 규정했고 guard 부착 여부를 명시하지 않았다. 실측(T4)에 따르면 `terminalWireFormatBoot.test.ts` 는 **자기 프로세스 안에서 후보 포트를 실제로 열어 가용성을 확인**하므로 guard 아래에서는 6/6 전건이 `B0_FORBIDDEN_TCP_LISTEN` 으로 실패한다. guard 를 떼면 6/6 통과한다(T4b). **계층 C 의 실행 계약에 "guard 미부착" 을 추가한다.**

### 6.2 두 monolithic 구성은 서로를 대체하지 않는다

A1 은 2222 를 건드리지 않는 대신 4개 테스트의 본체 단언에 도달하지 못한다. B 는 그 4개를 실제로 실행하지만 2222 배타 점유가 필요하고 재사용 결함 1건을 떠안는다. **두 구성을 모두 돌려야 541개 등록 테스트 전부가 한 번 이상 실제로 단언에 도달한다.**

### 6.3 이 호스트에서 절대 green 은 불가능하다

PLATFORM 실패(A0 의 11, monolithic 의 2)는 winpty/PowerShell 부재에서 오며 Linux/WSL2 레인에 내재한다. 원본 §10 갈래 A·C 가 요구하는 `§9.1 green` 은 **Windows 레인에서만** 판정 가능하다. 이 작업은 그 gate 를 충족했다고 주장하지 않는다.

### 6.4 실행 순서 불변식 (RG-01 §6 에 추가)

- A0 의 78파일 스윕과 A0 #3 의 `server/tools` 는 **같은 시간대에 돌리지 않는다** — 전자는 `process.cwd()` 하위에 임시 디렉터리를 만들고 후자는 추적 아티팩트를 일시 변조한다.
- A0 #3 은 **반드시 `--test-concurrency=1`**.
- 계층 C 는 **guard 미부착**.
- B 와 C 는 각각 단독이며 서로 병렬 금지.
- **측정 중에는 워크트리를 편집하지 않는다.** T2 가 이 규칙을 어겨 baseline 자격을 잃었다(§0.1.1).

### 6.5 실행하지 않은 것

- 계층 B 의 두 번째 항목(`authority-promotion-evidence.test.mjs` 및 Playwright E2E)은 외부 2222 서버 기동을 요구하며 frontend/E2E 범위다. RG-06 의 §9.1·§9.4 범위 밖이므로 실행하지 않았다.

## 8. 증거 색인

### 8.1 편집(redaction) 고지 — 적용 범위와 규칙

monolithic 실행 로그 **세 파일**(`T1-monolithic-guard-*.log`, `T1b-monolithic-guard-final-*.log`, `T3-tierB-monolithic-noguard-*.log`)에만 아래 두 치환을 적용했다. 다른 파일은 원시 그대로다 — `node:test` 로그(T2 계열·T4 계열·T5 계열·T6)에는 자격증명 형태 문자열이 애초에 0건이다.

| 규칙 | 치환 결과 | 적용 수 (**각 파일**) |
| --- | --- | --- |
| `Manual entry key: <base32>` | `Manual entry key: <redacted-ephemeral-totp-secret>` | **5회** |
| 블록 문자(U+2580–U+259F)만으로 이루어진 연속 행 = 스캔 가능한 QR | 연속 블록마다 한 줄짜리 `<redacted-totp-qr-block: …>` | **100행이 5줄로** (QR 5개 × 20행) |

편집 사유는 조직 규정(비밀·토큰·키를 추적 파일·증거 번들에 쓰지 않는다)이다. 값은 실행마다 새로 생성되는 fixture 전용 비밀이지만 형태가 자격증명이므로 예외를 두지 않았다. **편집 전 원본은 커밋하지 않고 세션 스크래치패드에 보존**했으며 그 사전 해시는 아래와 같다.

```
53dab001b865acfd979fc4fb93edd677f468fd158207220879ef9e4a2405e6b9  T1-monolithic-guard-20260916T202955Z.log  (pre-redaction)
5391259bc749f2e74df585e59eefd15714fe7dfa1812128851f9427253df4427  T3-tierB-monolithic-noguard-20260916T203908Z.log  (pre-redaction)
49fb9ed999675b43cd3e24ffc851266e52f8e969d9b864e298be44d1924b0496  T1b-monolithic-guard-final-20260916T222555Z.log  (pre-redaction)
```

**이 두 해시는 저장소 안의 어떤 것으로도 재계산할 수 없다** — 대상 바이트가 의도적으로 커밋되지 않았기 때문이다. 따라서 이것은 검증 가능한 증거가 아니라 **편집이 일어났다는 선언**이며, 그렇게만 읽어야 한다. 검증 가능한 것은 치환 흔적의 개수(세 파일 모두 5 + 5)와, 편집 후에도 `T1`·`T1b` 가 `PASS 535 / FAIL 6 / EXIT=1`, `T3` 이 `PASS 538 / FAIL 3 / EXIT=1` 을 그대로 담는다는 사실이다. 제거된 행은 전부 QR 블록 또는 비밀 문자열이고 테스트 결과 행은 하나도 제거되지 않았다.

### 8.2 해시 매니페스트

`SHA256SUMS.txt` 는 `raw/` 의 **모든 파일**(`raw/.gitignore` 포함)을 담으며, 경로는 이 문서가 있는 디렉터리 기준의 `raw/<파일>` 이다. 따라서 검증은 `docs/analysis/2026-09-17.rg06-regression/` 에서 `sha256sum -c SHA256SUMS.txt` 로 한다.

루트 `.gitignore` 가 `*.log` 를 제외하므로 `raw/.gitignore` 가 `!*.log` 로 되살린다.
