# Issue #11 AC-9 — is the observe-only constraint actually guarded?

HEAD `5c82d523bf3753ba490b64649af6aa3dc0b76dd0`. All edits reverted byte-identically;
`server/src/services/SessionManager.ts` confirmed back at
`968a1b39bb9273f1d34a0d458b1c9f10d525879a5f7904346ec290e483ad5eea` with a clean
`git status` on that path.

> **Issue AC-9**: shadow는 renderer delivery나 기존 authority 결정을 바꾸지 않는다.
> **`REL-BGSTAB-011` AC-4**, second clause: shadow 결과가 renderer delivery나 runtime
> authority를 변경해서는 안 된다.

This is the AC that most needs a guard, because a shadow that quietly influences delivery
is not visible as a red test anywhere else. So the question is not "is there an assertion
about it" — there is — but **can that assertion fail.**

## First, the good news: the comparer is a real instrument

Before mutating, the two hazards the brief names for AC-4 were checked by reading the
committed tests, then confirmed by their passing behaviour:

- **The comparison fires, per axis.** `REL-BGSTAB-011 AC-4` asserts the full eight-axis
  map by `deepEqual` — six `match`, `parserTail`/`eviction` `unavailable` — not a single
  aggregate verdict. A comparison that never ran would leave all eight `unavailable`.
- **It can disagree, and disagree selectively.** The harness carries a real negative
  control: `retainedTerminalShadowProjectionMutator` corrupts `checkpoint.normal.cellHash`
  for one named session. `REL-BGSTAB-011 AC-7` then asserts `comparer.result === 'mismatch'`
  **and** `axes.cells === 'mismatch'` **while** `axes.logicalLines === 'match'` and
  `axes.cursor === 'match'` — so the comparison discriminates per axis rather than failing
  wholesale — **and** asserts a healthy sibling session stays `unavailable` with no
  mismatch blocker. That is a per-arm control, not a per-probe one.

So AC-4's instrument hazard is genuinely addressed. **That is not where the gap is.**

## Mutation M3 — the shadow's verdict gates delivery. DEAD MUTATION.

Injected in `applyHeadlessOutput` immediately before the delivery block
(`SessionManager.ts:8012`): if the session is in `shadow` mode and
`comparer.result === 'mismatch'`, return without delivering. That is issue AC-9's
prohibition violated in its loudest form.

`npx tsx --test src/services/RetainedTerminalAuthority.test.ts` → **exit 0, 52/52 green.**

A survivor has two causes, and the humble-sounding one — "my guards are vacuous" — is the
one that ships deferred work on a measurement that never happened. So the mutation was
instrumented rather than believed:

```
[M3-PROBE] sessionId=… mode=… comparerResult=…
```

**The injection site is reached 289 times. `comparer.result` is `unavailable` on all 289.**
Never `match`, never `mismatch`.

| value at delivery time | occurrences |
|---|---:|
| `unavailable` | 289 |
| `match` | 0 |
| `mismatch` | 0 |

M3 therefore never fired once (`[M3-FIRED]` count: **0**). It is a **dead mutation**, and
it says nothing about the tests.

**But it says something about the property, and that is the finding.** The comparer samples
only at global headless idle under a ≥5 s low-duty interval; delivery is decided on the
synchronous output path. In the committed suite the two never coincide, so the verdict is
structurally unavailable wherever delivery is decided. Consequently:

> **Route A of AC-9 — "the shadow's verdict must not change delivery" — is
> *unfalsifiable through the public surface* of this suite.** Not covered, not uncovered:
> the third disposition. The existing `deliveries.some(...)` assertions pass because the
> verdict is never consulted, not because a consultation was rejected.

Raw: `raw/mutation-M3.log`, `raw/mutation-M3-instrumented.log`.

## Mutation M4 — the shadow's mere presence changes the bytes. CAUGHT, but unowned.

Same site, a route that **is** reachable: when the session is in `shadow` mode, drop one
trailing byte from the delivered payload. Quiet, not loud — no verdict involved, just the
shadow's existence altering what the renderer receives.

**Fired 105 times.** → **exit 1, 48 pass / 4 fail.** The four catching tests:

- `ACK-01 PERF-BGSTAB-011 routes each ordinary reservation tuple unchanged after commit`
- `ACK-01 PERF-BGSTAB-011 routes each rollover reservation tuple unchanged after commit`
- `ACK-16 enabling shadow after disabled output preserves committed source identity`
- `ACK-16 failed writes and headless recreation discard projected snapshot reservations`

**Not one of them is named for AC-9's property**, and two belong to a different requirement
(`PERF-BGSTAB-011`) added by a later lane of this epic. Fourth disposition again:
**covered but unowned.** Rewriting any of those four for its own stated reason would
silently unguard AC-9's delivery-integrity half.

### The test that is named for AC-9 caught neither

`REL-BGSTAB-011 AC-7` — which carries the AC-9 assertions
`assert.ok(harness.deliveries.some(entry => entry.data.includes('legacy-delivery-survives')))`
and `deliveryAuthority === 'legacy'` — **passed under M4** (confirmed in
`raw/mutation-M4.log`: `✔ Retained server model shadow and driver lease RED contract —
REL-BGSTAB-011 AC-7`).

The reason is the Class B shape: `some(e => e.data.includes(substring))` is true of the
correct payload **and** of a payload the shadow has corrupted by a trailing byte. A
substring predicate cannot see a suffix change. The assertion is a presence check wearing
an integrity check's name.

## Summary of AC-9 as measured

| Route by which a shadow could change delivery | Disposition | Evidence |
|---|---|---|
| comparer **verdict** gates delivery | **unfalsifiable through the public surface** | M3 dead: 289 reaches, verdict `unavailable` 289/289, fired 0 |
| shadow **presence** alters delivered bytes | **covered but unowned** | M4 caught by 4 tests, none named for this property |
| — as seen by the test named for it | **not discriminated** | `REL-BGSTAB-011 AC-7` green under M4 |

**Bound.** Two routes were injected. Two routes is not all routes: delivery *ordering*,
delivery *timing*, and mutation of `authorityEpoch`/`authorityRevision` by the shadow were
not injected, and nothing here says they are guarded.

**These are test-surface findings, not production defects.** M3 and M4 are injected code;
production delivers correctly on both routes today. What is missing is a predicate that
would notice if it stopped.

## Proposed remedy

One test whose **name is the property** — the shadow changes neither the bytes delivered
nor the authority decision — asserting delivered payload **equality** against the emitted
source rather than `includes`, and asserting `authorityEpoch`/`authorityRevision` equality
across a shadow-enabled and a shadow-disabled run of the identical input. The harness
already supports that second arm: `createHarness({ retainedShadowEnabled: false })` is used
by `ACK-16`. Per the standing brief, prefer the predicate the repository already trusts —
here `ACK-01`'s "routes each reservation tuple **unchanged**" is the stronger predicate that
already exists and has simply never been pointed at AC-9.

Route A cannot be closed by a predicate alone: a test that wants to falsify it must first
construct a state where the comparer's verdict **is** available at a delivery decision. If
that state is unreachable through the public surface, the honest record is the third
disposition, not a passing test.
