## WHAT COULD NOT BE VERIFIED, AND WHY — THE RESIDUAL
The AC-4(b) pacing wiring could NOT be exercised at runtime, and the cause is architectural
rather than a flaky probe:

  WsRouter.ts:2515-2522 advertises `authorityMode: 'legacy'` and
  `checkpointDeliveryActive: false` whenever no authority view is promoted, which is the
  state of a normal session today. The live server log recorded ZERO checkpoint activity
  (control: the log has 49 lines, so the search could have produced a hit).

Server checkpoint authority is inactive by design — REL-BGSTAB-007 is `planned` and
promotion is gated behind PH-004/PH-005, owned by #11 and #12. The checkpoint write lane
therefore does not execute in a production session, so a browser cannot today distinguish
a coordinator that honours the frame budget from one that ignores it.

RESIDUAL, recorded rather than left implicit:
  "The AC-4(b) production wiring is verified by typecheck and call-site read, and is
   UNVERIFIED AT RUNTIME. It becomes verifiable when server checkpoint authority is
   promoted (#11 / #12). Present-in-source and applied-at-runtime remain different claims
   for this wiring."

This is not a discrimination failure of the kind #81 and #85 describe. Those were avoided:
the probe used input frames and buffer content rather than prompt text, and one
deterministic sequence rather than a retry-sensitive flow.
