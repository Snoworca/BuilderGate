## New findings, all introduced by the fixes — all now fixed
RND-001 MEDIUM — the FND-001 fix deleted the O(1) chunk short-circuit, so every
  compatibility admission walked the whole queue. Because non-compatibility
  entries no longer count toward the chunk cap, the queue length is no longer
  bounded by it. Reviewer measured 0.58 ms per admission behind 50,000 queued
  live writes. FIXED: the scan now stops as soon as either cap is exceeded, since
  exact totals past that point cannot change the decision.
RND-002 LOW — admission still encoded the payload twice: once to cache
  `encodedBytes`, once for `compatibilityWriteBytes` eight lines later. FIXED:
  the second read now uses the cached value.
RND-003 LOW, behavioural — clearing the frame deadline at `checkpoint-begin`
  resets the budget of a PREVIOUS checkpoint still draining, because begin is
  admissible mid-drain. Reviewer measured pacing degrading from 2.25 to 3.5
  writes per yield. FIXED: the clear moved to where the drain actually starts, in
  finalizeCheckpointTransaction.
  NOT covered by a dedicated test. The pacing suite builds one checkpoint per
  coordinator, so neither the carry-over nor this reset is visible to it. Stated
  rather than implied.
RND-004 LOW — the header written to CORRECT the FND-004 overclaim made a smaller
  one: it said every arm asserts convergence, and the control arm did not. FIXED
  by making the sentence true — the control arm now runs to quiescence and
  asserts `pendingCommands === 0`, which it previously never checked at all.
