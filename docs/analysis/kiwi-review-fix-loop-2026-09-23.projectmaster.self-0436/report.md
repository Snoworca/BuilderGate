## 5. HIGH 넷 — 제 주장 셋이 무너졌다

**FND-001 `resolveNameCollision` 이 서버를 멈춘다.** `counter += 1` 이 2⁵³에서 포화해 후보 문자열이 매 회 같아지고 `while` 이 끝나지 않는다. **동기 루프라 Node 이벤트 루프 전체가 정지**하고 파일 두 개면 재현된다. 파일 이름은 사용자가 정한다. `timeout 5 node` 로 프로세스가 돌아오지 않는 것을 메인이 직접 확인.

내가 리뷰어에게 넘긴 전제 — *"실제 호출자는 유한한 디렉터리를 보므로 종료한다"* — 가 틀렸다. 호출자 버그가 필요 없다.

**FND-006 AC-11 이 자기가 이름 붙인 결함을 못 잡는다.** AC 원문은 *"참조하는 모든 `var(--x)` 의 x 가 실재한다"* 인데 테스트는 **선언 이름**만 대조한다. 파일에 `var(` 를 스캔하는 코드가 0줄. 저장소의 유일한 `var()` 참조가 정확히 미검사 대상이고, **나는 그 테스트를 AC-11 증거로 등재했다.**

**FND-009 AC-2 의 값 비교가 문자열 부등뿐이다.** paper 를 어둡게 뒤집어도, `--fg` 를 `#DCDCDC`(chrome 의 `#dcdcdc` 와 대소문자만 다름)로 해도 8/8 통과. **그리고 내가 커밋에 적은 변이 증명은 *이름*을 건드린 것이라 같은 테스트의 다른 단언을 건드렸다** — 값 비교 쪽은 증명된 적이 없다.

**FND-003 경로를 넘기면 디렉터리가 사라진다. 충돌한 경우에만.** 같은 입력이 predicate 에 따라 다른 *모양*의 값을 낸다. 투입 예정 지점 `FileService.ts:313` 은 basename 이 아니라 경로를 받는다.
