## Program membership, proven rather than assumed

`server/tsconfig.json` uses `include: ["src*"]`, so there is no `#82`-style `files` allowlist on
the server side. That is a reason to expect membership, not evidence of it. A deliberate type
error was injected and the compiler named **this file**:

```

  error TS2322: Type 'string' is not assignable to type 'number'.
```

restored byte-identically (`83eeb389aa89e08d5f6e8a36e3befc34c940dce38aa03764db58061265ba096e`
before and after). Clean `tsc --noEmit` exit **0**; the new suite is **2/2**; regression on the
two suites sharing this state is **12/12 and 12/12**.

## The mutation table, and the two things it changed

Per the standing brief, a test written against already-correct behaviour has never been shown
capable of failing, so *a green that was never red says nothing*.

| mutation | what it breaks | result |
|---|---|---|
| **M1** — enable the server responder **without** clearing `legacyEnabled` (the "thirteenth site") | the literal invariant | **CAUGHT** by arm 1 |
| **M2** — remove `responder.active` from the server reply guard | one discriminator | **SURVIVED** |
| **M3** — remove **both** `admission.mode` and `responder.active` (group deletion) | both discriminators | **CAUGHT** by arm 3 |

**M2's survival is not a gap.** One-at-a-time deletion cannot separate *"nothing verifies
this"* from *"a redundant sibling enforces it"*; group deletion can, and M3's catch settles it:
`admission.mode` alone closes the path when `responder.active` is gone. That is the brief's
group-deletion rule producing a clean answer instead of a suspicion.

### The fixture could not pose its question, and that was found by measuring, not reading

The first draft of arm 2 probed both reply paths with **fixed** lease ids. Under M2 and M3 it
stayed green — and the tempting, self-critical conclusion was *"my guard is vacuous"*.

It was not. `activeLeaseId` is a **third** discriminator, and a fixed id closed the path on its
own before the guards under test were ever reached. The fixture was returning a clean zero over
a question it never asked. Repaired by probing each path with **the lease the runtime currently
holds**, which removes the confound without weakening anything.

### And the mutation was live, which is what made the next finding possible

After the repair M3 *still* survived. Before concluding anything about the predicate, the
standing brief requires checking that the mutation changed behaviour at all. It did — the
observable is not byte-identical:

```
unmutated: … rollback-admission-stopped  server=false   compatibility-driver-rebound server=false …
M3:        … rollback-admission-stopped  server=TRUE    compatibility-driver-rebound server=TRUE  …
```

So M3 is a **live** mutation that arm 2 genuinely does not catch, and the reason is a real
property of the system rather than a weak predicate: **the server path closes exactly as the
legacy path opens, so removing two guards lets the server responder outlive the rollback's
revoke step without ever producing an overlap.**

That is the finding, and reading the assertions would never have produced it:

> **"never both enabled" does not imply "the old responder closed on time".** They are
> different properties, and the overlap count is zero in both worlds.

Arm 3 was written to own the second one — `MIG-BGSTAB-002` AC-5 revokes the new responder
*before* the legacy responder is re-enabled, so from `rollback-admission-stopped` onward no
step may admit a server reply. M3 is caught there.

This is #11's "the relationship between two criteria can have a gap the criteria do not",
arriving at the level of a single test's arms.

## What the three arms own

1. **`…the server and legacy responders are never both enabled, at any step of promotion or rollback`** — the literal reading of AC-2, sampled after **every** step of the AC-2 barrier and the AC-5 rollback ordering, i.e. at each **prefix** rather than at the end state.
2. **`…no handoff step admits a query reply on both the server and the compatibility path`** — the hazard reading. Necessary, and demonstrated **not sufficient**.
3. Arm 3, inside test 2 — the ordering property M3 exposed.

Every arm **asserts its own preconditions before its property**: that all nine states were
sampled, that some step had the server enabled, that some step had legacy enabled, that each
reply path accepted somewhere. If the fixture ever stops driving the transition, these tests
**fail** rather than passing over an empty set.

## What this still does not license

**AC-2 is not checked, and should not be.** What exists now is a named owner for the invariant
on **one** side-effect path. The bound from `04` is unchanged and is the honest limit:

- **query reply is one path.** Output delivery, semantic facts and resize were not examined for
  whether they arbitrate on `active`/`admission.mode` or on the booleans.
- the literal both-true state at `:2838`, `:3197`, `:6110` is **intra-statement** and remains
  unobservable to any in-process sampler. Arm 1 samples **between** operations, which is the
  granularity a caller can observe; it cannot see inside one.
- three mutations are not all mutations.

What has changed is that the cheapest way to break this invariant is no longer free. A
thirteenth assignment site now reddens M1's arm, and a rollback that leaves the server
responder open now reddens arm 3.
