| value | sha256 |

The pin matches HEAD and **not** the worktree, because lane #11 has an uncommitted edit to
that artifact in flight (see below). I computed both sides of the script's own comparison
rather than running the script: it drives Playwright against
`PLAYWRIGHT_BASE_URL=https://localhost:2222` and, per CLAUDE.md, will have `start.bat` boot a
production server if nothing is listening. **I have not run it.**

Two further properties of the same function, read from source and stated as such:

- it `deepEqual`s the output of `git status --porcelain` over production paths against a
  pinned list (`redExpectedProductionGitStatusLines`);
- it pins byte hashes of `server/src/services/SessionManager.ts`, `server/src/ws/WsRouter.ts`,
  `server/src/types/ws-protocol.ts`, `server/src/utils/headlessTerminal.ts` and a frontend
  baseline.

**So the instrument that certifies promotion asserts that production is byte-identical to a
RED baseline taken in another tree.** Any production fix this lane lands turns its own named
verification red, for a reason that has nothing to do with whether the fix is correct. This
is the `#94` shape — an evidence device imported from a Wave-3 tree — and it is recorded here
rather than worked around. **I am not re-sealing it**; the standing brief's `#103` entry
forbids buying a green that way, and the same reasoning applies a fortiori to a guard I would
be re-sealing in my own favour.
