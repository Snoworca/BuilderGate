## The twelve failures split two ways, and the split is the point

**Eleven are one platform class.** All eleven raise
`CONFIG_ERROR … 'winpty probe timed out while starting PowerShell'` from
`SessionManager.assertPowerShellWinptyAvailable` (`SessionManager.ts:4875`), each after
~1.62 s. This host is Linux. These are `#102`'s family.

**But the mechanism is not the one #102 records.** #11 measured `#102` as `resolveSpawnCwd`
calling the real unmocked `existsSync` and dying at a test's *first* assertion — it confirmed
this by creating the directory and watching the monolithic runner go 538/3 → 539/2. The
eleven failures here die in a **different function on a different cause**: a winpty backend
probe timeout. Per the standing brief, *a name match across commits is not a cause match*;
this is the same rule applied across *instruments*. I am therefore **not** inheriting `#102`'s
label for these eleven. They are a second, separately measured Windows-host dependency, and
`#102`'s fixture fix would not necessarily clear them.

**One is substantive**, and it is on this lane's path.

```
✖ MIG-BGSTAB-002 checkpoint identity follows the committed authority source across reserved ordinal gaps
  AssertionError [ERR_ASSERTION]: Expected values to be strictly equal:
  + actual   'fallback'

      at connectProductionView (server/src/services/TerminalAuthorityController.test.ts:798:10)

```

The scenario reserves a source ordinal without committing it
(`sessionData.nextTerminalAuthoritySourceSeq += 1n`), emits one record, then connects a view.
The assertion that fails is `assert.equal(snapshot.mode, 'authoritative')` — **before**
`promoteProductionViews` is reached. So what is measured is: with a reserved-but-unconsumed
ordinal gap, a newly subscribed view receives a `fallback` recovery snapshot rather than an
authoritative one.

Three things kept apart, at the strength each is held:

1. **Measured, by execution:** the assertion fails, at this HEAD, with those two values.
2. **Read from source, not yet measured:** `WsRouter.ts:5053` computes
   `mode = snapshot.health === 'healthy' && !(truncated && data.length === 0) ? 'authoritative' : 'fallback'`,
   which makes degraded snapshot *health* the plausible route. This is a search-derived
   causal claim and carries that discount; I have not injected anything to confirm it.
3. **Hypothesis I tested and discarded.** My first guess was that the fixture's `'split'`
   transport mode is inadmissible under Wave 0 decision 0B (`REL-BGSTAB-024`,
   `isTransportEligible` admits only `unified`). Measured: **24 tests in this file use the
   `'split'` fixture and 23 of them pass.** The hypothesis is wrong, and `isTransportEligible`
   governs the binary wire format rather than snapshot authority. Recorded because a wrong
   guess that was checked is worth more to the next reader than a right one that was not.

**Why it matters for this lane rather than being a stray red.** Degradation blocks promotion
(`REL-BGSTAB-011` AC-7, `MIG-BGSTAB-002` AC-1). If a reserved ordinal gap reliably degrades
the snapshot, then a session that ever reserves an ordinal it does not consume is
**permanently unpromotable** — the same shape as `#28`'s SGR-palette parity false positive,
which `MIG-BGSTAB-002`'s own 2026-09-16 Change Note records as having blocked promotion
forever. Whether that shape is present here is **not yet established**; it is this lane's
first executable question.

## Promotion is reachable in production code, and unreachable from the product

Both halves were measured, and they pull in opposite directions.

**Reachable.** `server/src/index.ts:1552` calls `attachProductionTerminalAuthority(...)`
**unconditionally** on the real boot path — no config gate. The adapter
(`TerminalAuthorityProductionAdapter.ts`, 4,826 lines) exposes `beginPromotion`,
`beginRollback` and `promoteSession`, and three debug routes are registered
(`terminal-authority-{test-isolation,rollback,fault}`). `checkpointDeliveryActive: true` with
`authorityMode: 'checkpoint'` is asserted and **passes** at
`WsRouterCheckpointProtocol.test.ts:733` in a 15/15 suite.

**Unreachable from the product.** Promotion is entered by the client control frame
`terminal-authority:canary-request` (`TerminalAuthorityProductionAdapter.ts:3477`). Searching
all of `frontend/src` and `frontend/tests` for that string returns **exactly one hit**, and it
is `frontend/tests/e2e/wave3-terminal-authority-promotion.spec.ts:1355`. **No production
client ever asks to be promoted.**

So issue AC-1 — *only a parity-gated session is promoted* — is today satisfied **vacuously**:
in an ordinary session nothing is promoted because nothing ever requests it. That is the
empty-enumeration hazard at product level, and it is the reason the safety ACs cannot be
retired by a green suite.

### This bears directly on #10's residual — and does not close it

#10 recorded (`PROVENANCE.md:359-366`) that its AC-4(b) checkpoint-lane pacing wiring could
not be exercised because `WsRouter.ts:2515-2522` advertises `authorityMode: 'legacy'` and
`checkpointDeliveryActive: false` when no authority view is promoted, *"which is every
ordinary session today"*, so **a browser** cannot distinguish a coordinator that honours the
frame budget from one that ignores it. #11 confirmed the adjacent comparer verdict was
`unavailable` at all 289 delivery decisions.

What I can say at this HEAD:

- **#10's stated cause is confirmed and sharpened.** It is not merely that promotion is gated
  — it is that the only trigger is a frame no product code path emits. Measured by search
  (one hit, in a test), so discounted accordingly; the *complementary* execution-side
  measurement is that `checkpointDeliveryActive: true` is reachable and asserted green.
- **The residual is not closed.** #10's claim is about the **live browser** at
  `https://localhost:2222`. A unit fixture reaching `checkpointDeliveryActive: true` is a
  different statement. Closing it requires a real promoted session in a real browser, driving
  `terminal-authority:canary-request` the way the E2E spec does. That is on this lane, it is
  now known to be *possible*, and it has not been done yet. I will not record it as closed on
  the strength of a passing unit assertion.
