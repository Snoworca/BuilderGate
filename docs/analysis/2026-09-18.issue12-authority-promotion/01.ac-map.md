two integers is the disagreement test from the standing brief run in the passing direction.
It is not proof the parser is right — both could share a blind spot — but a disagreement
here would have been a finding, and there is none.

## Divergences — recorded, not reconciled

**(a) Issue AC-2: a state invariant is not a window property.** The issue asks that the
interval during which two responders are simultaneously active be **zero**. The corpus states
the *steady-state* form twice — `MIG-BGSTAB-002` AC-3 (`하나만 활성화`) and `REL-BGSTAB-007`
AC-12 (`혼합하지 않는다`) — and the *ordering* form once (`MIG-BGSTAB-002` AC-2, one epoch
barrier). It never states an absence over a **transient interval**. Measured: `동시 활성` 0,
`동시에 활성` 0, `두 responder` 0, `구간이 0` 0, `simultaneous` 0, `겹` 0, against controls
`barrier` 7/6, `ACK` 152/69, `both` 16/13, `concurrently` 2/2.

This matters because the two claims fail differently. A steady-state invariant is satisfied
by an implementation that has a brief overlap and then settles; the issue's property is not.
Per the standing brief, an untestable safety property is a finding — so the first question
this lane must answer is **how a non-zero window would be observed**, before any claim that
it is zero.

**(b) Issue AC-4: half the dedup key is unspecified.** The issue names a six-component key.
`REL-BGSTAB-011` AC-5 specifies three of them — `streamEpoch`, `sourceSeq`, record-local
`ordinal`. Measured absent from all 913 rows: `valueHash` 0, `factType` 0, `튜플` 0,
`duplicate fact` 0, `같은 fact` 0, against controls `identity` 32/15, `key` 92/41,
`ordinal` 4/4, `dedup` 2/2. `sessionId` scoping is implied by `REL-BGSTAB-007` AC-9
(`Authoritative model과 source sequence는 session별 하나`) but not stated as part of a
dedup key.

**(c) Issue AC-8: the subject and the qualifier both diverge.** `REL-BGSTAB-011` AC-5 does
carry the exactly-once/observable-zero disjunction — this is *more* than #11 credited it
with, because #11 read it as covering only the fact class and it names
`terminal query side effect` explicitly. What it does not carry is (i) the issue's specific
hazard — a query sequence **split across the owner-transition boundary** — and (ii) the word
**silent**. `관측 가능한 정책` returns 0 across the corpus while `silent` returns 23 hits
across 21 requirements, so the vocabulary is available and is not used here. The issue's
claim is about *recording*: a missing reply that is recorded is conformant, one that is not
is the defect. No criterion states that.

**(d) Issue AC-11: the fence the rollback must keep is unspecified, and one criterion points
the other way.** `MIG-BGSTAB-002` AC-5's ordering includes **`기존 ACK/backlog 폐기`** —
discard the existing ACK/backlog. The issue requires the **dedup ledger** be *retained*
until the epoch stabilises. These need not be the same object, and I have not yet measured
whether the implementation treats them as one; but the criterion that mentions discarding is
checked and the clause requiring retention does not exist. Measured: `dedup ledger` 0,
`epoch 안정` 0, `안정될 때까지` 0, `수렴할 때까지` 0, `ledger를 유지` 0, against controls
`ledger` 9/6, `retain` 52/27, `보존` 19/12, `stabil` 14/9.

This is the clause the standing brief singles out from #10: *a rollback that drops its fence
is worse than no rollback.* It is the only one of the twelve where the SRS and the issue may
be in tension rather than merely differing in coverage. **Reducing it to a measurable
question before ruling on it** (the #10 move): the hazard the retention clause exists to
prevent is a side effect being replayed a second time after the epoch flips back. So the
question is not *"is the dedup ledger part of `ACK/backlog`?"* but *"after a rollback, can a
fact already settled in the pre-rollback epoch be settled again?"* That is an experiment,
and it is on this lane's list.
