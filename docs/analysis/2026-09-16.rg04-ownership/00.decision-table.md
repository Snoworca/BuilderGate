### 1.2 `REPLY_DA1_CONPTY` — **삭제**

값은 `'\u001b[?61;4c'` 로 ConPTY 의 DA1(Device Attributes) 응답이다.

결정 근거는 "미사용" 보다 강하다 — **이 spec 이 단언하는 방향에 적용될 수 없는 상수다.**

- spec 의 DA1 응답 단언은 전부 **`page-to-server`** 방향이다: `:7414`, `:7781`, `:7788`, `:8056`, `:8213`
  (`harness.matching('page-to-server', … message.data === REPLY_DA1)`).
- 그 방향의 응답자는 브라우저의 **xterm.js** 이며, 플랫폼과 무관하게 `'\u001b[?1;2c'` 를 답한다.
- ConPTY 의 device-attributes 응답은 **서버 측**에서 발생하며 이 방향을 통과하지 않는다.

즉 상수는 재구성 비용이 큰 프로토콜 지식을 담고 있지 않고, 이 파일의 어떤 단언과도 관계가 없다.
값 자체는 5바이트이며 ConPTY 문서에서 언제든 복원 가능하다. **가짜 사용·ts-ignore·noUnused 완화는
쓰지 않았다.**

### 1.3 `waitForSnapshot` (promotion spec) — **삭제**

- promotion spec 안에서 호출부 **0건** (선언 `:363` 뿐).
- 형제 `wave3-terminal-authority-fairness.spec.ts:320` 에 **같은 이름의 다른 구현**이 있고 그쪽은

## 4. 신규 결함 1건 — 발견·수정 (RG-04 범위 안)

**첫 control 실행은 실패했다.** 실패는 타입 작업과 무관한 별개 원인이었다.

`frontend/tests/e2e/workspaceOwnershipFixture.ts:52` 의 "live loopback 증명" 판정이
`isLoopbackIp(address.ipAddress)` 를 쓴다. 그런데

- Chromium 이 CDP 로 보고하는 IPv6 peer 는 **대괄호 리터럴 `[::1]`** 이다(`raw/control-playwright-ownership.json` 의 `serverAddr` 참조).

**수정 위치 선택**: `isLoopbackIp` 쪽이 아니라 **CDP 형식이 들어오는 경계(fixture)** 에서 정규화했다.

## 9.2 원시 증거 파일 명명 규칙 (3회차 리뷰 결과 도입)

초회에는 control 결과를 `raw/control-playwright-ownership.json` 이라는 **고정 이름**으로 썼고,

덮어쓰는 증거 번들은 **한 번의 편집만으로 검토 불가능해진다.**

**규칙**: 실행 산출물은 run 마다 고유한 이름으로 쓰고 **어떤 것도 덮어쓰지 않는다.**
형식은 `control-run-{n}.{ISO8601-UTC}.{확장자}` 다.

| 파일 | 성격 |
| --- | --- |
| `control-run-1.2026-09-15T20-15Z.list.log` | 원본 |

| `control-run-2.2026-09-15T20-46-39Z.json` | 원본 |

재구성본은 파일 첫 필드 `_provenance` 에 **원본이 아님**을 명시한다. 값은 세션 기록에 출력된
디코드 결과를 옮긴 것이며 독립 리뷰어도 덮어쓰기 전 작업 트리에서 같은 값을 디코드했다.
**바이트 단위 동일성은 주장하지 않는다** — 주장하는 것은 열거된 필드 값뿐이다.
