## Regression baseline and comparison

Acceptance is set equality of failing test names against a baseline, not an exit
code. A run that fails only for the known Linux/WSL2 baseline reasons and a run
that additionally fails because a store broke both exit non-zero, so an exit code
cannot tell them apart. `tools/issue24-regression-diff.mjs` does the comparison.

**Authoritative pair: `raw/baseline.v3.json` and `raw/after.v3.json`.** The
baseline was captured at `e7c162c` in a detached worktree, using the current
capture tool, so both sides carry per-file test counts and the gate's strict path
runs with no unverified dimension.

| run | files | failing | verdict |
| --- | --- | --- | --- |
| `raw/baseline.v3.json` (`e7c162c`) | 31 | 17 | — |
| `raw/after.v3.json` (changed tree) | 33 | 16 | **no new failures**, gate exit 0 |

Two files are new on the after side — the suites this change adds. The gate
reports added files and does not treat them as a problem; the direction it
refuses is a file the baseline ran that the after run did not, because that is a
suite which stopped running and whose failures would drop out of the comparison.
One test is no longer failing:
`TerminalResourcePolicy.test.ts :: OBS-BGSTAB-005 second review regression`. It is
load-dependent and is reported rather than claimed as a fix.
