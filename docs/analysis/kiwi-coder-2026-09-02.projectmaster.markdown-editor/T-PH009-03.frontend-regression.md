> ### 이 "통과"가 덮지 않는 범위 — 테스트 파일 82개
>
> **`exit 0` 을 "테스트가 타입 검사를 통과했다"로 읽으면 안 됩니다.** 위 두 명령을 합쳐도 검사되지 않는 테스트 파일이 **82개** 있습니다. 사실 세 가지로 나누어 적습니다.
>
> **사실 1 — `tsc -b` 는 테스트 파일을 하나도 보지 않습니다.**
> `frontend/tsconfig.json` 은 `"files": []` 이고 `references` 가 `./tsconfig.editor.json`·`./tsconfig.app.json`·`./tsconfig.node.json` **셋뿐**입니다. `tsconfig.test.json` 은 그 자신의 주석이 밝히듯("Deliberately NOT listed in tsconfig.json references") solution 에 **의도적으로 등재되지 않았습니다** — 테스트 전용 타입 오류가 `npm run build` 와 CI 를 깨뜨리지 않게 하려는 선택입니다. 따라서 `tsc -b` 가 통과했다는 것은 **그 참조 셋(`src`, `src/editor`, node 설정)이 통과했다**는 뜻이지 테스트에 관한 진술이 아닙니다.
>
> **사실 2 — `tsconfig.test.json` 은 `include` 가 아니라 `files` 허용목록이며, 현재 47개만 담습니다.**
> 이 파일은 `"include": ["src"]` 에 더해 `"files"` 로 테스트를 **한 파일씩 명시 등재**합니다. 주석도 "an allowlist that grows one file at a time" 라고 적고 있습니다. 목록 방식이므로 **새로 추가되는 테스트 파일은 명시적으로 등재하지 않는 한 영원히 검사 밖에 있습니다.** 허용목록 47개 중 `tests/e2e` 경로 항목은 **0건**입니다.
>
> **사실 3 — 그래서 실제로 검사받지 않는 테스트 파일이 `37 + 45 = 82`개입니다.**
>
> | 대상 | 디스크 | 검사됨 | **미검사** | 근거 |
> |---|---:|---:|---:|---|
> | `tests/e2e/` `*.spec.ts` | 37 | 0 | **37** | 허용목록에 0건이며 다른 어떤 tsconfig 의 `include` 에도 들어가지 않음 |

> | 합계 | 129 | 47 | **82** | |
>
> 측정 방법은 `tsconfig.test.json` 의 `files` 배열을 파싱해 `tests/unit` 디스크 목록과 차집합을 낸 것입니다(허용목록 47, 디스크 92, 차집합 45, e2e 항목 0).

### 5.4 기준선 `52bb643` 에서 동일하게 재현된 실패 — 무관

#### 기준선 워크트리를 어떻게 만들었는가 (거짓 대조 회피)

`git worktree add` 는 **gitignore 된 파일을 따라 넣지 않습니다.** 그대로 두면 그 파일을 읽는 테스트가 기준선에서만 실패해 **워킹트리가 오히려 개선된 것처럼 보이는 거짓 대조**가 됩니다. 그래서 아래를 명시적으로 채워 넣고 대조했습니다.

| 항목 | 처리 | 이유 |
|---|---|---|
| `server/config.json5` | 워킹트리에서 **복사** | 없으면 서버가 부팅하지 못하거나 다른 설정으로 뜹니다 |
| `server/certs/` | 워킹트리에서 **복사** | HTTPS 자체 서명 인증서 |
| `frontend/node_modules` | 워킹트리 실물로 **junction** | `npm install` 은 react-mosaic 패치를 날리므로 금지 |
| `server/node_modules` | 워킹트리 실물로 **junction** | 위와 같음 |
| `server/dist/` | **복사하지 않음** | `dev.js` 는 `tsx watch src/index.ts` 로 소스를 직접 실행하므로 불필요. 부팅 성공으로 확인 |
