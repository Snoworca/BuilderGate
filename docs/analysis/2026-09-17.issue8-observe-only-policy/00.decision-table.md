## 2. The three failures had three different causes, stacked

The scanner throws on the first missing signature, so only one cause was visible at a time. Each
fix exposed the next. This is why the count stayed at three while the reason changed.

| # | Cause | Pre-existing at `bc94bea`? |
| --- | --- | --- |
| A | `1ae3787` (REL-BGSTAB-009) moved the grace lane from `WebSocketProvider#bufferGraceMessage` into `terminalGraceBuffer#applyGraceBufferedMessage`; the consumer catalog still named the old owner | **no** — introduced inside this epic |
| B | `ConfigFileRepository.ts`'s classification `accessEvidenceSha256` pin went stale when `resourceLimits.telemetry.sampleIntervalMs` was retired, so the file lost its exemption and its `@resource-limits-root.[dynamic]` render access surfaced as an unregistered call site | yes |
| C | the `reserved-copy-option-decoy` mutation fixture pinned a CRLF marker against `SessionManager.ts`, which is LF in this checkout, so the fixture failed on its own setup and could not pose its question | yes, on any LF checkout |
| D | `TerminalResourcePolicyObservations.ts`'s compact decision list never gained `resourceLimits.terminal.checkpointMaxBytes` when REL-BGSTAB-023 registered it | yes |

Cause A matters beyond itself. Both prior records — VE-11 on `REL-BGSTAB-001`, and this
Requirement's 2026-09-16 Change Note — classify these three test names as pre-existing and
out of scope. Measured ancestry: `1ae3787` is **not** an ancestor of `a6c7edc` (VE-11's HEAD) or of
`8f8f934` (the Change Note's baseline), and **is** an ancestor of `bc94bea`. A regression introduced
after those measurements was therefore sheltering under a "pre-existing" label inherited from trees
in which it did not exist. The label was correct for causes B, C and D and wrong for A, and nothing
in the failing output distinguished them.

## 4. AC-1 is the Class B instance

AC-1's text requires the manifest to name each key's real consumer path. Its check was
`existsSync`, which is true of the correct state *and* of the defect: the file still exists after
the consuming expression leaves it. AC-6's AST scan was the only thing that could see the drift.

AC-1 now additionally asserts that each entry's `evidenceSignature` — the consuming expression
itself — occurs in the file the manifest names, and asserts its own check count first so the loop
cannot pass vacuously over an empty set.

Falsification, run and recorded: restoring `consumerPath` to `frontend/src/contexts/WebSocketContext.tsx`
for the four grace tuples reddens AC-1, and the failing assertion is the new one, by its own
message — `manifest names frontend/src/contexts/WebSocketContext.tsx#applyGraceBufferedMessage as
the consumer, but its evidence signature ... does not occur in that file`
(`raw/ac1-mutation-M1.20260917T144451Z.log`). The manifest was restored byte-identically afterwards.
This reaches the **specific** layer: the mutation reddens AC-1 *through AC-1's own assertion*.

What this check does **not** establish, stated because a textual hit reads like more than it is: it
does not show the expression is owned by the named symbol, is reachable, or is anything but a
comment or an import. AC-6 carries ownership and liveness. This is a second independent condition on
the same claim, not a replacement. In particular it would **not** have caught cause A had the
catalog named the symbol's leaf identifier instead of the expression, because `bufferGraceMessage`
still exists in `WebSocketContext.tsx` — only its body left.

  other lanes in this session may hold that port, so it was skipped deliberately rather than
  overlooked. The dependent-suite comparison in §5 is narrower: it covers the 19 files importing the
  changed modules and does not speak for the other ~59.
- **No browser verification.** Every change is server-side or tooling; no Settings UI, stored shape,
  public runtime payload or product default was touched, and `activationEligible` remains false.
- **No process was started or stopped.** No listener was bound by this work, `stop.bat` was not
  invoked, and TCP 2001/2002 were not touched. That is a negative claim this bundle cannot
  reproduce, stated as such.
