## 1. Premise state of the issue body

The issue body describes two live defects in `frontend/src/utils/terminalOutputScheduler.ts`:
a per-code-point `TextEncoder.encode()` call in the UTF-8 prefix loop, and a coalesce step
that builds one unbounded string. **Neither is present at this HEAD.**

Both were in the file at the parent of commit `c25d761`
(`feat(terminal): decode binary frames in the browser and stop killing live terminals`):
`takeUtf8Prefix` called `getUtf8ByteLength` — i.e. `textEncoder.encode(value).length` — once
per code point, and `coalesceChunks` returned `[{ data: chunks.map(chunk => chunk.data).join('') }]`.
`c25d761` replaced both with the byte-segment representation the file has today: a segmented
deque of `Uint8Array` entries with a consumed-head index, `subarray()` slicing, a
continuation-byte back-scan (`findUtf8SliceEnd`), and a merge step that only combines two
inactive segments when their combined size fits the effective flush budget.

The issue body is therefore stale on mechanism. The outcome half — regression coverage and a
recorded legacy-versus-current cost comparison — is what this re-verification re-establishes
on this host.

## 2. Behavioural-equivalence and allocation evidence

The paired benchmark harness in `frontend/tests/benchmarks/` loads the legacy implementation
from revision `ca111fef3b5a5a25d3aa488415c929e90ade46fd` through `git show` and runs it against
the current production module over the Wave-1 mixed corpus (110 bytes) and boundary corpus
(65,542 bytes). Every run recomputes the comparison live; only the canonical artifact
`docs/analysis/kiwi-planner-2026-07-15.projectmaster.wave2-hotpath/scheduler-benchmark.json`
is the recorded one, and default verification leaves it byte-for-byte unchanged.

Method: the existing harness entry point `runPairedTerminalOutputSchedulerBenchmark` was driven
five times in one process from a scratchpad driver — no second harness was written. Manifest
values (seed 7008, 1 warm-up, 3 trials, 250 ms calibration, 512 bootstrap iterations) are the
ones the harness pins.

Deterministic gates — **identical in all five repetitions**:

| Gate | Legacy baseline | Current |
| --- | --- | --- |
| prefix-loop `TextEncoder.encode()` calls | 65,638 | 0 |
| per-code-point temporary allocations | 65,638 | 0 |
| encoder result allocations | 65,640 | 2 |
| accepted ingress count | 2 | 2 |
| max encode calls per accepted ingress | — | 1 |
| output digest parity | true | true |

Output digest parity across the whole corpus is the behavioural-equivalence evidence: the two
implementations emit the same bytes.

Wall-clock, five repetitions (scheduler elapsed p95 per trial, ms):

| | min | median | max |
| --- | --- | --- | --- |
| legacy baseline | 290.672 | 354.877 | 399.637 |
| current | 2.559 | 5.200 | 13.289 |

The paired-bootstrap p95 gate passed in all five runs. The candidate spread (2.6–13.3 ms) is
wide relative to its own magnitude, so the defensible timing claim is the ordinal one — the
current implementation is roughly two orders of magnitude cheaper on this corpus — not a point
estimate. The allocation counts above, unlike the timings, are exactly reproducible.

Raw: `raw/paired-benchmark-repetitions-20260917T091554.json` (+ `.log`),
`raw/benchmark-test-20260917T091458.log`.

## 3. Regression coverage

`frontend/tests/unit/terminalOutputScheduler.test.ts` carries the `PERF-BGSTAB-009` AC-1…AC-10
contracts, including the corpus the issue's third acceptance criterion names: ASCII, `한글`,
a combining sequence (`é`), a ZWJ sequence (`가‍🙂`), split ANSI/OSC ingress compared
against an unsplit xterm control write, isolated high/low surrogates, and N-1/N/N+1 `maxBytes`
budgets. `terminalOutputSliceAlignment.test.ts` drives the real scheduler over 200 randomised
1/2/3/4-byte corpora and asserts no write slice starts on a continuation byte, with an
anti-vacuity check that a naive fixed-width split would have misaligned.

## 4. Defect found and fixed in this pass

`frontend/tsconfig.test.json` is an explicit allowlist, and it did **not** list
`tests/unit/terminalOutputScheduler.test.ts` or any file under `tests/benchmarks/`. The
AC-1…AC-10 guards and the AC-9 benchmark harness for this very requirement were therefore in no
TypeScript program. Adding `tests/unit/terminalOutputScheduler.test.ts` plus three benchmark
files (`terminalNoRenderFixture.ts`, `terminalNoRenderFixtureEvidence.ts`,
`terminalOutputSchedulerBenchmark.test.ts`) turned `npm run typecheck:tests` red with 10 errors
(`raw/typecheck-tests-red.log`): a union member read without narrowing in the NO_RENDER fixture,
a lease type missing `policyId`/`profileVersion`, two parameters shadowing the `typeof` they
annotate, an invalid `readonly` modifier on `Array<...>`, five callbacks that control-flow
analysis had narrowed to `null`, and a module namespace narrowed to `never`.

All ten are now fixed and the suite is green (`raw/typecheck-tests-green.log`). The five
callback sites previously used optional-call syntax, which would have silently skipped the
assertion had the callback never been captured; they now assert capture before invoking. All
tests still pass, so none of those sites was vacuous.

A fifth entry, `tests/benchmarks/terminalNoRenderFixture.test.ts`, was added afterwards: it is
a separate file from the fixture module it drives, it holds the `AC-8` and `AC-10` NO_RENDER
guards, and nothing imports it, so the allowlist reached it through no other entry. It
type-checks clean on first inclusion, so it contributes coverage rather than a fix. Two of the
first four entries were also clean on inclusion — all 10 errors came from
`terminalOutputScheduler.test.ts` (9) and `terminalNoRenderFixture.ts` (1) — so "clean on
inclusion" does not distinguish the fifth entry from the rest; what distinguishes it is that no
other entry pulls it into the program. The allowlist gained **five** entries in total. Commit `86ea78a`, whose message and evidence rows were written before this entry was
added, says "세 파일"; that count is superseded here and in the report.

`frontend/src/utils/terminalOutputScheduler.ts` is unmodified by this pass — the production
source digest the benchmark pins is unchanged.

## 6. Conditions not met

- Issue #4's fifth acceptance criterion asks for "CPU/allocation/**long-task** 지표". The
  allocation counters and the scheduler elapsed p95 in §2 cover the first two. There is no
  long-task instrumentation anywhere in `frontend/tests/benchmarks/`, and none was added: a
  long-task measurement is a browser main-thread observation, and this harness runs the
  scheduler under Node with no renderer. Scheduler elapsed p95 is the nearest available proxy
  and is not the same measurement. `PERF-BGSTAB-009` AC-9, which is the contract the SRS
  actually holds, does not require it.
- Timing on this host is noisy enough that only the ordinal claim in §2 is made. A point
  estimate of the speedup is not supported by five repetitions.

No listener was opened on any port during this work; TCP 2001/2002 were never touched.
