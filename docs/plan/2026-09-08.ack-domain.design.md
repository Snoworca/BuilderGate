## Scope and sequence

1. Prove and fix pending reservation rollover first: current code stores nextTerminalAuthoritySourceSeq but reloads the epoch from committed retained state. Before a flush, (7,max) -> (8,0) -> (7,1) is a candidate defect. Reproduce through real SessionManager behavior before fixing; review all resets/restores of the reservation cursor.
2. Preserve reservation tuple in pending output and OutputAuthorityMetadata through router enqueue and FairTerminalDeliveryInput/Delivery. Only actual output frames carry an output identity; source-less control/dataGap delivery remains supported.
3. Add ACK union and parser behavior, source lookup and domain-specific error validation; preserve old delivery branches and common settlement.
4. Propagate tuple to wire and binary output adapter along with negotiated fair connectionEpoch; run actual browser write completion ACK path. Reject malformed source identities observably; do not silently switch ACK domains.
5. Reissue affected provenance/evidence; verify exact-source tests and runtime capability acceptance separately from build success.

## Error precedence and settlement

| Order | Check |
| --- | --- |
| 1 | Both domains present -> ACK_DOMAIN_CONFLICT; neither -> ACK_DOMAIN_MISSING; malformed discriminant/ordinal -> observable invalid-domain/value rejection. Preserve existing legacy invalid-delivery-seq parser behavior. |
| 2 | Unknown/retired lane and released lane -> existing ACK_UNKNOWN_LANE / ACK_STALE_EPOCH precedence. |
| 3 | Delivery seq <= delivery watermark, or source tuple <= source floor/settled watermark -> ACK_DUPLICATE, zero credit. |
| 4 | Delivery seq beyond issued ceiling, or source tuple beyond highest enqueued source (including no source history) -> ACK_OVER_ACK. |
| 5 | Issued-but-unsent delivery, queued source tuple, or source hole below ceiling without an exact sent entry -> ACK_OUT_OF_ORDER. |
| 6 | Resolve exact source tuple to deliverySeq, then run common cumulative settlement through that entry, updating both watermarks from entries actually removed. |

- Source epochs older than the newest enqueued epoch remain ACKable when their exact entry is still sent and unsettled. Connection rollback/release retains the stale-lane gate.
- Example: output(100,d1), dataGap(d2), output(103,d3). source100 -> credit d1; delivery2 -> credit d2; source103 -> credit d3. Repeated source100/delivery2 returns zero. If source103 arrives first it settles d1..d3 once; later delivery2 is duplicate.
- Reserved-but-not-enqueued identities are outside the lane ceiling. Queued-but-unsent identities are inside its ceiling but not ACKable.

## Snapshot-rollover addendum

- Trigger: independent P2a High finding, reproduced by additional ACK-01 tests (7 total, 5 pass/2 fail). Snapshot-only resize can move epoch/source at commit and invalidate a source-only reservation projection.
- Chosen design: one projected `(streamEpoch, sourceSeq, snapshotSeq)` cursor for existing semantic admission; no second allocator or unbounded operation map.
- Extract one pure state-ordinal transition shared by reservation and committed-state advancement. Reuse canonical uint64 advance logic. Preserve semantics: output advances source then snapshot unless source rollover already reset both; resize advances snapshot only; rejected source advances source only. Either rollover resets the other ordinal according to the existing contract.
- Projection computes only; actual ledger epoch adoption/bump and retained record/fact reset remain commit responsibilities. Output pending stores immutable reserved epoch/source. Model commit must agree with that tuple before router delivery; mismatch uses the observable existing degradation/recovery failure path, never metadata substitution.
- Every successful healthy headless output write advances the same source/snapshot revision, including when shadow record collection is disabled. These revisions describe the actual model write, not a new snapshot serialization or proof of retained authority. Shadow mode alone controls records/facts/comparer collection and existing authority/canary gates. Attach, rollback/debug restore, recreation and degraded-drain settlement must synchronize/invalidate the whole projected tuple; never combine max source from one epoch with another epoch.
- Preserve normal busy resize latency: if no write/resize is in flight, projected epoch equals committed epoch, and projected snapshot is below MAX64, immediate resize remains allowed. Its snapshot increment commutes with queued outputs without changing their reserved source identities. Advance the projected snapshot for that immediate resize; output pending snapshots are not an exact-identity contract.
- When projected epoch differs from committed epoch or projected snapshot equals MAX64, resize must not overtake admitted output. Reserve its transition at admission and append it to the current finite headlessWriteChain prefix. Future output admissions append after the resize; do not wait for a globally empty queue.
- Queued resize projection and actual application must follow admission order in the rollover risk region. No source tuple is reissued during flush. Source-only rejection and failed/degraded operations invalidate or settle the projection through existing fallback ownership before new healthy admission.
- Existing SessionManagerBusyResize behavior and tests remain unchanged for ordinary ordinals. Any necessary fixture extension must reflect real complete session state and not weaken immediate/half-applied-write assertions.

## Epoch issuance refinement

- Reproduced after composite fixes: the existing epoch ledger issues globally unique values across sessions, while a pure arithmetic rollover predicts local epoch+1. A sibling session can advance nextIssue between reservation and commit, producing a different committed epoch. Global RED: C:/Users/beom/AppData/Local/Temp/buildergate-p2a-global-epoch-red.log, SHA256 3EBC1251F5BD791DF2799C3907385ED37C980947D2C100B6672C4F0CD2E8C9E1.
- Preserve the existing global issuer and session-owned committed epoch. Add a reservation operation to that same ledger: consume its next global issue without changing the session's current epoch/reason. Do not create another counter or unbounded source map.
- Pure ordinal transition decides rollover and source/snapshot values; it does not choose the final epoch when used for admission. On rollover admission, obtain the actual epoch from the ledger reservation operation and retain it with the output or queued resize.
- At model commit use the stored, internally issued epoch through the existing adoption surface instead of bumping/issuing again. Validate against current session/retained epoch and reject stale generation/epoch commits observably; never move a newer committed epoch backward because of an old pending reservation. Non-reserved direct transitions continue using the existing issuer.
- Test ledger interleavings: reserve leaves current/reason unchanged; other session creation/bump cannot consume a reserved value; later adoption uses the exact reservation; forget/recreate never reissues reserved values; uint64 exhaustion is observable.
- SessionManager integration must include a sibling whose creation advances global issuance between configured epoch and rollover. Fixed expected values must follow the existing global issuer, not an invented local +1 rule. Correct any newly authored +1 assumption only after independent review, retain exact tuple/health/equality assertions, and add explicit contention controls rather than remove the sibling scenario.
- Review status: analysis_review No findings before implementation; correcting the newly authored sibling-case +1 expectation to the deterministic global issue is approved while preserving sibling contention, exact tuples, counts, health and the single-session +1 control. This is a refinement of the existing sole epoch issuer, not a new epoch policy or an implementation completion claim.
