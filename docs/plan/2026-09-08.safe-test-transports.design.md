## B0 reuse and narrow implementation boundary

- Reuse the transport pattern in server/src/ws/WsRouterRestoreMetadata.test.ts: createLocalEndpoint uses a unique process/UUID Windows pipe or Unix .sock; server.listen(endpoint) accepts HTTP/WS over it; stopLocalWsHarness closes connections/server and removes only its owned Unix path. Its LiveWsClient uses connectSocket(endpoint). Extract the HTTP endpoint/listen/close mechanics only; do not import a test module that registers tests or construct its SessionManager, WebSocket router or PTY for ordinary HTTP route tests.
- Search existing test utilities again before adding a helper. If absent, use one test-only helper shared by the monolithic HTTP fixtures, not a production service or generic transport framework.
- Provide an owned HTTP server fixture accepting an existing Express app and an async request operation using http.request({ socketPath, method, path, headers }). Preserve request JSON byte length, headers, response status, body bytes and existing JSON parsing assertions. Do not change the production router or introduce runtime flags.
- Create one unique endpoint per fixture, bind no TCP port, and reject bind errors instead of searching for an alternate port. Track sockets opened by that server; close requests/connections and await server.close during cleanup. Cleanup must run in finally for success, assertion failure and request errors. A bounded cleanup timeout fails the test observably; it must never trigger process termination.
- On Unix, remove only the exact helper-created socket path after closure. Verify it belongs to the allocated temporary directory; do not remove a pre-existing path or another fixture's endpoint. On Windows the OS pipe namespace requires no filesystem unlink. Concurrent fixtures must use distinct endpoints and cannot close each other's servers/sockets.
