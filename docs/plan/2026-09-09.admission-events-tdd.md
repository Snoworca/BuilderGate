# Admission event reporter and validation TDD

Scope: PERF-BGSTAB-010, agreed successor SDS-AC-3/6. Reporter and validator only; fixed20 wiring, process execution and three clean admission runs are later work. Existing collector/settlement helpers do not implement this event protocol. Reuse installed Node `countCompletedTest` semantics: suite events increment suites only; ordinary nested parents count as tests; non-suite outcome priority is skip, todo, cancellation, failure, pass. No production/test-runtime imports or child execution are needed for these pure controls.

Concrete protocol: `schemaVersion:'admission-events/v1'` on every record; closed `type` values `summary`, `pass`, `fail`, `complete`, `output`, `end`. No unknown record keys. Summary has `{file:string|null,success:boolean,counts:{tests,topLevel,suites,passed,failed,cancelled,skipped,todo}}`, all counts nonnegative safe integers. Pass/fail/complete have `{file:string|null,name:string|null,nesting:number|null,details:{type:string|null,failureType:string|null},skip:{present:boolean,value:boolean|string|null},todo:{present:boolean,value:boolean|string|null}}`. Missing directive is `{present:false,value:null}`; presence preserves false and empty string rather than inferring it from truthiness. Cancellation failure types are the installed Node `testTimeoutFailure`, `cancelledByParent`, `testAborted`; unsupported failure values must not become successful evidence. Output has `{stream:'stdout'|'stderr',text:string}`. End has `{eventCount:nonnegative safe integer}` counting all preceding protocol records. Exactly one final end; trailing or truncated data is invalid.

Default async-generator `admission-event-reporter.mjs` accepts the native async event stream and yields complete LF-terminated JSON strings. It maps test:summary, test:pass/fail/complete, test:stdout/stderr to the schema, selecting only the listed fields; native unrelated progress events are ignored. Native summary counts are projected to the eight fields. Native details.error.failureType becomes failureType. Stream-source errors reject and must not emit a successful end. Output text is serialized, never reparsed as protocol.

`evaluateAdmissionEvents(records,expectedEntryFiles)` in `admission-event-validation.mjs` accepts an array of parsed protocol records and returns `{accepted:boolean,reasons:string[],counts:{tests,topLevel,suites,passed,failed,cancelled,skipped,todo}}`; malformed schemas/framing/counts produce accepted=false and nonempty reasons. Expected file IDs are exact strings with no implicit basename matching. Pure tests use two entries; later gate wiring supplies the exact agreed20. Require one successful nonempty summary per expected file and one file:null root summary, reconcile eight counters across independent pass/fail accounting, file sum and root, and require bad counters0. Ordinary event.file may be a helper definition and must not serve as entry attribution. Complete events never count twice. Raw malformed/truncated JSONL is rejected by the future stream decoding gate before invoking the parsed-record evaluator; these tests cover missing end and invalid parsed-record tails without inventing another decoder API.

Tests are authored before either implementation. Independent review precedes implementation; no full gate, timing or runtime completion is claimed.

Native directives are counted by presence (`!== undefined`), including false/empty string. Suite directives also fail admission even though Node excludes suites from skipped/todo test counters. Reporter must reject nonfinite/invalid fields before JSON serialization can coerce them.
