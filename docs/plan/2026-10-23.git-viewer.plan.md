## 1. 목표

에이전트가 터미널에서 코드를 바꾸면, 사용자는 IDE 없이 브라우저에서 아래 세 가지를 본다.

1. 세션 하단바의 브랜치 칩: 브랜치, 변경 수, ahead/behind
2. Git 창: 커밋 그래프와 커밋 상세
3. diff

## 3. 원칙

- **TDD:** 각 작업은 실패하는 테스트를 먼저 쓰고 red 를 확인한 뒤 구현한다. 테스트를 약하게 고쳐 green 을 만들지 않는다.
- **작은 단위:** 작업 하나 = 커밋 하나 = 이슈 하나. 커밋 메시지에 이슈 번호와 Requirement ID 를 적는다. AI 서명은 넣지 않는다(조직 규정). 스테이징은 명시한 경로만 한다(`git add -A` 금지).
- **SRS:** speckiwi mutation 은 CLI 에 `--root .` 를 붙여 실행한다(MCP mutation 금지). 커밋 전에 `kiwi/.status.json` 의 lock 을 되돌리고 `check:srs-change-notes`·`check:kiwi-status` 를 돌린다.
- **비동기:** 서버의 git·fs 호출은 전부 비동기다. `asyncFileProcessing.test.ts` 의 GUARDED 에 `./git/gitRunner.ts`·`./git/GitService.ts`·`../routes/gitRoutes.ts` 를 넣는다. `execFileSync` 같은 동기 변형도 이 가드에 잡힌다(`*Sync(` 패턴).
- **i18n:** UI 문구는 전부 `messages.{en,ko}.json` 을 거친다. 키는 시안 ⑧ 표를 따른다. 작업마다 `i18nGuards.test.ts` 를 돌린다.
- **봉인 소스:** `WsRouter.ts` 를 비롯한 봉인 소스 6개는 고치지 않는다. 고칠 파일 중 소비자 매니페스트가 카탈로그한 것은 없다(MetadataRow·App·MosaicTile 은 목록에 없음을 확인함). 카탈로그한 파일을 고치게 되면 커밋 직전에 재봉인하고 `check:consumer-manifest` 를 돌린다.
- **포트·프로세스:** E2E 는 2222 에서만 한다. 2001·2002 프로세스는 건드리지 않는다.
