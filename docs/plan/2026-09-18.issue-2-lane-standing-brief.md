# Standing brief — BuilderGate Orca epic (#2) lanes

Reconstructed 2026-09-18 after the session scratchpad was cleared and the original was lost.
Every rule below was earned by a specific measured defect in #6, #7, #8 or #9. None is theoretical.

## Safety (non-negotiable)

- **TCP 2001/2002 are in production.** Never stop them, by any means. One PID holds both.
  Verify it is intact before and after anything that touches processes.
- Never kill node broadly, kill a process tree, or stop a process you have not identified through
  `/proc` as owned by this checkout.
- Verification port is **2222**. No arbitrary-port workarounds.
- Never `git add -A`. Stage explicit paths.
- Never write to the worktree while a review round holds it. The frozen-HEAD contract is two-way:
  if HEAD moves mid-review, the reviewer cannot say which tree it examined.
- Read with `git --no-optional-locks` so you never take `index.lock` from a lane.
- Do not open the enforcement gate, change Settings UI, stored shape, public runtime payload or
  product defaults unless the issue explicitly asks.

## Evidence discipline

- **Evidence in the scratchpad is not evidence — commit it.** #9 nearly lost 70 logs when the
  scratchpad was cleared mid-session; they survived only because a review round asked *"can this be
  verified from the tree?"* Artifacts behind any claim belong in `docs/analysis/<date>.<slug>/` with
  a `SHA256SUMS.txt` that `sha256sum -c` accepts from the bundle root.
- **Supersede, never rewrite.** A Change Note, evidence row, commit subject or report sentence that
  a later measurement falsifies gets a *new* entry naming the claim and what falsified it. Never
  amend, even when the commit is unpushed and amending is trivial. A clean history hides that the
  error was made and caught, and that is the most transferable evidence this work produces.
- **A claim being true and its artifact establishing it are different statements.** To the next
  reader an unsupported true claim and a false one look identical.
- **A retraction is a new claim and needs its own evidence.** After an overclaim the pull is toward
  an equal and opposite understatement, and it *feels like rigour*. Say what is now **unknown**,
  not what is now **unlikely**, unless you measured the unlikeliness.
- **Unmeasured, unknowable, and not-yet-looked-at are three different words.** A question inspection
  can answer is not an unknown.
- **Preserve weak evidence under a provenance label rather than deleting it** — deleting it also
  deletes the fact that it was offered.
- Change Notes go **last**, after the final table write (#65 swallowing hazard). Regenerate
  `kiwi/.status.json` as the final spec action (#91: `add-change-note` leaves it one write stale).

## The two failure classes in a verifying surface

| | Class A — disconnected instrument | Class B — under-resolved predicate |
|---|---|---|
| Symptom | does not run, or checks something other than its name | runs, passes, true of the correct state **and** of the defect |
| Found by | **"does this run?"** — answerable by inspection | **"name a defect this assertion would still pass"** |
| Cases | #4 tsconfig, #5 fixture fields, #38/#56 CI, #82, #84 | #6 `includes`, #7 AC-5 raw-text guard, #8 `existsSync` |

Class C, added by #86: **source-text regex tests** — connected, run, green, and never execute the
code they describe. 69 test files read production source; 118 `doesNotMatch` over it; 14 vacuous.
Not all are defects: an absence assertion guarding against *re-introduction* is legitimately
vacuous. The defect is only where the **name claims a behavioural property and the predicate checks
token absence**.

## Sweeps and enumeration

- **Enumerate with an AST, never a regex.** #6 measured regex at 56 of 130 statements (43%),
  missing 25 `if` guards, 24 `break;`s and 14 multi-line expression statements.
- **Sweep two axes**: statement deletion *and* boolean-operand deletion. Statement deletion removes
  every operand of a predicate at once and cannot discriminate them.
- **The post-fix sweep is mandatory, not a formality.** Run before the fix it says what is
  uncovered; run after it says whether what you wrote covers it. In #6 the second run caught the
  test written to satisfy the first.
- **Never report a raw survivor count as a gap count.** One-at-a-time deletion conflates "nothing
  verifies this" with "a redundant sibling enforces it". Delete the group and re-run; only a group
  deletion that stays green is a gap. #7: 27 survivors → 5 gaps.
- **Name the defects your sweep could not produce**, and state which enumeration you swept and what
  it excludes. A stated gap is not a covered area.
- **A no-op claim needs two independent grounds.** A reasoned no-op and a measured no-op are
  different things.
- **When a scanner throws on the first violation, fixing it may reveal more.** Say so in advance,
  re-run, report what surfaces. #8: one visible cause hid three more, and a fifth appeared later.

## Instruments fail silently, and in one direction

**Assume your instrument is the least tested code in play, because it is.** This epic has recorded
17+ instrument self-defects and **zero** production defects found by review across #7 and #8.

- **A mechanical instrument's confidence is a property of its enumeration, not of its results.**
- **A test's strength is a property of its predicate, not of its passing.**
- **A fixture whose inputs are defined in terms of each other cannot falsify the guard that
  separates them.** It returns clean numbers over a question it never asked. Three axes of one
  disease: enumeration (what you looked at), discrimination (what your predicate separates),
  articulability (what your fixture can pose).
- **Controls are per-arm and per-precondition, not per-probe.** A validated control on one arm
  validates nothing about the other. #9's AC-2 probe gave three confident wrong answers in an hour.
- **Verify your control fires before you believe your subject's silence.** A probe whose control
  produces nothing is indistinguishable from a subject that produces nothing, and it fails toward
  *"no defect found"* — the direction that ships defects. Equal budgets on both arms.
- **An enumeration that can return zero must assert its own count before it asserts its property.**
  A universal claim over an empty set is true.
- **Every scripted edit and mutation must assert its own match count.** A replacement that matches
  nothing is indistinguishable from one that succeeded.
- **Prove a file is in the program before believing a clean typecheck** — inject a type error,
  confirm the compiler names the file, restore byte-identically.
- **Probe the numbers, not the verdict.** Nothing on this epic's instrument-defect list was caught
  by reading a verdict; the self-caught ones were caught by printing a count, an exclusion list, or
  the committed bytes.
- **These instruments do not fail toward looking broken.** One that crashes is fixed within the
  minute and never reaches a report, so the surviving population is *selected for plausible-clean
  output*. So: **a tally is a lower bound, not a count**; when unsure, the prior is that it is too
  low; and the next defect is in whatever currently returns a tidy number, not in what failed
  loudly.

## Guards

- **A guard answers the question it was aimed at. The next defect is in the question you did not
  aim at.** #7's `members.length > 10` was correct and load-bearing, and a quoted member walked
  past it while keeping it satisfied.
- **A guard has two failure directions and fixing one is not neutral toward the other.** Before
  loosening a guard to stop a false red, **re-run the evasions it was written to catch and say in
  the commit that you did.** #7 round 3 reopened, one commit later, an evasion round 2 had closed.
- **Stop improving a proxy; enumerate the thing.** #7 closed a proxy-for-property defect with three
  new proxies — name pattern → identifier-only walk → substring → type declaration. What ended it
  was pinning the whole shipped member set.
- **Pin what ships, not what declares it.** `useImperativeHandle<T, R extends T>` admits literal
  members the interface never declares.
- **Allowlists rot.** Make addition cost a decision, not a keystroke: attach a reason per entry, add
  a second condition the name alone cannot satisfy, or derive the list. **Ask what the cheapest way
  to make a future red go green is — if it is "change one word", you have rebuilt the thing.**
- **An allowlist built to replace a rotted one rots identically unless membership is pinned.**
- **Every exemption is a claim.** "This is fine because X" needs X measured, and an exemption you
  grant your own work is where you are least likely to measure it. #9's exemption was licensing an
  unverified hand-typed duplicate of a live registry.
- **A gate closed for the wrong reason is not a closed gate, it is a coincidence.** Assert the
  *reason*, not the state. #9 found the enforcement gate held shut by a stale test count rather than
  by the absence of a stable contract — anyone fixing the count would have opened it.
- **A seal written only on a green run cannot record anything but green.** Ask what values a sealed
  field can take across all paths that reach the seal; if the answer is one, it is a constant no
  matter what it is named.

## Known-failure lists and inherited classifications

- **A "pre-existing failures" list is an allowlist, and worse than a code one** — red is its normal
  state, so nobody looks again. Entries must record **the measured cause and the commit it was
  measured at**, not just a test name. A name match across commits is not a cause match.
- **Before inheriting any "pre-existing" label, verify the named cause still produces the failure at
  your HEAD.** #8 did and found a regression this epic had introduced into itself, hiding under a
  label from a tree where it could not have occurred.
- **Past execution records from another branch are not evidence of the integrated state** — CLAUDE.md
  says so, and #9 found evidence guards imported wholesale from a Wave-3 tree that have never been
  satisfiable here (#94).

## Moving code

- **"Token-identical" answers the behaviour question; it does not answer the identity question.**
  Before moving or renaming a symbol, search for anything naming it as a **string** rather than as
  an import: catalogs, manifests, evidence signatures, source-text assertions, CI globs, doc anchors.
- **Search for the moved content as well as its name** — evidence-signature indexes survive a rename
  search.

## Process

- **Premise check first, always.** For each AC record separately: does the named defect still exist
  in production code, and does the surface that would verify it exist and bear load. Run the tests;
  do not infer from a checkbox, a sealed manifest, or a "No findings" comment.
- **The epic's dominant pattern is a hypothesis, not a prior.** #7 applied "the defect is already
  fixed and the real one is in the verifying surface" as a habit and was wrong about the strongest
  part of its suite. If you cannot state what result would change your mind, you are not predicting.
- **Pre-register before sweeping; report falsification before the disposition.** State the criterion
  in terms of what nobody has examined, not a syntactic category.
- **Report the uneven result, not the average.** Say what you expected to be rotten and wasn't.
- **Writing a rule does not install it.** Three times in this epic a defect appeared in a script
  written *after* its author had written the rule against it. The moment you feel you have just
  understood a failure mode is when the check is most suppressed.
- **When you correct a number, say which way it moved.** If your corrections keep moving the same
  way, say so out loud rather than fixing the latest one.
- **The checkbox is the current claim; evidence rows are the lifecycle record.** Do not uncheck a
  criterion that passes today because it failed at an earlier tree. Do uncheck one whose named
  verification does not pass here, or whose supporting run happened in another tree.
- **`cmd | tail` throws away the exit code.** A pipeline's status is the last command's. Never
  conclude green from a piped invocation; capture status before piping or use `pipefail`. Exit code
  is a claim about a process, not about your question — read the output. `WsRouterSplitHandshake.test.ts`
  returns exit 0 with fourteen broken assertions.
- **Do not auto-dismiss LOW findings.** Most are record accuracy. Flag the departure if a skill's
  `--auto` would reject them.
- **Report to the orchestrator at each phase boundary.** Do not close the issue and do not push.
  Give the frozen HEAD SHA and wait.

## Evidence in the scratchpad is not evidence — commit it

#9 (2026-09-18), and it was nearly a total loss.

A review round found #9's watcher tally unverifiable from the tree: every supporting log lived in
the session scratchpad. The lane committed them into `docs/analysis/` an hour before **the
scratchpad was cleared mid-session.** All 70 logs would have been gone, and every claim derived
from them would have become an assertion no one could check.

**The rule:** a number you derived from a log is only as durable as the log. If a claim will appear
in an evidence row, a report, or a message to the orchestrator, **the artifact behind it belongs in
the repository**, with a `SHA256SUMS.txt` that `sha256sum -c` accepts from the bundle root. The
scratchpad is for work in progress, never for the record.

This is the same principle as superseding rather than deleting: **the value of evidence is that
someone else can check it later**, and an artifact that only you can see has the epistemic status
of a memory.

Note the mechanism that saved it — the review round asked *"can this be verified from the tree?"*
rather than *"is this number right?"* Ask that of your own claims before a reviewer does.

## An exemption you write for your own work needs the same evidence as a finding

#9 exempted an occurrence from a scan on the ground that it was "the membership pin that mirrors
the registry". Measured: the array is referenced exactly once, by a function **called nowhere in
the repository**. Nothing compared it to the live registry, so letting it diverge reddened nothing.
The exemption was licensing an **unverified hand-typed duplicate of a live registry** — the exact
defect class that work existed to remove.

What #9 did next is the model: it did not withdraw the exemption and did not soften the wording. It
**made the claim true** — read the file as text, extract the array literal, assert the extraction is
non-empty *before* asserting equality, then deep-equal against the registry in order.

**Every exemption is a claim.** "This is fine because X" needs X measured, and an exemption you
grant your own work is where you are least likely to measure it. Asserting the extraction is
non-empty before comparing is the empty-enumeration rule applied to an exemption's own evidence.
