## Scope and reuse

Introduce one test-only module, `tools/wave3/admission-fixture-ownership.mjs`, exposing `createOwnedAnalysisLeaf(prefix)`. Reuse the collector's exported `createSegmentReparseGuard()` with default native probing and `forceFresh: true`; reuse unchanged `captureFrozenProvenance`. Do not add caller-supplied filesystem, native admission or root overrides to the collector. Existing opaque admission, retained descriptor checks,64/8192 batch bounds and all freshness boundaries remain intact.

The helper derives its checkout from its own module URL and uses only `docs/analysis/kiwi-coder-2026-07-27.pm.fair-readmission-closure-v3` beneath that checkout. Allocation validates a nonempty ASCII leaf prefix using a closed letters/digits/hyphen grammar, rejects separators/dot traversal/drive syntax, generates a fresh nonce internally (the private filename namespace may retain existing internal prefix conventions; changing that private filename is not a semantic scenario change), validates exact parent containment, and returns a frozen capability without filesystem mutation:

```text
createOwnedAnalysisLeaf(prefix)
  -> frozen { workspaceRoot, manifestPath, capture(phase), createDirectory(), createFile(text), cleanup(priorFailure?: { error: unknown }) }
```

The capability is single-use: an attempted state is set before capture/createDirectory I/O, and either method rejects every repeat or cross-method attempt before I/O or ownership overwrite. Ownership is a separate recorded identity, not the attempted flag. Once cleanup observes absence or succeeds, the capability is retired and cannot acquire or delete a subsequently created leaf.

No arbitrary caller path becomes deletion authority. Module-relative roots do not themselves authorize executing native tests in the original user checkout; real runs require the reviewed canonical workspace preflight. Unit tests use a virtual module with inert filesystem/native boundaries, never original settings or real listeners.

## Operations and ownership

1. `capture(phase)` checks that the nonce leaf is absent, performs fresh native parent validation and establishes the fixed parent if needed with pre-mutation containment/reparse checks. Before establishing the shared parent, inspect the checkout root and existing docs/analysis bases for existence, ordinary directory role and fresh native reparse safety; validate each missing descendant creation boundary. Shared parents are never scheduled for cleanup. It invokes the unchanged native collector with this root/path/phase. Only after successful return does it inspect and record a regular leaf's BigInt `dev`, `ino`, `birthtimeNs` identity and expected role, before returning control to caller assertions.
2. `createDirectory()` checks absence, performs the same fresh containment/parent validation immediately before mkdir, then records the created directory's BigInt identity and expected directory role. This preserves the directory-as-invalid-manifest adversary without recursive deletion.
   `createFile(text)` uses the same single-attempt admission and fresh parent guards, accepts only a string, and writes exactly that text with `{encoding:'utf8',flag:'wx'}` before recording regular-file BigInt identity. It supplies the remediation pre-existing-file sentinel without an unnecessary full capture or weakening the adversary into a directory. Collision, partial write failure or failed identity confirmation does not grant deletion authority; preserve the uncertain leaf. It shares cross-method retirement and existing confirmed-file cleanup.
3. `cleanup()` verifies current containment, fresh native parent/leaf state and exact recorded identity/role immediately before mutation. It unlinks only the owned regular file or uses empty-directory rmdir for the owned directory. It never recursively removes the analysis parent or a nonempty directory.
4. Collision, foreign replacement, role change, reparse parent/leaf, unsupported identity or unconfirmed ownership preserves the existing path and reports an error. A collector failure before successful return does not grant ownership, even if a leaf appeared. No attempt may reinterpret that leaf as a successful capture.
5. An absent leaf or an already successfully removed owned leaf makes repeated cleanup idempotent. Absence is not authority to remove a later replacement: retained state must prevent subsequent calls from acquiring new ownership. Permission/deletion errors remain visible and must not be converted into success.

The post-return identity sample binds cleanup to the observed regular file; it is not an atomic proof that those bytes are the exact file returned by capture. Native checks and lstat also do not eliminate every TOCTOU window. This helper does not replace or weaken the collector's retained-FD identity/freshness boundary. Preserve uncertain artifacts rather than guessing ownership.
