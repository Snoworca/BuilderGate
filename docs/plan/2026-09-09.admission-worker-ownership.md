## Lifecycle

1. Each Worker allocates its capability without I/O, using a validated namespace and internally generated nonce. It reports ready with index and manifest path. The parent associates the message with the actual Worker instance that emitted it, not merely a self-reported index.
2. Parent validates one ready record per expected Worker, matching index, canonical fixed analysis parent, expected regular-leaf naming and distinct resolved paths. Unknown/duplicate index, changed path, path escape or identical sibling path fails. The parent obtains read authority only; it cannot adopt or delete that path.
3. Preserve the existing ready counter and shared start release. No capture occurs before that barrier. The Worker calls its own capability capture and retains all existing local manifest/import/provenance assertions before captured notification.
4. Captured records must match the same registered Worker/index/ready path and preserve phase/hash identity. Parent verifies both actual manifests while Workers retain their capabilities. Immediately before each read, reuse canonical containment and fresh native parent/leaf reparse validation and require a regular leaf; retain existing semantic assertions. Do not await Worker exit before those reads: Workers are intentionally waiting for cleanup permission.
5. Use a dedicated cleanup-permit Atomics slot, separate from existing start/capture counters. Set its state before notify; an early permit cannot be lost and cannot bypass the existing start barrier or authorize pre-start capture. Parent finally releases start and every cleanup permit independently regardless of prior errors, then awaits every successfully started Worker exit. A permit on a failure path means permission to clean, not proof that parent validation succeeded.
6. Worker waits for cleanup permission after either successful capture or a captured body failure, then calls its own capability cleanup with tagged prior error. Capture failure without confirmed ownership preserves any uncertain leaf and reports it. Worker reports original/cleanup failures without hiding either and exits naturally. Parent records all original and cleanup errors/exit outcomes and checks absent successfully cleaned leaves; cleanup failure never permits parent fallback deletion, and it never unlinks or recursively removes them.
7. Keep shared canonical analysis parents intact. Unconfirmed exit or cleanup failure never grants parent fallback deletion authority. Preserve affected paths and diagnostics.

## Minimal reuse

Proposed narrow shared operations: a finite condition wait with explicit timer disposal; parent release-and-await over registered Worker handles/exit promises and per-Worker permit functions; and Worker capability cleanup after the dedicated permit. Keep scenario-specific capture/provenance assertions in each existing test. Final function signatures should follow the inert RED harness, with no collector API, caller filesystem or public root override.

Register each successful Worker construction and its exit/error handlers before handing the handle to later setup code. If constructing a later Worker throws, finally still releases and awaits those already created. Avoid constructing all Workers with an untracked array.map that can lose earlier handles on a later throw.

Condition waits must stop polling on resolve, timeout, predicate error or early Worker failure. Clear both deadline and pending poll timers; no recursive poll may survive settlement. Keep existing failure deadlines; timeout rejects the scenario, while cleanup permits and natural exit waiting still run. Never add a killing timeout to force settlement.
