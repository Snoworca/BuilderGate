# 에이전트가 선택 입력을 기다리는 탭 표시 (FR-AITUI-024)

## 이슈

- 탭 위의 진행 줄로 세션이 실행 중인지는 보이지만, Claude Code 가 권한 요청이나 선택지를 띄우고 기다리는 탭은 알아볼 수 없다. 그런 탭에 아이콘(? · ! 등)을 띄우고, 선택 입력을 받으면 아이콘을 없애 달라는 요청이었다.
- 사용자는 화면 판정 방식에 부하(메모리 · CPU · 주기적 확인)가 있는지와 Claude Code hook 방식과 비교해 충분한지도 물었다. 설명을 들은 뒤 화면 판정 방식과 주황 ? 배지를 골랐고, 워크스페이스 목록에도 입력 대기 탭 수를 표시하는 것까지 함께 넣기로 했다.
- 같은 대화에서 워크스페이스 목록의 노란 숫자가 무엇인지도 물었다. 이 숫자는 그 워크스페이스에서 실행 중(`status === 'running'`)인 탭 수이다(`WorkspaceSidebar.tsx` 의 `getRunningCount`).

## 원인

- 서버는 PTY 출력으로 `running`/`idle` 만 정해 내보낸다. 내부에 `waiting_input` 활동이 있지만 `idle` 로 합쳐진다.
- MCP 의 `agentStatus`(`waiting_input` 포함)는 에이전트가 스스로 보고할 때만 생긴다. 손으로 띄운 Claude Code 에서는 생기지 않고, 탭 막대도 이 값을 읽지 않는다.
- 권한 요청이나 선택지를 따로 감지하는 곳은 없었다.

## 방식을 고른 근거

- **화면 판정:** 서버는 재연결할 때 화면을 복원하려고 세션마다 headless 터미널을 이미 들고 있다. 그래서 추가로 쓰는 메모리가 없다. 판정은 출력이 멈출 때만 화면 맨 아래 16줄을 읽으므로 CPU 비용도 1 ms 미만이고, 주기적 폴링이 없다. 설정이 필요 없고, ssh · WSL · 컨테이너 안의 Claude Code 와 Codex 에도 동작한다.
- **Claude Code hook:** Claude Code 가 직접 알리므로 화면 모양이 바뀌어도 맞는다. 하지만 받는 경로와 모든 세션의 세션 식별자 환경 변수가 새로 필요하고, PC 마다 설정해야 한다. hook 은 Claude Code 가 도는 기계에서 실행되므로 ssh 너머에서는 서버에 닿지 못하고, Codex 는 따로 만들어야 한다. 나중에 놓치는 경우가 보이면 같은 표시를 켜는 추가 신호로 얹을 수 있다.

## 해결

- **판정 함수** (`server/src/utils/agentChoicePrompt.ts`)
  - `isAgentChoicePrompt`: 화면 맨 아래에 커서 표식(❯ › ▶ ➤)이 붙은 선택지가 있어야 한다. 그리고 그 아래 8줄 안에 메뉴 안내 줄(「Enter to select」, 「Esc to cancel」 등, 「esc to interrupt」 는 제외)이나 다음 번호 선택지가 있어야 한다.
  - 실제 화면을 캡처해 보니 Claude Code 의 폴더 신뢰 메뉴에는 번호가 없었다(「❯ No, exit / Yes, I trust this folder」). 그래서 번호만 보는 규칙으로는 이 메뉴를 놓치므로, 안내 줄 규칙을 함께 둔다.
  - `isChoiceAnsweringInput`: Enter · Esc · 숫자 · 글자 · 붙여넣기는 「답함」이다. 방향키 · Tab · Shift+Tab · PageUp/Down · 포커스 보고 · 마우스 보고 · 커서 위치/장치 속성/OSC 응답은 「답하지 않음」이다.
  - `readHeadlessBottomRows`: 화면 맨 아래 줄만 읽고 scrollback 은 읽지 않는다.
- **점검 시점** (`server/src/services/AgentAwaitingInputTracker.ts`)
  - 출력이 나오면 점검을 하나 예약한다. 출력이 250 ms 멈추면 읽고, 출력이 계속 이어지면 늦어도 1.5 초 뒤에 읽는다.
  - 답하는 키가 들어오면 바로 지운다. 그 전에 시작된 읽기가 표시를 다시 켜지 못하게 세대 번호로 막는다.
  - 방향키는 지우지 않는다. 메뉴 안에서 커서를 옮길 때 배지가 깜빡이지 않게 하려는 것이다.
- **`SessionManager.ts`**: 다음 지점에 tracker 를 연결했다.
  - PTY 출력 처리기 맨 앞에서 `noteOutput` 을 부른다.
  - `data.pty.write` 뒤에서 `noteInput` 을 부른다.
  - 세션을 제거할 때 `forget` 을 부른다.
  - 화면은 `headlessWriteChain` 이 끝난 뒤에 읽는다.
  - 결과는 `onAwaitingInputChange` 콜백으로 내보낸다.
- **`WorkspaceService.ts`**: 탭에 `awaitingInput` 을 표시하고 `tab:updated` 를 내보낸다. `index.ts` 가 이를 `broadcastAll` 로 모든 연결에 보내므로, 구독하지 않은 다른 워크스페이스의 탭에도 전달된다. 디스크에 쓸 때는 이 필드를 뺀다.
- **프런트엔드** (`AwaitingInputBadge.tsx`, `awaitingInputTabs.ts`)
  - 탭 이름 앞에 주황 동그라미 ? 를 그린다.
  - 워크스페이스 목록에는 실행 중 숫자 옆에 주황 「?N」 을 그린다.
  - 색은 새 토큰 `--attention`(#ff7a1a)이다. 실행 중 숫자의 호박색(`--warn`)과 모바일 잠금 키의 주황(`--lock`)과 구별된다.
  - i18n 키 `workspace.tabBar.awaitingInput` 과 `workspace.item.awaitingInput.{one,other}` 를 en·ko 에 추가했다.
  - 개수 함수 `countAwaitingInputTabs` 는 `.ts` 파일에 따로 두었다. 컴포넌트를 떼어 내 실행하는 `workspaceCapacityUi.test.ts` 가 `.tsx` 를 불러오지 못하기 때문이다. 이 테스트의 주입 목록에도 새 이름 세 개를 더했다.

## 2222 브라우저 확인에서 찾아 고친 것 (2026-11-17)

커밋 전에 2222 에서 브라우저로 확인해 달라는 요청을 받았다. 2002 가 이 체크아웃의 `server/data` 와 설정을 쓰므로, HEAD(16704ffe) 의 깨끗한 워크트리에 이번 변경을 얹고, 그 워크트리 안에서 따로 설정과 데이터를 두어 2222 를 띄웠다. 처음 두 번은 메뉴가 떠도 배지가 켜지지 않았다. 단위 테스트와 지난번 직접 실행이 놓친 결함이 둘 있었다.

- **커서가 ASCII `>` 였다.** 데몬은 `TERM` · `WT_SESSION` · `TERM_PROGRAM` 없이 실행된다. 이 환경에서 Claude Code 는 유니코드를 쓰지 못한다고 보고 메뉴 커서를 `❯` 대신 `>` 로 그린다. 2002 에서 도는 Claude Code 의 입력 줄도 `> Try "..."` 로 그려지고 있었다. 반면 지난번 직접 실행은 Git Bash 에서 `TERM=xterm-256color` 를 물려받아 `❯` 가 나왔다.
  - 판정 규칙이 `>` 하나를 커서로 받아들이도록 고쳤다. AC-1 은 처음부터 `>` 를 커서 표식에 넣어 두었으므로, 코드를 AC 에 맞춘 것이다.
  - `>>` 는 PowerShell 의 이어 쓰기 줄이므로 제외한다.
  - 이 환경으로 캡처한 신뢰 메뉴와 대기 화면을 자료에 더했다.
- **키 큰 화면에서 메뉴가 화면 중간에 있었다.** 브라우저 터미널은 143×40 이었다. Claude Code 는 셸 프롬프트 아래에 이어서 그리므로 메뉴가 18번째 줄쯤에 있었고, 화면의 마지막 16줄은 비어 있었다. 지난번 직접 실행은 80×24 화면이어서 메뉴가 맨 아래까지 밀려 이 차이가 드러나지 않았다.
  - `readHeadlessBottomRows` 가 화면의 마지막 줄이 아니라 내용이 있는 마지막 줄까지 최대 16줄을 읽게 고쳤다. scrollback 은 여전히 읽지 않는다.
  - AC-2 문구를 이에 맞춰 고쳤다.
- 둘 다 실패하는 테스트를 먼저 넣고 고쳤다. `agentChoicePrompt.test.ts` 는 처음에 2건, 다음에 1건이 실패했고, 고친 뒤 25/25 가 되었다.
- 고친 뒤 2222 브라우저 확인 결과(Playwright 로 띄운 headless Chromium, 스크린숏 `.playwright-mcp/awaiting-23..25`)
  - 셸 프롬프트에서는 배지가 없었다.
  - 신뢰 메뉴가 뜨자 탭 이름 앞에 주황 ? 가 생겼다(레이블 「선택을 기다리는 중」).
  - 다른 워크스페이스에 있을 때 목록에 「?1」 이 보였다(레이블 「선택을 기다리는 탭 1개」).
  - 그 워크스페이스로 돌아왔을 때와 아래 화살표를 눌렀을 때 배지가 유지되었다.
  - Enter 를 누르자 브라우저에서 4 ms 뒤에 사라졌다.
  - 그 뒤 Claude 입력 줄에서는 다시 켜지지 않았고, 「?N」 이 남은 워크스페이스도 없었다.
- 확인하다 보니 스크립트의 경로 치환이 실패해, Claude Code 가 홈 폴더에서 떴고 「Yes, I trust this folder」 가 선택되었다. `~/.claude.json` 에서 홈 폴더의 `hasTrustDialogAccepted` 를 보니 그대로 `false` 였다. 저장되지 않았으므로 되돌릴 것은 없었다.

## 요구사항

- 새 target `agent-awaiting-input` 에 FR-AITUI-024 를 등록했다. Active Target 은 다른 작업(`loop-existing-session`)의 것이라 바꾸지 않고 `register-target` 으로만 등록했다.
- AC-3 문구를 실제 동작에 맞춰 고쳤다. 메뉴 안을 움직이는 키는 표시를 지우지 않고 다음 화면 판정에 맡긴다는 내용이며, 변경 노트에 이유를 남겼다.
- AC-1~AC-4 는 체크했다. AC-5(화면 표시)는 처음에 체크하지 않았다가, 2222 브라우저 확인 뒤에 체크했다(VE-9). 상태는 implemented 이다.
- 2026-11-17 에 증거 VE-8(ASCII 커서 · 키 큰 화면 테스트)과 VE-9(2222 브라우저 확인)를 더했다. 변경 노트 세 줄도 남겼다(커서 표식, AC-2 문구, AC-5 체크).

## 남은 일

- 서버 변경은 2002 를 다시 시작해야 적용된다. 다시 시작하면 도는 세션이 끊기므로 시점은 사용자가 정한다. 그 전까지 2002 에서는 프런트엔드만 바뀌고, 서버가 표시를 보내지 않으므로 배지는 보이지 않는다.
- 2222 에서는 폴더 신뢰 메뉴로만 확인했다. 권한 요청과 AskUserQuestion 화면은 ASCII 커서로 캡처하지 못했고, 번호 메뉴 규칙과 직접 만든 ASCII 번호 메뉴 테스트로만 덮었다.
- 그리드(모자이크) 보기의 칸 머리에는 배지를 넣지 않았다.
- Claude Code 가 메뉴 문구나 모양을 바꾸면 판정 규칙을 고쳐야 한다. 이때는 새 화면을 캡처해 자료에 더한다.
