# md 편집창 탭 단위 닫기 및 복원 경합 수정

- **커밋**: `ee67ed40` fix(editor): md 편집창을 탭 단위로 닫고, 닫은 문서가 복원으로 되살아나지 않게 한다
- **요구사항**: `FR-MDE-011` (신설), `FR-MDE-009` AC-13 (추가), `FR-MDE-006` (창 전체 닫기 분기 승계)

## 이슈

사용자 보고 두 건.

1. md 편집창에 탭이 여러 개 있을 때 타이틀바 `X` 를 누르면 창이 닫히고, 다시 띄우면 그동안 떠 있던 탭이 전부 사라져 있다. 편집창은 탭을 하나씩 닫아야 닫히도록 할 것.
2. (후속) `CLAUDE.md` 를 띄움 → 창 `X` 로 종료 → `AGENTS.md` 를 띄움 → 닫았던 `CLAUDE.md` 가 탭으로 함께 나온다.

## 문제 원인

### 1. 타이틀바 X 가 워크스페이스의 모든 문서를 버렸다

`EditorWindow.requestCloseWindow` → `onCloseWindow` → `useEditorWindows.closeWindow` 가
`setDocuments(current => current.filter(d => d.workspaceId !== workspaceId))` 로 그 워크스페이스의
문서 전부를 한 번에 제거했다. 하필 이 분기는 **dirty 한 문서가 하나도 없을 때** 타는 쪽이라
확인 질문이 없었다 — 열두 개 탭이 한 번의 누름에 말없이 사라지고 되돌릴 방법도 없었다.

### 2. 복원이 사용자가 닫은 문서를 되살렸다

`useEditorWindows` 의 복원은 페이지 로드 시 저장된 레코드를 읽어 파일을 순서대로 읽은 뒤,
**그 결과가 도착한 순간 열려 있는 문서**와 비교해 없는 것을 추가한다. 그 시점에서
"사용자가 일부러 닫은 문서" 와 "애초에 열린 적 없는 문서" 는 구별되지 않는다.

저장소 자체는 정상이었다(닫으면 지워진다). 되살린 것은 로드 시점에 이미 읽어 둔 배열이다.

## 해결 방법

### FR-MDE-011 — 타이틀바 닫기는 문서 하나를 닫는다

- `frontend/src/components/editor/editorWindowCloseControl.ts` 신설.
  `planEditorWindowCloseControl` 이 한 번의 누름을 **활성 문서 하나**로 해석한다.
  첫 dirty 탭이 아니라 활성 탭인 이유는, 화면에 있는 파일에 대한 질문이어야 답할 수 있기 때문이다.
  활성 경로가 어떤 탭도 가리키지 않으면 첫 탭으로 떨어진다 — 아무 일도 안 하는 컨트롤은
  고장난 컨트롤과 구별되지 않는다.
- `EditorWindow` 는 그 문서의 패널 핸들 `requestClose()` 를 부른다. 탭의 `x` 와 같은 경로이므로
  `FR-MDE-006` 의 저장 확인 분기가 그대로 돈다. 탭을 패널 뒤로 닫으면 저장 안 한 본문을
  확인 없이 버리게 된다.
- `useEditorWindows.closeWindow` 는 **삭제**했다. 호출자만 떼고 남겨두면 다음에 닫기 컨트롤을
  배선하는 사람이 찾아 쓰게 된다. 창은 마지막 문서가 닫힐 때 `closeDocument` 가 이미 없앤다.

### FR-MDE-009 AC-13 — 닫은 문서는 복원되지 않는다

- `frontend/src/hooks/editorRestoreAdmission.ts` 신설.
  `selectRestorableDocuments` 가 이미 열린 경로와 **이번 페이지 로드에서 사용자가 닫은 경로**를
  함께 거른다.
- 훅은 닫힘을 `closedByUserRef` 에 기록하고, 손으로 다시 열면 그 기록을 철회한다.
  철회하지 않으면 한 번 닫은 파일은 그 로드 동안 영영 복원될 수 없다.
- 멈추는 것이 아니라 거르는 것이다. 하나를 닫은 사용자는 나머지에 대해 아무 말도 하지 않았다.

## 검증

측정은 실행 중인 서버(TCP 2222)와 실제 브라우저로 했다. 파일 읽기를 5초로 늦춰 경합 창을 넓혔다.

| | 닫은 뒤 복원이 도착하면 |
|---|---|
| 수정 전 | `["AGENTS.md","CLAUDE.md"]`, 창 1개 — 닫은 것이 돌아옴 |
| 수정 후 | `["AGENTS.md"]` — 돌아오지 않음 |

`AGENTS.md` 는 이번 로드에서 연 적도 닫은 적도 없는, 저장소가 들고 있던 것이라 복원이
제 일을 늦게 한 것이다.

탭 단위 닫기(3개 탭):

| 동작 | 탭 | 창 |
|---|---|---|
| X 1회 | 2 | 1 |
| X 2회 | 1 | 1 |
| X 3회 | 0 | 0 |
| 다시 열기 | 그 파일 하나만 | 1 |

대조군 3개가 같은 실행에서 통과했다. 그중 첫 번째가 가장 중요하다 — 복원 테스트를
통과시키는 가장 값싼 방법이 "사용자가 뭔가 닫으면 복원을 아예 멈추는 것" 이기 때문이다.

1. 평범한 새로고침은 여전히 두 문서를 모두 복원한다.
2. X 한 번은 여전히 탭 하나만 닫는다.
3. 닫았다 손으로 다시 열면 열린다.

## 기록해 두는 것

- **사용자가 처음 본 두 증상은 모두 수정 전 빌드에서 관측된 것이었다.** 2222 가 서빙하던
  `server/dist/public` 이 09:55 빌드였고 소스 변경은 18:15 였다. `frontend/dist` 를 다시 빌드해
  체크아웃 안에서 복사했다. 운영 배포본(`C:\Work\agent-tools\builder-gate__\web`, 2026-07-10)은
  건드리지 않았고 확인했다. `npm run build` 의 postbuild `stageFrontendAssets()` 는 설치본을
  가리키므로 이 체크아웃의 배치에 쓸 수 없다.
- **첫 측정에서 "X 를 눌러도 아무 일이 없다" 가 한 번 나왔으나 결함이 아니었다.** 직전 실행이
  남긴 탭을 비동기 복원이 되돌려 놓는 중이어서, X 가 탭 하나를 닫는 동시에 복원이 다른 하나를
  넣어 개수가 안 변한 것처럼 보였다. 저장소를 비우고 각 단계의 **관측 가능한 종료 상태**를
  기다리도록 고쳐 다시 측정했다.
- 복원 경합에 대한 **상시 E2E 는 추가하지 않았다.** 5초 지연 라우트가 필요해 느리고, 배선은
  단위 테스트의 소스 가드가 고정한다. 회귀가 나면 그 가드가 먼저 빨개진다.
