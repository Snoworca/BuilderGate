# 아이폰 홈 화면 앱이 위로 밀려 보이는 문제와 상태 표시줄 밑에 깔린 창 수정 (FR-ARCH-016 AC-6, AC-7)

## 이슈

아이폰 홈 화면에 추가한 BuilderGate 앱에서 화면 전체가 위로 밀려 보이고 아래쪽이 비는 문제를 고쳐 달라는 요청. 새로고침하거나, 앱을 다시 열거나, 홈 화면에 다시 추가해도 증상이 남았다. Safari 탭에서는 정상이었고, 증상은 가끔씩 나타났다.

## 문제 원인

임시 진단 표시를 2002 개발 서버에 올려 실제 아이폰(iOS 26, 화면 402x874)에서 값을 읽었다.

| 값 | 홈 화면 앱(증상) | Safari 탭 |
| --- | --- | --- |
| `screen` | 402x874 | 402x874 |
| `innerHeight`, `100dvh` | 812 | 654 |
| `100lvh`, `100vh` | 874 | 754 |
| `safe-area-inset-top / bottom` | 62 / 34 | 0 / 0 |
| `.app` 위치와 높이 | top 62, 높이 716 | top 0, 높이 654 |

- 홈 화면 앱은 반투명 상태 표시줄과 `viewport-fit=cover` 를 쓰므로, 페이지가 화면 전체(874)를 덮어야 한다.
- 그런데 iOS가 페이지 높이를 상태 표시줄 높이를 뺀 812로 주었다. 페이지는 그 높이로 화면 맨 위부터 그려졌다.
- 루트(`html`)의 높이가 `100%`(=812)였으므로, 위 여백 62 + 앱 716 + 아래 여백 34 = 812가 되었다. 그 결과 화면 아래 62pt가 비고, 앱 전체가 위로 몰려 보였다.
- 같은 상태에서도 `100lvh` 는 874를 정확히 돌려주었다.
- 키보드 판정(`kbInset=0`)과 키 막대는 정상이었다. 처음에 세운 「키보드가 올라왔다고 잘못 판단했다」는 가설은 이 값으로 기각했다.

## 해결 방법

- 홈 화면 앱일 때만 루트 높이를 `100lvh` 로 잡는다(`html.standalone-app { height: 100lvh; }`).
- iOS가 페이지 높이를 바르게 줄 때는 `100lvh` 와 `100%` 가 같으므로, 정상일 때의 화면은 달라지지 않는다.
- 브라우저 탭에는 `standalone-app` 클래스가 붙지 않으므로 영향이 없다(AC-4).
- 키보드가 올라온 상태는 기존처럼 `app--viewport-locked` 가 화면에 고정된 높이를 쓴다.
- 위쪽 상태 표시줄 띠의 색과 흐림 효과는 v0.11.7부터의 모습 그대로 두기로 했다(사용자 결정).

## 검증

- 단위 테스트: `frontend/tests/unit/standaloneViewport.test.ts` 에 `100lvh` 단언을 추가했다. CSS 수정을 되돌린 상태에서 그 단언으로 실패하는 것을 확인한 뒤, 수정을 넣고 `homeScreenApp.test.ts` 와 함께 9/9가 통과했다. `tsc -p tsconfig.app.json` 도 깨끗하다.
- 실제 기기: 2002에 수정을 올린 뒤, 사용자가 아이폰 홈 화면 앱에서 키 막대가 홈 인디케이터 바로 위까지 내려오고 앱이 화면을 채우는 것을 확인했다.
- SRS: FR-ARCH-016 AC-6 문구 갱신 및 체크, VE-5(테스트), VE-6(실기기), Change Note 추가. `speckiwi validate` 오류 0건, `check:kiwi-status` 와 `check:srs-change-notes` 통과.
- 진단 표시(`ViewportDiag`)는 확인을 마친 뒤 지웠고, 커밋에는 들어가지 않는다.

## 추가 수정: 상태 표시줄 밑에 깔린 창과 메뉴 (AC-7)

높이를 고친 뒤, 홈 화면 앱에서 메신저 창을 닫을 수 없고 워크스페이스 메뉴에서 워크스페이스를 추가할 수 없다는 보고가 이어졌다.

- 원인: v0.11.7에서 상태 표시줄을 반투명으로 바꾼 뒤로, 앱 본체는 안전 영역 여백으로 상태 표시줄을 피했다. 그러나 앱 바깥에서 화면에 고정되는 창 레이어(`.window-dialog-layer`), 모바일 워크스페이스 메뉴(`.mobile-drawer`), 모바일 Git 화면(`.git-mobile`)은 `top: 0` 이나 `inset: 0` 으로 화면 맨 위부터 그려졌다. 화면을 채우는 메신저 창도 `innerWidth x innerHeight` 크기로 (0,0)에 놓였다. 그래서 닫기 버튼과 추가 버튼이 상태 표시줄 밑에 깔렸다. 높이 수정과는 무관하게 v0.11.7부터 있던 문제다.
- 해결: `html.standalone-app` 아래에서만 창 레이어를 안전 영역으로 옮기고, 메뉴와 Git 화면에 위아래 여백을 넣었다. 설정 화면과 메신저 알림도 상태 표시줄 높이만큼 내렸다. 화면을 채우는 창의 크기는 `readSafeViewportSize()`(`utils/standaloneViewport.ts`)가 안전 영역을 측정해 정한다. 브라우저 탭에서는 이 함수가 `innerWidth x innerHeight` 를 그대로 돌려준다.
- 검증: 테스트 11/11(새 함수가 없어 파일 로드가 실패하는 것을 먼저 확인), 대화상자·메신저·i18n 가드 테스트 143/143, 앱 `tsc` 깨끗. 사용자가 실제 아이폰에서 메신저 창 닫기와 워크스페이스 추가가 되는 것을 확인했다. SRS: FR-ARCH-016 AC-7 추가 및 체크, VE-7(테스트), VE-8(실기기), Change Note.
