# 설치 시 2002 인스턴스 종료, 중복 실행 한 줄 안내, 탭 동작 중 표시 보고서

- 날짜: 2026-10-14
- 버전: 0.10.13
- 요구사항: OPS-BGSTAB-021, FR-BGSTAB-033, FR-UIDS-009 (target `release-0-10-13`, 새로 등록)

## 1. 설치 시 2002 포트의 BuilderGate 종료 (OPS-BGSTAB-021)

### 문제

- MSI 는 업그레이드할 때만, 설치 검증(InstallValidate) 전에 `BuilderGate.exe stop` 을 한 번 불렀다.
  결과는 무시했다(`Return="ignore"`).
- `stop` 은 정상 종료만 시도한다. 실패하면 그대로 끝나고 강제 종료는 하지 않는다.
- 처음 설치하는 경우나, 포터블·소스 실행본이 2002 포트를 쓰는 경우에는 아무것도 하지 않았다.

### 해결

| 파일 | 변경 |
| --- | --- |
| `tools/daemon/msi-stop-port-owner.ps1` (신규) | 2002·2001 포트를 쓰는 프로세스를 찾는다. 실행 파일이 `BuilderGate.exe` 이거나, 명령줄에 `--internal-app`·`--internal-sentinel` 이 있거나, BuilderGate 체크아웃(`server/package.json` 이름이 `buildergate-server`)의 `server\dist\index.js` 일 때만 BuilderGate 로 본다. 그 감시자는 명령줄의 `--internal-sentinel-state` 상태 파일에 적힌 `appPid` 로 짝을 찾는다. 감시자를 먼저, 리스너를 그다음에 PID 로 종료한다. 포트가 빌 때까지 최대 20초 다시 확인하고, 그래도 BuilderGate 가 남으면 exit 1 로 끝난다. |
| `tools/build-msi.js` | 위 스크립트를 `-EncodedCommand` 로 MSI 에 넣는다. WiX Util 확장의 `WixQuietExec` 로 실행한다. 명령줄이 속성값에 들어가므로 255자 제한이 없고, 콘솔 창이 뜨지 않으며, 출력이 MSI 로그에 남는다. 순서는 `StopRunningDaemon` → `StopPortOwner` → `InstallValidate` 이다. 설치·업그레이드 때 실행되고(`NOT REMOVE="ALL"`), 실패하면 설치를 멈춘다(`Return="check"`). Util 확장이 없으면 빌드할 때 추가한다. |

광역 종료(이미지 이름 종료, 프로세스 트리 종료)는 쓰지 않는다. BuilderGate 가 아닌 프로세스는 종료하지
않는다.

### 검증

- Windows 실제 프로세스 통합 테스트 3건(임의 포트, 2001/2002 는 쓰지 않음).
  - BuilderGate 형 리스너와 그 짝 감시자는 종료된다.
  - 다른 인스턴스의 감시자와 무관한 리스너는 그대로 남는다.
  - 빈 포트에서는 아무것도 하지 않고 exit 0 이다.
- MSI 렌더링 테스트 3건(x64·arm64·x86).
- 로컬 WiX 5.0.2 로 세 아키텍처의 MSI 를 실제로 빌드하고 역컴파일했다. CustomAction 과 실행 순서를
  확인했다. 설치는 하지 않았다.
- `-EncodedCommand` 형태로 감싼 스크립트를 실제로 실행해 `param` 블록이 동작하는 것을 확인했다.

### 남은 사항

- 종료할 수 없는 BuilderGate(예: 관리자 권한 프로세스)가 남을 때의 실패 경로는 자동 테스트하지 않았다.

## 2. 이미 실행 중일 때 다시 실행 (FR-BGSTAB-033)

### 문제

이미 실행 중이면 포트와 두 PID 를 출력했다. 그 뒤 `main` 이 계속 진행해 "Deployed in background…" 와
HTTPS 안내까지 출력했다. 같은 포트를 다른 위치의 BuilderGate 가 쓰면 "다른 프로그램" 으로 안내했다.

### 해결

| 파일 | 변경 |
| --- | --- |
| `tools/daemon/already-running.js` (신규) | 한 줄 메시지, 자기 데몬 판정(상태 파일), 같은 포트의 BuilderGate 판정(`/health` 의 `status`·`buildId`·`rootsForeign`), 보고(한 줄 + `--open` 이면 브라우저)를 담는다. |
| `tools/start-runtime.js` | daemon 모드이고 `--reset-password` 가 아니면, 의존성 빌드·설정 preflight 전에 자기 데몬을 확인한다. 포트 선택(`chooseStartPort`) 전에는 같은 포트의 BuilderGate 를 확인한다. 실행 중이면 `BuilderGate is already running at https://localhost:<port>.` 한 줄만 출력하고 exit 0 으로 끝난다. |

### 검증

- 단위 테스트 9건(수정 전 red). 배선 순서는 소스 순서 단언으로 고정했다.

## 3. 탭 모드 동작 중 표시 (FR-UIDS-009)

### 해결

| 파일 | 변경 |
| --- | --- |
| `frontend/src/components/Workspace/workspaceTabClass.ts` (신규) | 탭 버튼의 클래스를 정한다. 상태가 `running` 이면 `is-running` 을 붙인다. |
| `WorkspaceTabBar.tsx` | 위 함수로 클래스를 정한다. |
| `WorkspaceTabBar.css` | `is-running` 탭의 `::after` 가 색상 막대(`border-top`) 위에서 탭 너비 10%의 밝은 띠로 좌우로 움직인다. `transform` 만 움직인다. 움직임 줄이기 설정에서는 띠를 숨기고 막대를 밝게 한다. |

`running`/`idle` 표시는 REL-BGSTAB-035 의 3.5초 유지 규칙을 그대로 따른다.

### 검증

- 단위 테스트 7건(수정 전 red).
- `workspaceCapacityUi` 하네스에 새 함수를 주입했다. 이 하네스는 컴포넌트의 import 를 빼고 의존성을
  주입한다.
- 2222 실브라우저(터미널 40개 중 `repro-1`):
  - 명령 전에는 띠가 없다.
  - 실행 중에는 띠가 있다(탭 200px 의 띠 20px). 0.5초 간격으로 `translateX` 가 177px 에서 90px 로
    바뀌었다.
  - 끝난 뒤에는 띠가 사라진다.
  - 스크린샷: `.playwright-mcp/fr-uids-009-*.png`
