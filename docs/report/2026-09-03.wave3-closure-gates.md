## 문제 원인

### 문제 1: Lexical Census Drift

`tools/wave3/fair-readmission-closure-v3.lexical.test.mjs` 는 세 소스 파일의 admitted import 엣지 개수를 동결하는데, `TerminalResourcePolicyCanary.test.ts` 에 대한 기대값이 14 였으나 실제 코드베이스의 값은 15 입니다.

**근본원인**: 
- 커밋 `f1e354c`(2026-07-27)에서 census 를 동결했을 당시 세 파일 중 둘이 저장소에 존재하지 않았습니다
- 즉 미추적 파일이 있던 워킹트리의 census 를 기록한 것입니다
- 15번째 엣지를 추가한 커밋은 저장소에 없으며, 파일들이 `5918146`(2026-08-31)에 들어올 때 이미 15개였습니다
- `docs/research/binary-comms/baseline/wave3-baseline.md:103` 에서 이 실패를 D-1 로 기록해두었습니다

**계약 검토**:
- SDS(`docs/spec/steps/2026-07-27.pm.fair-readmission-closure-v3-lexical/design.md`) 의 SDS-AC-2 는 개수를 규정하지 않고 "proved immutable literal-const dynamic imports SHALL produce normal contained/external edges" 라는 전칭만 규정합니다
- 작성 시점의 실측치 "16"은 §1(서술)·§3(basis)·§6(actual) 에만 나타납니다
- 비용 최소화 원칙: census 를 지키려 소스를 고치는 것은 SDS 의 Non-goals("source normalization", "source rewrite")를 자기 계약이 강제하는 모순

### 문제 2: Boundary Gate 의 공허한 통과

`tools/wave3/fair-readmission-closure-v3.boundary-gate.test.mjs` 가 형제 9개 스위트를 `spawnSync` 로 재실행하는 로직을 가지고 있으나, 환경변수 필터링이 없어 `NODE_TEST_CONTEXT` 를 상속했습니다.

**동작 분석**:
- Node.js 의 재귀 가드가 `NODE_TEST_CONTEXT` 를 감지하고 `skipping running files` 로 0개 실행 후 exit 0 반환
- 게이트는 126ms 만에 통과했습니다 (실행 0건, stdout 0줄)
- `env` 필터를 넣어 실제로 돌리면 **180초 이상 소요**되어 게이트의 120초 예산을 초과합니다
  - 형제 9개 직접 실행 시간: 181.7초
  - 이 중 `wave.test.mjs:107` 의 `captureFrozenProvenance` 한 호출이 88.7초

**기존 계약과의 충돌**:
- `admission` SDS 에서 이미 대체: "Replace the nine-file gate with one nonrecursive fixed gate covering every functional suite but excluding only itself"
- `boundary` SDS 의 Status 는 이미 `superseded` 로 표기됨
- 두 게이트가 `boundary.test.mjs` 에 대해 **서로 반대되는 계약** 단언:
  - boundary-gate: 해당 파일을 **포함**해야 함
  - admission-gate: 해당 파일을 **제외**해야 함
