# MCP 기본값 정리: 원격 링크 예시는 http, 외부 IP 목록 기본값은 `*`

## 이슈

사용자 요청: MCP 기본 설정의 프로토콜을 https 에서 http 로 바꾼다. 외부 IP 대역을 입력하는 칸의 기본값이 비어 있으므로, 기본값을 `*` 로 주고 경고 메시지만 띄운다.

요구사항: SEC-MCP-001 AC-11(신규), AC-8 · AC-9(기존 동작 유지). 원격 링크 예시는 FR-MCP-020 · FR-MCP-027 범위다.

## 원인

- MCP 리스너의 전송 보안 기본값은 서버(`server/src/index.ts`)·설정 저장소(`McpControlConfigStore.ts`)·대화상자 모두 이미 `none`(HTTP)이었다. https 는 원격 링크 URL 입력칸의 예시 문구(placeholder)와 ko/en 도움말에만 남아 있었다.
- 바인드 모드를 "외부 접근 허용(IP 목록)" 으로 바꾸면 허용 목록이 빈 채로 남았다. 그래서 주소를 직접 입력하기 전에는 저장할 수 없었다(`mcp.validation.whitelistRequired`).

## 해결

- `PeerLinksPanel.tsx` 의 placeholder 와 `mcp.peers.link.urlHelp`(ko/en)의 예시를 `http://10.0.1.13:3333/mcp` 로 바꿨다.
- `withMcpBindMode` 는 외부 모드로 전환할 때 목록이 비어 있거나 공백만 있으면 `*` 를 채운다.
  - MCP 가 켜져 있으면 기존 AC-8 경고("모든 IP 의 접근을 허용합니다")가 뜨고, 저장할 때 한 번 확인을 받는다.
  - 사용자가 입력한 목록은 그대로 둔다. 루프백 모드로 돌아가도 목록을 바꾸지 않는다.
  - 저장된 설정을 불러올 때(`createMcpSecurityDraft`)는 `*` 를 채우지 않는다.
- 서버는 이미 `*` 를 허용 목록에서 받는다(SEC-MCP-001 AC-7). 서버 변경은 없다.

## 검증

- 테스트를 먼저 작성하고, 구현 전에 의도한 이유로 실패하는 것을 확인했다(`actual: ''`, placeholder 불일치).
- 구현 후 `frontend/tests/unit/mcpControlDialog.test.ts` 40/40, `i18nGuards.test.ts`, `peerLinksModel.test.ts` 가 통과했고, `npx tsc -b` 도 통과했다.
- 독립 서브에이전트 리뷰에서 막을 문제는 없었다. 낮음 등급 지적(AC 문구의 "MCP 가 켜져 있을 때" 조건, 테스트가 인용할 요구사항, 도움말 문자열 확인)은 반영했다.

## 남은 점

외부 모드에서 루프백으로 돌아간 뒤 저장하면 목록에 `*` 가 남는다. 루프백 모드에서는 서버가 이 목록을 쓰지 않는다. 다만 나중에 다시 외부 모드로 바꾸면 목록이 비어 있지 않으므로 자동 채움 없이 `*` 가 그대로 쓰인다. 이때도 경고와 저장 확인은 나온다.
