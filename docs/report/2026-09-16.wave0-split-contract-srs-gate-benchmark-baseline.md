## 3. 0A/0B 결정 — **0B(유예·대체)**. 0A 는 기각

전체 근거는 결정 기록 §2 에 있다. 결정적인 셋만 요약한다.

- **E-1.** `server/src/ws/terminalWireFormat.ts` 의 `isTransportEligible` 이 `transportMode === 'unified'` 하나만 허용한다. binary 는 채택이 끝난 결정인데, split 을 production 에 복원하면 그 채택된 데이터 평면이 꺼진다. 0A 는 여기서 단독으로 기각된다.
- **E-2.** production 은 split 을 가져본 적이 없다. `server/src/index.ts` 의 `new WsRouter(...)` 가 `config.realtime.wsTransportMode` 를 넘기지 않고, `server/src/test-runner.ts` 의 `assert.doesNotMatch(construction, /wsTransportMode/u)` 가 **그 누락을 의도적으로 고정**한다. 0A 는 이 green 단언 삭제에서 시작해야 한다.
- **E-3.** 브라우저는 split 에 도달할 수 없다. `buildControlWebSocketUrl` 은 `mode=split` 을 emit 하고 upgrade 경로는 `wsTransportMode` 를 읽는다. 정본 파서 `parseWsTransportRequest` 는 production 경로에서 호출되지 않는다.

**기각한 대안**: 0A(복원), 0B-삭제(코드 제거 — #21/#22 범위이고 `REL-BGSTAB-008 AC-10`·`MIG-BGSTAB-002` 테스트를 고아로 만든다), 부분 혼합(이슈가 금지, E-1 때문에 관측 불가능한 중간 상태가 된다), FR-BGSTAB-006/007 본문 직접 수정(2026-07-02 사용자 승인 이력을 소급 변조).

**Rollback**: SRS 계약과 characterization 테스트로만 구성되어 runtime 변경이 없다. superseding Requirement 를 `discarded` 로 전이하고 테스트를 되돌리면 끝이며, 배포 rollback·soak 가 필요 없다. 전환 감시 지표는 위 `test-runner.ts` 단언 자체다 — 깨지면 split 이 production 배선에 들어온 것이다.

**사용자 승인 필요 항목** (결정 기록 §5): A-1 `FR-BGSTAB-006/007` Status 강등 · A-2 split 코드 삭제 · A-3 `realtime.wsTransportMode` operator 노출 변경 · A-4 결함 D-1 의 동작 수정 · A-5 `FR-BGSTAB-015` retirement.

## 5. 설정 inventory

- **경로**: `server/src/schemas/settingsInventory.json`, **pin**: `server/src/schemas/settingsInventory.test.ts`
- leaf 수는 Zod 스키마에서 **런타임에 도출**한다(`listConfigSchemaLeafPaths`). 손으로 적은 두 번째 목록과 대조하는 방식이 아니므로 스키마가 바뀌면 반드시 깨진다.
- 분류 결과: **user-visible 33 / reserved 31 / safety-only 16 / inert 1**, 합계 **81**.
- 유일한 inert 는 `pty.maxBufferSize` — `ptySchema` transform 이 `maxSnapshotBytes` 로 접는 입력 전용 legacy alias 이고, shipped surface 에 남은 언급은 `binaryFrameCodec.ts` 의 주석 한 줄뿐이다.
- 한 leaf 가 여러 설명을 만족할 수 있으므로 **precedence 를 fixture 안에 명시**했다: `inert` → `reserved` → `safety-only` → `user-visible`. `reserved` 가 `safety-only` 보다 앞서는 이유는 `RESERVED_WAVE6_SETTING_KEYS` 가 이미 부여한 분류를 유지하기 위해서다. 겹침은 숨기지 않고 `editableInSettings` 필드로 드러낸다.
- **재사용한 것**(재구축하지 않음): `retiredSettingsResidue.test.ts` 의 retired key·shipped surface, `TerminalResourcePolicyInventory.ts` 의 consumer manifest, `RuntimeConfigStore` 의 `FIELD_SCOPES`/`RESERVED_WAVE6_SETTING_KEYS`. 뒤 둘은 export 해서 **전사본이 아니라 살아있는 표와 대조**한다.

## 6. Benchmark — 재사용한 것과 새로 만든 것

**재사용**: Wave-1 의 봉인된 1,224 raw sample / 408 summary group 을 그대로 둔다. 세션×클라이언트 12/12 셀, p50/p95/p99, seeded bootstrap CI, seed·payload·warm-up·trial·build·hardware·OS·browser·config digest 가 이미 있고 `PERF-BGSTAB-008` AC-1..AC-7 을 충족한다.

**재생성하지 않은 이유**: 그 두 파일의 digest 는 `PERF-BGSTAB-008` VE-2/VE-3 과 `MIG-BGSTAB-001` 의 `g1-evidence-audit.json` 에 봉인되어 있다. 제자리에서 다시 만들면 G1 evidence audit 이 소급 무효가 된다. 새 데이터는 **새 디렉터리**로 나간다.

**새로 만든 것** — 이슈 AC 가 요구했으나 `PERF-BGSTAB-008` 이 계약한 적 없는 셋:

| 잔여 항목 | 이전 상태 | 지금 |
| --- | --- | --- |
| outlier 처리 | manifest 에 **아예 없음** | `outlierPolicy { rule, rationale, parameters, excludedSampleIds }` 필수. 현재 규칙은 `retain-all` 이며 **명시적 결정으로 기록**한다 — summary group 당 관측이 3개뿐이라 하나라도 버리면 bootstrap CI 를 낼 수 없다 |
| interleaved 순서 | `executionOrder: ["manifest","raw-samples"]` — artifact **방출** 순서일 뿐 | `execution { derivedFrom:'execution', interleaved, strategy, order[] }`. trial-major → workload → mode, mode 순서는 trial 마다 회전. 러너가 **실제 실행 순서를 기록하고 계획과 대조**해 다르면 실패한다 |
| visible/hidden | `viewMix` 가 세션 수에서 **파생**되어 24셀 중 12셀만 존재 | `single-active` / `all-active` 두 수준을 독립 변주. corpus 12 → 21. 세션이 1이면 두 수준이 같은 점이므로 그 3셀은 `visibilityFactor.structurallyUnreachable` 에 **사유와 함께 기록** |
