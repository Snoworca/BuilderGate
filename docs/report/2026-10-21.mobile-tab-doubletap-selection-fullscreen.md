## #155 — 탭을 바꾸면 터미널 화면이 비어 있음

**원인**
- 탭이 보이게 될 때 fit 을 다음 프레임에 한 번만 시도했다.
- 그 프레임에 컨테이너가 0×0 이면 기록만 남기고 다시 시도하지 않았다.
- coordinator 가 fit 을 거부하거나 미뤄도 다시 그리기를 하지 않았다.
- 크기가 같으면 이후의 convergence 루프도 다시 그리지 않았다.

**해결**
- 0, 120, 400, 1000ms 에 다시 확인한다(`terminalRevealSettle.ts`).
- 그릴 수 있는 크기면 아직 끝나지 않은 fit 을 다시 시도하고, fit 결과와 상관없이 전체 다시 그리기를 한다.

**한계**
- 에뮬레이션에서는 빈 화면 자체를 재현하지 못했다. 실기기 확인이 필요하다.

**커밋**: `524678d3`

## #156 — 탭 전환이 늦음

**원인**
- `setActiveTab` 이 서버 PATCH 응답을 받은 뒤에야 화면을 바꿨다.

**해결**
- 화면을 먼저 바꾼다.
- 저장은 `latestValueSaver` 로 한 번에 하나씩 보내고, 그사이 들어온 값은 마지막 것만 보낸다.

**후속 수정**
- 재연결 때의 재조회와 `workspace:updated` 가 저장 전의 선택을 예전 값으로 되돌렸다.
- 저장이 끝날 때까지 선택을 서버 데이터 위에 유지하도록 고쳤다.

**결과**
- PATCH 를 3초 지연시켜도 탭이 61~117ms 안에 바뀐다.

**커밋**: `671a9310`, `ee3f1be7`

## #157 — 두 번 탭으로 컨텍스트 메뉴 열기

**공통 감지**
- 300ms·24px 안의 두 번 탭을 감지한다(`doubleTap.ts`).
- 두 번째 touchend 는 막아서 click·dblclick 이 생기지 않게 한다.

**타이머로 길게 누르기를 처리하는 곳** (`useLongPress` 확장)
- 터미널, 그리드 칸, 탐색기 행·탭, 편집기 탭·제목 표시줄·본문.

**브라우저 contextmenu 에만 기대던 곳** (`useDoubleTap`)
- 상태 막대 경로, 워크스페이스 탭, 사이드바 워크스페이스.

**겹치는 동작 정리**
- 터미널: 메뉴를 열 때 키보드를 내린다.
- 탐색기: 폴더에 "열기" 항목을 추가했다. 1.5초 길게 누르기로 여는 동작은 두 번 탭에 반응하지 않는다.
- 상태 막대 경로: 터치로 탭하면 "복사됨" 표시를 300ms 늦춘다. 표시 때문에 글자 폭이 바뀌어 두 번째 탭이 빗나갔기 때문이다.

**커밋**: `208bb612`

## #158 — 한 줄 선택이 보이지 않음

**원인**
- 코드 모드는 현재 줄(`.cm-activeLine`)을 불투명하게 칠했다.
- CodeMirror `drawSelection()` 은 선택 영역을 줄 뒤쪽 레이어에 그리므로, 현재 줄 배경에 가려졌다.

**해결**
- 현재 줄 배경을 반투명(55%)으로 바꿨다. 줄 번호 칸은 불투명하게 둔다.
- 코드 모드의 선택 색을 강조색 30% 로 진하게 했다.

**검증**
- E2E 는 수정 전 빌드에서 실패하고, 수정 후 통과한다.

**커밋**: `1b483057`

## #159 — 휴대폰에서 탐색기·편집기 전체 화면

**해결**
- 휴대폰에서는 두 창이 `.app` 의 크기를 잰다(`windowFillSelector`).
- 편집기는 `.app` 의 크기 변화를 ResizeObserver 로 따라간다.

**결과**
- 두 창 모두 0,0,412×839 로 앱 전체를 덮는다.

**커밋**: `d2342f1e`
