## 1. 이슈 설명

다음 네 가지 수단이 없었다. 파일을 세션 폴더로 올리는 방법, 여러 항목이나 폴더를 기기로 받는 방법, 압축 파일을 푸는 방법, 로컬 HTML 페이지를 렌더링해서 보는 방법이다. 모바일 하단 바는 글자 버튼 7개가 360px 폭에 들어가지 않아 업로드를 넣을 자리가 없었다.

## 2. 문제 원인과 위험

- 기존 `/files/write` 는 JSON 문자열 본문을 받고 텍스트 크기 한도를 적용한다. 그래서 바이너리 파일을 올릴 수 없었다.
- 단일 파일 다운로드(FR-FEX-021)는 여러 항목과 폴더를 비활성으로 두었다.
- 로그인 토큰(JWT)이 `localStorage` 에 있다. HTML 을 앱과 같은 출처에 띄우면 페이지 스크립트가 그 토큰을 읽을 수 있다.
- 아카이브는 신뢰할 수 없는 입력이다. 엔트리 이름, 링크, 선언 크기를 아카이브를 만든 사람이 정한다.

## 3. 해결 방법

### #139 업로드·ZIP 다운로드 (FR-FEX-022~026, FR-FOP-006)
- 업로드:
  - JWT 로 보호되는 바이너리 스트리밍 PUT 이다. 받은 바이트는 숨김 임시 파일에 쓰고, 다 받으면 배타적으로 배치한다(link 또는 COPYFILE_EXCL). 그래서 동시에 같은 이름을 올려도 조용히 덮어쓰지 않는다.
  - 업로드가 60초 동안 멈추면 끊는다. 다른 요청은 300초 본문 기한을 유지한다.
- 진입점: 경로 막대 버튼, 우클릭 메뉴의 고정 위치(적용되지 않으면 비활성), OS 드롭과 대상 칩. 단축키는 두지 않았다.
- 업로드 진행은 기존 파일 작업 팝오버를 그대로 쓴다. 실패는 파일 단위로 보이고 재시도할 수 있다. 연결이 끊긴 파일은 서버에 이미 도착했는지 확인한 뒤에만 자동 재시도한다. 업로드 중에 페이지를 떠나려 하면 경고한다.
- ZIP 다운로드:
  - 먼저 개수와 크기를 계산한다. 1 GiB 또는 1만 개를 넘거나 계산이 1초를 넘으면 확인 바를 띄운다.
  - 토큰은 실제로 받기 시작할 때만 발급한다. 스트림은 deflate level 1 로 만든다.
  - 엔트리마다 차단 규칙을 적용하고, `.git` 과 `node_modules` 는 뺀다.
- 모바일 하단 바: [업로드][다운로드][붙여넣기][더보기] 네 칸으로 고정했다. 선택 띠와 더보기 시트를 더했다. 목록은 사용자 결정에 따라 데스크톱 목록과 같다.
- 충돌 모달 문구: 건너뛰기, 둘 다 유지, "남은 n개에도 같은 선택 적용"으로 통일했다.

### #140 압축 풀기 (FR-FEX-027, FR-FOP-007)
- 기존 파일 작업 모델에 `extract` 를 추가했다. 메뉴 항목은 "압축 풀기"(smart)와 "여기에 풀기"(here) 둘이다.
  - smart: 최상위가 폴더 하나뿐이면 그 폴더를 그대로 푼다. 아니면 아카이브 이름의 폴더를 만들어 그 안에 푼다. 그 이름이 이미 있으면 `이름 (2)` 를 쓴다.
- 쓰지 않고 건너뛰는 엔트리: zip/tar slip, 절대 경로, 예약 이름, 링크·장치 엔트리, 차단 경로·확장자.
- 거부하는 아카이브:
  - 풀린 크기 10 GiB 초과, 엔트리 10만 개 초과
  - 풀린 크기가 64 MiB 를 넘으면서 압축률이 1000 을 넘는 경우
  - 쓰는 도중 사전 계산값을 넘는 경우
  - 암호 ZIP, 분할 ZIP
- 이름 처리: UTF-8 표시가 없는 ZIP 이름은 CP949 로 해석한다. tar 의 pax·GNU 긴 이름은 그대로 유지한다.
- 건너뛴 목록은 앞의 1000건만 담고, 이름이 4096바이트를 넘는 엔트리는 거부한다.

### #141 HTML 뷰어 (FR-MDE-028, SEC-MDE-002, FR-MCP-013)
- 편집기 창 탭에 렌더링/소스 토글을 두었다. 렌더링 iframe 은 `sandbox="allow-scripts allow-forms allow-modals allow-popups"` 이고 `allow-same-origin` 은 없다.
- 토큰 라우트 `/api/html-view/<token>/<path>`:
  - 모든 응답에 `CSP: sandbox …` 를 붙인다.
  - 세션 폴더 규칙을 따르고, 숨김 경로는 차단한다. 단, 연 HTML 파일 자신의 폴더 경로에 있는 숨김 segment 는 허용한다.
  - 토큰은 마지막 사용 후 30분에 만료된다.
- 저장하지 않은 미리보기:
  - 서버 초안으로 서빙한다(`?draft=n`, 토큰당 10 MiB, 전체 64 MiB 상한).
  - srcdoc 은 앱의 CSP 를 물려받아 인라인 JS 를 막기 때문에 쓰지 않는다.
- MCP 도구 `buildergate.editor.open_html` 을 추가했다.

## 5. 남은 것과 한계

- HTML 뷰어:
  - 페이지 스크립트는 세션 폴더의 숨김이 아닌 파일을 읽을 수 있고, 외부로 보낼 수 있다. 외부 CDN 로드와 JS 실행이 요구사항이라 연결 차단은 넣지 않았다.
  - `/` 로 시작하는 절대 경로는 페이지의 문제로 보고 지원하지 않는다.
- copy·move 충돌 모달: 서버가 남은 충돌 개수를 주지 않으므로 체크박스에 숫자를 붙이지 않는다.
- 실제 기기에서만 확인할 수 있는 동작은 단위 테스트에서 소스 계약으로만 확인했다. wake lock, 시트를 아래로 끌어 닫기, 트리 스프링 로딩이 여기에 해당한다.
- 서버 회귀 묶음의 `terminalPathGateKeys.test.ts` 1건은 git 이 추적하지 않는 로컬 `server/config.json5` 의 `wsSendMode` 값 때문에 실패한다. 이번 변경과는 무관하다.
