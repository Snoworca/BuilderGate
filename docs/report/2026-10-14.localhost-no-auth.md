# 이 컴퓨터에서는 로그인 화면을 건너뛰는 설정 (FR-BGSTAB-034)

## 요청

설정에 "localhost 에서 인증하지 않기"를 추가한다. 켜면 로컬호스트에서는 로그인 화면이 나오지 않는다. 위험은 사용자가 책임지며, 기본값은 false 다.

## 분석

- 로그인 토큰을 받는 경로는 비밀번호 로그인(`POST /api/auth/login`) 하나뿐이었다.
- 연결 주소가 loopback 인지만 보고 "로컬"이라고 판정하면, 다음 세 경우가 그대로 통과한다.
  - **같은 PC 의 리버스 프록시**: 원격 방문자의 요청도 127.0.0.1 에서 온 것으로 보인다.
  - **DNS 재바인딩**: 악성 도메인을 127.0.0.1 로 연결하면 브라우저는 그 요청을 같은 출처로 취급한다.
  - **사이트 간 요청**: 다른 사이트가 사용자 브라우저를 시켜 `localhost` 로 요청을 보낸다.

## 해결

- **설정**: `auth.localhostNoAuth` 를 추가했다(기본값 `false`). 설정 화면의 인증 카드에 경고 문구와 함께 체크박스를 두었다. 저장하면 재시작 없이 바로 적용된다.
- **서버**: `POST /api/auth/local-login` 을 추가했다. 아래 네 조건을 모두 만족할 때만 비밀번호 로그인과 같은 토큰을 준다.
  1. 소켓 주소가 127.0.0.1, ::1 또는 ::ffff:127.0.0.1 이다.
  2. `Host` 가 localhost, 127.0.0.1 또는 [::1] 이다.
  3. `Origin` 이 없거나, 위 셋 중 하나다.
  4. `X-Forwarded-For`, `Forwarded`, `X-Real-IP` 헤더가 없다.
- **응답 코드**: 설정이 꺼져 있으면 403 `LOCAL_LOGIN_DISABLED` 를 낸다. 설정은 켜져 있지만 조건을 만족하지 못하면 403 `LOCAL_LOGIN_REFUSED` 를 내고, 거절한 이유를 서버 로그에 남긴다.
- **브라우저**: 저장된 토큰이 없거나 401 을 받으면, 먼저 `local-login` 을 시도한다. 거절되면 예전처럼 로그인 화면을 보여 준다.

## 한계

- 프록시 헤더를 붙이지 않는 리버스 프록시는 막을 수 없다. 이 위험은 설정 화면 경고에 적어 두었다.
- 설정이 켜져 있으면, 로그아웃한 뒤 새로고침할 때 바로 다시 로그인된다.

- `ConfigFileRepository.ts` 의 리소스 한도 접근은 위치만 옮겨졌다. 그래서 분류 핀의 해시만 갱신했다. 리소스 한도 접근이 새로 늘지는 않았다.
- 소비자 매니페스트를 재봉인했다. 소비자 튜플은 변하지 않았고, 분류 핀 1건만 바뀌었다.
- 편집 가능 설정 스냅샷에 키가 하나 늘었다. 그래서 OBS-BGSTAB-005 차등 증거의 해시 2개와 raw GREEN 해시를 갱신했다.
