# 터치 화면에서 터미널 글자를 복사하는 기능 추가

## 개요

이 보고서는 아이폰·아이패드·안드로이드에서 터미널 글자를 복사할 수 있게 한 작업을 기록한다.

- 요구사항: FR-ARCH-017(신설), `docs/spec/10.product-architecture.srs.md`
- 이슈: #219
- 브랜치: `feat/terminal-text-copy`(`feat/home-screen-app` 위)
- 작업일: 2026-11-02

## 증상

- 터미널을 길게 누르거나 두 번 탭하면 터미널 메뉴가 열린다. 메뉴의 **복사** 항목은 선택된 글자가 있을 때만 켜진다.
- 터치 화면에는 터미널 글자를 선택할 방법이 없어서, 복사 항목이 늘 꺼져 있었다.
- 붙여넣기는 되고 복사만 안 되므로 고장으로 오해하기 쉬웠다.

## 원인

- 터미널은 글자를 WebGL 캔버스에 직접 그린다. 그래서 iOS와 안드로이드의 기본 선택 손잡이가 나타나지 않는다.
- PC에서는 마우스 드래그로 선택하지만, 터치 화면에서 한 손가락 드래그는 스크롤에 쓰인다(FR-ARCH-010).

## 해결 방법

- 터치 화면(`pointer: coarse`)에서는 터미널 메뉴의 **붙여넣기** 바로 아래에 **텍스트 선택** 항목을 보인다. 마우스 화면에서는 보이지 않으므로 PC 메뉴는 그대로다.
- 이 항목을 고르면 **터미널 텍스트** 창을 연다.
  - 창을 여는 순간의 터미널 버퍼를 일반 글자로 보여 준다. 일반 버퍼는 스크롤백과 화면을, 전체 화면 프로그램이 쓰는 대체 버퍼는 화면만 담는다.
  - xterm이 화면 폭 때문에 나눈 줄은 다시 한 줄로 합친다. 줄 끝의 빈 줄은 빼고, 최근 2000줄까지만 담는다.
  - 창은 마지막 줄로 스크롤된 상태로 열린다. 입력칸이 없으므로 키보드가 올라오지 않는다.
  - 본문은 OS 기본 선택 손잡이와 복사 메뉴를 쓸 수 있다(`user-select: text`, `-webkit-touch-callout: default`).
  - **모두 복사** 버튼은 전체를 클립보드에 쓴다. 실패하면 그 사실을 창에 보인다.
- 창은 읽기 전용 사본이다. 터미널의 입력, 출력, 크기 권한, 선택은 바뀌지 않는다.
- 탭 보기(`App.tsx`)와 그리드 보기(`MosaicContainer.tsx`) 메뉴 모두에 넣었다.

- `terminalTextCopy.test.ts`: 구현 전에는 모듈이 없어 실패했고, 구현 후 10/10.
- i18n 가드와 인접 메뉴 테스트 39/39, terminal-view-behavior 93/93, 앱 타입 검사 오류 0.
- 아이폰 실기기: 사용자가 2222에서 길게 누르기 메뉴의 **텍스트 선택**으로 창을 열어, 글자를 선택해 복사하는 것과 **모두 복사**가 잘 되는 것을 확인했다.
