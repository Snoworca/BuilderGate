# 휴대폰에서 Claude Code 선택지를 탭할 때마다 키보드가 올라옴 (FR-ARCH-010 AC-8)

## 이슈

- 2026-11-15 사용자 보고: 휴대폰에서 Claude Code 가 선택지를 보여 줄 때 선택지를 탭하면 매번 시스템 키보드가 올라와 화면이 작아진다.
- 다음 질문을 보려면 키보드를 내려야 하고, 다시 탭하면 키보드가 또 올라온다. 키보드가 올라온 상태에서 한 번 더 탭해야 선택된다.
- 사용자는 의도하지 않은 선택을 막으려고 일부러 그렇게 만든 것인지도 물었다. 일부러 막은 것이 아니다.

## 원인

- Claude Code 는 전체 화면 모드(alt screen)에 있는 동안 마우스 추적을 계속 켜 둔다. 설치본 `claude.exe` 에서 `altScreenMouseTracking` 이 alt screen 에 들어갈 때 켜지고 나올 때 꺼지는 것을 확인했다. 메뉴가 떠 있을 때만 켜는 것이 아니다.
- 휴대폰의 탭은 호환용 `mousedown` · `click` 을 만든다. xterm 은 그 `mousedown` 에서 클릭을 앱에 보내기 전에 입력 칸에 포커스를 준다(`@xterm/xterm` 6.0.0 `CoreBrowserTerminal.ts` 의 `this.focus()`). 이어서 `TerminalRuntimeLayer` 의 `onClickCapture` 도 포커스를 준다(FR-ARCH-010 AC-3).
- 그래서 선택지를 누르는 탭과 키보드를 여는 탭이 한 동작에 묶여 있었다.
- 두 번째 탭에서야 선택되는 현상은 코드로 원인을 확정하지 못했다. 키보드가 올라오면서 화면 크기가 바뀌는 것과 관련이 있을 것으로 추정하며, 실기기에서 확인해야 한다.

## 해결

사용자가 고른 방식은 「입력 줄 근처를 탭하면 키보드, 그 밖은 클릭만」이다(다른 후보는 키보드 버튼, 두 번 탭이었다).

- **판정** (`utils/terminalTouchTapPolicy.ts`): `shouldTapOpenKeyboard({ mouseTracking, keyboardUp, rows })` 는 다음 조건을 모두 만족할 때만 false(클릭만)를 돌려준다.
  - 터미널 안 프로그램이 마우스를 추적한다.
  - 시스템 키보드가 내려가 있다(`isSystemKeyboardUp`, 키 줄과 같은 판정).
  - 탭한 행이 커서 행에서 `INPUT_LINE_TAP_ROWS`(1) 행보다 멀다. Claude Code 는 입력 칸을 테두리 상자 안에 그리므로 위아래 테두리 행도 입력 줄로 친다.
- **행 계산**: `readTerminalTapRows(term, clientX, clientY)` 가 탭한 행과 커서 행을 보이는 화면 기준으로 계산한다.
- **배선** (`TerminalRuntimeLayer.tsx`): 탭의 `mousedown` 에서 위 판정이 클릭만이면 `setTapFocusSuppressed(true)` 를 걸고, `mousedown` 은 그대로 xterm 에 보내 앱이 클릭을 받게 한다. 이어지는 `click` 에서 억제를 풀고 전파를 멈춰 포커스를 주지 않는다. `click` 이 오지 않으면 다음 터치가 억제를 푼다.
- **억제** (`TerminalView.tsx`): `setTapFocusSuppressed(true)` 동안에는 다음 네 가지가 적용된다. 이 장치는 특수 키보드 패널의 포커스 억제(FR-MKB-008)와 같은 방식이며, 플래그는 따로 둔다.
  - 모든 포커스 진입(`focusTerminalInput`, 포커스 복원)을 막는다.
  - xterm 이 스스로 준 포커스는 `focusin` 에서 바로 푼다.
  - helper textarea 에 `inputmode="none"` 을 건다. blur 가 늦더라도 키보드가 올라오지 않게 하려는 것이다.
  - 억제는 1초 뒤에 저절로 풀린다.
- **그대로인 경우**: 키보드가 이미 올라와 있을 때, cmd 같은 일반 셸(마우스 추적 없음)에서, 탭 위치를 셀로 바꿀 수 없을 때는 지금처럼 탭하면 포커스를 준다.

## 요구사항

- FR-ARCH-010 AC-8 을 추가했다. 실기기 확인 전이라 체크하지 않았다. 검증 증거 VE-5 · VE-6 과 변경 노트를 남겼다.

## 검증

- `tests/unit/terminalTouchTapPolicy.test.ts` 11/11: 판정 함수와 행 계산을 검사한다. 먼저 export 가 없어 실패하는 것을 확인했다.
- `tests/unit/terminalRuntimeLayerTouchFocus.test.ts` 11/11: 실제 `TerminalRuntimeLayer` 를 렌더한다. 키보드 상태는 가짜 `visualViewport` 로 정한다. 검사한 내용은 다음과 같다.
  - 먼 탭의 `mousedown` 이 xterm 에 그대로 닿고, 억제가 `[true, false]` 순서로 걸렸다 풀리며, 포커스가 없다.
  - 입력 줄 근처 탭, 키보드가 올라온 상태, 일반 셸에서는 지금처럼 포커스를 준다.
  - `click` 이 없으면 다음 터치가 억제를 푼다.
  - 레이어를 고치기 전에는 클릭만 동작을 검사하는 두 건이 실패했다.
- `tests/unit/terminalMobileFocusSuppression.test.ts` 6/6: 실제 `TerminalView` 에서 억제 중 `inputmode="none"` 이 걸리고 자기 포커스가 풀리는지, 해제 뒤 포커스가 다시 되는지, 1초 뒤 저절로 풀리는지 검사한다.
- `tests/unit/terminalClipboardAdapterContract.test.ts`: 핸들 멤버 고정 목록에 `getTapRows`(숫자 두 개) · `setTapFocusSuppressed`(boolean)를 붙여넣기 경로가 아니라는 사유와 함께 등록했다. 4/4.
- `test:unit:terminal-view-behavior` 101/101, `test:unit:mobile-keyboard` 103/103.
- 프런트 단위 전수 2919건 중 실패 17건은 모두 전용 러너 대상 파일이다. 핸들 계약 테스트는 등록 뒤 통과했다.
- `tsc -p` 로 app · editor · node · test · e2e-ownership 을 각각 돌려 모두 오류 0이다. `speckiwi validate` 오류 0, `check:kiwi-status` · `check:srs-change-notes` 통과.

## 남은 일

- 실제 휴대폰 확인: iOS · Android 에서 `inputmode="none"` 과 즉시 blur 로 키보드가 정말 올라오지 않는지, 첫 탭에 선택이 되는지 확인해야 한다.
- Android 에서 뒤로 가기로 키보드만 내리면 입력 칸에 포커스가 남는다. 이 상태에서는 xterm 의 포커스가 `focusin` 을 다시 일으키지 않으므로, `inputmode` 를 거는 방식만 작동한다. 이 경우도 실기기에서 확인해야 한다.
- 키보드가 올라와 있는 동안 선택지를 탭하면 지금처럼 키보드가 그대로 남는다(AC-8 범위 밖).
