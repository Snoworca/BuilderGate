# 터미널 와이어 포맷 설정 배선 수정

## 이슈 설명

D-S5(회계 재벤치 후 기본값을 `binary-optin` 으로 승격)를 착수하려는 과정에서 설정 배선 결함이 발견되었습니다. 프로덕션 환경에서 `config.json5` 의 `realtime.terminalWireFormat` 설정이 WebSocket 라우터에 도달하지 않아 어떤 설정 값을 입력하든 기본값 `json` 으로 수렴하고 있었습니다.

## 문제 원인

`server/src/index.ts` 의 1531줄에서 프로덕션 `new WsRouter(...)` 호출이 `realtime` 옵션을 생성자에 넘기지 않았습니다. 그 결과 `WsRouter.ts:640` 의 폴백 로직에서 리터럴 `'json'` 이 항상 선택되었으며, 설정 파일의 값은 효과를 발휘할 수 없었습니다.

이는 `IR-BGSTAB-001` AC-7 을 위반합니다. 해당 AC 는 `terminalWireFormat` 을 "서버가 협상에 응할 수 있는지만 정하는 킬 스위치" 로 정의하는데, 현재 상태에서 서버는 협상의 여지를 허용하지 않고 있었습니다.

수신 측(라우터가 옵션을 처리하는 로직)은 이미 완성되어 있었습니다. `WsRouter.ts:143` 에서 `realtime?: Partial<RealtimeConfig>` 를 받으며 `:640` 에서 이를 참조합니다. 부재한 것은 송신 측 생성자 옵션의 한 줄뿐이었습니다.

## 해결 방법

`server/src/index.ts` 의 생성자 옵션에 다음 한 줄을 추가했습니다.

```javascript
realtime: { terminalWireFormat: config.realtime?.terminalWireFormat },
```

이 접근법은 의도적으로 `wsTransportMode` 를 제외합니다. 만약 `config.realtime` 객체 전체를 넘겼다면 zod 가 채운 `wsTransportMode` 도 함께 전달되어 `WsRouter.ts:639` 의 하드코딩된 `'unified'` 를 대체했을 것입니다. 그러면 `WsRouterSplitHandshake.test.ts` 가 특성화한 Wave-1 미구현 영역의 todo 14건이 노출되어 회귀 테스트가 실패했을 것입니다.

회귀 테스트도 추가했습니다. `server/src/test-runner.ts` 에 이름 "server startup passes the configured terminal wire format into WsRouter construction" 으로 등록된 테스트는 세 가지를 검증합니다.

1. 생성자 옵션에 `realtime: { terminalWireFormat: config.realtime?.terminalWireFormat` 이 포함되어 있을 것. 표현식의 출처까지 고정하여 검증합니다.
2. 그 슬라이스에 `wsTransportMode` 가 없을 것(음성 단언).
3. 슬라이스가 옵션 객체 전체를 담았을 것. 중첩 호출의 `});` 가 슬라이스를 잘라 음성 단언이 공허해지는 것을 방지합니다.

## 잔존 이슈

### HIGH — AC-7 다른 절의 추가 위반

AC-7 이 규정하는 "킬 스위치" 는 두 절로 이루어집니다. 첫 번째 절(`terminalWireFormat`)은 이제 고정되었으나, 두 번째 절(`wsTransportMode`)은 여전히 배선되지 않았습니다. 현재 `WsRouter` 에는 `wsTransportMode` 가 전달되지 않아 전송 모드 게이트를 서버 설정이 아니라 클라이언트가 보내는 쿼리 파라미터가 정합니다.

이는 설정이 `split` 이어도 클라이언트가 파라미터를 생략하면 바이너리가 켜질 수 있음을 의미합니다. 배선 결함 자체는 선재하지만, **이번 변경이 그 위반을 도달 가능하게 만들었습니다.** 이전에는 `terminalWireFormat` 이 어떤 설정으로도 `json` 을 벗어날 수 없어 위반을 만들 수 없었습니다. 기본 설정(두 키 모두 미설정)에서는 도달하지 않습니다.

### MEDIUM — 부트 설정 로더 회귀 테스트 부재

설정 파일에서 `config` 객체가 만들어지는 구간을 실행하는 테스트가 저장소에 0개입니다. 설정 로더가 `realtime` 을 흘리는 회귀는 조용히 zod 기본값 `json` 으로 수렴하며 어떤 테스트 스위트도 잡지 못합니다. 별도 작업으로 부트 프로브 테스트를 만들 계획입니다.

### MEDIUM — 설정 출처의 불일치

한 생성자 안에서 설정 출처가 둘로 갈렸습니다. `resourceLimits` 와 `stabilityModes` 는 런타임 스토어(`RuntimeConfigStore`)에서 오는데 `terminalWireFormat` 만 정적 `config` 를 직접 읽습니다. `RuntimeConfigStore` 에 그 키가 없어 현재로서는 대안이 없습니다.

### MEDIUM — 킬 스위치 핫리로드 불가

`WsRouter.ts:589` 에서 필드가 `readonly` 로 선언되어 있으며 생성자에서 한 번만 읽힙니다. 따라서 서버가 실행 중인 상태에서 설정을 변경해도 새 연결부터만 새 값을 반영합니다. 기존 연결의 협상 모드 결정은 불변입니다.

### LOW — AC-8 미구현

`/api/runtime-config` 엔드포인트에 `realtime.terminalWireFormat` 을 노출하는 AC-8 이 아직 구현되지 않았습니다.
