# 첫 실행 포트 선택과 기본 브라우저 열기

- 날짜: 2026-09-29
- 요구사항: FR-BGSTAB-032 (첫 실행 때 빈 포트를 고르고, 실행 파일이 기본 브라우저를 연다), 타깃 `exe-first-run-port-browser`
- 관련: OPS-BGSTAB-020 (MSI 설치와 LocalAppData 사용자 데이터)
- 커밋: 이 보고서가 들어간 커밋

## 이슈

MSI 설치판은 처음 실행할 때 부트스트랩 설정의 포트 2002 를 쓴다. 그래서 이미 2002 를 쓰는 BuilderGate 가 있는 PC 에서는 포트가 겹친다. 사용자는 포트를 `.port` 파일에 기록하는 방안을 제안했고, 논의 끝에 다음 세 가지로 정했다.

1. 첫 실행 때 빈 포트를 골라 저장한다.
2. 시작 메뉴 바로가기로 실행하면 실제 포트로 브라우저를 연다.
3. exe 로 처음 실행하면 기본 브라우저로 페이지를 연다. 사용자가 추가로 요청했다.

## 원인

- 포트는 이미 `config.json5` 의 `server.port` 에 저장된다. 설치판에서는 이 파일이 LocalAppData 에 있어 버전이 바뀌어도 남는다. 따라서 `.port` 파일을 더하면 포트를 적는 곳이 둘이 되므로 채택하지 않았다.
- 문제는 첫 실행의 고정 기본값(2002)이었다.
- 포트가 사용 중인지 미리 확인하는 코드가 없어서, 서버가 포트를 잡는 시점에야 실패했다.
- 콘솔 창이 금방 닫히므로, 바로가기로 실행하면 사용자가 주소를 볼 수 없었다.

## 해결

- **`tools/daemon/first-run.js`** (신규)
  - 첫 실행 판정: 데이터 루트에 데몬 상태 파일(`runtime/buildergate.daemon.json`)이 아직 없으면 첫 실행이다. zip 에는 `config.json5` 가 이미 들어 있으므로, 설정 파일이 있는지로는 판정할 수 없다.
  - `chooseStartPort`: 첫 실행이고 포트가 `-p` 로 주어지지 않았는데 그 포트를 다른 프로그램이 쓰면, 100 이내에서 그보다 큰 빈 포트를 고른다. 고른 포트는 `config.json5` 의 `server.port` 만 고쳐 저장한다.
  - `isPortFree`: IPv4·IPv6 두 스택을 모두 검사한다.
  - `shouldOpenBrowser`·`hasDefaultBrowser`·`openBrowser`:
    - 브라우저는 패키지 실행 파일, 데몬 모드에서만 연다. 조건은 첫 실행이거나 `--open` 을 준 경우다.
    - `BUILDERGATE_NO_BROWSER=1` 이면 열지 않는다.
    - Windows 에서는 기본 https 처리기가 등록된 경우에만 `rundll32 url.dll,FileProtocolHandler` 로 연다.
    - 브라우저를 열다가 실패해도 시작은 실패하지 않는다.
- **`launcher.startDaemon`**: 자기 데몬이 떠 있지 않은데 포트가 사용 중이면 상태 파일을 쓰기 전에 exit 2 로 끝낸다. 메시지에 포트 번호와 바꾸는 방법(`-p`, `server.port`)을 적는다. 자기 데몬이 이미 떠 있으면 전처럼 "already running" 으로 보고한다.
- **`start-runtime.js`**: 위 기능들을 연결했다. 페이지를 열 때 여는 주소를, 기본 브라우저가 없으면 직접 열 주소를 출력한다.
- **`cli.js`**: `--open` 옵션을 추가했다.
- **`build-msi.js`**: 시작 메뉴 바로가기가 `--open` 으로 실행한다.
- **`packaged-bootstrap-smoke.js`**: 스모크 실행은 첫 실행에 해당하므로 `BUILDERGATE_NO_BROWSER=1` 을 둔다.
- **README**: 영문·한국어 모두에 `--open` 옵션과 첫 실행 동작을 적었다.

## 검증

- **단위**: 새 케이스는 모두 구현 전 실패를 확인했다.
  - `first-run.test.js` 8/8
  - `launcher.test.js` 25/25 (새 1건)
  - `cli.test.js` 9/9 (새 1건)
  - `build-msi.test.js` 6/6 (새 1건)
- **실측**: MSI 관리 설치 이미지의 exe, `LOCALAPPDATA`=임시 폴더, 검증 포트 2222
  - 새 데이터 루트의 `server.port` 를 2221 로 두고 더미 리스너로 2221 을 점유했다.
    - "Port 2221 is in use … using 2222 and saving it" 이 출력됐고 `config.json5` 가 2222 로 바뀌었다.
    - `/health` 가 2222 에서 응답했다.
    - 기본 https 처리기(`MSEdgeHTM`)가 등록돼 있어 브라우저 열기가 실행됐다.
  - 이어서 더미로 2222 를 점유하고 두 번째로 실행했다.
    - exit 2 와 안내 메시지가 나왔다.
    - 데몬 상태 파일 해시와 config 는 바뀌지 않았다.
  - 더미 프로세스는 명령줄을 확인한 뒤 그 PID 하나만 종료했다. 2001/2002 는 같은 PID 로 유지됐다.
- **회귀**
  - `tools/daemon/*.test.js` 253/256. 실패 3건은 앞 작업(OPS-BGSTAB-020)에서와 같은 WSL 환경 실패이며, 바꾼 모듈과 무관하다.
  - `test:release-pipeline` exit 0. 소비자 매니페스트 검증도 exit 0 이며 봉인은 변동이 없다.

## 한계

- 포트 선택은 검사 시점과 서버가 포트를 잡는 시점 사이에 다른 프로그램이 포트를 가져가는 경쟁을 막지 못한다. 그런 경우에는 전처럼 시작이 실패한다.
- 자체 서명 인증서라서, 처음 열린 페이지에는 브라우저의 인증서 경고가 뜬다.
- 바로가기의 `--open` 을 실제 시작 메뉴에서 눌러 보지는 않았다. 설치에 관리자 권한이 필요해서다.
