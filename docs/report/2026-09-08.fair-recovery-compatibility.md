# Preserve JSON output after session-local fair fallback

- Requirement scope: PERF-BGSTAB-010 AC-1/7/8, with stale-ACK and semantic-status controls from AC-5/6/9. This is the reproduced JSON compatibility recovery defect, not fair ledger resumption, full REL-BGSTAB-012 retained-state recovery, binary ownership, P4/P9 completion or final A-5.
- Before the change, timeout or overflow released the affected lane. A last-lane fallback removed the connection scheduler and recovered through the existing JSON transport. With a healthy peer, the scheduler remained, so post-snapshot output continued entering the released lane and was silently lost. Hidden output could also attempt dataGap admission into that lane.
- The scheduler now exposes its existing fallback reason through a read-only O(1) lookup. After replay/repair/checkpoint-active holds, the router selects the existing compatibility transport for that fallback session, including hidden-output routing. Other lanes retain their scheduler, epoch, credit and output order. No lane is revived, no ordinal is reissued and no second fallback registry or codec transition is introduced.
