# 휴대폰 메신저 창에서 키보드가 올라오면 대화 목록이 스크롤되지 않는 문제 수정 (FR-MSG-013 AC-6, #248)

## 이슈

휴대폰에서 메신저 창의 입력란을 눌러 키보드가 올라오면, 대화 목록을 스크롤할 수 없는 문제를 고쳐 달라는 요청. 키보드를 내리면 다시 스크롤되었다.

## 문제 원인

- 휴대폰에서 메신저 창은 화면 전체를 덮는 크기(`useViewportRect`, `rect: viewport`)로 열린다. 이 크기는 `innerWidth x innerHeight` 에서 왔다.
- iOS는 키보드가 올라와도 `innerHeight` 를 줄이지 않는다. 대신 visual viewport의 `height` 와 `offsetTop` 만 바뀌고, 화면에 보이는 부분이 옮겨진다.
- 그래서 메신저 창의 아래쪽 절반이 키보드 밑까지 이어졌고, 대화 목록(`.msgr-log`)의 스크롤 영역도 키보드 밑으로 들어갔다. 이 상태에서 대화 목록을 끌면 목록 대신 페이지가 밀렸다가 원래 자리로 돌아갔다.
- 터미널 화면은 이미 보이는 영역에 맞춰 그려지지만(FR-MKB-007, `useVisualViewportLock`), 메신저 창에는 그 처리가 없었다.

## 해결 방법

- 새 순수 함수 `keyboardViewportRect` 가 키보드가 올라와 있을 때 창의 위치와 높이를 정한다. 창은 visual viewport의 위쪽(창 레이어보다 위로는 가지 않음)에서 시작해 키보드 바로 위에서 끝난다.
- 홈 화면 앱에서는 창 레이어가 상태 표시줄 아래에서 시작하므로(FR-ARCH-016 AC-7), 그 위치를 기준으로 좌표를 계산한다.
- 키보드가 내려갔거나 두 손가락으로 확대한 상태(`scale` 이 1이 아님)에서는 지금처럼 화면 전체를 채운다.
- `useViewportRect` 는 window `resize` 와 visualViewport `resize`, `scroll` 을 구독한다. 측정은 한 프레임에 한 번으로 묶고, 키보드 애니메이션 중간 값이 남지 않도록 마지막 이벤트 뒤 `KEYBOARD_SETTLE_MS` 가 지나면 한 번 더 잰다.

## 검증

- 새 테스트 `messengerKeyboardViewport.test.ts` 가 수정 전에 실패하는 것을 먼저 확인했다.
- 수정 뒤: 새 테스트와 `standaloneViewport` 테스트 13건, 메신저 관련 단위 테스트 9개 파일과 i18n 가드 126건이 모두 통과했다. `tsc -p tsconfig.app.json` 은 오류가 없다.
- 2002 프런트엔드에 올린 번들(`index-CeYqB-Bp.js`)로, 사용자가 아이폰에서 키보드를 올린 상태로 대화 목록이 스크롤되는 것을 확인했다.
