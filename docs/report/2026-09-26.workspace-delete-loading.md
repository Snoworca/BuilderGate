# Workspace 삭제 진행 표시

- 날짜: 2026-09-26
- 요구사항: FR-UIDS-006 (신규, `docs/spec/44.ui-design-system.srs.md`). PERF-BGSTAB-015 AC-2·AC-3을 승계하고 AC-1(서버 동시 종료)은 유지한다.
- 설계: `docs/research/2026-09-26.workspace-delete-loading.md` (디자이너 서브에이전트 연구)
- 커밋: `da9d15cf`

## 이슈

요청은 다음 흐름이었다: 삭제 버튼을 누르면 로딩 UI가 뜨고, 로딩이 사라지는 순간 Workspace 삭제가 화면에 반영된다. 직전 구현(`1c348e3d`)은 확인하자마자 목록에서 빼는 방식이라 이 흐름과 달랐다.

## 설계 결정

| 안 | 판정 |
|---|---|
| 확인창 안 진행 표시 | 채택: 누른 자리에서 바로 반응이 보이고, 맥락이 유지되며, 이중 제출이 자연히 막힌다 |
| 전용 로딩 창, 전체 화면 오버레이, 사이드바 행 busy | 기각: 창이 튀거나, 과하거나, 요청한 흐름과 다르다 |

## 해결

- 상태: `confirm` → `deleting` → (성공) 창 닫힘과 행 제거가 같은 커밋 / (실패) `error` → 다시 시도. 순수 함수는 `workspaceDeleteFlow.ts`에 있다.
- 시간
  - 클릭 즉시 진행 상태로 바뀐다.
  - 최소 표시는 500ms이다.
  - 10초가 지나면 느림 안내로 바뀐다.
  - 클라이언트 타임아웃과 취소는 없다. 서버가 터미널 종료를 되돌릴 수 없기 때문이다.
- 문구
  - 버튼: `모두 삭제` → `삭제하는 중…` → `다시 시도`
  - 진행: `터미널 N개를 종료하고 있습니다. 보통 몇 초 안에 끝납니다.`
  - 실패: `Workspace를 삭제하지 못했습니다. 일부 터미널은 이미 종료되었을 수 있습니다.`와 `원인:` 줄
  - 마지막 Workspace: `마지막 Workspace는 삭제할 수 없습니다.`
- `useWorkspaceManager.deleteWorkspace`
  - 서버 응답과 `holdUntil`을 기다린 뒤 한 동기 블록에서 제거하고 `onRemoved()`를 부른다.
  - 404는 성공으로 친다.
  - 그 밖의 실패는 던져서 창이 보여 주게 한다.
- `ConfirmModal`
  - `role="alertdialog"`, 레이블·설명 연결, 본문 `aria-live="polite"`를 단다.
  - 새 prop: `busy`, `busyLabel`, `error`, `hideConfirm`, `initialFocus`(취소에 초점, Tab 가두기).
  - 진행 중인 버튼은 초점을 잃지 않도록 `aria-disabled`를 쓴다.
  - `busy`를 넘기지 않는 기존 호출자는 이전과 같은 라벨을 그린다.
- 공용 부품: `BusyLabel`(폭 고정 라벨 교체), `Spinner tone="on-fill"`(빨간 버튼 위 흰 호), `.ui-inline-alert`.
- 터미널 없는 Workspace는 창 없이 지우고, 실패하면 창을 오류 상태로 연다. 이전에는 실패가 보이지 않았다.
- `workspaceRemoval.ts`(낙관적 복원)는 지웠다.

## 남은 것

- 편집기 E2E 1건 실패 (`FR-MDE-008 the tray lists every workspace…`)
  - 원인: 앞선 실행이 남긴 같은 이름의 `e2e-mde-save-tray-ws` Workspace 때문에 `.first()`가 다른 행을 고른다.
  - 이 스펙의 teardown이 `Workspace ownership tracking failed`로 끝나서, 실패할 때마다 Workspace가 하나씩 남는다. 이번 실행도 2개(`d4a9d0de…`, `df8cf872…`)를 남겼다.
  - 생성 응답을 실행 산출물에서 복구하지 못해서(trace.zip 손상) 지우지 않았다.
- 기다리는 동안 뒤쪽 터미널이 "Shell exited"로 바뀔 수 있다. 어두운 오버레이 뒤라 두었다.
- 서버가 끝내 답하지 않으면 창이 잠긴 채 남는다. 30초 뒤 닫기를 풀지는 열린 질문이다.
