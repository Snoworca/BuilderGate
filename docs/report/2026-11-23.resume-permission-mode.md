# 세션 복구가 Claude 세션의 권한 모드를 잃는 문제 수정 (FR-AITUI-025, #253)

## 이슈

세션을 복구할 때 그 세션이 쓰던 권한 모드(bypass 등)를 기억해 두었다가 같은 모드로 이어 달라는 요청. 2026-11-23 오전 재시작 뒤 자동 복구한 Claude 세션들이 bypass 모드가 풀린 채(manual · auto) 돌아왔다. 2026-11-18 에도 같은 일이 있었다(#243).

## 문제 원인

- 이어하기 명령은 탭에서 에이전트를 띄운 실행 명령(`runtime.launchCommand`)의 인자를 재사용한다(`SessionSnapshotService.agentEntry` → `buildResumeCommand`). 실행 명령을 모르면 플래그 없는 `claude --resume <id>` 가 된다. 서버가 그 실행을 보지 못한 경우나, 셸 기록(↑)·자동 완성으로 입력해 타이핑 추적이 명령을 놓친 경우가 여기에 해당한다.
- 한 번 플래그 없이 복구되면 그 명령이 다음 저장의 실행 명령이 되므로, 그 뒤 복구도 계속 플래그 없이 이어졌다. 그날 자동 저장본의 Claude 세션 18개 중 8개가 플래그 없이 저장되어 있었고, 그 세션들의 대화 기록은 직전까지 `bypassPermissions` 였다.
- 끝난 attach 세션을 `--resume <id>` 로 바꿔 열 때도 플래그가 붙지 않았다.

## 해결 방법

- 처음에는 복구 직전에 대화 기록(`~/.claude/projects/<folder>/<id>.jsonl`)의 마지막 `permissionMode` 를 읽으려 했다. 그러나 Claude 는 이 값을 사용자 메시지를 처리할 때만 쓴다. 그래서 새 플래그로 다시 띄운 직후에는 기록 끝에 이전 모드가 남아 있고, 그 방식이면 막 bypass 로 다시 띄운 세션이 다음 복구에서 오히려 default 로 내려간다(세션 7개로 확인). 그래서 판단 시점을 저장 시점으로 옮겼다.
- 자동 저장과 저장 목록에서 고른 저장은, 탭에서 Claude 가 실행 중인 항목의 권한 모드를 아래 순서로 정한다(`decideLivePermissionMode`).
  1. 에이전트가 시작된 뒤 보낸 메시지가 있으면 기록의 마지막 모드(턴 중 Shift+Tab 변경 포함)
  2. 실행 명령을 알면 그 명령의 플래그(명령을 바꾸지 않음)
  3. 실행 명령을 모르면 탭 안 Claude 프로세스 명령줄의 플래그(모르는 모드면 바꾸지 않음)
  4. 둘 다 모르면 기록의 마지막 모드
- 정한 모드에 맞춰 기존 권한 플래그를 지우고 새 플래그를 `--resume <id>` 앞에 넣는다(`applyClaudePermissionMode`). bypass 를 떠나는 경우에는 `--allow-dangerously-skip-permissions` 를 붙여 Shift+Tab 으로 돌아갈 수 있게 한다.
- 복구는 저장한 명령을 그대로 입력한다. 끝난 attach 세션만 기록의 마지막 모드를 붙인다. 살아 있는 attach, 다른 에이전트, retry 는 바꾸지 않는다.
- 기록은 뒤에서부터 256KB 단위로 읽고, 한 줄이 그보다 길면(붙여 넣은 이미지) 다음 단위와 이어 붙여 읽는다. 16MB 까지만 읽는다.

## 검증

- 새 테스트 `SessionSnapshotPermissionMode.test.ts` 가 구현 전에 실패하는 것을 먼저 확인했다. 수정 뒤 24/24 통과.
- 변이 3종(저장 시 판단 끔, 끝난 attach 의 기록 무시, 기록의 마지막 값 우선)이 각각 해당 테스트를 실패시켰다.
- 독립 리뷰에서 나온 결함 2건(256KB 를 넘는 줄을 건너뜀, 턴 중 바꾼 모드를 놓침)과 경미한 문제 1건(모르는 모드 값)을 테스트로 먼저 재현한 뒤 고쳤다.
- 회귀: `SessionSnapshot*` · `WorkspaceServiceAgentResume` · `agentSession` 테스트 11개 파일, `src/test-runner.ts` 532건, server `tsc --noEmit`, `check:srs-change-notes`, `check:kiwi-status` 통과.
- 실제 데이터: 이 PC 에서 실행 중인 Claude 세션 15개(화면상 모두 bypass)를 실제 프로세스 명령줄과 대화 기록으로 판정해 모두 `bypassPermissions` 를 얻었다. 막 다시 띄워 기록 끝이 `default`·`auto` 인 세션 7개도 포함된다.

## 한계

- `claudep` 처럼 래퍼 안에서 권한 플래그를 넣는 경우에는 그 플래그를 볼 수 없다.
- 저장 창이 미리 채우는 인자에는 이 규칙을 적용하지 않았다. 사용자가 확인하고 고치는 화면이기 때문이다.
