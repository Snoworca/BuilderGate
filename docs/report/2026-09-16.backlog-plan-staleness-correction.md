# 남은 작업 백로그 계획의 낡음 정정 — 이슈 #36

## 이슈

`docs/plan/2026-09-01.remaining-work-backlog.plan.md` 는 커밋 `80b523c`(2026-09-01)에서 생성된 뒤 한 번도 갱신되지
않았다. 그런데 **같은 커밋이 A 그룹 네 항목을 전부 고쳤다.** 이 문서를 읽고 착수하면 이미 끝난 일을 다시 하게 된다.

이슈 본문은 여섯 항목(A1~A4, C1, C3)이 이미 해소되었다고 주장하면서, 자기 근거가 고르지 않다는 점을 스스로 밝힌다 —
**A1~A4 는 커밋 내용·파일 실재·커밋 메시지로 판정했을 뿐 재실행하지 않았고**, C1·C3 만 직접 확인했다.

## 문제 원인

계획 문서에 갱신 주체가 없다. 항목을 고친 커밋이 그 항목을 "남은 것"으로 적어 둔 문서를 같이 고치지 않는다.

### SRS 진단 기준선

`docs/research/binary-comms/04-srs-amendment-plan.md:71` 이 선행 부채로 기록하고 `:560-561`·`06-work-plan.md:2155`
가 **증가 감시 기준선**으로 쓰는 값은
`{"errors":1,"warnings":19,"byCode":{"SRS-W018":5,"SRS-W023":14,"SRS-E002":1}}` 다.

오늘 `npx speckiwi validate --json`(CLI 3.0.0, 워크트리 루트)은 **errors 0 / warnings 0 / `byCode` 빈 객체**를 낸다.
부채 해소인지 CLI 버전 차이로 같은 진단을 더는 내지 않는 것인지는 **구분하지 않았다.** 그 기준선에 의존하는 델타
게이트(전 코드 델타 0)는 현재 상태에서 의미를 잃는다. **기준선 조정은 별도 결정이므로 이 작업에서 하지 않았다.**
