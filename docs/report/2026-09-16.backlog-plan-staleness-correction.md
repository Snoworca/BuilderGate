### A3 를 "해소" 가 아니라 "부분 해소" 로 내린 이유

- **기전은 소유권 레지스트리다.** `frontend/tests/e2e/workspaceLeakGuard.ts` 의 globalSetup `recordWorkspaceBaseline`(`:98`)은
  빈 레지스트리 디렉터리와 `records/`·`run.json` 만 만든다 — `ready(options)` 를 호출하되 **돌려받은 `ids` 는 버린다.**
  런 시작 전 워크스페이스는 기록되지 않는다. 정리(`cleanupRegistry:148` ← `removeWorkspacesCreatedDuringRun:194`)는
  `records/` 아래 파일만 훑고, 그 파일은 스펙이 자기 생성 응답(POST `/api/workspaces` 201)의 id 를
  `registerWorkspaceCreation`(`:119`)으로 등록했을 때만 생긴다. 같은 파일 `:6` 이
  `// REL-BGSTAB-001: list differences and workspace names never grant ownership.` 로 **집합 차분 모델을 금지한다.**
  커밋 `80b523c` 의 메시지에 적힌 "런 전 목록과의 차분" 서술은 `dbf61c1` 이 대체한 현재 구현과 맞지 않으므로
  기전 근거로 쓰지 말 것.
- **남는 것 (1)**: 등록하지 않는 스펙의 산출물은 정리 후보가 아니다. 여기서 **두 수를 구분한다.**
  - **grep 기준 14개**: `api/workspaces`/`createWorkspace` 를 치면서
    `workspaceOwnershipFixture`·`registerOwnedWorkspace`·`workspaceLeakGuard`·`workspaceTeardown` 중 어느 것도
    참조하지 않는 스펙 — `auth-bootstrap`, `markdown-editor-appearance`, `markdown-editor-entry`,
    `markdown-editor-lifecycle`, `markdown-editor-modal-regression`, `markdown-editor-persistence`,
    `markdown-editor-placement`, `markdown-editor-save`, `perf-bgstab-010-ac6-server-ack-fault`,
    `perf-bgstab-010-ac9-isolated`, `session-env-isolation`, `settings-password-policy`, `settings-resource-limits`,
    `wave2-screen-repair-resync` (`.spec.ts`). **문자열 일치이지 누수 표면이 아니다.**
  - **실제 생성 기준 2개**: `/api/workspaces` 에 `method: 'POST'` 를 치는 곳을 전수로 확인하면
    `markdown-editor-persistence.spec.ts:124`, `markdown-editor-save.spec.ts:161`·`:184` 뿐이다.
    정리되지 않는 산출물을 남기는 것은 이 둘이다.
  - 나머지 12개는 만들지 않는다 — 3개(`auth-bootstrap`, `settings-password-policy`, `settings-resource-limits`)는
    `page.route` 가로채기만 하는 mock-only 로 `frontend/tests/unit/workspaceOwnershipMigration.test.ts:10` 의
    `mockOnly` 집합에 고정되어 있고, 2개(`perf-bgstab-010-ac6-server-ack-fault`, `perf-bgstab-010-ac9-isolated`)는
    같은 파일 `:201-203` 이 워크스페이스 생성·삭제 0건을 단언으로 핀한다. 남은 7개는 목록 조회(GET)·워크스페이스
    PATCH·탭 단위 요청만 친다.
  - 판정은 **부분 해소 그대로**이며, 바뀐 것은 근거가 되는 수(14 → 2)뿐이다.
- **남는 것 (2)**: 완료 조건의 "실패 경로" 는 *스펙* 실패만 덮는다. globalTeardown 은 SIGINT·강제 종료에서 보장되지
  않고, globalSetup 이 throw 하면 실행되지 않는다. DELETE 실패의 기전은 이렇다 — `cleanupRegistry`(`:161-181`)의
  루프는 실패를 `result.failed` 에 넣고 `continue` 하므로 **모든 레코드를 끝까지 시도**하며(건너뛰는 것은 그 레코드의
  `unlink` 뿐), throw 는 루프가 다 돈 뒤 `removeWorkspacesCreatedDuringRun`(`:196-197`)에서 일어난다. 한 건이라도
  실패한 런은 throw 로 끝나고, 실패한 워크스페이스는 삭제되지도 레코드가 지워지지도 않는다.
- **B2 신규 실패 2건이 같은 뿌리다.** `B2 source inventory preserves owned workspace mutation boundaries:
  markdown-editor-persistence.spec.ts` · `… markdown-editor-save.spec.ts` 가
  `live workspace DELETE must delegate to the owner-checked single-ID helper` 로 깨진다 — 두 스펙이 소유자 검사를
  거치는 단일 ID 헬퍼 대신 `/api/workspaces/{}` 에 직접 `DELETE` 를 친다
  (`frontend/tests/unit/workspaceOwnershipMigration.test.ts:205`).

  그 리스너가 사라진 뒤에 포집되어 2222 에 대한 `ss` 일치가 없고 `/proc` 일치는 포집 스크립트 자신의 bash(PID 128934)
  뿐이다 — **존재가 아니라 부재를 기록한 파일이다.** 게다가 **그 파일의 첫 줄이
  `# 2222 ownership at 20260916T031730Z (not mine; another lane)` 로 미증명 식별을 단정한다** — 본문이 뒷받침하지
  않는 헤더이므로 그대로 인용하지 말 것. 원시 증거는 불변으로 두고 정정은 문서에만 남긴다. (커밋 `4bd89ac` 의
