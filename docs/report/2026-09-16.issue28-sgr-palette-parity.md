## 1. 이슈 전제의 정정

이슈 제목이 인용한 `retainedStateParity-gate-failed` 는 소스에 존재하지 않는다 (`server/src`·`frontend/src` grep 0건). 실제 blocker 는 두 개다.

| blocker | 발생 조건 | 소스 |
|---|---|---|
| `retained-state-parity-mismatch` | 6개 principal axis 중 하나라도 `mismatch` | `server/src/services/SessionManager.ts:2989-2992` |
| `retained-state-parity-unavailable` | mismatch 는 없으나 parity 조건이 불충족 (7가지 원인) | 같은 곳 |

**#28 이 관측한 것은 `retained-state-parity-mismatch` 다.** `-unavailable` 이 아니다. 근거: 아래 기전이 `cells` axis 를 `mismatch` 로 만들며, `mismatch` 가 하나라도 있으면 `comparerMismatch` 가 참이 되어 `SessionManager.ts:2990` 이 `-mismatch` 를 선택한다.

#26 이 예고한 `cells` 대 `unicodeWidth` 비대칭이 정확히 판별자였다. `cells` 는 `cellHash + attributeHash` 를, `unicodeWidth` 는 `cellHash` 만 비교한다 (`server/src/utils/headlessTerminal.ts:348-362`). SGR 밀집 콘텐츠에서 `cells=mismatch` / `unicodeWidth=match` 가 관측된다 — 즉 문자·폭은 온전하고 **attribute 만** 어긋난다.

## 2. 기전

xterm 은 ANSI palette 색을 **두 가지 교환 가능한 mode** 로 저장한다.

| SGR | `getFgColorMode()` | `getFgColor()` |
|---|---|---|
| `ESC[33m` | `0x01000000` (P16) | `3` |
| `ESC[38;5;3m` | `0x02000000` (P256) | `3` |

둘은 같은 palette slot 을 가리키고 화면상 결과가 동일하다. 그런데 `@xterm/addon-serialize` 는 **index 0..15 를 언제나 P16 short form 으로 재출력한다.** 따라서

1. 세션이 `ESC[38;5;3m` 로 그린다 → cell 은 P256 으로 저장
2. checkpoint 의 `rehydrateAnsi` 는 `ESC[33m` 을 담는다
3. round-trip consumer 가 그것을 먹으면 cell 은 P16 으로 복원
4. `projectRetainedBuffer` 의 `attributeTokens` 가 `getFgColorMode()` 를 그대로 담으므로 `attributeHash` 가 달라진다
5. `cells` axis = `mismatch` → `retained-state-parity-mismatch` → **승급 영구 차단**

실측 범위: fg·bg 모두 **index 0..15 에서만** 발생. 16 이상과 truecolor 는 안정적이다 (`raw/red-*.log` 의 AC-1 실패 목록과 BOUNDARY CONTROL 통과가 양쪽을 동시에 고정한다).

### 크기·밀도 가설의 기각

- **크기는 원인이 아니다** — #26 이 이미 기각했고, 여기서 독립적으로 확인된다.
- **밀도도 원인이 아니다** — **SGR palette 색 한 줄이면 충분하다.** 2,000줄이 필요한 것이 아니다. 이슈가 밀도를 원인으로 본 것은 밀집 콘텐츠일수록 index 0..15 를 포함할 확률이 1에 가까워지기 때문이다.
- "동일 크기 plain 텍스트가 첫 시도에 성공" 한 관측도 이것으로 설명된다. plain 텍스트에는 palette cell 자체가 없다.

## 3. 수정

`server/src/utils/headlessTerminal.ts` 에 `canonicalPaletteColor(mode, color)` 를 추가하고 `projectRetainedBuffer` 의 attribute token 에 적용했다. P16 이면서 index 0..15 인 색을 P256 으로 승격해 canonical token 을 만든다. DEFAULT(`0x0`)와 RGB(`0x03000000`)는 손대지 않는다.

`server/src/services/RetainedTerminalAuthority.test.ts` 의 `hashConsumerBuffer` 는 production hash 의 **독립 재구현** 이므로 같은 계약을 따라야 한다. import 하지 않고 같은 규칙을 별도로 작성해 독립성을 유지했다(`canonicalPaletteColorToken`).

### 두 번째 관측(서버 사망)의 부하 분리

이슈는 13,000줄 SGR 밀집 입력 중 3/3 실행에서 서버가 60~80초에 사망했다고 보고했으나, 그 측정 환경은 node 프로세스 약 480개였다.

조용한 환경(`node` 프로세스 **11개**, load average **0.69**, `raw/load-env-20260916T073144Z.txt`)에서 13,000줄 SGR 밀집 입력을 retained headless model + shadow comparer round-trip 에 통과시켰다.

```
{"lines":13000,"wallSeconds":47.447,"peakRssMb":411,"comparisons":26,"cellsMismatches":0,"survived":true}
```

**사망하지 않았다.** 47.4초, 최대 RSS 411MB, 26회 비교 전부 `cells=match`.

**이 결과의 한계를 명시한다.** 이것은 in-process 모델 부하 재현이며 실제 서버·PTY·WebSocket 전체 스택이 아니다. 또한 이슈가 함께 보고한 ConPTY `AttachConsole failed` 는 Windows ConPTY 증상이라 이 WSL/Linux 레인에서 원리상 재현 불가능하다. 따라서 **"서버 사망이 재현되지 않았다" 가 아니라 "부하를 제거한 모델 경로에서는 사망이 관측되지 않았고, 완전한 배제에는 Windows 호스트의 전체 스택 재현이 더 필요하다"** 가 정확한 결론이다.

## 6. 신규 결함 2건 (이 작업에서 수정하지 않음)

### D1 — `MIG-BGSTAB-002 checkpoint identity follows the committed authority source across reserved ordinal gaps` 는 테스트 계약과 production invariant 가 서로 모순이다

- 결정적이다(3/3 동일 실패). 플랫폼 문제가 아니다 — fixture 가 `AuthorityIntegrationFakePty` 를 쓰고 실제 shell 을 띄우지 않으므로 Windows 에서도 같게 실패한다.
- 연쇄: 테스트가 `nextTerminalAuthoritySourceSeq += 1n` 로 의도적 ordinal gap 을 만든다(`TerminalAuthorityController.test.ts:487`) → `synchronizeTerminalAuthoritySourceOrdinal` 이 한 방향으로만 clamp 하므로(`SessionManager.ts:5115-5121`) gap 이 남는다 → `SessionManager.ts:8096-8098` 의 엄격 동등 검사가 `terminal-authority-reservation-commit-mismatch: reserved=7/2, commit=7/1` 을 throw → `markHeadlessDegraded` → `headlessHealth='degraded'` → `WsRouter.ts:5052-5054` 가 `mode='fallback'` 을 고른다.
- **모순의 핵심**: 테스트의 assertion 메시지는 reserved ordinal gap 이 *허용* 된다고 명시하는데, `SessionManager.ts:8096` 은 같은 gap 을 hard fault 로 만든다. 어느 쪽이 정본인지는 제품 결정이다.
- 선재 정황: 검사 술어는 `ba769c2` 가 도입했고 그 커밋은 이 테스트 파일을 갱신하지 않았다. **다만 다른 커밋을 checkout 하지 않았으므로 green→red 전이를 실행으로 증명하지는 못했다.** 정황 근거이며 측정이 아니다.
- **`FR-BGSTAB-027` 과 기전이 다르다.** 이 fixture 는 SGR 을 전혀 쓰지 않고, 더 결정적으로 `throw`(`:8098`)가 `scheduleRetainedTerminalComparison`(`:8124`) 보다 먼저 일어나 comparer 자체가 실행되지 않는다.

### D2 — frontend 가 같은 P16/P256 노출을 갖는다 (시험 표면 한정)

`frontend/src/utils/terminalRetainedState.ts` 의 `canonicalizeCell`(`:441-442`)·`captureTerminalRetainedState`(`:537-538`)·`streamingCellRun`(`:625-626`)이 `fgMode`/`bgMode` 를 그대로 해시에 넣는다. 서버와 동일한 divergence 가 frontend 자체 함수로 재현된다(index <16 에서만, truecolor·16 이상은 안정).

- **production 경로에서는 두 digest 를 비교하지 않는다.** `captureTerminalRetainedState` 의 호출부는 `TerminalView.tsx:3034`·`:4109` 둘뿐이고 둘 다 증거를 *생산* 만 한다. 소비자는 테스트 전용 `window.__buildergateTerminalDebug` 다.
- 반면 E2E 는 raw 대 rehydrated 를 직접 비교한다 — `frontend/tests/e2e/wave3-terminal-authority-promotion.spec.ts:6384-6386`·`:6771`·`:7161`.
- **지금 green 인 이유는 fixture 운(luck) 이다.** 모든 E2E fixture 가 우연히 index ≥16(`38;5;45`, `38;5;214`, `38;5;196` 등)만 쓴다. fixture 가 낮은 index 로 바뀌거나 실제 shell prompt 가 코퍼스에 들어오면 즉시 red 가 된다.
- **여기서 고치지 않은 이유**: 수정은 `ph005-retained-stream-v1` 해시 계약과 `digest` 값을 바꾸므로 contract 버전 pin 을 서버와 lockstep 으로 올려야 한다. #28 의 범위를 넘는 별도 결정이다.
- 한계: 서버를 띄우지 않았으므로 E2E 실패는 재현된 해시 divergence 와 rehydrate 경로로부터의 **추론** 이지 관측이 아니다.

### 노출되지 않는 것 (확인함)

서버 screen-repair 의 `getCellStyle`/`getStyleKey`(`headlessTerminal.ts:883`,`:905`)는 한 줄 안에서 SGR 을 run-length 로 묶어 *출력* 하는 데만 쓰인다. 교차 provenance 비교가 아니므로 P16/P256 차이가 잘못된 patch 를 만들지 않는다.
