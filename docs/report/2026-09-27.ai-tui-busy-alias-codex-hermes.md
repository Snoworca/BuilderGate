# AI TUI 실행 중 표시: 별칭(claudep), Codex, Hermes

- 날짜: 2026-09-27
- 요구사항: FR-AITUI-010 AC-5..AC-7 (추가)
- 커밋: `2c229f8f`
- 앞선 작업: `docs/report/2026-09-26.ai-tui-busy-subagent.md` (`f01ad97f`)

## 이슈

- Claude가 여전히 작업 중에 실행 중으로 유지되지 않는다는 보고가 있었다. 사용자는 2222에서 `claudep`을 쓰고 있었다.
- Codex와 Hermes도 같은지 질문을 받았다.

## 원인

| 대상 | 작업 중 화면 | 문제 |
|---|---|---|
| `claudep`·`codexp` 같은 복구 옵션 별칭 | Claude·Codex와 같음 | AI 화면으로는 인식된다. 그러나 1.5초 유예가 정확한 이름(claude/codex/hermes/opencode)에만 적용되어 0.2초 기준이 걸렸다 |
| Codex 0.157 | BuilderGate가 `tui.animations=false`로 띄우므로 "Working (Ns • esc to interrupt)"의 초 숫자만 1초마다 바뀐다 | repaint로 분류되어 3초 keepalive 창이 지나면 대기가 되었다 |
| Hermes (hermes-agent) | "(◔_◔) pondering...  ( 5.2s)"를 약 1초마다 다시 그린다 (`cli_refresh_interval` 1.0) | 초 숫자만 바뀌면 전용 감지기가 repaint_only를 낸다. 그 관찰이 곧바로 대기로 이어졌다 |

## 해결

- 복구 옵션으로 인식된 에이전트도 AI 유예(1.5초)를 받는다.
- 제자리에서 다시 그려지는 경과 시간 틱은 작업 중의 증거로 보고 keepalive 창을 새로 연다.
  - 해당 형태: "12s", " 5.2s", "01m05s", "3:07"
  - 세 도구 모두 작업 중에만 이런 틱을 표시한다.
- Hermes 감지기의 repaint_only 관찰도 실행 중인 세션을 유지한다. 감지기의 busy 관찰은 마지막 busy 시각을 갱신한다.

## 남은 것

- **E2E를 돌리지 못한 이유:** 사용자 브라우저가 2222에 연결되어 있어, E2E가 만든 새 세션의 입력 임대(driver lease)를 먼저 가져간 것으로 보인다. 그래서 E2E의 입력이 거부되었다(`acceptRetainedTerminalMutationIdentity`의 `driver-lease-failure`). 기존 동작이다.
- **다중 클라이언트 입력 제한:** 같은 세션을 두 브라우저가 볼 때 한쪽만 입력할 수 있다. 이것은 별도 문제다.
- 별칭 사례의 명령 이름 `e2e-recovery-claudealias`는 정확한 이름 `claude`와 다르다. 따라서 복구 옵션 경로(`markRecoveryCommandForeground`)를 거친다.

## 추가: 실제 Claude Code 출력으로 다시 고침 (`01ec8284`)

사용자가 여전히 동작하지 않는다고 알려 왔다. 2222의 디버그 캡처로 사용자의 `claudep` 세션을 직접 들여다봤다.

### 캡처로 확인한 것

- 약 0.11초마다 스피너 프레임이 온다.
- 각 프레임 약 20ms 뒤, 색 초기화(`\x1b[m`)만 담긴 3바이트 조각이 따로 온다.
  - 이 빈 조각이 repaint_only로 분류되었다.
  - 그래서 앞 프레임이 예약한 running 전이(250ms)를 매번 취소했다.
  - 작업하는 동안 running에 한 번도 도달하지 못했다.
- 창 제목은 작업 중 `◐`/`◑`를 약 1초마다 번갈아 쓰고, 끝나면 `✳`가 된다.
- 앞선 단위 테스트와 가짜 TUI는 이 빈 조각을 만들지 않아서, 테스트는 통과했지만 실제로는 동작하지 않았다.

### Orca 조사 결과 (Explore 서브에이전트)

- 주 신호는 에이전트 훅이다. 사용자 지시로 이번에는 쓰지 않았다.
- 보조 신호는 창 제목이다.
  - 점자(U+2800–28FF)나 `◐◑◒◓`(U+25D0–25D3)가 있으면 작업 중이다.
  - `✳`로 시작하면 Claude가 유휴 상태다.
  - 침묵만으로는 유휴가 되지 않는다. 작업 제목은 3초 동안 유효하다.
- 코드 위치: `src/shared/agent-title-core.ts`, `agent-title-status.ts`.

### 수정

- 출력 가능한 글자가 없는 조각은 상태를 바꾸지 않고, 예약된 running 전이도 취소하지 않는다.
- AI 화면의 창 제목에 스피너가 있으면 곧바로 running이 된다. 작업 제목이 올 때마다 3초 동안 유지한다.
- 창 제목이 `✳`이면 짧은 대기(idleDelayMs) 뒤 idle이 된다. 그 사이에 작업 제목이 오면 idle 전환을 취소한다.

### 검증

- 단위 테스트 12/12. 캡처한 실제 바이트열을 재생하면 수정 전에는 24/24가 idle, 수정 후에는 24/24가 running이었다.
- runner 10개 필터와 node 테스트 92/92가 통과했다.
- 2222 재시작 뒤 사용자 세션의 실사용 확인은 사용자가 다음 작업을 돌릴 때 캡처로 확인한다.
