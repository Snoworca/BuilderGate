# 세션 저장: 모든 터미널 한 번에 저장, 재시작 뒤 자동 이어하기

- 날짜: 2026-09-28
- 요구사항: FR-AITUI-013 (전체 터미널 세션 저장), FR-AITUI-014 (재시작 뒤 자동 이어하기), FR-AITUI-015 (저장 창과 복구 결과 화면). 타깃 `session-save-all`
- 부분 승계: FR-AITUI-008 AC-2 (선택 이어하기), FR-AITUI-009 AC-1~AC-4 (AI 탭만의 저장 창·배너·이어하기 창), FR-AITUI-012 AC-1·AC-2 (저장한 탭에 한해). 각 요구사항에 Change Note를 남겼다.
- 커밋: (미커밋)

## 이슈

사용자 보고: "세션이 한 박자 늦게 뜨거나 아예 뜨지 않는 경우가 종종 있다."

기대 동작:
- 종료했다가 다시 시작하면 세션이 열리고, 셸이 마지막 디렉터리에서 보인다.
- 그 위에서 `{마지막 실행 명령어} {인자} {세션 id}`가 실행되어 에이전트가 이어진다.

추가 지시:
- 저장 창은 모든 워크스페이스의 모든 터미널과, 그 안의 에이전트·id를 보여 준다.
- 한 번에 저장하며, 에이전트가 없는 탭은 셸 상태만 저장한다.
- id를 모르거나 불확실하면 사용자가 명령(셀렉트)과 id를 직접 고친다.
- `claudep`·`codexp`처럼 도구 › 에이전트 명령어에 등록한 명령으로 시작했으면 그 명령으로 이어한다.
- 결정 사항: 재시작 뒤 이어하기는 묻지 않고 자동 실행한다. 저장본은 한 번 복구하면 소진된다.

## 원인

1. **이어하기가 사용자 클릭에 달려 있었다.** 재시작 뒤 배너 → 이어하기 창에서 탭을 골라야 명령이 들어갔다. id가 "추정"인 탭은 기본으로 선택되어 있지 않았다.
   - 실측: 2222의 `data/session-snapshot.json`에 오늘 14:24(KST)에 저장된 세 항목이 전부 `pending`인 채로 남아 있었다. 한 번도 이어지지 않은 것이다.
2. **저장 창이 AI 탭만 다뤘다.** 일반 셸 탭은 목록에 없었고, id를 고칠 방법이 없었다.
3. **디렉터리 복원 자체는 이미 동작했다.** 고아 탭 복구가 탭의 `lastCwd`에서 셸을 다시 만든다.
   - 터미널 표시 지연도 측정했다. 재시작 직후 페이지를 열면 세 터미널 모두 0.26~0.31초 안에 글자가 보였고, 새로고침에서도 0.18~0.38초였다.
   - 즉 "안 뜬다"의 실체는 이어하기가 일어나지 않은 것이다.

## 해결

### 서버 (`SessionSnapshotService`)

- **`GET /api/session-snapshot/preview`** (FR-AITUI-013 AC-1/AC-2)
  - 모든 탭을 돌려준다. 탭마다 디렉터리, 실행 중인 명령, 에이전트, 실행 명령(launcher)과 인자, 세션 id·확실도, 같은 디렉터리의 다른 살아 있는 세션 후보(Claude·Codex)를 담는다.
  - launcher는 도구 › 에이전트 명령어에 등록된 이름일 때만 유지하고, 그 밖이면 기본 명령으로 둔다.
  - 인자에서는 `--resume`, `-c`, `resume --last` 같은 세션 선택자를 뺀다.
- **`POST /api/session-snapshot {items}`** (AC-3~AC-6)
  - 탭별 `agent | shell | command` 항목을 검증해 저장본을 새로 쓴다.
  - id 형식이 틀렸거나 등록되지 않은 launcher이면 400과 문제 탭 id를 돌려주고, 아무것도 쓰지 않는다.
  - id가 빈 에이전트 항목은 셸로 저장한다.
  - 기존 `{tabIds}` 형식과 mode 없는 옛 저장본 항목도 그대로 읽는다.
- **서버 시작 시 `autoRestore()`** (FR-AITUI-014)
  - 고아 탭 복구 전에 `restoreCwdFor`를 등록해, 저장본의 탭이 저장된 디렉터리에서 열린다.
  - 셸이 준비되면 이어하기 명령을 셸에 맞게 인용해 한 번 입력하고, 저장본을 소진 처리한다.
  - 에이전트 항목은 20초 안에 그 탭에서 에이전트가 감지되면 `confirmed`, 아니면 `unconfirmed`로 기록한다. 감지는 foreground 앱이거나 셸의 프로세스 트리에 에이전트가 있는 경우다. 프로세스 목록은 틱당 한 번만 읽는다.
- **`POST /api/session-snapshot/retry`**: 실패한 탭 하나를 고친 항목으로 다시 입력한다.
- **`SessionManager.getAgentRuntimeInfo`**: `runningCommand`를 내준다. 표시할 때는 셸 인용 없이 보여 준다.

### 프런트엔드

- **새 저장 창** (`SessionSaveDialog`, `RestoreEditor`)
  - 워크스페이스별 모든 터미널을 보여 준다. 필터는 전체 / 확인 필요 / 에이전트 / 셸만이다.
  - 추정이거나 못 찾은 행은 편집기가 열린 채 나온다. 편집기는 이어할 명령 셀렉트(에이전트별 등록 명령 · 셸만 · 직접 입력), 인자, 세션 id와 후보를 제공한다.
  - "재시작 뒤 입력" 미리보기가 있다. id 형식 오류는 그 행을 빨갛게 하고 저장을 막는다.
- **재시작 결과 배너와 결과 창** (`RestoreReport`)
  - 배너는 이어하기 성공·실패·셸만 개수를 알린다. 실패가 없으면 5초 뒤 사라진다.
  - 결과 창에서 실패한 탭을 고쳐 다시 실행할 수 있다.
- 헤더 저장 버튼은 탭이 하나라도 있으면 누를 수 있다.
- 옛 `SessionRestoreDialog`·`SessionRestoreBanner`와 그 전용 i18n 키 51종을 제거하고, 새 키를 en/ko에 추가했다.

### 실측 (https://localhost:2222, 작업 트리 빌드)

- **사용자가 남긴 pending 저장본으로 재시작**
  - `claudep --resume …`과 `codexp resume …` ×2가 입력되었고, 약 12초 안에 세 탭 모두 `confirmed`였다.
  - 첫 빌드는 `foregroundAppId`만 보고 판정해서, 에이전트가 떠 있었는데도 셋 다 `unconfirmed`로 잘못 기록했다. 프로세스 트리 판정을 추가해 고쳤고, 테스트를 먼저 추가했다.
- **새 흐름: preview → 모두 저장 → 재시작**
  - 등록 별칭 `claudep`·`codexp`가 유지되었다.
  - 세 탭 모두 저장된 디렉터리에서 열리고 `confirmed`였다.
- **실패 경로**
  - 형식은 맞지만 존재하지 않는 codex id를 넣고 재시작했다. 배너가 "이어하기 2 · 실패 1"로 남았고, 결과 창에 "고쳐서 다시 실행"이 나왔다.
  - `retry`에 올바른 id를 넣자 `confirmed`가 되었다.
- **저장 창 스크린샷**: `.playwright-mcp/session-save-dialog.png`, `-invalid.png`, `session-report-*.png`
  - 실측에서 세션 id 입력칸이 찌그러지는 레이아웃 결함과, 재시도 편집기 셀렉트가 자기 명령(`codexp`)을 표시하지 못하는 결함이 나왔다. 둘 다 수정했다.
- **운영 데몬**: 2001/2002 데몬(PID 2864)은 전 과정 동안 그대로였다. 2222 교체는 이 체크아웃 exe의 PID만 하나씩 종료했다(`/T` 없음).

## 한계

- Claude 탭의 id는 같은 디렉터리에 다른 Claude 세션이 살아 있으면 "추정"으로 나온다. 실측에서도 그랬다. 저장 창에서 후보를 골라 확인하도록 설계했다.
- `confirmed`는 "에이전트 프로세스가 떴다"는 뜻이다. 그 세션이 그 id의 대화인지까지 보장하지는 않는다.
- 저장본은 한 번 쓰면 소진된다. 다음 재시작에도 이어가려면 다시 저장해야 한다.
- 운영 데몬(2001/2002)은 이 빌드로 올려야 반영된다.
