## 1. 이슈

`IR-BGSTAB-001` AC-7 은 두 가지를 규정합니다.

> 바이너리 인코딩은 `wsTransportMode` 가 `unified` 일 때만 활성화될 수 있고, `wsTransportMode` 의 기존 닫힌 enum(`unified`, `split-shadow`, `split`)과 그 fallback 규칙을 변경해서는 안 된다. 설정 값만으로 바이너리가 켜져서는 안 되며, 설정은 서버가 협상에 응할 수 있는지만 정하는 kill switch 여야 한다.

그런데 운영자가 `config.json5` 에 `realtime.wsTransportMode` 를 `split` 또는 `split-shadow` 로 설정한 서버가, 쿼리 파라미터를 생략한 클라이언트에게 `terminal-binary:capability` 로 협상을 열어 주었습니다. 설정이 kill switch 로 작동하지 않았습니다.

---

## 2. 문제 원인

협상 게이트는 단일 진입점입니다.

```
WsRouter.ts  ensureTerminalBinaryGroup
  └→ createTerminalBinaryGroupSession({ wireFormat, transportMode })
       └→ terminalBinaryGroupSession.ts:78  isBinaryNegotiable(wireFormat, transportMode)
            └→ terminalWireFormat.ts:55  isTransportEligible(transportMode) === 'unified'
```

수정 이전에 그 자리는 다음과 같았습니다.

```ts
transportMode: meta.wsTransportMode ?? this.wsTransportMode,
```

두 피연산자 모두 설정을 반영하지 않았습니다.

- `meta.wsTransportMode` 는 **클라이언트가 쿼리 파라미터로 요청한 값**입니다. 운영자 설정이 아닙니다.
- `this.wsTransportMode` 는 생성자에서 `options.realtime?.wsTransportMode ?? 'unified'` 로 대입되는데, `index.ts` 가 그 옵션을 넘기지 않아 **프로덕션에서 항상 `'unified'`** 로 수렴했습니다. `undefined` 가 되는 것이 아닙니다 — `??` 가 기본값을 채웁니다.

그래서 클라이언트가 파라미터를 생략하면 게이트가 `'unified'` 를 보고 협상을 열었습니다.

### 2.1 AC-7 의 문면 모호성

AC-7 의 "`wsTransportMode` 가 `unified` 일 때만" 에서 그 이름이 **설정 키**를 가리키는지 **클라이언트 요청값**을 가리키는지는 문면으로 판정되지 않습니다. 조사 결과 이 저장소에서 `wsTransportMode` 라는 이름은 설정 키(`config.schema.ts:56`), 연결별 서버 메타데이터(`ws-protocol.ts:830`), `connected` 메시지의 와이어 필드(`WsRouter.ts:1736`) 셋을 동시에 가리키며, AC-7 은 한정어를 붙이지 않습니다.

양쪽 해석이 각자 구멍을 남깁니다.

| 해석 | 남는 구멍 |
| --- | --- |
| 설정값을 본다 | 실제 토폴로지가 split 인 연결에 바이너리가 나갈 수 있다 |
| 요청값을 본다 | split 로 설정된 서버에 클라이언트가 `?wsTransportMode=unified` 를 보내면 통과한다 |

### 2.2 라우팅 필드를 그대로 배선할 수 없는 이유

`this.wsTransportMode` 에 설정을 배선하면 AC-7 은 충족되지만 다른 두 요구사항을 위반합니다.

- `REL-BGSTAB-006` 본문(`:2521`): "이 characterization은 split 계약의 restore 또는 supersede를 미리 선택하거나 runtime split activation을 승인하지 않는다."
- `REL-BGSTAB-006` AC-5(`:2533`): "…FR-BGSTAB-006/007의 Status·Stability·본문을 변경하거나 split runtime을 활성화하지 않는다."
- `REL-BGSTAB-008` AC-10(`:3029`): "Wave-1 REL-BGSTAB-006에서 관측된 production unified와 standalone split limitation을 그대로 보존하고 split activation/parity를 주장하지 않는다."

`this.wsTransportMode` 가 `'split'` 이 되면 `:1579` 의 fallback 을 거쳐 `meta.wsTransportMode` 에 실리고, `:735`·`:883`·`:1140`·`:1154`·`:1167`·`:2363` 의 lane 분기가 열립니다. 그것이 금지된 split runtime 활성화입니다.

## 3. 해결 방법

설정된 전송 모드를 **협상 게이트에만** 전달하는 별도 옵션을 두었습니다.

```ts
/**
 * The transport mode the operator configured. It answers only AC-7's
 * question of whether binary negotiation may open, and deliberately does not
 * feed `wsTransportMode` below: REL-BGSTAB-006 AC-5 leaves split runtime
 * inactive, so routing stays unified whatever this says.
 */
binaryNegotiationTransportMode?: 'unified' | 'split-shadow' | 'split';
```

게이트는 삼항 연산자입니다. `if` 문이 아닙니다.

```ts
const configured = this.binaryNegotiationTransportMode;
const created = createTerminalBinaryGroupSession({
  now: () => Date.now(),
  wireFormat: this.terminalWireFormat,
  transportMode: configured === 'unified' ? (meta.wsTransportMode ?? this.wsTransportMode) : configured,
});
```

**설정과 연결이 둘 다 `unified` 일 때만** 게이트가 열립니다. 그래서 §2.1 의 모호성을 우회합니다 — 어느 해석을 택하든 위반이 남지 않습니다.

`this.wsTransportMode` 와 lane 분기는 손대지 않았으므로 §2.2 의 제약도 지켜집니다. 옵션을 넘기지 않는 기존 호출자에서는 `?? 'unified'` 때문에 `configured === 'unified'` 가 항상 참이 되어, 게이트 식이 변경 이전과 **문자 그대로 같은 식**으로 환원됩니다.

`WsRouter.ts` 는 핀 파일이라 뮤턴트가 false kill 을 낼 수 있습니다. 그래서 대조군을 먼저 돌려 **파일 해시가 바뀐 상태에서도 부트 프로브가 6/6 green** 임을 확인했고, 그로써 이후 red 의 원인이 핀이 아니라 게이트 로직임을 분리했습니다.
