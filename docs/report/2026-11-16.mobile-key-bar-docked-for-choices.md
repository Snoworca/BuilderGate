# 선택지 화면에서 키보드 없이 방향키 쓰기 (FR-MKB-013 AC-6)

## 이슈

- 2026-11-16 사용자 보고: 휴대폰·패드에서 Claude Code 가 선택지만 보여 주는 화면일 때, 선택을 잘못해서 이전 선택지로 돌아가려고 방향키를 쓰려 해도 키 줄이 나오지 않는다. 화면 여기저기를 누르다가 키보드가 올라오면 그때서야 입력할 수 있다.
- 사용자는 모바일·패드 화면 어딘가에 키보드 버튼을 두어야 하는지도 물었다.

## 원인

- 방향키가 있는 키 줄은 시스템 키보드가 올라와 있을 때만 보인다(FR-MKB-013 AC-2).
- 전날 고친 동작 때문에 선택지를 탭하면 클릭만 되고 키보드는 올라오지 않는다(FR-ARCH-010 AC-8). 그래서 선택지 화면에서 키 줄을 띄우는 방법은 입력 줄 근처를 탭하는 것뿐이었다.
- 키 줄의 `sendKey` 는 키를 보낸 뒤 터미널에 포커스를 돌려준다. 키보드가 내려간 상태에서 이대로 키 줄을 쓰면 방향키를 누를 때마다 키보드가 올라온다.

## 해결

사용자에게 세 가지 안을 보여 주었다. 사용자가 고른 안은 「선택지 화면에서만 표시」이다. 나머지 두 안은 「키 줄 항상 표시」와 「떠 있는 키보드 버튼만」이었다.

- **표시 조건** (`mobileKeyboardModel.ts` 의 `shouldDockMobileKeyBar`): 다음 조건을 모두 만족하면 키 줄을 화면 아래에 붙인다.
  - 터치 기기다.
  - 작업 공간 화면이고, 활성 탭이 있다.
  - 활성 탭의 프로그램이 마우스를 추적한다(Claude Code 등).
  - 시스템 키보드가 내려가 있다.
  - 키보드 위의 키 줄이 떠 있지 않다.
- 이때는 visual viewport 고정을 걸지 않는다. 키 줄은 콘텐츠 열의 맨 아래에 그려진다. 홈 화면 앱에서는 safe-area 여백 위에 놓인다.
- **마우스 추적 읽기** (`useActiveTerminalMouseTracking`): xterm 은 모드가 바뀌어도 이벤트를 내지 않는다. 그래서 활성 탭의 `getMouseTrackingActive()` 를 500 ms 마다, 그리고 탭을 바꾼 즉시 읽는다.
  - 값이 바뀔 때만 상태를 갱신한다. 같은 값으로 상태를 설정해도 React 가 한 번 더 렌더하는 것을 테스트로 확인했고, ref 로 막았다. 막지 않으면 `AppContent` 가 0.5초마다 다시 렌더될 수 있었다.
  - 이벤트 방식은 봉인 파일인 `TerminalView.tsx` 를 고쳐야 해서 쓰지 않았다.
- **붙은 키 줄의 동작**:
  - 키는 `sendKeyWithoutFocus` 로 보낸다. 터미널에 포커스를 주지 않으므로 키보드는 내려간 채로 있다.
  - 오른쪽 끝 버튼은 「⌨ 키보드」다. 누르면 `restoreFocus` 로 터미널에 포커스를 주어 시스템 키보드를 올린다. 키보드가 올라오면 지금처럼 키 줄이 키보드 바로 위로 옮겨 간다.
- 일반 셸(cmd 등, 마우스 추적 없음)에서는 지금과 같다.
- i18n: `mobileKeyboard.switch.showKeyboard`(키보드 열기)와 `mobileKeyboard.switch.keyboardLabel`(키보드)을 en·ko 에 추가했다.

## 남은 일

- 실제 휴대폰·패드 확인: Claude Code 탭에서 키보드가 내려간 상태로 다음 세 가지를 확인해야 한다.
  - 화면 아래에 키 줄이 보이는지
  - 방향키로 선택지를 옮길 때 키보드가 올라오지 않는지
  - 「키보드」 버튼을 누르면 키보드가 올라오는지
- Claude Code 는 세션 내내 마우스를 추적하므로, Claude Code 탭에서는 키 줄이 사실상 항상 보인다. 그만큼 터미널이 한 줄 남짓 줄어든다.
- 키보드를 닫으면 위쪽 키 줄이 400 ms 동안 남았다가 사라진 뒤 아래쪽 키 줄이 나타난다. 그 사이에 잠깐 키 줄이 바뀌는 것이 보일 수 있다.
