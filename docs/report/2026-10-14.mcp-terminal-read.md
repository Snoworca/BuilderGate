# 입력 없이 터미널 텍스트를 읽는 MCP 도구 (FR-MCP-009)

## 요청

MCP 로 세션에 출력된 텍스트를 입력 없이 확인하는 도구를 설계하고 구현한다. 운영 서비스가 MCP 포트를 쓰고 있으므로, 테스트할 때는 다른 MCP 포트를 쓴다.

## 문제

- MCP 로 출력을 읽는 방법은 `buildergate.terminal.exec` 에 `waitMs` 를 주는 것뿐이었다.
- 이 방법은 먼저 세션에 명령을 입력한다. 그래서 실행 중인 코딩 에이전트의 화면을 보려고 하면, 그 에이전트에게 입력이 전달됐다.

## 설계

- **도구 이름**: `buildergate.terminal.read`.
- **동작**: 서버의 헤드리스 터미널에서 마지막 N줄(화면 + 스크롤백)을 돌려준다. 터미널에는 아무것도 쓰지 않는다.
- **터미널 지정**: `exec` 와 같다. `terminalId` 를 주거나, `terminalName` 과 함께 `workspaceId` 또는 `workspaceName` 을 준다.
- **줄 수**: `lines` 로 정한다. 기본값은 40이고, 1~200 범위를 벗어나면 그 안으로 맞춘다.
- **응답**: `{ ok, terminalId, sessionId, output }`.
- **오류**:
  - 서버 쪽 터미널이 없으면 `TARGET_NOT_LIVE` 를 낸다.
  - 없는 터미널이거나 이름이 겹치는 터미널이면 `exec` 와 같은 오류 코드를 낸다.
- **권한**: `mcp:terminals.exec` 가 필요하다.
  - `exec` 에 `waitMs` 를 주면 이미 같은 화면 내용을 볼 수 있으므로, 같은 권한으로 묶었다.
  - 이 권한은 고정 액세스 키에만 있다. 따라서 세션 에이전트는 다른 세션의 화면을 읽을 수 없다. 화면에 비밀값이 찍혀 있을 수 있기 때문이다.
- **그 밖의 변경**:
  - 서버 지침에 "입력 없이 화면을 읽는 도구"라고 적었다.
  - MCP 감사 로그에 라벨을 붙였다("터미널 화면 읽기").
  - 영어·한국어 i18n 문자열을 넣었다.

## 검증

- **새 테스트 7건**: 모두 구현 전에 실패하는 것을 먼저 확인했다.
  - 서버 5건: `McpManagementTools.test.ts`
  - 서버 지침 1건: `McpModernProtocol.test.ts`
  - 프런트 감사 라벨 1건: `mcpControlDialog.test.ts`
- **회귀 확인**: 아래가 모두 통과했다.
  - 모놀리식 러너 533개
  - `TerminalResourcePolicy` 21/21
  - `test:release-pipeline`
  - 서버·프런트 타입 검사, 빌드, i18n 가드
- **실제 MCP 호출**:
  - 운영 데몬이 MCP 로 127.0.0.1:3333 을 쓰고 있다. 그래서 2222 테스트 서버의 MCP 는 3334 로 바꿔서 켰다.
  - `initialize` 응답의 지침과 `tools/list` 에 새 도구가 나왔다.
  - 테스트 전용 워크스페이스에서 `echo <마커>` 를 실행한 뒤 `read` 하면 마커 줄이 돌아왔다.
  - 1.5초 뒤 다시 읽어도 결과가 같았다. 읽기가 입력을 보내지 않는다는 뜻이다.
  - `lines=1` 은 프롬프트 한 줄만 돌려주었다.
  - 없는 id 는 `TARGET_NOT_FOUND` 를 냈다.
- **정리**:
  - 테스트 워크스페이스는 정확한 id 로 지웠다.
  - 첫 시도에서 응답 필드 이름(`workspaceId`)을 잘못 읽어, 워크스페이스 하나가 지워지지 않고 남았다. 이것도 다음 실행에서 정확한 id 로 지웠다.
  - 테스트 서버를 종료하고, MCP 설정 파일(꺼짐, 3333, 원래 키 해시)을 백업본으로 되돌렸다.
