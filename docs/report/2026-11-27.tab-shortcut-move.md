# Alt+Shift+T 새 탭 단축키와 탭 Workspace 이동 확대 (FR-ARCH-018, FR-ARCH-019, #259)

## 이슈

새 탭을 여는 키보드 단축키를 추가하고, 탭을 다른 Workspace 로 옮기는 방법을 늘려 달라는 요청. 사이드바로 끌어 놓아 옮기기, 멈춘 탭도 옮기기, 새 Workspace 로 옮기기를 포함한다. 새 탭이 지금 탭과 같은 셸과 작업 폴더로 열리는지도 물음. 자세한 내용은 이슈 #259 에 정리했다.

## 요구사항

- FR-ARCH-018 (Alt+Shift+T 로 탭 바 「+」 버튼과 같은 새 탭 열기, AC-1~4). Status implemented, Target `tab-shortcut-move`.
- FR-ARCH-019 (끌어 놓기로 Workspace 사이 이동, 탭 상태와 무관한 이동, 새 Workspace 로 이동, AC-1~3). Status implemented, Target `tab-shortcut-move`.

## 문제 원인

- 새 탭은 탭 바의 「+」 버튼으로만 열 수 있었다. 「+」는 이미 지금 탭의 셸과 작업 폴더를 쓰므로, 단축키도 같은 경로를 타면 같은 결과가 된다.
- 탭 이동은 터미널 우클릭 메뉴의 「Workspace 이동」 하나뿐이었다. 멈춘 탭, 연결이 끊긴 탭, 복구할 수 없는 탭은 프런트가 메뉴를 끄고, 서버 `WorkspaceService.moveTab` 이 `SESSION_NOT_MOVABLE` 로 거부했다.
- 멈춘 탭은 터미널 대신 종료 화면이 떠서 터미널 우클릭 메뉴 자체를 열 수 없었다.

## 해결 방법

- 기본 전역 단축키 Alt+Shift+T 를 추가하고, `new-tab` 동작을 단축키 체계에 더했다. 프런트와 서버가 모두 이 동작을 검증한다.
- 터미널 안에서 누르면 `TerminalView` 가, 터미널 밖에서 누르면 `App` 의 창 keydown 처리기가 `requestNewTab()` 신호를 보낸다. `App` 은 이 신호를 「+」와 같은 `handleTabBarAddTab` 경로로 처리한다. 그래서 탭 한도에 닿았으면 새 탭을 만들지 않는다.
- 탭 이동은 `useDragReorder` 에 외부 드롭 대상을 더해, 탭을 사이드바의 Workspace 로 끌어 놓을 수 있게 했다. 드롭 대상은 `tabDragStore` 로 강조한다.
- 이동 제한을 프런트와 서버에서 모두 풀었다. 멈춘 탭, 연결이 끊긴 탭, 복구할 수 없는 탭도 옮길 수 있다.
- 이동 대화상자에 「새 Workspace로 옮기기」를 더했다. 누르면 Workspace 를 새로 만들고 탭을 그곳으로 옮긴다.
- 요청 범위에는 없었지만 탭 바 우클릭 메뉴에도 「Workspace 이동」을 더했다. 멈춘 탭은 터미널 우클릭 메뉴를 열 수 없으므로, 이 메뉴가 없으면 멈춘 탭을 실제로 옮길 방법이 없기 때문이다.
- `TerminalView.tsx` 를 고쳤으므로, 그 파일을 근거로 하는 소비자 매니페스트를 다시 봉인했다.

- 2222 서버에서 ego 브라우저로 실제 화면을 확인했다.
