# 형제 worktree 파일 읽기 전용 열기 실제 환경 확인 (SEC-FOP-002)

## 개요

이 보고서는 SEC-FOP-002를 실제 브라우저와 실제 MCP 호출로 확인한 결과를 기록한다. SEC-FOP-002는 세션 폴더와 같은 git 저장소에 속한 형제 worktree의 파일을 읽기 전용으로 여는 요구사항이다. 확인일은 2026-10-28이다.

대상 커밋은 `4f563e62`다. 확인 시점의 HEAD는 `47f50165`다.

앞선 보고서 `docs/report/2026-10-26.worktree-read-only-open.md`는 실제 브라우저와 MCP 호출을 확인하지 않았다고 적었다. 이 보고서는 그 한계 일부를 채운다.

이번에 직접 확인한 AC는 AC-2, AC-3, AC-6, AC-7, AC-10이다. AC-1, AC-4, AC-5, AC-8, AC-9는 이번 확인에 넣지 않았다. 이 항목은 자동 테스트 VE-1~VE-5로 확인했다.

서버 기동 시각은 `server/dist` 빌드 시각보다 뒤다. 따라서 서버는 그 빌드 산출물로 기동되었다. `buildId 0f7027057a12`가 커밋 `4f563e62`의 빌드와 같은지는 이 보고서 작성 시점에 대조하지 않았다.

브라우저와 도구는 다음과 같이 썼다.

- 기본 브라우저 도구는 ego lite다. ego에는 이미 로그인되어 있었다.
- 자체 서명 인증서 경고 화면에서 "고급"을 누르고 localhost로 진행했다.
- Claude in Chrome은 쓰지 못했다. 확장이 "이 세션의 탭 그룹이 아니다" 오류를 반복해서 냈다. 사용자가 확장을 다시 연 뒤에도 같은 오류가 났다.

MCP 호출은 다음 순서로 했다.

- 브라우저 로그인 상태에서 `POST /api/mcp-control/sessions/:sessionKey/claim-code`를 불러 클레임 코드를 받았다.
- `http://127.0.0.1:3333/mcp`에 `initialize`를 보냈다.
- `buildergate.session.claim`으로 세션 토큰을 받았다.
- 고정 접근 키는 회전하지 않았다.
- 클레임 코드와 세션 토큰 값은 출력하거나 기록하지 않았다.

픽스처는 다음과 같이 만들었다.

- 세션 임시 폴더 안의 git 저장소다.
- 주 worktree `d`(브랜치 main)와 형제 worktree `d-1`(브랜치 wt1)로 구성했다.
- `d-1`에는 다음 파일이 있다.
  - `docs/design.html`: `style.css`를 링크한다.
  - `docs/style.css`: `h1{color:teal}`
  - `notes.md`: `# notes in d-1`
- 테스트 워크스페이스 `wt-verify`(id `6d74dc2d-542f-425c-a90d-d95cdaf4b2ad`)를 REST로 만들었다.
- PowerShell 탭 `wt-d`를 REST로 만들었다. 탭의 cwd는 `d`다.

절차 메모는 다음과 같다.

- ego의 클릭 API에는 수정자 키 옵션이 없었다. 그래서 CDP `Input.dispatchMouseEvent`에 `modifiers: 2`를 넣어 Ctrl+클릭을 보냈다. 실제 키보드 입력이 아니라 합성 이벤트다.
- 스크린샷은 `.playwright-mcp/wt-verify-0[1-7]-*.png`에 저장했다. 이 폴더는 `.gitignore` 대상이므로 커밋하지 않는다.

여섯 절차 모두 기대한 결과와 일치했다.

## 정리(cleanup)

- 편집기 창을 모두 닫았다.
- 테스트 워크스페이스 `wt-verify`는 생성 응답의 정확한 ID `6d74dc2d-542f-425c-a90d-d95cdaf4b2ad`로만 삭제했다. 응답은 DELETE 200이었다.
- 다른 워크스페이스는 삭제하지 않았다. 남은 워크스페이스는 사용자의 Workspace-1, Workspace-2, Workspace-3이다.
- PowerShell 탭 `wt-d`는 워크스페이스와 함께 삭제되었다. 삭제 뒤 워크스페이스 목록에 `wt-verify`가 없음을 확인했다.
- 픽스처 저장소(`d`, `d-1`)는 세션 임시 폴더에 그대로 남겨 두었다. MCP가 쓰려던 `d-1/docs/mcp-written.html`은 생기지 않았다.
- 운영 데몬 2001과 2002는 건드리지 않았다.

## 남은 한계

- AC-1, AC-4, AC-5, AC-8, AC-9는 브라우저 확인에 넣지 않았다. 자동 테스트 VE-1~VE-5로만 확인했다.
- "화면의 파일" 메뉴와 이미지 뷰어는 브라우저로 확인하지 않았다.
- Claude in Chrome은 쓰지 못했다. 탭 그룹 오류가 해결되지 않았다. 그래서 ego 브라우저로 확인했다.
- Ctrl+클릭은 CDP 합성 이벤트다. 실제 키보드 수정자 입력으로 확인한 것이 아니다.
- VE-6은 수동 증거다. 반복 실행하는 자동화는 없다. 회귀는 VE-1~VE-5의 자동 테스트가 막는다.
- 서버 `buildId 0f7027057a12`와 커밋 `4f563e62`의 대응은 확인하지 않았다.
- `docs/worklog/2026-10-28.jsonl`은 다른 레인이 같은 날 만든 미추적 파일이다. 이 작업의 로그 한 줄도 그 파일에 추가했다.
