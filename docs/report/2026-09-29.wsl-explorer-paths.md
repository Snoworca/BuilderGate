# WSL 터미널에서 연 파일 탐색기가 비어 있음

- 날짜: 2026-09-29
- 요구사항: FR-FEX-019 (Windows 호스트에서 WSL 마운트 경로는 해당 Windows 경로를 가리킨다), 타깃 `wsl-explorer-paths`
- 커밋: (미커밋)

## 이슈

사용자 보고: 서버를 Windows(PowerShell)에서 실행한 상태에서 WSL 기반 터미널에서 파일 탐색기를 띄우면 아무것도 나오지 않는다.

## 원인

- WSL 탭의 셸 훅은 현재 디렉터리를 Linux 경로로 기록한다(예: `/mnt/c/work`). 탭의 cwd와 헤더에 그 값이 그대로 표시된다.
- 탐색기는 이 경로를 루트로 삼아 `GET /api/sessions/:id/files?path=/mnt/c/work`를 요청한다.
- 서버의 세션 루트는 `C:\work`로 변환되어 있다. 반면 요청 경로는 변환 없이 `path.resolve('C:\work', '/mnt/c/work')`로 풀려 `C:\mnt\c\work`가 된다.
- 이 경로는 세션 루트 밖이므로 `403 PATH_TRAVERSAL`로 거절되고, 탐색기는 빈 목록을 보인다.
- `~`(`/home/<user>`) 같은 배포판 내부 경로는 우연히 동작했다. 세션 루트가 `\\wsl.localhost\<distro>\...` UNC 경로여서 그 루트가 곧 배포판 루트였기 때문이다.

실측(https://localhost:2222, WSL 탭, `cd /mnt/c/work`): 수정 전 `403 PATH_TRAVERSAL`, 탐색기 빈 화면.

## 해결

- `server/src/utils/pathValidator.ts`
  - `toHostPath(p, platform)`를 추가했다. win32에서 `/mnt/<drive>/...`를 `<DRIVE>:\...`로 바꾸고, 그 밖의 경로와 다른 OS에서는 그대로 둔다.
  - `validatePath`가 대상 경로를 풀기 전에 이 변환을 거친다. 목록·읽기·stat·검색·쓰기·파일 작업이 모두 같은 검증을 거치므로 한 곳에서 해결된다.
  - 세션 루트 밖이면 여전히 거절한다.
- `server/src/services/FileService.ts`: cwd 파일의 `/mnt` 변환이 같은 함수를 쓰도록 바꿨다. 두 변환 규칙이 서로 어긋나지 않는다.

## 검증

- **단위 테스트**: `server/src/utils/wslHostPath.test.ts` 3/3 통과(Windows tsx). 먼저 실패를 확인한 뒤 구현했다. 디스크 테스트는 임시 세션 루트와 하위 디렉터리의 `/mnt` 형태가 루트 안으로 풀리는지, 형제 디렉터리는 `PATH_TRAVERSAL`로 거절되는지 본다.
- **관련 스위트**: 파일 관련 node:test 22개 파일 236/236, 모놀리식 러너 533/533.
- **실측**: 2222를 재빌드한 exe로 다시 띄워 확인했다. 소유 Workspace를 만들어 정확한 id로 삭제했다.
  - WSL 탭에서 `cd /mnt/c/work/git/_Snoworca` 후 터미널 메뉴로 탐색기를 열었다.
  - `200`과 경로 `C:\work\git\_Snoworca`가 돌아왔고, 목록이 표시됐다(`.playwright-mcp/wsl-explorer.png`).

## 한계

- 대문자 드라이브(`/mnt/C/...`)도 같은 드라이브로 본다. WSL 기본 마운트는 소문자다.
- `/mnt/wsl`처럼 한 글자가 아닌 `/mnt` 하위는 변환하지 않는다.
- `wsl.conf`에서 `automount root`를 바꾼 환경(예: `/c/...`)은 다루지 않는다.
