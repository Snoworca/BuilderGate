# 사용량 감시가 멈춘 WSL을 깨워 포커스를 빼앗는 문제 수정

## 개요

이 보고서는 사용량 감시가 멈춘 WSL을 반복해서 깨우던 문제를 고친 결과를 기록한다.

- 요구사항: FR-USAGE-008(신설), `docs/spec/49.usage-limits.srs.md`
- 이슈: #229
- 브랜치: `fix/usage-wsl-wake`(main `8d5b390d` 기준)
- 작업일: 2026-11-02

## 증상

- Windows에서 BuilderGate를 띄워 두면, 다른 프로그램에서 타이핑하는 중에 포커스를 자주 잃었다. 1분에 두 번쯤 보이지 않는 창이 앞으로 나와 포커스를 가져갔다.
- WSL 창이나 WSL 탭을 하나도 열지 않았을 때만 생겼다. WSL에서 Claude나 Codex를 쓰지 않아도 생겼다.
- 0.10.32에서 사용량 감시(FR-USAGE)가 들어온 뒤부터 생긴 문제다.

## 원인

### 측정

- 포커스를 가져간 창은 WSLg(`msrdc.exe /wslg`)였다. WSL 배포판(Ubuntu)이 매분 :23초와 :50초에 시작되고, 약 15초 뒤 다시 멈췄다. 시작할 때마다 `msrdc.exe`가 새로 떴다.
- 그 시점에 `wsl.exe`는 실행되지 않았다. 따라서 배포판은 `\\wsl.localhost` 경로의 파일 읽기 때문에 시작된 것이다.
- Process Monitor로 `Path contains wsl.localhost` 이벤트를 기록했다. 그 경로를 읽은 프로세스는 2222 서버(node.exe) 하나뿐이었다.

| 시각 | 읽은 경로 | 결과 | 원인 코드 |
| --- | --- | --- | --- |
| 매분 :50초 | WSL 홈의 `.codex\sessions`, `.claude\buildergate-usage.json`, `.claude.json` | NOT FOUND | 서버의 사용량 갱신 타이머(`readReadings`, 60초) |
| 매분 :23초 | WSL 홈의 `.claude` | NOT FOUND | 브라우저 사용량 패널의 60초 요청(`GET /api/usage-limits`)에 답하면서 하는 수집 상태 확인(`claudeCollectionStatus`) |

### 구조

- 사용량 감시는 Windows에서 Windows 쪽 홈과 WSL 쪽 홈을 둘 다 읽는다. WSL 쪽은 `\\wsl.localhost\<배포판>\home\<사용자>` 경로로 읽는다.
- WSL은 안에서 도는 프로그램이 없으면 약 15초 뒤 멈춘다. 멈춘 상태에서 그 경로를 읽으면 배포판이 다시 시작된다.
- 배포판이 시작될 때마다 WSLg가 함께 실행되고, 이때 보이지 않는 창이 포커스를 가져간다.
- 패널을 숨겨도 서버 타이머와 브라우저 요청은 계속되므로 문제가 그대로 남았다.
- WSL 탭을 하나 열어 두면 배포판이 멈추지 않아서 문제가 생기지 않았다(2분 관찰, 재시작 0회).

## 해결 방법

`server/src/services/usage/usageSources.ts`를 고쳤다.

- `createUsageLocations`: Windows에서는 먼저 `wsl.exe -l --running -q`로 실행 중인 배포판 목록을 읽는다. 이 명령은 배포판을 시작하지 않는다.
  - 실행 중인 배포판이 없으면 WSL 홈을 찾지도 읽지도 않는다. WSL 홈을 찾는 `wsl.exe -e` 호출도 하지 않는다.
  - WSL 홈이 있는 배포판이 실행 중일 때만 WSL 쪽 경로를 읽는다. 다른 배포판만 실행 중이면 읽지 않는다.
  - 서버 갱신과 수집 상태 확인이 같은 함수를 쓰므로 두 경로가 모두 고쳐졌다.
- `parseRunningDistros`: `wsl.exe` 출력은 UTF-16이 기본이고 `WSL_UTF8`이 있으면 UTF-8이다. 둘 다 읽는다.
- `holdWslReadings`: WSL을 읽지 않은 갱신에서는 마지막으로 읽은 WSL 계정 값을 그대로 돌려준다. 오래되면 FR-USAGE-004의 기준대로 오래된 값으로 표시된다.

## 검증

- `usageSources.test.ts`: 구현 전에는 새 테스트 6건이 모두 실패했고, 구현 후 9/9가 통과했다.
- 변이 확인: 실행 여부 검사를 빼면 AC-1 테스트 2건이 실패한다.
- 사용량·에이전트 세션·사용량 라우트 테스트 100/100, 서버 타입 검사 오류 0.
- 2222 실기기: 수정한 서버를 재시작한 뒤(PID 25896) WSL 탭이 없는 상태로 16:01:26~16:03:58에 관찰했다. Ubuntu는 계속 멈춰 있었고 `msrdc.exe`는 한 번도 새로 뜨지 않았다. 수정 전에는 같은 조건에서 1분에 두 번 시작됐다. 사용자도 포커스가 빠져나가지 않는 것을 확인했다.

## 남은 점

- 기본 배포판이 아닌 다른 배포판만 실행 중이면, 서버를 띄운 뒤 처음 한 번 WSL 홈을 찾는 `wsl.exe -e` 호출이 기본 배포판을 시작할 수 있다. 결과는 서버 실행 동안 저장되므로 반복되지 않는다.
- 배포판이 멈춰 있는 동안에는 설정 화면의 Claude 수집 상태 목록에 WSL 폴더가 보이지 않는다.
