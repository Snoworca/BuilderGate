# 메신저: 세 번째 참여자가 재시작 전까지 연결되지 않던 문제 (#267, #266)

## 이슈

현장 제보(2026-11-27): 두 사람이 잘 쓰던 방에 한 사람이 더 들어왔는데, 그 사람만 계속 접속 불량이었다. 그 사람이 BuilderGate 를 완전히 종료했다가 다시 켜자 정상이 되었다. 방화벽, 네트워크, VPN 문제는 아니었다.

요구사항: FR-MSG-014 AC-6, FR-MSG-008 AC-8(둘 다 신규).

## 원인

재시작으로 풀렸으므로 원인은 프로세스 메모리 상태다. 조사 서브에이전트가 네 가지를 단위 테스트로 재현했다.

| | 내용 | 재시작으로 풀림 |
|---|---|---|
| H3 | 사내망 리스너가 기동 때 열리지 못해도 '받는 중'으로 남고, 연결 코드와 입장권에 주소를 계속 실었다. 다시 열기 시도도 없었다. | 예 |
| H1 | 같은 서버로 가는 링크가 둘이면 상대가 둘을 번갈아 끊었다(60초에 62번 붙고 61번 끊김). | 같은 PC 에 프로세스가 둘이었다면 예 |
| H2 | 서로에게 링크를 가진 두 서버가 서로를 `PEER_NAME_IN_USE` 로 거절했다. | 아니오 |
| H4 | 방 링크를 연락처로 바꿔도 kind 가 room 으로 남아 연락처로 보이지 않았다. | 아니오 |

## 해결

- **H3 (FR-MSG-014 AC-6):**
  - 리스너가 실제로 열려 있을 때만 '받는 중'으로 보인다. 열지 못하면 원인을 보이고, 주소를 내주지 않는다.
  - 5초에서 시작해 대기를 두 배씩 늘리며(최대 60초) 다시 열기를 시도한다. 열리면 열려 있는 연락처 창에 알린다.
  - 멈춘 뒤에는 예약된 재시도가 리스너를 열지 않는다. 재시도 중에 허용 목록만 바꾸면 저장만 한다.
- **H1·H4 (FR-MSG-008 AC-8):**
  - 연결 코드나 주소로 추가할 때, 같은 서버의 방 링크가 있으면 그 링크를 연락처 링크(kind contact)로 바꾼다.
  - 다른 서버의 방 링크와 이름이 같으면 NAME_TAKEN 을 유지한다.
  - 링크는 같은 서버의 메신저 링크끼리만 합친다. MCP 설정에서 직접 등록한 링크는 건드리지 않는다.
  - 상대가 정한 이름이 기존 연락처 이름을 차지하지 못한다.
- **H2:** 해결하지 못하고 #277 로 넘겼다(아래 참조).

## 되돌린 시도

H2 를 풀려고 '들어온 연결이 내 나가는 링크를 대신한다'를 세 번 구현했다. 독립 리뷰가 매번 링크 가로채기를 재현했다.

1. 이름만 대고 접속하면 연결을 가로챘다.
2. 열린 초대 코드로 이름을 먼저 묶어 둔 뒤 가로챘다.
3. 발급 키 해시로 신원을 증명하게 했지만, 증명의 비밀이 링크 키 자체였다. 그 키는 여러 곳이 함께 쓰는 MCP 고정 키이거나, 사람이 복사해 붙여넣어 남이 볼 수 있는 코드였다.

그래서 피어 링크 관리자는 HEAD 그대로 두었다. HEAD 의 거절 동작을 지키는 테스트 2건만 추가했다. 다음 설계 방향은 #277 에 적었다. 핵심은 들어오는 연결을 믿지 않고, 한 쌍의 서버 사이에 링크가 둘 생기지 않게 막는 것이다.

## 검증

- 모든 동작 변경은 실패하는 테스트를 먼저 썼다.
- 서버 피어·메신저·라우트 테스트 257/257, 모놀리식 러너 533/533, `TerminalResourcePolicy.test.ts` 21/21.
- 프런트 메신저·i18n 테스트 97/97, 서버 `tsc`, 프런트 `tsc -b` 통과.
- 리뷰어들의 공격 재현 프로브를 다시 돌렸다. 가로채기가 한 건도 없었고, 결과는 HEAD 와 같았다.
- 소비자 매니페스트는 `server/src/index.ts` 해시만 다시 봉인했다. 정확한 소비자 튜플과 분류는 바뀌지 않았다.

## 남은 점

- **#277:** 서로 링크를 가진 두 서버의 교착(H2, 서로 연결 코드를 주고받은 경우).
- **현장 원인 판별:** 이번 제보의 원인이 H3 인지, 같은 PC 에 프로세스가 둘이었는지는 현장 로그로 아직 확인하지 않았다. 판별 방법은 #267 댓글에 있다.
- **이름 대소문자:** 대소문자만 다른 이름으로 두 번째 연결을 여는 동작은 HEAD 에 원래 있던 것이다. 그대로 두었다.
