# MCP 워크스페이스·터미널 관리 도구 + MCP 2026-07-28 프로토콜

## 요청

1. 워크스페이스 생성/삭제/이름 변경/목록
2. 세션 터미널 생성/삭제/명령어 실행/목록 — 워크스페이스는 id 또는 이름으로 지정
3. (추가 요청) 최근 출시된 MCP 프로토콜 적용

권한 범위는 사용자 결정(2026-09-28): **쓰기·실행 도구는 고정 접근 키에만**, 세션 토큰은 목록 조회만.

## MCP 2026-07-28

- `params._meta["io.modelcontextprotocol/protocolVersion"]` 가 있는 요청은 무상태로 처리: 요청마다 Bearer 인증, `Mcp-Session-Id` 미발급.
- `MCP-Protocol-Version`·`Mcp-Method`·`Mcp-Name`(Base64 sentinel 해석) 불일치 → 400 / `-32020`, 미지원 버전 → 400 / `-32022` + `{supported, requested}`, 모르는 메서드 → 404 / `-32601`.
- `server/discover` 구현, 모든 결과에 `resultType: "complete"` 와 `_meta` serverInfo, `tools/list` 는 이름순 + `ttlMs`/`cacheScope: "private"`.
- `initialize` 는 기존 세션 방식 유지. 모르는 버전은 `2025-11-25` 로 답한다(이전에는 받은 값을 그대로 되돌렸다).
- `tools/call` 결과에 `content`(JSON 텍스트)·`structuredContent`·`isError` 를 추가(양쪽 모두). 이전에는 이 필드가 없어 표준 클라이언트에는 빈 결과로 보였을 수 있다. 기존 최상위 필드는 그대로 둔다.

## 실측에서 잡은 결함

`terminal.exec` 가 명령을 입력만 하고 실행하지 않았다. 입력 게이트웨이의 `submit` 은 "Enter 포함 허용" 권한 검사일 뿐 Enter 를 붙이지 않는다. 명령 뒤에 `\r` 을 붙이도록 고치고 `McpWorkspaceControl.test.ts` 로 고정했다(붙이지 않도록 되돌리면 2건 실패).
