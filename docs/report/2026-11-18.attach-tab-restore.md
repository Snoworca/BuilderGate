# 재시작 자동 복구가 claude attach 탭을 되살리지 못하던 문제 (#242)

## 이슈

2026-11-18 08:43 에 2002 서버가 다시 뜬 뒤, 백그라운드 세션에 `claude attach <id>` 로 붙은 탭들의 자동 복구 결과가 셋으로 갈렸다. 두 탭은 failed(멈춘 채 입력하면 `TARGET_NOT_FOUND`), 두 탭은 빈 셸, 세 탭은 정상이었다. 같은 종류의 탭인데 결과가 다른 원인을 찾아 고쳐 달라는 요청이었다.

## 원인

1. **종료 직전 멈춤 기록**: 08:41:02 에는 세션 22개가 모두 정상이었고, 08:41:12 에 서버가 끝났다. 그 사이 두 탭의 셸 종료가 `process-exit` 로 처리되어 탭이 `stopped` · `recoverable: false` 로 저장됐다. 다음 기동의 고아 복구는 멈춘 탭을 건너뛰므로 세션이 없었고, 자동 복구는 `input-not-scheduled` 로 실패했다. 어느 탭이 걸리는지는 종료 순서에 따른 우연이다.
2. **attach 탭의 세션 id 추정**: attach 클라이언트는 `~/.claude/sessions/<pid>.json` 을 남기지 않는다. 그래서 저장이 같은 폴더의 다른 Claude 세션 id 를 골랐고, 이어하기 명령은 `claude attach X --resume <다른 id>` 가 됐다. attach 는 `--resume` 을 쓰지 않아 대상이 살아 있던 탭만 우연히 붙었다. 후보가 없으면 셸로 저장됐다.
3. **끝난 attach 대상**: 백그라운드 세션이 끝나 있으면 `claude attach` 는 `No session matching` 으로 끝나 빈 셸이 된다.

## 해결

- `WorkspaceService.isRecoverableOrphanTab`: `process-exit` 로 멈춘 탭이라도 시작할 때 저장본에 처리 대기 항목이 있으면 고아 복구에서 셸을 다시 연다. 탭 삭제 · 세션 직접 삭제로 멈춘 탭은 그대로 둔다. (FR-AITUI-014 AC-8)
- `SessionSnapshotService.resolveAll`: 실행 명령이 `claude attach <id>` 인 탭은 폴더 추정을 하지 않는다. id 로 시작하는 백그라운드 세션(`findClaudeAttachSession`)을 `exact`, method `claude-attach` 로 저장하고, 다른 탭의 추정 후보에서도 그 id 를 뺀다. `buildResumeCommand` 는 attach 를 `claude attach <id>` 그대로 둔다. (FR-AITUI-016 AC-9)
- 자동 복구와 손으로 하는 복구: attach 항목은 `claude attach <id>` 로 입력한다(옛 저장본의 `--resume <추정 id>` 는 버린다). 백그라운드 세션이 더는 돌지 않으면 `claude --resume <전체 id>` 를 입력한다. 전체 id 는 저장된 id 가 대상으로 시작할 때 그것을, 아니면 `projects/*/<id>*.jsonl` 대화 기록에서 찾는다. (FR-AITUI-014 AC-9)

## 남은 것

- attach 대상을 id 가 아닌 이름으로 준 경우(`claude attach "og-flow 2136"`)는 pid 파일에 이름이 없어 전체 id 를 찾지 못한다. 이때는 그 이름 그대로 attach 를 입력하고, 대상이 끝났으면 되살리지 못한다.
- 복구 명령의 기본 인자 설정은 #243 에서 다룬다.

## PR #244 리뷰에서 고친 것 (2026-11-18)

- **사용자가 끝낸 탭이 매번 되살아나는 문제**: 자동 저장은 멈춘 탭도 담으므로 「저장본에 있다」만으로는 저장 때 살아 있었는지 알 수 없다. 이제 복구하는 저장본의 저장 시각 **뒤에** 멈춘 탭만 되살린다(`SessionSnapshotService.stoppedAfterRestoreSave`, `WorkspaceService.setStoppedTabRecoveryChecker`).
- **다른 폴더에서 `--resume`**: `claude --resume` 은 그 세션의 폴더에서만 대화를 찾는다. attach 탭은 백그라운드 세션의 폴더를 cwd 로 저장해, 다시 열 때 그 폴더에서 열린다.
- **손으로 고른 세션 무시**: 저장 대화상자에서 attach 대상과 다른 세션을 고르면 `--resume <그 id>` 로 만든다.
- **짧은 16진수 이름**: attach 대상은 8자 이상 16진수일 때만 id 접두로 본다.
- 남은 한계: 마지막 자동 저장 뒤, 서버가 내려가기 전에 사용자가 직접 끝낸 탭은 구별하지 못해 되살아난다. 리뷰가 지적한 「끝난 세션을 resume 할 때 원래 실행 인자가 빠진다」는 #243 에서 다룬다.
