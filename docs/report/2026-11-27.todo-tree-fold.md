# 할 일 대분류와 항목 접기 (FR-TODO-008)

## 이슈 설명

할 일 목록이 큰 대분류 하나 아래 하위 목록으로만 보인다. 다른 프로젝트도 함께 진행하므로 대분류를 여러 개 두고 싶은데, 모든 대분류가 항상 펼쳐져 있으면 목록이 길어진다. 그래서 대분류와 항목을 접고 펼쳐 그 아래 목록을 숨길 수 있어야 한다는 요청이다.

- 대분류를 프로젝트 단위로 여러 개 둔다.
- 접으면 그 아래 모든 행이 숨고, 펼치면 다시 보인다.
- 접힌 행은 숨은 항목 수를 보여 준다.

## 문제 원인

- 자료구조는 이미 대분류 여러 개를 지원했다. 대분류 > 항목 > 세부의 3단 구조이고, 「대분류 추가」 라벨의 키(`todo.addCategory`)도 커밋 이전 카탈로그에 있었다(`messages.ko.json` 2018행, e0f339e3 이전). 서버에 저장된 대분류가 1개뿐이어서 한 덩어리로 보였다.
- 없었던 것은 접기다. 커밋 이전의 `todoModel.ts`, `todoPanelStore.ts`, `TodoPanel.tsx` 에는 `collapsed` 가 한 건도 없었다.
- 4단(프로젝트 단계) 구조를 추가하는 안도 검토했으나, 서버 저장 구조와 MCP 도구까지 바뀌므로 채택하지 않았다. 대분류를 프로젝트 단위로 쓰고 접기만 더하기로 정했다. 같은 결정이 요구사항 Rationale 에 적혀 있다(`docs/spec/52.todo-panel.srs.md` 494행).

## 해결 방법

행 번호는 커밋 e0f339e3 기준이다.

- 하위 항목이 있는 대분류와 항목 행의 상태 표시 왼쪽에 접기 버튼을 둔다. 버튼은 `aria-expanded` 를 갖고, 제목과 툴팁은 `todo.fold` / `todo.unfold` 키로 i18n 을 거친다(`TodoPanel.tsx` 428~431행).
- 접으면 그 아래 모든 행(상세 설명 포함)을 숨긴다. 접힌 행의 제목 옆에 숨은 항목 수 `+N` 을 보이며, 툴팁은 `todo.hiddenCount` 복수형으로 만든다(`TodoPanel.tsx` 474행).
- `todoRows` 는 접힌 항목 아래로 내려가지 않는다. 자식 순회는 `open` 판정(`todoModel.ts` 152행)을 통과한 경우에만 이어진다(157행, 163행).
- 접힘 상태는 `buildergate.todoPanel` 저장값의 `collapsed` 필드에 항목 id 별로 저장한다. 저장소는 `window.localStorage` 다(`todoPanelStore.ts` 10행, 151~156행, 164행).
- 하위가 없는 행은 같은 폭을 비워 정렬을 맞춘다. 새 항목 입력칸도 같은 열에서 시작한다.
- 하위 추가, 안쪽 드롭, 하위 항목 제출 시 부모를 펼친다(`TodoPanel.tsx` 149행, 218행, 291행).
- 점선 트리는 보이는 행만 잇고, 대분류의 진행 원은 접혀 숨은 항목까지 세어 그린다(요구사항 AC-5).
- 요구사항 FR-TODO-008 을 `docs/spec/52.todo-panel.srs.md` 473행에 신규 추가했다. Status 는 implemented, 검증 방법은 test 다.
