## 1. 이슈 설명

전체 서버 검증을 안전하게 수행하기 위해, 등록된 각 테스트가 **어떤 명령·cwd·env·filter 로 실행되어 어떤 테스트를 수집하고, 어떤 포트와 자식 프로세스와 임시 파일을 소유하며, 그 종료 책임이 누구에게 있는지**를 표로 확정한다. 아울러 schema default 가 아닌 **실제 resolved config/capability 스냅샷**을 기록하고 MCP disabled envelope 의 load/merge 를 재검증한다.

이 작업은 **결정 task** 다. 이슈 본문이 명시하듯 "구현 성공을 주장하지 않고 reviewed 결정표와 실행 가능한 다음 RED 계약으로 완료한다."

## 4. 발견한 신규 결함 (별도 이슈 대상)

### 4.1 고정 포트 2222 경로의 프로세스 내 재사용 실패

`invokeLoopbackLoginOverTcp`(`test-runner.ts:21809`)를 쓰는 auth 테스트 3개는 **단독 실행에서는 통과**하지만, 한 프로세스에서 **두 번째 이후로 실행되면 `ECONNRESET` 으로 실패**한다. 실패는 특정 테스트가 아니라 **순서에 고정**된다.

구조적 소인은 고정 리터럴 포트 `2222`(`:21811`)와 `res.on('end')` 안에서 `server.close()` 직후 `resolve()` 하는 패턴(`:21826-21830`)이다. 다만 세 로그 어디에도 `EADDRINUSE` 가 없으므로 **원인은 확정하지 않았다**(RED-1).

### 4.2 owned-endpoint guard 의 이름 접두 false positive

`require-owned-http-test-pipe.cjs:7` 의 허용 패턴은 `^buildergate-http-<pid>-<uuid>$` 다. `WsRouterRestoreMetadata.test.ts:35` 는 `buildergate-**ws**-<pid>-<uuid>` 라는 **정당한 owned unix socket** 을 만드는데 접두가 달라 거부된다. 오류 메시지는 `B0_FORBIDDEN_TCP_LISTEN` 이지만 **TCP 는 전혀 관여하지 않는다**(RED-2).

## 7. 검증

- 원시 증거 16개 SHA256 전수 일치(`sha256sum -c SHA256SUMS.txt`).
- **독립 리뷰 10회**를 거쳐 제기된 **61건**을 전량 정정했다(결정표 §10). 라운드별 지적 수는 16 → 14 → 10 → 7 → 7 → 2 → 1 → 1 → 1 → 2 로 수렴했고, 최종 라운드의 지적은 정정 이력 산술 표기 1건이었다.
- 정정에는 계수 오류, 인용 오류 다수, **"어떤 실행도 2222 listener 를 띄우지 않았다" 는 거짓 주장**, 실패 분류를 오류 문자열이 아닌 이름 접두로 묶은 과장, stale 증거 아티팩트, 로그가 뒷받침하지 않는 근본 원인 단정, 자식 프로세스 stdout 을 잘못된 테스트에 귀속시킨 추출 결함이 포함된다.
