# Claude 터미널에서 마우스 휠 스크롤이 안 되다가 창 크기를 바꾸면 되는 문제

- 날짜: 2026-09-29
- 요구사항: REL-BGSTAB-039 (복원된 터미널은 마우스 보고 형식을 유지하고, 모든 마우스 보고는 PTY에 닿는다), 타깃 `mouse-report-restore`
- 커밋: (미커밋)

## 이슈

사용자 보고:
- Claude 터미널에서 마우스 휠을 올려도 스크롤되지 않을 때가 있다.
- 그리드 모드에서 창 경계를 잡고 조금 움직이면 그때부터 스크롤된다.

## 원인

- Claude Code 2.1은 대체 화면(alternate screen)에서 마우스 추적과 SGR 보고 형식(`?1006h`)을 켜고 동작한다.
  - 휠을 굴리면 xterm이 직접 스크롤하지 않는다. 휠을 `ESC[<64;x;yM` 보고로 Claude에 보내고, Claude가 자기 대화 화면을 스크롤한다.
- 새로고침·로그인·탭 런타임 재생성·복구 때 BuilderGate는 서버의 헤드리스 화면을 `@xterm/addon-serialize`로 직렬화해 새 xterm에 쓴다.
  - 이 addon은 마우스 추적 모드(`?1000/1002/1003h`)는 복원하지만 보고 형식(`?1006h`)은 복원하지 않는다.
  - 그래서 복원된 터미널은 기본 형식으로 돌아간다.
- xterm은 기본 형식의 마우스 보고를 `onData`가 아니라 `onBinary`로 내보낸다. BuilderGate는 `onBinary`를 구독하지 않았다.
  - 따라서 휠 보고가 조용히 버려졌다.
- 창 크기를 바꾸면 Claude가 화면을 다시 그리면서 `?1006h`를 다시 보낸다. 그래서 그때부터 스크롤되었다.

실측(https://localhost:2222, 실제 Claude Code 2.1.283, 휠을 올릴 때 브라우저가 보낸 바이트):
- 처음 띄운 직후: `ESC[<64;85;17M`
- 새로고침 뒤: 없음(키 입력은 정상 전송)
- 창 폭 변경 뒤: `ESC[<64;81;17M`

## 해결

- `server/src/utils/headlessTerminal.ts`
  - `readHeadlessMouseEncoding`: xterm 코어의 현재 보고 형식을 읽는다. RIS·`reset()`도 그대로 반영된다.
  - `mouseEncodingRestoreSequence`: SGR이면 `?1006h`, SGR-pixels이면 `?1016h`를 만든다.
  - 복원 스냅샷(`serializeHeadlessTerminal`)과 retained checkpoint 끝에 이 시퀀스를 붙인다.
  - 기본 형식이면 아무것도 붙이지 않는다(출력이 전과 바이트 단위로 같다). 붙인 길이도 바이트 한도에 포함된다.
- `frontend/src/utils/terminalMouseEncoding.ts`(신규): 브라우저 쪽의 같은 판정과, `onBinary` 보고를 보낼지에 대한 판정.
- `frontend/src/components/Terminal/TerminalView.tsx`
  - 브라우저 로컬 스냅샷에도 보고 형식을 붙인다.
  - `term.onBinary`를 구독해, 7비트 바이트로만 된 기본 형식 보고는 입력 경로로 보낸다.
  - 0x7F를 넘는 바이트가 든 보고는 텍스트 입력 경로가 UTF-8로 바꿔 버리므로 보내지 않고 `mouse_binary_report_dropped` 디버그 이벤트를 남긴다.

## 한계

- 기본 형식 보고 중 열·행 좌표가 95를 넘는 것(바이트 0x7F 초과)은 여전히 PTY에 닿지 않는다. 바이너리 입력 경로가 필요하다.
  - 그 경로는 봉인·authority 핀 대상인 `WsRouter.ts`를 고쳐야 한다.
  - SGR을 쓰는 앱(Claude Code, Codex 등)에는 해당하지 않는다.
- 보고 형식은 xterm 내부 필드(`_core.coreMouseService.activeEncoding`)에서 읽는다. xterm을 올려서 이름이 바뀌면 이 기능이 조용히 꺼진다(값이 `null`이 되어 아무것도 붙이지 않는다).
  - 서버 테스트가 실제 xterm headless로 이를 검사하므로, 그 경우 테스트가 빨개진다.
