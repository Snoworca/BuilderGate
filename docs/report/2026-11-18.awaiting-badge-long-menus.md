# 긴 선택 메뉴에서 선택 대기 ? 배지가 꺼지던 문제 (FR-AITUI-024 AC-1, AC-2)

## 이슈

- 0.11.7 에서 Claude Code 가 선택지를 띄우고 기다리는 탭의 ? 배지가 처음에는 떴다가 나중에는 뜨지 않았다. 원인을 확인하고 화면 판정을 고쳐 0.11.8 로 내 달라는 요청이다.
- 같은 건에서 텔레그램 훅 알림은 잘 오는데 BuilderGate 배지는 왜 안정적이지 않은지도 물었다.

## 문제 원인

- `server/src/utils/agentChoicePrompt.ts` 의 `isAgentChoicePrompt` 는 커서 행(`❯ 1.`) 아래에 내용이 있는 행이 8개(`MAX_ROWS_BELOW_CURSOR`)를 넘으면 하단 문구(`Enter to select` 등)가 화면에 있어도 `false` 를 돌려주었다.
- 2002 의 「노마디안 / og-flow 지휘 2221」, 「노마디안 / og-flow 지휘 2224·2225」 탭에서 뜬 AskUserQuestion 메뉴는 설명이 달린 선택지 3개, `Type something`, 구분선, `Chat about this`, 하단 문구, 이름이 붙은(`-n`) 세션이 그리는 아래 테두리 때문에 커서 아래가 10행이었다. 그래서 상한에 걸려 배지가 꺼졌다.
- 테스트 픽스처가 선택지 2개(Red/Blue) 짜리만 있어 상한 값이 그 모양에 맞춰져 있었다. 긴 메뉴는 테스트에 없었다.
- 읽는 범위도 맨 아래 16행(`CHOICE_PROMPT_SCAN_ROWS`)뿐이라, 화면이 좁아 설명이 접힌 메뉴에서는 커서가 그 창 밖으로 밀릴 수 있었다.
- 처음에 배지가 뜬 것은 짧은 메뉴였을 것으로 추정한다. 당시 화면은 확인하지 못했다.
- 텔레그램 알림이 잘 오는 이유: `~/.claude/hooks/notify-telegram.py` 는 Claude Code 가 직접 보내는 Notification 이벤트(`notification_type` 이 `permission_prompt`)를 쓴다. 화면 모양과 무관하다. BuilderGate 는 화면 텍스트를 읽어 추측하므로 메뉴 모양에 민감하다. 훅 신호를 BuilderGate 가 받는 방식은 이번 작업에서 하지 않았다. 사용자가 화면 판정 수정을 고르셨다.

## 해결 방법

커밋 `e2b6a900` (FR-AITUI-024 AC-1, AC-2)

- 판정 기준을 하단 문구로 바꿨다.
  - 화면 맨 아래 몇 행 안에 하단 문구가 있고, 그 위에 커서 선택지가 있으면 메뉴 길이와 상관없이 선택 대기로 본다.
  - 하단 문구가 없으면 기존 규칙(커서가 맨 아래 8행 안에 있고 다음 번호 선택지가 있음)만 쓴다. 이 경로에서는 하단 문구를 더 받지 않는다.
- 읽는 행 수를 16 에서 40 으로 늘렸다.
- 2002 의 두 탭 화면을 양성 픽스처로 추가했다. `terminal.read` 가 합쳐 준 구분선 행은 다시 나누었고, 구분선은 `repeat()` 로 만들었다.
- 새 테스트 5개를 먼저 실패시킨 뒤 고쳤다.

커밋 `d5dedd26` (독립 리뷰 반영)

- 독립 리뷰에서 회귀가 확인되었다. 입력 줄에 「Enter to select」 같은 글을 쓰다가 멈추면 그 입력 줄이 하단 문구로 읽혀 ? 가 켜졌다. Claude Code 와 Codex 모두 해당했다. 답변에 인용된 하단 문구는 상태 줄이 없으면 1행 여유로만 막혀 있었다. 하단 문구 아래 4행 이상(백그라운드 에이전트 패널 등)인 메뉴는 놓쳤다.
- 하단 문구 탐색을 맨 아래에서 위로 하도록 바꾸었다. 커서 표식(`❯`, `›`, `▶`, `➤`, `>`)으로 시작하는 행, 즉 입력 줄이나 선택지를 만나면 멈춘다. 메뉴가 뜨면 입력 줄이 사라지기 때문이다.
- 하단 문구 아래에 허용하는 행 수를 6행으로 정했다.
- 실패하는 테스트 3개를 먼저 넣고 고쳤다.
