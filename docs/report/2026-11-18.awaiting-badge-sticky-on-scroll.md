# 메뉴를 스크롤하면 선택 대기 ? 배지가 꺼지던 문제 (FR-AITUI-024 AC-6)

## 이슈

- 선택을 끝내지 않았는데도 선택 대기 ? 배지가 화면 스크롤만 하면 사라진다는 문제다. 직접 확인해 고쳐 달라는 요청이다.
- 확인 대상은 2002 의 「노마디안 / og-flow 지휘 2221」 탭이다. 스크롤하면 메뉴가 위로 밀려 있었고, 하단 문구 자리에 「Jump to bottom (ctrl+End) ↓」 구분선이 보였다.

## 문제 원인

- `server/src/services/AgentAwaitingInputTracker.ts` 는 출력이 멈출 때마다 화면을 다시 읽고, 메뉴가 화면에 보이지 않으면 입력 대기 표시를 바로 지웠다.
- 스크롤하면 Claude Code 가 메뉴를 다시 그리면서 하단 문구와 아래쪽 선택지가 화면 밖으로 밀려난다. 사용자가 답하지 않았는데도 메뉴가 보이지 않는 것으로 판정되어 ? 가 꺼졌다.
- 마우스 휠은 메뉴에 답하는 키가 아니므로, 스크롤을 답으로 볼 근거가 없다.
- 2002 는 08:43:17 에 시작된 프로세스(PID 82988)이고, 그 뒤 `dist` 만 `6d6ff30a` 로 다시 빌드되었다. 그래서 2002 는 0.11.7 서버 코드로 돌고 있었고 0.11.8 의 수정도 반영되어 있지 않았다.

## 해결 방법

커밋 `cadfd138` (FR-AITUI-024 AC-6 신설)

- 한 번 켠 선택 대기 표시는 다음 경우에만 지운다.
  - 사용자가 답하는 키를 입력했을 때
  - 세션이 종료되었을 때
  - 에이전트가 메뉴를 떠났다고 볼 수 있는 화면이 보일 때
- 「메뉴를 떠난 화면」 판정은 새 함수 `showsAgentPromptOrWork` 가 맡는다. 다음 중 하나가 화면에 보이면 떠난 것으로 본다.
  - 규칙선 사이의 입력 줄(초안이 여러 줄이어도 인정)
  - `esc to interrupt`, `? for shortcuts`
  - Codex 의 `% context left`, `for agents` 안내
  - 마지막 줄의 셸 프롬프트(PowerShell, cmd, `$ # % λ`, 프롬프트 표식만 있는 줄)
- 규칙선 사이에 놓인 번호 선택지는 입력 줄로 보지 않는다.
- 시간 제한은 두지 않았다. 메뉴는 몇 시간씩 기다릴 수 있기 때문이다.
- 2002 에서 스크롤 상태로 캡처한 2221 화면을 픽스처로 넣었다.

독립 리뷰 결과 반영 (같은 커밋에 포함)

- 커서를 「Chat about this」 에 둔 채 스크롤하면 규칙선 사이의 선택지가 입력 줄로 읽혀 ? 가 꺼지는 결함이 확인되어, 이를 막는 테스트를 추가했다.
- 리뷰에서 starship, zsh, 왼쪽에 이름이 붙은 규칙선, 긴 에이전트 목록, 여러 줄 초안, Codex 안내 변형에서도 ? 가 남아야 한다는 경우를 찾아 모두 테스트로 막았다.
