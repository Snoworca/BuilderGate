- Scope: P4a only. PERF-BGSTAB-011 AC-10 source ACK control-message subset and AC-7 intermediate JSON provenance; PERF-BGSTAB-010 AC-5/6 compatibility and rejection observability. P4b write-completion, recovery-lane/producer convergence, automatic binary ACK, final A-5 and broad AC completion remain open.
- Both protocol copies expose the same exclusive legacy/source identity. Legacy deliverySeq-only messages keep their wire shape; source messages require explicit kind and canonical uint64 epoch/sequence strings. Rejections use the same exclusive identity, including the actual server outbound union.
- Parser order preserves record/type, common identity, domain conflict/missing, then domain-specific value checks. Malformed incoming ACKs stay on the warning path and never enter the scheduler. Valid rejected ACKs retain their exact identity in all four router paths.
- Browser rejection validation runs before generic session dispatch. Valid source/legacy rejections retain diagnostic identity; malformed rejections, including those without sessionId, expose their reason through a warning without mutating session/output state.

## Remaining dependency

Current checkpoint-start terminates the fair lane; post-checkpoint direct output bypasses that released lane. Therefore a connection-wide accepted capability cannot establish frame-level fair credit ownership. P4b must capture ACK identity at intake and first establish recovery-lane ownership and all-binary-OUTPUT fair admission before automatic source ACK generation. No new header flag, JSON bypass or second scheduler is introduced by this change.
