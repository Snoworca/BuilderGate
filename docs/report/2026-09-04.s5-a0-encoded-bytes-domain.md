# PERF-BGSTAB-011 AC-1/AC-9 완성: encodedBytes 바이트 도메인 전환

## 이슈 설명

PERF-BGSTAB-011의 AC-1과 AC-9는 fair-delivery credit 회계의 도메인 전환을 규정하고 있습니다. AC-1은 회계 대상인 `encodedBytes`를 JSON 봉투가 아닌 payload 본문 바이트로 산정할 것을, AC-9는 그 전환을 wire format이 여전히 JSON인 상태에서 먼저 수행한 뒤 단독 효과를 측정할 것을 요구합니다.

## 문제 원인

`server/src/ws/wsSendPolicy.ts`의 `fairDeliveryBytes()` 함수가 회계 목적으로 `createWsTransportMessage(...)`를 재호출하고 있었으며, 이 호출의 결과인 `.byteLength`는 JSON 봉투 전체(message body + sessionId, connectionEpoch, deliverySeq, deliveryKind 등 식별 필드)를 포함합니다. 그 결과 lane의 credit window 소비가 codec 구현에 따라 움직였고, 도메인이 본문에서 벗어나 있었습니다.

## 해결 방법

`fairDeliveryBytes()` 함수의 구현을 다음과 같이 변경했습니다:

```typescript
Math.max(1, Buffer.byteLength(input.payload, 'utf8'))
```

이 변경으로:
- 회계가 순수 payload 텍스트의 UTF-8 바이트 길이만 계상하도록 됩니다.
- 하한 1은 IR-BGSTAB-001 AC-10이 "본문이 0 바이트인 delivery는 1로 계상한다"고 직접 규정한 조항을 구현합니다. 이는 본문이 0 바이트인 delivery가 예산을 전혀 쓰지 않고 lane을 점유하는 것을 방지합니다.
- 함수의 `deliverySeq` 매개변수가 필요 없어져 호출부의 지역 변수와 함께 제거되었습니다.

## 보고만 하고 고치지 않은 발견 사실

### 1. visibilityWeight와 driverWeight의 방향 모순
`resolveFairTerminalDeliveryPolicy`가 만드는 `visibilityWeight` 8이 `driverWeight` 16보다 작습니다. 이는 deficitQuantum 기준으로 visible 클래스가 driver 클래스의 절반 quantum을 받는다는 의미이며, 스케줄러 테스트가 전제하는 "visible 우선" 명제와 방향이 반대입니다.

### 2. slow-credit lane 단정의 공허함
`FairTerminalDeliveryScheduler.test.ts`의 `slow-credit` lane에 대한 `creditBytes` 단정이 이번 변경 이전부터 공허했습니다. 해당 lane에 `acknowledge` 호출이 없어 `creditBytes`가 항상 0이기 때문입니다. 도메인 일관성만 유지하고 공허함 자체는 건드리지 않았습니다.

### 3. 이중 payload 보유 설명의 부정확성
`docs/research/binary-comms/06-work-plan.md:1057`은 dataGap의 `payload` 이중 보유가 S5-a0 단계에서 해소된다고 기술했으나, 실제 구현에서는 회계가 여전히 `input.payload`를 읽고 있어 그 서술이 저장소 사실과 불일치합니다.

### 4. 벤치마크 테스트의 누락된 지도
`src/benchmarks/` 아래의 8개 테스트 파일(`terminalFairnessCharacterization.test.ts` 등)이 CLAUDE.md의 테스트 표면 지도에 포함되지 않았으며, 광역 회귀 명령에도 포함되지 않습니다. 이번 변경과 직결된 스위트임에도 불구하고 누락되어 있습니다.

### 5. terminal resource consumer manifest의 이중 핀
manifest 파일은 source provenance 뿐 아니라 `server/src/services/TerminalResourcePolicy.test.ts` 자체도 핀합니다. 따라서 해당 테스트 파일을 수정하면 두 개의 서명 봉인이 red가 됩니다.
