# 터미널 와이어 포맷 부트 프로브 추가

## 이슈 설명

직전 작업(커밋 `21917f3`)에서 `server/src/index.ts`가 `realtime` 옵션을 `WsRouter`에 넘기도록 배선했습니다. 그때 추가한 회귀 테스트는 소스 텍스트 읽기에 기반해 "그 줄이 있다"만 증명하고 "값이 실행 중에 흐른다"는 증명하지 못했습니다.

## 문제 원인

설정 파일에서 `config` 객체를 거쳐 라우터까지 이어지는 구간을 실행하는 테스트가 저장소에 0개였습니다. `config`는 모듈 최상위 `export const config = loadConfig()`이고 `index.ts`는 부트스트랩을 export 하지 않는 최상위 부수효과 모듈이기 때문입니다.

그 구간의 회귀는 조용합니다. `realtimeSchema`가 `defaultObject`라서 `realtime`이 사라져도 에러 없이 `json` 기본값으로 채워집니다.

## 해결 방법

`server/src/ws/terminalWireFormatBoot.test.ts`를 새로 작성했습니다(326줄). 임시 설정 파일로 `src/index.ts`를 자식 프로세스로 부팅하고, `/health`로 기동을 확인한 뒤 `/api/auth/login`으로 JWT를 받고, WebSocket으로 `terminal-binary:capability` 오퍼를 보내 응답을 관측합니다.

테스트 케이스는 다음과 같습니다.

1. `terminalWireFormat: "binary-optin"` → `accepted: true` 응답
2. 명시적 `terminalWireFormat: "json"` → `terminal-binary:rejected` 응답
3. `realtime` 블록 없음 → 응답이 오기만 하면 통과(어느 응답인지는 단언하지 않음)

케이스 3이 어느 응답인지 단언하지 않는 이유가 있습니다. `IR-BGSTAB-001` AC-7이 "이 키의 기본값이 어느 값인지는 이 Requirement의 불변식이 아니며 `MIG-BGSTAB-004` 소관"이라고 명시하고, 같은 문서의 2026-08-18 변경 노트가 그 불변식을 의도적으로 제거했다고 기록하기 때문입니다. 기본값을 핀하면 승인된 마이그레이션을 회귀로 오표기하게 됩니다.

## 구현에서 다룬 함정

### 포트 예약

`index.ts`가 `HTTP_PORT = PORT - 1`을 함께 바인딩하고 그 `listen()`에 error 핸들러가 없어 충돌 시 `process.exit(1)`합니다. 따라서 인접한 두 포트를 동시에 잡아 보고 둘 다 놓는 방식으로 예약합니다. 예약 프로브는 호스트를 지정하지 않습니다. 서버가 호스트 없이 `listen()`하여 듀얼스택 `::`에 바인딩하므로, `'0.0.0.0'`으로 검사하면 비어 있다는 거짓 판정이 납니다.

### 환경 변수 정제

저장소에 `BUILDERGATE_*`가 31개 있고 늘어나므로 접두사를 통째로 제거한 뒤 필요한 넷만 설정합니다. `PORT` env가 `config.server.port`를 가리는 함정도 있습니다.

### 조기 종료 처리

자식이 즉시 죽는 경우 `waitHealthy` 타임아웃을 기다리지 않도록 exit 이벤트를 경합시키고 폴링에 취소 플래그를 둡니다.

### 정리 작업

Windows에서 자식 exit 직후에는 임시 디렉터리가 잠겨 있어 `rmSync`가 `EPERM`을 냅니다. 재시도 옵션을 주고, 그래도 실패하면 삼킵니다.

## 검증 과정에서 정정된 것

### 케이스 2의 형태 변경

처음에는 케이스 2를 "설정 없음"으로 두었으나, 이것이 스키마 기본값을 핀해 AC-7이 명시적으로 배제한 불변식을 되살린다는 지적을 받았습니다. 명시적 `terminalWireFormat: "json"`으로 바꿨습니다.

### 케이스 3 추가로 커버리지 보완

케이스 2의 수정이 새 구멍을 만들었습니다. 두 케이스 모두 `realtime`을 명시하게 되어 실제 배포 형태(키 없음)가 커버리지에서 빠졌습니다. 케이스 3을 추가해 메웠습니다.

### CLAUDE.md의 서버 환경 변수 기술 개선

처음에는 "`BUILDERGATE_SERVER_ROOT`를 빠뜨리면 즉시 `server/certs/`와 `server/data/`에 쓰기가 발생한다(실측)"이라고 적었으나, 실제 사실과 다릅니다. `server/data/`는 그 변수와 무관하게 `process.cwd()` 기준이고, `server/certs/`는 인증서가 유효하면 재사용만 합니다. 두 장치를 나눠 서술하고 실측한 범위와 코드 근거뿐인 범위를 갈라 적도록 정정했습니다.
