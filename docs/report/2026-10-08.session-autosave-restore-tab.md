# 세션 자동 저장 · 직접 저장본 목록 · 복구 탭

- 날짜: 2026-10-08
- 요구사항: FR-AITUI-016, FR-AITUI-017, FR-AITUI-018, FR-AITUI-019, NFR-AITUI-001 (대상 `session-autosave`)
- 승계: FR-AITUI-007(버튼으로만 저장), FR-AITUI-014 AC-3(저장본은 한 번 쓰면 소진), FR-AITUI-015 AC-7(배너 닫힘을 브라우저에 기억)
- 시안: `docs/research/2026-10-08.session-restore-tab-design.html`
- 커밋: `ce9648a6` (브랜치 `feat/session-autosave-restore-tab`)

## 1. 이슈

세션을 수십 개 띄워 쓰면 메모리 부족으로 서버가 강제 종료되는 일이 생깁니다. 지금까지는 사용자가 "세션 저장" 버튼을 눌러야 이어하기 정보가 남았습니다. 그래서 버튼을 누른 뒤에 띄운 에이전트 세션은 종료와 함께 사라졌습니다.

사용자가 정한 요구는 다음과 같습니다.

- 세션을 정해진 간격마다 자동으로 저장합니다. 저장하는 순간 지연이나 끊김이 없어야 합니다.
- 확실하지 않은 세션 id(추정값)도 일단 저장합니다.
- 자동 저장본은 한 곳에만 덮어씁니다. 수동 저장본은 목록으로 쌓고, 몇 개까지 둘지는 설정에서 정합니다.
- 재시작하면 최신 수동 저장본과 자동 저장본 중 더 최근 것을 자동으로 복구합니다.
- 세션 저장 창에 "복구" 탭을 두고, 날짜별 저장본을 골라 직접 복구합니다.
- 자동 복구가 끝나면 그 사실을 기록해 두고, 새로고침해도 복구 배너를 다시 띄우지 않습니다.
- 설정: 자동 저장은 기본 켜짐, 간격은 최소 5분입니다.

## 2. 원인 분석

| 항목 | 내용 |
|---|---|
| 저장 주기 | 저장 경로(`SessionSnapshotService`)는 이미 있었으나 버튼으로만 실행되었습니다. |
| 끊김 위험 | 세션 id 해석기(`agentSessionResolver.ts`)가 동기 파일 I/O 를 썼고, 탭마다 에이전트 기록 디렉터리를 다시 읽었습니다. 비용이 탭 수 × 파일 수로 늘어 이벤트 루프를 막습니다. 대조 측정: 탭 50개 조건에서 기존 경로가 이벤트 루프를 34.7초 동안 막았습니다. |
| 저장 구조 | 저장본 파일이 하나뿐이고 재시작 한 번에 소진되어, 목록·선택 복구를 할 수 없었습니다. |
| 배너 | 배너를 닫았다는 사실을 브라우저 localStorage 에만 기억해서, 다른 브라우저나 5초 안의 새로고침에서는 배너가 다시 나왔습니다. |

## 3. 해결 방법

### 서버

- **해석기 캐시(NFR-AITUI-001)**: `loadAgentStateCache()` 가 Claude·Codex 기록을 비동기 I/O 로 한 번만 읽습니다. 자동 저장 한 주기의 모든 탭이 이 캐시를 공유하고, 탭 사이마다 이벤트 루프에 양보합니다.
- **자동 저장(FR-AITUI-016)**
  - `server/data/session-autosave.json` 하나를 매 주기 덮어씁니다.
  - 모든 탭을 기록합니다. 세션 id 는 확실도(exact·estimated)와 함께 저장합니다.
  - 실행 중이던 명령은 `runningCommand` 로 기록만 하고, 재시작 때 입력하지 않습니다.
  - 세션 id 를 못 찾았거나 추정값이면, 에이전트 시작 뒤에 만든 최신 수동 저장본의 값을 이어받습니다. 그것도 없으면 직전 자동 저장본의 값을 이어받습니다.
  - 재시작 직후 이어하기한 에이전트를 확인하는 동안에는 저장을 미룹니다.
  - 겹치는 주기는 건너뛰고, 프로세스 목록은 한 주기에 한 번만 읽습니다.
  - 쓰기 실패 시 기존 파일을 그대로 두고 다음 주기에 다시 시도합니다.
- **수동 저장본 목록(FR-AITUI-017)**
  - `server/data/session-snapshots/<id>.json` 에 저장마다 파일을 하나씩 만듭니다. 보관 개수를 넘으면 오래된 것부터 지웁니다.
  - 예전 `session-snapshot.json` 은 첫 시작 때 목록의 항목 하나로 옮깁니다.
  - API: `GET /list`, `GET /list/:id`, `DELETE /list/:id`. 없는 id 는 404(`SNAPSHOT_NOT_FOUND`)입니다.
- **재시작 복구와 직접 복구(FR-AITUI-018)**
  - 기동할 때 더 최근 저장본을 고르고(시각이 같으면 수동 저장본), 재시작마다 복구합니다.
  - 복구 결과에 원본(종류·id·시각)을 함께 기록합니다.
  - 배너 표시 여부는 `session-restore-state.json` 에 기록합니다(`POST /report/ack`).
  - 직접 복구(`POST /list/:id/restore`)의 대상 탭 규칙은 이렇습니다.
    - 탭이 셸 프롬프트 상태면 그 탭에 입력합니다.
    - 사용 중이거나 닫힌 탭은 저장된 워크스페이스에 새 탭을 엽니다. 그 워크스페이스가 없으면 클라이언트의 활성 워크스페이스에 엽니다.
- **설정(FR-AITUI-019)**
  - `session.autoSave.{enabled, intervalMinutes}` 와 `session.snapshotRetention` 을 Zod 스키마, RuntimeConfigStore, SettingsService, ConfigFileRepository 에 추가했습니다.
  - 기존 설정 파일에 키가 없으면 새로 삽입합니다.
  - 바꾼 값은 서버 재시작 없이 타이머에 반영됩니다.

### 프런트

- 세션 저장 창에 `저장 | 복구` 탭을 넣었습니다. 복구 탭(`SessionRestoreTab.tsx`)은 시안 구조를 따릅니다.
  - 왼쪽: 자동 저장본, 그리고 날짜별 수동 저장본. "재시작 시 복구 대상"·"지난 자동 복구에 사용" 표시와 삭제(확인 창) 기능이 있습니다.
  - 오른쪽: 항목별 체크, 복구 위치, "실행 중이던 명령도 입력" 선택.
  - 결과는 기존 복구 결과와 같은 행 형식으로 보여 줍니다.
- 배너: 서버가 "아직 표시 안 됨"이라고 할 때만 이 클라이언트가 띄우고, 띄우자마자 서버에 알립니다. localStorage 헬퍼는 제거했습니다. 배너와 결과 창에는 복구 원본을 표시합니다.
- 설정 화면에 "세션 자동 저장" 카드를 추가했습니다. 켜기/끄기, 간격(분), 보관 개수, 마지막 자동 저장 시각을 보여 주고, 범위 밖 값은 저장 전에 알립니다.
- i18n: 키를 en 57개, ko 56개 추가하고(ko 는 복수형 `one` 범주가 없어 하나 적음) `apiError.SNAPSHOT_NOT_FOUND` 를 매핑했습니다. 낡은 안내 문구(`sessionSave.all.doneBody`)도 고쳤습니다.

### 봉인

- 서버 파일의 resourceLimits 접근 위치(문자 오프셋)가 밀려서 `ConfigFileRepository` 분류 핀이 바뀌었습니다. 접근 자체는 HEAD 와 같은 1건입니다.
- 인벤토리 핀을 갱신하고 그 이유를 주석으로 남겼습니다.
- `--accept-classification-change` 로 다시 봉인했습니다. 대조한 결과 바뀐 필드는 `accessEvidenceSha256` 하나뿐입니다.
- 설정 키를 추가해 차등 실행 해시가 바뀌었으므로 `--rerun-differential` 로 GREEN 스냅샷을 갱신했습니다. disabled 와 observed 의 결과는 여전히 서로 같습니다.
