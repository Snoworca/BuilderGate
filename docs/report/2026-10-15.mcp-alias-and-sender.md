# MCP 에이전트 별칭 안내와 세션 간 메시지의 보낸 쪽 태그 (FR-MCP-010, FR-MCP-011)

## 요청

1. MCP 로 붙은 에이전트에게 "새 세션 열어서 claudep 실행해"라고 하면, 에이전트가 `claudep` 가 무엇인지 먼저 확인한 뒤에 실행한다. 이 확인 단계를 없앤다.
2. MCP 로 다른 세션에 글을 보낼 때, 보낸 세션을 함께 표시할지 정하는 인자를 둔다.
   - 콘솔에 명령을 실행할 때는 표시하지 않는다(false).
   - 세션끼리 대화할 때는 `[from: …]` 를 붙인다(true).

## 원인

- 별칭(`claudep`, `codexp`)은 설정에 등록되어 있었다(FR-AITUI-011). 그러나 BuilderGate 내부에서만 썼고 MCP 로는 전달하지 않았다. 그래서 MCP 에이전트에게는 처음 보는 명령이었다.
- `message.send` 는 본문을 받은 그대로 전달했다. 보낸 쪽 정보는 감사 로그에만 남았다. 그래서 받는 에이전트는 누가 보냈는지 몰랐고, 어디로 답해야 하는지도 몰랐다.

## 해결

### FR-MCP-010: 별칭 안내

- 서버 지침과 `buildergate.terminal.exec` 도구 설명에 등록된 별칭을 넣는다. 각 별칭이 어느 에이전트를 실행하는지도 함께 적는다.
  - 예: "claudep (Claude Code), codexp (Codex). They are the user's own launch commands; run them as given."
- 이 문구는 요청이 올 때마다 별칭 설정을 읽어 만든다. 그래서 별칭을 바꾸면 다음 연결부터 반영된다.
- 등록된 별칭이 없으면 별칭 문구를 넣지 않는다.

### FR-MCP-011: 보낸 쪽 태그

- `includeSender` 인자를 추가했다.
  - `message.send`: 기본값 `false`.
  - `reply_to_leader`: 기본값 `true`.
- 값이 `true` 이면 서버가 인증된 호출자 정보로 태그를 만들어 본문 앞에 붙인다.
  - 형식: `[from: <별칭> · sessionKey <키>] 본문`.
  - 태그와 본문은 같은 줄에 있다. 줄을 바꾸면 셸이 그 줄바꿈을 Enter 로 받기 때문이다.
  - 별칭에 들어 있는 대괄호와 줄바꿈은 지운다.
- 자기 세션이 없는 고정 액세스 키는 `[from: external MCP client]` 로 표시한다.
- 본문이 `[from:` 으로 시작하면 서버가 `(from:` 으로 바꾼다. 태그를 위조할 수 없게 하려는 것이다.
- 서버 지침에 다음 두 가지를 적었다.
  - 이 태그가 무엇을 뜻하는지, 그리고 그 `sessionKey` 로 `buildergate.message.send` 를 써서 답하라는 것.
  - 대화할 때는 `true` 를 쓰고, 셸 명령을 보낼 때는 이 인자를 빼라는 것.
- `terminal.exec` 에는 이 인자를 두지 않았다. 셸 명령 앞에 태그가 붙으면 명령이 깨지기 때문이다.

## 검증

- **새 테스트 8건**: 구현 전에 모두 실패하는 것을 먼저 확인했다(`server/src/services/McpAliasAndSender.test.ts`).
- **회귀 확인**: 아래가 모두 통과했다.
  - MCP 스위트 38건
  - 모놀리식 러너 533개
  - `TerminalResourcePolicy` 21/21
  - `test:release-pipeline`
  - 타입 검사와 빌드
- **실제 MCP 호출**:
  - 운영 데몬이 MCP 로 3333 을 쓰고 있다. 그래서 2222 테스트 서버의 MCP 는 3334 로 켰다.
  - 별칭 `claudep`/`codexp` 를 등록하자 `initialize` 응답의 지침과 `terminal.exec` 설명에 나왔다.
  - 고정 키로 보낸 글에는 `[from: external MCP client]` 가 붙었다.
  - claim 으로 세션(probe-a) 자격을 받아 보낸 글에는 `[from: probe-a · sessionKey sess_…]` 가 붙었다.
  - 위조한 `[from: fake] forged` 는 `(from: fake] forged` 로 도착했다.
- **정리**:
  - 테스트 워크스페이스는 정확한 id 로 지웠다.
  - 별칭 파일과 MCP 설정 파일은 백업본으로 되돌렸다.
  - 테스트 서버를 종료했다. 운영 데몬의 2001, 2002, 3333 포트는 손대지 않았다.

## 참고

- 운영에 반영하려면 두 가지가 필요하다. 먼저 설치본을 이 버전으로 업데이트한다. 그다음 에이전트가 MCP 에 다시 연결한다. 지침과 도구 목록은 보통 연결할 때 한 번만 읽기 때문이다.
- SRS 작성 중 AC 라벨의 중복을 정리하다가, 기존 요구사항 4건의 줄까지 같이 바꿨다. 커밋 전에 그 4건을 원래대로 되돌렸다.
