# 그리드 도구 막대에 가로 정렬 버튼 추가 (FR-UIDS-017)

## 이슈 설명

그리드 보기에는 터미널을 좌우로 나란히 놓는 세로 정렬 버튼만 있다. 모니터를 세로로 돌려 쓰는 사용자는 터미널을 위아래로 쌓는 보기가 필요하다.

- 세로 정렬 바로 오른쪽에 가로 정렬 버튼을 둔다.
- 누르면 그 워크스페이스의 모든 터미널을 원래 순서대로 위에서 아래로, 같은 높이의 한 열로 쌓는다. 터미널 수와 화면 비율과 상관없이 한 열이다.
- 결정 사항(담당자 확인): 버튼 위치는 세로 정렬 오른쪽이다. 아이콘은 테두리 사각형을 가로선 2개로 3칸 나눈 모양이며, 가로 막대 셋은 사이드바 햄버거 아이콘과 같아 쓰지 않는다. 이름은 한글 「가로 정렬」, 영문 「Stack horizontally」다. 화면 방향을 감지해 자동으로 바꾸는 기능은 넣지 않는다. 버튼만 둔다.

## 문제 원인

- 그리드 타일 도구 막대에는 균등 분할, 세로 정렬, 포커스, 자동만 있었다. 위아래로 쌓는 고정 프리셋이 없었다.
- 세로 정렬은 `frontend/src/utils/mosaic.ts:391` 의 `buildEqualColumnsMosaicTree` 가 react-mosaic `'row'` 방향(좌우 일렬)으로 만든다.
- 툴바 토글 판정은 `mode` 만 비교했다. 균등 분할, 세로 정렬, 가로 정렬은 모두 mode `equal` 을 공유하고 `equalPreset` 으로만 구분된다. 그래서 고정 프리셋이 켜진 상태에서 균등 분할을 누르면 자유 배치로 떨어졌다. 커밋 이전 `MosaicContainer.tsx` 의 `handleLayoutModeChange` 는 `source === 'toolbar' && layoutMode === mode` 이면 `'none'` 을 돌려줬다(`git show 071a2510^` 기준). 이 결함은 리뷰에서 발견됐고, 기존 세로 정렬에도 같은 형태로 있었다.

## 해결 방법

행 번호는 커밋 `071a2510` 기준이다.

- `equalPreset` 에 `rows` 를 추가했다. `buildEqualRowsMosaicTree`(`mosaic.ts:395-398`)는 `'column'` 방향 일렬을 만든다. `LinearEqualPreset`, `isLinearEqualPreset`, `buildLinearPresetMosaicTree`(`mosaic.ts:401-409`)로 두 고정 프리셋을 columns 와 같은 경로에서 만든다.
- 저장값 검증(`mosaicLayoutStorage.ts:108`)이 `rows` 를 받는다. 다음 경로가 모두 현재 프리셋으로 트리를 다시 만든다. 복원(`useMosaicLayout.ts:107-108`), 탭 변경(`buildTreeForMode`, `MosaicContainer.tsx:265-266`, 호출 `:301`·`:403`), 모드 적용(`applyModeToTree`, `:497-498`), 드래그 재정렬(`handleTileDragEnd`, `:633-634`). `columns` 만 보던 분기는 없앴다.
- `handleColumnsLayout` 을 `handleLinearLayout(preset)` 으로 합쳤다(`MosaicContainer.tsx:549`). 툴바는 `onColumnsLayout={() => handleLinearLayout('columns')}` 와 `onRowsLayout={() => handleLinearLayout('rows')}` 를 받는다(`:883-884`).
- 툴바 순서는 균등 분할, 세로 정렬, 가로 정렬, 포커스, 자동이다(`MosaicToolbar.tsx:111-146`). 가로 정렬 버튼은 `command="rows"`, 아이콘 `rows`, 이름 `grid.toolbar.horizontal` 을 쓴다(`:126-132`). `aria-pressed` 는 기존 `ToolbarButton` 이 `active` 값으로 채운다(`:35`). 균등 분할의 `active` 는 `equalPreset === 'smart'` 일 때만 켜진다(`:115`).
- 버튼 전환 판정을 `frontend/src/components/Grid/gridLayoutToggle.ts` 의 순수 함수로 분리했다. `resolveToolbarLayoutMode`(`:15`)는 켜진 배치를 다시 누르면 자유 배치로 돌아가고, 다른 버튼이면 그 배치로 바꾼다. 균등 분할은 프리셋이 `smart` 일 때만 켜진 것으로 본다. `resolveLinearLayoutToggle`(`:27`)은 고정 프리셋 두 개를 같은 규칙으로 판정한다.
- 기존 세로 정렬도 같은 수정을 받는다. 세로 정렬이 켜진 상태에서 균등 분할을 누르면 이제 자유 배치가 아니라 균등 분할이 된다.
- 아이콘 `rows` 는 `frontend/src/components/common/iconGlyphs.ts:156-164` 에 추가했다. 테두리 사각형 `M4 3h16v18H4z` 와 가로선 `M4 9h16`, `M4 15h16` 으로 이루어진다.
- 이름은 `messages.en.json` 에 「Stack horizontally」, `messages.ko.json` 에 「가로 정렬」을 같은 키 `grid.toolbar.horizontal` 로 넣었다.
- 요구사항 FR-UIDS-017 을 `docs/spec/44.ui-design-system.srs.md:1086` 에 추가했다. Status 는 implemented, 검증 방법은 test 다. AC-1~6, 검증 증거 VE-1(테스트), VE-2(수동 확인), Change Note 1건이 있다.

## 남은 한계

- 가로 정렬이 켜진 상태의 드래그 재정렬과 경계선 드래그(자유 배치로 전환)는 코드로만 확인했다. 브라우저에서는 확인하지 않았다.
- 테스트 13건 중 7건(`:51`, `:56`, `:89`, `:105`, `:147`, `:152`, `:158`)은 소스 텍스트 패턴을 검사한다. 컨테이너 재구성 경로(복원, 탭 변경, 모드 적용, 드래그 재정렬)를 실제로 렌더해 확인한 테스트는 없다. 실행으로 확인한 것은 토글 판정(`:124`)과 저장값 복원(`:95`)이다.
- smart 배치의 rows/cols 추론이 가로 띠 트리를 탭 수에 따라 다르게 분류한다. 보이는 오동작은 없다(리뷰 지적, minor).
- 영어 문구 「Stack horizontally」는 영어 독자에게 좌우 배치로 읽힐 수 있다. 기존 「Stack vertically」가 좌우 배치를 뜻하는 것과 같은 방식이며, 담당자가 정한 문구라 바꾸지 않았다.
- 배치 버튼을 누른 뒤 2초 안에 탭을 추가하거나 삭제하면 직전 저장값으로 돌아가는 기존 결함이 있다. 모든 모드에 공통이고 이번 범위 밖이라 고치지 않았다(구현 세션 기록).
