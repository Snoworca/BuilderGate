## 1. 복구로 연 탭이 새로고침해야 보이는 문제 (FR-AITUI-022, #226)

### 증상

- 세션 복구로 항목을 복구하면 복구 완료가 표시되지만 탭 막대에 탭이 나타나지 않았다. 새로고침해야 탭이 보였다.
- 복구가 실패한 줄 알고 다시 복구하면, 새로고침 뒤 같은 탭이 두 벌 열려 있었다.

### 원인

- 평소 탭을 만들면 서버가 열려 있는 모든 브라우저에 `tab:added`를 보낸다. REST 탭 생성(`workspaceRoutes.ts`), 루프 실행(FR-LOOP-004 AC-8), MCP 터미널 생성이 모두 그렇다. 브라우저는 이 알림을 받아 탭을 추가한다.
- 세션 복구(FR-AITUI-018 AC-6)는 `server/src/index.ts`에서 `workspaceService.addTab`을 직접 부르고 이 알림을 보내지 않았다.
- 그래서 서버에는 탭이 생겼지만 브라우저는 몰랐고, 새로고침으로 전체 상태를 다시 읽을 때 비로소 탭이 보였다.

### 해결 방법

- 복구용 탭 열기를 `server/src/services/sessionRestoreTabOpener.ts`로 분리했다. 대상 워크스페이스를 고르는 순서(저장된 워크스페이스 → 지금 활성 워크스페이스 → 정렬 순서가 가장 앞인 워크스페이스)는 그대로다.
- 탭을 연 직후 `tab:added`를 모든 브라우저에 보낸다. 복구를 요청한 브라우저도 받는다.
- 브라우저의 `tab:added` 처리(`useWorkspaceManager.ts`)는 이미 같은 탭을 두 번 넣지 않으므로 고치지 않았다.
- 기존 탭에 복구하는 항목과, 새 탭을 열지 못한 항목은 알림을 보내지 않는다.

## 2. 저장 버튼 문구 (FR-AITUI-023, #227)

### 증상

- 세션 저장 창에서 모두 선택을 해제해도 버튼이 **모두 저장 (0)**이었고, 하나만 골라도 **모두 저장 (1)**이었다.
- 세션 복구 탭은 같은 자리에 **선택한 N개 복구**를 쓴다.

### 해결 방법

- `sessionSave.all.saveAll` 문구를 바꿨다. 한국어는 **선택한 {count}개 저장**, 영어는 **Save {count} selected**다.
- 선택이 없거나 잘못된 항목이 있으면 버튼을 누를 수 없는 동작은 그대로다.
