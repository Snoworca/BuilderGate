# RG-06 — 안전한 전체 서버 monolithic·광역 `node:test` 회귀 복구

- 이슈: Snoworca/BuilderGate#40 (상위 에픽 #2), 작업 키 **RG-06**
- 선행: #37 (RG-01 inventory), #3 (split 계약 0B)
- Requirement: **REL-BGSTAB-001 AC-1** — 작업 시작 시 Status `implemented`, Stability `stable`
- 소스 baseline: `a6c7edc37869baf868c6764af2418d8d9ce0496d`, branch `work/issue-2-orca-terminal-20260916`
- 결정표·원시 증거: `docs/analysis/2026-09-17.rg06-regression/`

## 1. 이슈

RG-01 이 실행 계층과 소유권을 정적으로 정리했지만, **전체 서버 회귀를 실제로 nonempty 로 수집해 안전하게 실행하고 남은 실패를 정직하게 특성화하는 일**은 남아 있었다. 원본 §9.1(monolithic)과 §9.4(광역 `node:test`)는 서로 대체 관계가 아니고, 그 둘을 "포트를 잡지 않는 실행" 과 "2222 를 배타로 점유하는 실행" 으로 나누면 커버리지가 새기 쉽다.

## 2. 문제 원인

측정해 보니 **green 은 이 호스트에서 달성 대상이 아니다.** 실패는 세 종류로 갈린다.

1. **PLATFORM** — WSL2/Linux 에는 winpty·PowerShell 이 없다. monolithic 2건, 광역 `node:test` 11건이 여기 속하며 제거할 수 없다.
2. **B0 guard 와 고정 포트의 구조적 충돌** — monolithic 의 4개 테스트(`SEC-MCP-001 AC-6`, `authRoutes` 3건)는 진짜로 TCP 2222 를 연다. guard 는 이를 옳게 거부한다. guard 를 떼면 이 4건은 통과하는 대신 실행이 2222 배타 계층으로 이동하고, 고정 포트의 프로세스 내 재사용 결함이 드러난다.
3. **guard 의 이름 접두 false positive** — 이것만이 실제 결함이었다. 아래 §3.

부수적으로, `server/tools` 스위트는 기본 동시성으로 돌리면 publication lock 경합으로 실패한다(3회 반복 모두 같은 이름).

## 3. 해결 방법

### 3.1 수정한 것 — B0 guard 의 owned-endpoint 이름 집합

guard 는 `buildergate-http-<pid>-<uuid>` 한 종류만 허용했다. `WsRouterRestoreMetadata.test.ts` 의 `createLocalEndpoint` 는 동일한 pid+uuid 규율로 `buildergate-ws-<pid>-<uuid>` unix socket 을 만드는데, TCP 가 전혀 관여하지 않는데도 `B0_FORBIDDEN_TCP_LISTEN` 으로 거부되었다.

TDD 로 처리했다.

- **RED** — 자기검사 `server/tools/test-owned-http-test-pipe.cjs` 에 "`ws` owned endpoint 가 전달된다" 단언과 거부 케이스들을 먼저 추가했다. 의도한 한 지점에서만 실패한다(`raw/RED-guard-selfcheck-*.log`; 최종 corpus 를 수정 전 guard 옆에서 돌린 `raw/RED2-guard-selfcheck-vs-a6c7edc-*.log` 는 `EXIT=1` 까지 보존한다).
- **구현** — 허용 이름을 `buildergate-<kind>-<pid>-<uuid>` 로 일반화하되 kind 를 `['http','ws']` **닫힌 집합**으로 고정했다. pid 일치·uuid 형식·tmpdir 직하위·`.sock` 접미·named pipe 접두 검사는 모두 그대로다. 오류 `code` 는 바꾸지 않았고(다른 테스트가 `code` 로 판정한다) 메시지만 원인을 정확히 말하도록 고쳤다.
- **GREEN** — 최종본의 증거는 `raw/GREEN4-guard-selfcheck-final-*.log`: `{"platform":"linux","rejected":36,"rejectedOutsideCorpus":7,"forwardedToCapturedOriginal":3,"openHandles":false}`, `EXIT=0`. corpus 가 바뀔 때마다 다시 캡처했으므로 `GREEN`~`GREEN4` 네 세대가 보존되어 있고 최종본의 증거는 `GREEN4` 하나다. `RED`~`RED4` 도 같다.

소켓 이름을 `http` 로 맞추는 대안은 택하지 않았다. WebSocket 하네스를 HTTP fixture 라고 부르게 되어 규약이 거짓말을 한다.

### 3.2 guard 를 둘러싼 보강

- **kind 리터럴 강제** — kind 는 `RegExp` 에 보간되므로, 메타문자가 섞이면 허용 이름이 조용히 넓어진다. guard 가 로드 시점에 모든 kind 를 `/^[a-z0-9]+$/` 로 검사하고 위반 시 `B0_INVALID_OWNED_ENDPOINT_KIND` 로 실패한다. **이 검사가 덮는 것은 kind 배열뿐이다** — 그것을 둘러싼 패턴 템플릿을 직접 고치는 편집은 지나간다. 그래서 자기검사 corpus 에 닫힌 집합 밖 kind 토큰 여섯 개와 구분자 없는 형태를 넣어 그런 편집이 관측되게 했다. 부수 효과로 로드 실패가 preload 프로세스 전체의 실패가 되는데, 안전 가드로서 옳은 선택이라고 보되 그 대가를 기록해 둔다.
- **자기검사를 수집되는 표면으로, 그리고 그 표면을 실재하게** — 기존 자기검사는 `*.test.*` 규약 밖이라 아무것도 수집하지 않았다. 신규 `server/tools/owned-http-test-pipe-guard.test.cjs` 가 그것을 자식으로 돌린다. 다만 `server/tools/*.test.*` 를 부르는 스크립트도 원래 없었으므로(CLAUDE.md 가 "스크립트 없음" 으로 적어 둔 그대로) `server/package.json` 에 `test:tools`(동시성 1 고정)를 추가하고, 루트 `test:release-pipeline` 체인에는 **wrapper 파일 하나만** 끼워 넣었다 — 스크립트를 만들기만 하고 아무도 부르지 않으면 표면은 실재하지 않기 때문이다. 처음에는 `test:tools` 를 통째로 체인에 넣었다가 되돌렸다: 그 스크립트가 끌고 오는 `fair-scheduler-checkout-provenance.test.mjs` 가 gitignore 된 `server/dist` 를 요구하기 때문이다. **다만 이 되돌리기가 게이트의 dist 의존을 없애지는 않는다** — 실측하면 `server/dist` 가 없는 트리에서 게이트는 여전히 기존 단계 `test:authority-pin` 에서 실패한다. 그 성질은 선재하며 §8 에 남은 항목으로 적는다. 현재 구성으로 게이트 3단계 전체가 통과하고 사후 `git status docs/analysis/terminal-fairness-authority` 가 비어 있음을 확인했다(dist 가 있는 트리에서). 또한 **`test:tools` 자체는 여전히 자동으로 불리지 않는다** — 체인에 들어간 것은 wrapper 파일 하나다. wrapper 는 corpus 크기를 **정확히** 단언하고, `BUILDERGATE_B0_GUARD_LOG` 를 켜 **guard 자신이 남긴 이벤트 수**로 자기검사가 실제로 guard 를 구동했는지 확인하며, `process.platform` 을 강제해 이 레인이 타지 않는 분기까지 한 번 더 돌린다. 자식 환경은 명시 구성한다(운영자 로그 비상속, `NODE_TEST_*` 제거).
- **mutation battery** — 재실행 가능한 스크립트로 커밋했다(`guard-mutation-battery.mjs`). mutant **28개**를 두 표면에 각각 돌려 **비동등 mutant 중 두 표면 모두에서 살아남은 것 0건**(`result=PASS`), control 은 양쪽 SURVIVED. 다섯은 술어가 아니라 `allowed` 식 자체를(`http`·`https` subject, 무인자 `listen()`, 환경 변수 backdoor, 뒤쪽 인자 opt-out), 둘은 guard 의 이벤트 로그 내용을 공격한다. 같은 battery 를 과거 corpus 에 직접 돌린 결과가 개선을 실측으로 보여 준다 — 자기검사 단독 생존 수가 `a6c7edc` **20** → `839db2a` **18** → `9845ea7` **14** → 최종 **6**(5건은 wrapper 가 잡고 1건은 동등)으로 줄었다. battery 자신도 `NODE_TEST_CONTEXT` 를 자식에게 넘기지 않으며, wrapper 자식이 테스트를 0개 돌리면 판정을 거부한다.
- **한계를 계약으로 적었다** — 고정 corpus 는 호출 순번·시각·argv 처럼 그 집합 밖에 방아쇠를 둔 결함을 원리상 볼 수 없다. 독립 리뷰가 그런 mutant 를 만들어 두 표면을 모두 통과시켰다. 자기검사 파일 끝과 결정표 §5.5 에 그 한계를 명시했다 — battery 의 주장은 "모든 결함을 잡는다" 가 아니라 "덮는다고 적은 불변식이 실제로 하중을 받는다" 다.

### 3.3 고치지 않고 특성화한 것

- PLATFORM 13건(monolithic 2 + 광역 11) — 호스트 내재.
- guard 정당 거부 4건 — guard 가 옳다. 실행 구성의 문제이지 코드 결함이 아니다.
- 선재 미해결 6건(`SEC-MCP-003 OSC 133`, `MIG-BGSTAB-002 checkpoint identity`, `OBS-BGSTAB-005` 3건, `S1 sidecar`) — 전부 "무엇이 옳은 동작인가" 라는 제품 계약 결정을 먼저 요구한다. RG-01 이 RED-5·RED-6 으로 후속 계약을 열어 두었다. **워크트리를 손대지 않고 수정 전 guard 사본으로 단독 실행한 T2c** 에서 여섯 건이 그대로 재현되므로 선재임이 증명된다.
- 비결정적 실패 1건 — §4.

### 3.4 실행 계약을 확정한 것

- `server/tools/*.test.*` 는 **`--test-concurrency=1` 필수**.
- 계층 C(`terminalWireFormatBoot.test.ts`)는 **guard 미부착** — 스스로 후보 포트를 열어 가용성을 확인하므로 guard 아래에서는 6/6 실패한다. RG-01 이 명시하지 않았던 조건이다.
- monolithic 은 guard 부착·미부착 **두 구성을 모두** 돌려야 541개 등록 테스트 전부가 한 번 이상 실제 단언에 도달한다.
- **측정 중에는 소스·guard 파일을 편집하지 않고 다른 측정 프로세스를 함께 돌리지 않는다** — 이 작업의 첫 광역 실행이 이 규칙을 어겨 baseline 자격을 잃었고, T2c 로 다시 측정했다. 실행 하네스가 자기 로그를 증거 디렉터리에 쓰는 것은 여기에 해당하지 않는다.

**수집 nonempty 와 커버리지 무손실**: 원본 §9.4 의 glob 합집합은 61파일, RG-06 의 광역 수집은 79파일로 상위집합이다. 78파일(계층 A0) + 1파일(계층 C) = 79 이며, `server/src/**/*.test.ts` 범위 안에서 분리로 잃은 파일은 0이다. monolithic 등록 배열은 541 항목, `server/tools/*.test.*` 는 작업 후 5파일이다.

**비결정적 실패 1건**: `PERF-BGSTAB-010 emergency cleanup preserves a public finalizer error while releasing held callbacks` 는 red 1 · green 7 이다. red 는 다른 프로세스와 파일 쓰기가 겹친 단 한 번의 전체 스윕에서만 나왔고, 단독 전체 스윕 4회와 단독 파일 실행 3회는 모두 green 이었다. **1회 green 으로 flake 로 분류하지 않았다** — "부하 아래에서 재현된 적이 있는 비결정적 실패" 로 기록하고 해소로 보지 않으며, 그 red 실행에는 이 작업 자신이 유발한 교란이 있었으므로 원인을 "전체 스윕 동시성" 으로 좁히지 않는다.

**`WsRouterSplitHandshake.test.ts` 의 todo 13건**은 `✖` 로 출력되지만 `fail` 로 집계되지 않으며, #3 이 0B 로 닫은 설계 상태다. 관측만 하고 변경하지 않았다.

## 5. 안전 — 증명되는 것과 증명되지 않는 것

- **증명된다**: 보존된 열두 시점의 포트 관측 전부에서 PID 30596 이 2001·2002 를 LISTENING 한다. 2–5차 라운드 관측은 필터를 파일 안에 기록하고 무필터 WSL `ss -ltn` 을 함께 담는다.
- **증명되지 않는다 — "종료한 프로세스 0개"**. 이는 재현 불가능한 부정 주장이다. 이 작업은 어떤 kill 도 하지 않았고 `stop.bat` 을 호출하지 않았으며 외부 서버를 기동하지 않았으나, 그것을 입증하는 아티팩트는 번들에 없다. 같은 요구사항의 RG-04 증거가 같은 한계를 명시한 바 있다.
- **증명되지 않는다 — 2222 의 해제**. 1차 라운드의 `netstat-*.txt` 는 `2001|2002|2222` 로 필터해 저장했고 그 필터가 파일 안에 남아 있지 않다. 게다가 WSL 이 호스팅하는 리스너의 Windows 측 표기는 신뢰할 수 없다. 더 나은 근거는 2–5차 라운드의 무필터 WSL `ss -ltn` 이며, 거기에 2222 도 19999–39999 도 없다.
- **증명되지 않는다 — before/after 의 구분**. 1차 라운드의 netstat 세 파일은 바이트가 동일해 서로 구분되지 않는다. 구별은 파일명과 문서 서술에만 있다.
- 계층 C 가 잡는 19999–39999 의 정확한 번호는 테스트가 출력하지 않아 기록되지 않았다.
- 상속 `BUILDERGATE_*` 0개, `NODE_ENV` 미설정 — 2–5차 라운드 환경 캡처에 보존(HEAD 도 같은 파일에 있다).
- 남긴 장기 백그라운드 프로세스 없음. 모든 실행은 마커 파일로 종료를 기다렸고 마커는 정리했다(이 진술 역시 아티팩트로 재현되지 않는다).

## 6. 증거 편집 고지

monolithic 실행 로그 넷(`T1`, `T1b`, `T1c`, `T3`)에만 편집을 적용했다. `TOTPService` 의 최초 설정 경로가 manual entry key 와 **스캔 가능한 QR 블록**을 stdout 에 출력하기 때문이다(그 출력의 존재 자체를 `test-runner.ts` 의 단언이 고정하고 있다). 값은 실행마다 새로 생성되는 fixture 전용 비밀이지만 형태가 자격증명이므로 조직 규정에 따라 예외를 두지 않았다. `node:test` 로그에는 해당 문자열이 애초에 0건이다.

편집 전 원본은 커밋하지 않고 세션 스크래치패드에 보존했다. 결정표 §8.1 이 사전 해시를 적어 두지만, **대상 바이트가 커밋되어 있지 않으므로 그 해시는 저장소 안에서 재계산할 수 없다** — 검증 가능한 증거가 아니라 편집이 일어났다는 선언으로 읽어야 한다. 검증 가능한 것은 치환 흔적의 개수와, 편집 후에도 네 로그가 PASS/FAIL/EXIT 행을 그대로 담는다는 사실이다.
