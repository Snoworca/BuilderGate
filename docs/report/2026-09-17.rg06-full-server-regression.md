# RG-06 — 안전한 전체 서버 monolithic·광역 `node:test` 회귀 복구

- 이슈: Snoworca/BuilderGate#40 (상위 에픽 #2), 작업 키 **RG-06**
- 선행: #37 (RG-01 inventory), #3 (split 계약 0B)
- Requirement: **REL-BGSTAB-001 AC-1** — 작업 시작 시 Status `implemented`, Stability `stable`
- 측정 HEAD: `a6c7edc37869baf868c6764af2418d8d9ce0496d`, branch `work/issue-2-orca-terminal-20260916`
- 결정표·원시 증거: `docs/analysis/2026-09-17.rg06-regression/`

## 1. 이슈

RG-01 이 실행 계층과 소유권을 정적으로 정리했지만, **전체 서버 회귀를 실제로 nonempty 로 수집해 안전하게 실행하고 남은 실패를 정직하게 특성화하는 일**은 남아 있었다. 원본 §9.1(monolithic)과 §9.4(광역 `node:test`)는 서로 대체 관계가 아니고, 그 둘을 "포트를 잡지 않는 실행" 과 "2222 를 배타로 점유하는 실행" 으로 나누면 커버리지가 새기 쉽다.

## 2. 문제 원인

측정해 보니 **green 은 이 호스트에서 달성 대상이 아니다.** 실패는 세 종류로 갈린다.

1. **PLATFORM** — WSL2/Linux 에는 winpty·PowerShell 이 없다. monolithic 2건, 광역 `node:test` 11건이 여기 속하며 제거할 수 없다.
2. **B0 guard 와 고정 포트의 구조적 충돌** — monolithic 의 4개 테스트(`SEC-MCP-001 AC-6`, `authRoutes` 3건)는 진짜로 TCP 2222 를 연다. guard 는 이를 옳게 거부한다. guard 를 떼면 이 4건은 통과하는 대신 실행이 2222 배타 계층으로 이동하고, 고정 포트의 프로세스 내 재사용 결함이 드러난다.
3. **guard 의 이름 접두 false positive** — 이것만이 실제 결함이었다. 아래 §3.

부수적으로, `server/tools` 스위트는 기본 동시성으로 돌리면 두 테스트가 같은 publication lock 을 두고 경합해 결정론적으로 실패한다.

## 3. 해결 방법

### 3.1 수정한 것 — B0 guard 의 owned-endpoint 이름 집합

guard 는 `buildergate-http-<pid>-<uuid>` 한 종류만 허용했다. `WsRouterRestoreMetadata.test.ts` 의 `createLocalEndpoint` 는 동일한 pid+uuid 규율로 `buildergate-ws-<pid>-<uuid>` unix socket 을 만드는데, TCP 가 전혀 관여하지 않는데도 `B0_FORBIDDEN_TCP_LISTEN` 으로 거부되었다.

TDD 로 처리했다.

- **RED** — 자기검사 `server/tools/test-owned-http-test-pipe.cjs` 에 "`ws` owned endpoint 가 전달된다" 단언과, 닫힌 집합 밖 kind·타 프로세스 pid·uuid 형식 위반 세 거부 케이스를 먼저 추가했다. 실행 결과 exit 1, 의도한 한 지점에서만 실패(`raw/RED-guard-selfcheck-*.log`).
- **구현** — 허용 이름을 `buildergate-<kind>-<pid>-<uuid>` 로 일반화하되 kind 를 `['http','ws']` **닫힌 집합**으로 고정했다. pid 일치·uuid 형식·tmpdir 직하위·`.sock` 접미·named pipe 접두 검사는 모두 그대로다. 오류 `code` 는 바꾸지 않았고(다른 테스트가 `code` 로 판정한다) 메시지만 원인을 정확히 말하도록 고쳤다.
- **GREEN** — exit 0, `{"rejected":21,"validForwarded":2,"actualBinds":0}` (`raw/GREEN-guard-selfcheck-*.log`).

소켓 이름을 `http` 로 맞추는 대안은 택하지 않았다. WebSocket 하네스를 HTTP fixture 라고 부르게 되어 규약이 거짓말을 한다.

### 3.2 고치지 않고 특성화한 것

- PLATFORM 13건(monolithic 2 + 광역 11) — 호스트 내재.
- guard 정당 거부 4건 — guard 가 옳다. 실행 구성의 문제이지 코드 결함이 아니다.
- 선재 미해결 6건(`SEC-MCP-003 OSC 133`, `MIG-BGSTAB-002 checkpoint identity`, `OBS-BGSTAB-005` 3건, `S1 sidecar`) — 전부 "무엇이 옳은 동작인가" 라는 제품 계약 결정을 먼저 요구한다. RG-01 이 RED-5·RED-6 으로 후속 계약을 열어 두었다. 무변경 트리에서 실행한 baseline 로그에 동일하게 나타나므로 선재임이 증명된다.
- 부하 의존 1건 — §4.

### 3.3 실행 계약을 확정한 것

- `server/tools/*.test.*` 는 **`--test-concurrency=1` 필수**.
- 계층 C(`terminalWireFormatBoot.test.ts`)는 **guard 미부착** — 스스로 후보 포트를 열어 가용성을 확인하므로 guard 아래에서는 6/6 실패한다. RG-01 이 명시하지 않았던 조건이다.
- monolithic 은 guard 부착·미부착 **두 구성을 모두** 돌려야 541개 등록 테스트 전부가 한 번 이상 실제 단언에 도달한다.

**부하 의존 1건**: `PERF-BGSTAB-010 emergency cleanup preserves a public finalizer error while releasing held callbacks` 는 전체 스윕에서 1회 실패(`same-path watcher probe must observe a fixture CWD file update before cleanup`), 전체 스윕 1회 통과, 단독 실행 3회 통과다. **1회 green 으로 flake 로 분류하지 않았다** — "전체 스윕 동시성 아래에서만 재현되는 부하 의존 실패" 로 기록하고 해소로 보지 않는다.

## 5. 안전

- **종료한 프로세스 0개.** `stop.bat` 미호출. 외부 서버 미기동.
- 보호 포트: 실행 전·2222 점유 실행 직전·직후·계층 C 직후 네 시점의 관측에서 PID 30596 이 2001·2002 를 LISTENING 하는 네 행이 완전히 동일하다.
- 2222 는 계층 B runner 프로세스 내부에서만 바인드되고 테스트와 함께 해제되었다. 실행 후 관측에 2222 는 없다.
- 계층 C 가 잡는 19999–39999 의 정확한 번호는 테스트가 출력하지 않아 기록되지 않았다. 해제는 직후 WSL `ss -ltn` 에 그 범위 리스너 0개로 확인했다.
- 남긴 장기 백그라운드 프로세스 없음. 모든 실행은 마커 파일(`.done-*`)로 종료를 기다렸고 마커는 정리했다.

## 6. 증거 편집 고지

monolithic 실행 로그 두 개(`T1`, `T3`)에만 편집을 적용했다. `TOTPService` 의 최초 설정 경로가 manual entry key 와 **스캔 가능한 QR 블록**을 stdout 에 출력하기 때문이다(그 출력의 존재 자체를 `test-runner.ts` 의 단언이 고정하고 있다). 값은 실행마다 새로 생성되는 fixture 전용 비밀이지만 형태가 자격증명이므로 조직 규정에 따라 예외를 두지 않았다. 편집 전 원본은 커밋하지 않고 세션 스크래치패드에 보존했으며, 사전 해시·치환 규칙·적용 수는 결정표 §8.1 에 있다. 편집 후에도 두 로그는 PASS/FAIL/EXIT 행을 그대로 담는다.
