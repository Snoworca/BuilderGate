# 터미널 탭이 서버의 NODE_ENV · PORT 를 물려받는 문제 수정 (FR-MCP-030, #257)

## 이슈

BuilderGate 탭에서 띄운 Vite 개발 서버의 개발용 자동 로그인이 꺼진 원인이 탭 셸에 물려받은 `NODE_ENV=production` 으로 밝혀져, 탭 셸이 서버의 `NODE_ENV` 와 `PORT` 를 물려받지 않도록 BuilderGate 를 고쳐 달라는 요청. 이 수정이 다른 사용자에게도 필요한 범용 수정인지도 물음. 증상과 원인은 이슈 #257 에 정리했다.

## 문제 원인

- 서버를 띄우는 모든 경로가 서버 자신을 위해 두 값을 설정한다. `tools/daemon/launcher.js` 의 `createRuntimeEnv` · `createDaemonRuntimeEnv` 가 `NODE_ENV=production` 과 `PORT=<listen port>` 를 넣고, `server/dist/index.js` 를 직접 실행하는 시작 스크립트도 같은 값을 넣는다.
- `SessionManager.buildShellEnv()` 는 서버 프로세스의 환경을 PTY 로 복사한다. 여기서 걸러 내는 것은 SEC-MCP-003 규칙의 호스트 에이전트 식별 변수(`CLAUDE*`, `AI_AGENT`)뿐이었다. 그래서 모든 탭이 두 값을 물려받았다.
- 2026-11-24 2002 포트 서버의 탭에서 실제로 확인했다. 탭 셸에 `NODE_ENV=production` 과 `PORT=2002` 가 있었다. 그 탭에서 띄운 Vite 개발 서버는 `MODE` 가 `development` 인데도 `import.meta.env.DEV` 를 `false` 로 냈다. Vite 는 `process.env.NODE_ENV === "production"` 한 줄로 운영 모드를 판정하기 때문이다. 셸에 `NODE_ENV` 가 있으면 Vite 는 기본값과 `.env` 의 개발 모드 지정을 적용하지 않고, 셸 값으로 `isProduction` 을 정한다(Vite 7.3.8 `dist/node/chunks/config.js` 의 `resolveConfig`: `isNodeEnvSet` 판정과 `const isProduction = process.env.NODE_ENV === "production"`).
- 같은 원인으로 `npm install` 은 devDependencies 를 건너뛰고, `process.env.PORT` 를 읽는 앱은 BuilderGate 포트에 바인딩하려다 실패한다. 오류 메시지가 원인을 가리키지 않으므로 사용자가 BuilderGate 때문이라고 알아차리기 어렵다. launcher 가 항상 두 값을 넣으므로 이 PC 만이 아니라 모든 사용자에게 해당한다.

## 해결 방법

- `stripServerRuntimeEnv()` 를 추가했다. `buildShellEnv()` 는 `stripHostAgentIdentity()` 다음에 이 규칙을 적용하고, 그 뒤에 `envPatch` 를 덮어쓴다. 그래서 세션의 `envPatch` 에 `NODE_ENV` 나 `PORT` 를 직접 넣으면 그 값을 받는다.
- 이름은 대소문자를 가리지 않고 비교한다. `VITE_PORT` · `NODE_ENV_FILE` · `NODE_OPTIONS` 처럼 이름을 포함하기만 하는 변수는 남긴다.
- 규칙은 사본에만 적용하므로 서버 프로세스의 값은 바뀌지 않는다.
- 패턴이 아니라 두 이름만 지운다. 서버는 launcher 가 넣은 값과 사용자가 운영체제에 설정한 값을 구별할 수 없다. 그래서 두 값을 일부러 설정한 사용자는 BuilderGate 탭에서 그 값을 잃는다. 이 경우에는 셸 프로필이나 `envPatch` 로 다시 넣을 수 있다. 이 감수 사항은 FR-MCP-030 본문에 적었다.

## 검증

- 새 테스트 3건(FR-MCP-030)을 더했다. 서버 프로세스에 두 값이 실제로 있는 상태에서 spawn 에 넘기는 환경에는 없는지(AC-1, AC-4), `envPatch` 값이 살아남는지(AC-2), 대소문자와 이름을 포함하기만 하는 변수를 어떻게 다루는지 확인한다. 기존 SEC-MCP-003 AC-4 테스트는 두 변수도 싣고 제거된 변수 수에 함께 센다(AC-3).
- 구현을 빼고 돌리면 AC-1/AC-4 와 AC-3 이 실패하는 것(9 pass, 2 fail)을 먼저 확인했다.
- origin/main(e4e892eb) 위에서 다시 실행: cwd=`server/` 에서 `npx tsx --test src/services/SessionManagerEnvIsolation.test.ts` 11/11 통과, `npx tsc --noEmit -p tsconfig.json` 오류 없음, `speckiwi validate` 오류 0건, `tools/check-kiwi-status-freshness.mjs` 통과.
