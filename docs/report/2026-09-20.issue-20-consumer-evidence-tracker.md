## 이번 작업에서 새로 쓴 단언 하나

`server/src/ws/terminalBinaryReconnectEpochBoundary.test.ts` (4 케이스, 전부 통과).

이슈 AC "socket/protocol mode 는 reconnect epoch 에서만 전환한다" 는 **메커니즘은 있었지만 아무것도
단언하지 않던** 유일한 칸이었다. `createTerminalBinaryGroupSession` 이 `wireFormat`·`transportMode` 를
생성 시점에 한 번 캡처하고 group 은 연결마다 새로 만들어지므로 성질 자체는 성립하지만,
그것을 깨는 변경이 들어와도 빨개지는 테스트가 없었다.

무엇을 고정했나:

1. JSON 으로 열린 group 은 offer 가 몇 번 오든 JSON 에 머문다(`isNegotiable`/`isNegotiated`/`encodeBinary`/`sendBinary`/`openChannel` 전부). → "지금 바꾸고 다음 메시지부터 새 모드" 가 클라이언트에서 도달 불가능하다.
2. `split`·`split-shadow` transport 는 살아 있는 group 안에서 바이너리 평면으로 옮겨갈 수 없다.
3. 살아 있는 group 의 재협상은 **codec epoch 를 움직이지 않고 채널 표를 비우지 않는다** — 이미 전송 중인 프레임이 무효화되지 않는다.
4. 다른 모드를 실어 나르는 것은 **새 group(=새 연결)뿐**이며, 설정 변경이 열려 있는 연결로 거슬러 올라가지 않는다.

**무엇을 고정하지 않았나(명시):** `codecEpoch` 는 오늘 상수 `0` 이고 아무도 올리지 않는다. 이 가드는
"올리는 코드가 생기면 그것이 조용하지 않고 논증된 편집이 되게" 하는 것이지, 올릴 때의 정확성을 증명하지 않는다.
