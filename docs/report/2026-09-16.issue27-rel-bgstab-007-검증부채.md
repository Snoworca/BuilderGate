## 2. 공허 테스트 판정 — 둘 중 하나만 공허했다

판정은 전부 뮤테이션으로 했다. 소스를 읽는 것만으로는 공허함이 확정되지 않는다.
전체 절차와 정확한 패치·명령·결과는 `docs/analysis/2026-09-16.issue27-rel-bgstab-007-verification-debt/probes.md` 에 있다.

### 2.1 AC-8 cache absent/poisoned parity — **공허했다. 재작성함**

`recoverView()` 구현(`TerminalAuthorityController.ts:1357`)이 파라미터를 **하나도 받지 않았다.**
인터페이스(`:238`)는 `input` 을 선언했으므로 타입 검사는 통과했고, 인자는 런타임에 조용히 버려졌다.
`absent` 와 `poisoned` 는 같은 nullary 함수의 두 호출이었고 `deepEqual(absent, poisoned)` 는 어떤 입력에도 실패할 수 없었다.

- **PROBE-C (공허함 증명)**: 두 호출의 인자를 동일하게 만들어 대비를 완전히 제거 → **여전히 green**.
- **수정**: `TerminalAuthorityRecoverViewRequest` 를 신설하고 `recoverView` 가 요청을 authoritative recovery 포트로 전달하게 했다.
  포트 인자는 optional 이라 기존 nullary 구현 4곳(`TerminalAuthorityController.ts:130`, `TerminalAuthorityProductionAdapter.ts:2292`,
  테스트 2곳)은 그대로 assignable 하다.
- **PROBE-D (teeth 증명)**: parity 테스트에 cache-sensitive 복구를 주입 → **red**.
- 음성 대조군 테스트 `Cache-poisoned authoritative recovery parity is failure-capable — REL-BGSTAB-007 AC-8` 을 추가해
  이 성질을 상시 감시한다. 단언이 다시 공허해지면 그 테스트가 먼저 깨진다.

부수 기록: 그 테스트의 제목은 `MIG-BGSTAB-002 AC-4` 다. 이슈는 `REL-BGSTAB-007 AC-8` 로 귀속했다. 불일치를 그대로 남긴다.

### 2.2 AC-3/AC-10 remount — **공허하지 않다. 이슈와 불일치**

이슈는 "PTY 출력이 없고 두 번 읽는 대상이 같은 세션 객체라서 항상 통과" 라고 했다. **기전도 결론도 틀렸다.**

`SessionManager.buildRetainedTerminalAuthorityState`(`SessionManager.ts:7556`)는 호출마다 새 객체를 만들고,
checkpoint 를 live headless 단말에서 **다시 직렬화**한다(`:7592-7597`). `before` 와 `after` 는 독립 스냅샷이다.

- **PROBE-A**: 재등록 시 `streamEpoch` 증가 주입 → **red**
- **PROBE-B**: remount 시 headless 모델 초기화 주입 → **red**

두 축 모두 실패 가능하므로 재작성하지 않았다. 다만 이 테스트가 덮는 범위는 `streamEpoch`/`sourceSeq`/`serializedData` 불변까지이고,
AC-3 이 요구하는 cells/attributes·cursor/saved cursor·modes·rows·cols/reflow 는 덮지 않는다 → 게이트 G6.
