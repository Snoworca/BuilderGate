# 세션 저장 대화상자가 Claude 탭의 권한 모드를 빠뜨리는 문제 수정 (FR-AITUI-025 AC-6, #255)

## 이슈

#253 수정(0.11.12)을 반영한 뒤에도, bypass 모드로 돌던 Claude 세션을 저장했다가 복구하면 기본(default) 모드로 열린다며 원인을 찾아 고쳐 달라는 요청. 직접 연 세션도 같다고 함.

## 문제 원인

- 저장 경로가 둘이다. 자동 저장과 저장 목록의 `save(tabIds)` 는 실행 중인 권한 모드를 다시 읽어 인자에 반영한다(`withLivePermissionModes`, FR-AITUI-025 AC-1). 저장 대화상자의 `saveAll(items)` 는 미리보기(`GET /api/session-snapshot/preview`)가 준 인자를 그대로 저장한다.
- 미리보기(`SessionSnapshotService.preview` → `launchOf`)는 탭의 시작 명령줄에서 인자를 가져오기만 하고 권한 모드를 보지 않았다. 그래서 시작 명령줄에 bypass 플래그가 없는 탭은 플래그 없이 저장됐다. 플래그 없이 시작한 뒤 Shift+Tab 으로 바꾼 탭과, 예전 버그로 플래그 없이 재개된 탭이 여기에 해당한다.
- 2026-11-24 실제 데이터로 확인했다. 09:34:16 자동 저장본에는 6개 탭에 `--dangerously-skip-permissions` 가 있었다. 그러나 25초 뒤 대화상자로 만든 수동 저장본에서는 같은 탭들의 플래그가 빠졌다. 복구는 더 최근인 수동 저장본으로 이뤄졌고, 6개 Claude 가 `--resume <id>` 만으로 다시 떴다.
- #253 보고서는 「저장 창이 미리 채우는 인자에는 규칙을 적용하지 않는다」를 한계로 적었다. 그러나 대화상자는 그 인자를 그대로 저장하므로, 이 한계가 곧 사용자가 겪는 결함이었다.

## 해결 방법

- 권한 모드 판정 부분을 `livePermissionMode()` 로 분리했다. 자동 저장(`withLivePermissionModes`)과 미리보기가 같은 판정 규칙(AC-1)을 쓴다.
- 미리보기는 Claude 탭(attach 제외)의 `args` 에 판정한 모드를 `applyClaudePermissionMode` 로 반영한다. 대화상자의 인자 칸과 「재시작 뒤 입력」에 플래그가 보이고, 저장도 그 인자로 이뤄진다.
- 사용자가 대화상자에서 인자를 고치면 고친 대로 저장한다. 사용자가 확인하고 고치는 화면이라는 성격은 그대로 유지된다.

## 검증

- 새 테스트 4건(FR-AITUI-025 AC-6)을 추가했다. 그중 2건(시작 명령줄을 모르는 탭, 플래그 없이 시작한 뒤 bypass 로 바꾼 탭)이 수정 전에 `args=[]` 로 실패하는 것을 먼저 확인했다. 수정 뒤 `SessionSnapshotPermissionMode.test.ts` 28/28 통과.
- 회귀: `SessionSnapshot*` 8개 파일과 `sessionSnapshotRoutes.test.ts`, 모두 113건 통과. server `tsc --noEmit` 오류 없음. SRS `validate` 오류 0건.
- 실제 앱(2222, 별도 워크트리 `builder-gate-ac6`): `claude --allow-dangerously-skip-permissions` 로 시작해 Shift+Tab 으로 bypass 로 바꾸고 메시지를 하나 보냈다. 대화상자의 인자 칸이 `--allow-dangerously-skip-permissions --dangerously-skip-permissions` 로 채워졌고, 저장 파일에도 같은 인자가 들어갔다. 서버를 다시 띄우자 복구된 Claude 프로세스가 `--dangerously-skip-permissions --resume <id>` 로 실행됐고, 화면에 `bypass permissions on` 이 표시됐다.
- 운영 서버 2002 는 검증 내내 같은 PID 로 유지했다.

## 한계

- 이미 플래그 없이 복구되어 지금 default 로 도는 세션은 이 수정으로 바뀌지 않는다. 그 세션은 Claude 를 종료하고 `claude --dangerously-skip-permissions --resume <id>` 로 다시 열어야 한다.
- 2002 는 서버 코드가 바뀌어도 재시작 전까지 이전 코드로 돈다.
