## 1. #152 — 휴대폰에서 탐색기가 떠 있는 창으로 열림

**문제**
- 휴대폰에서 탐색기가 412×520 크기의 떠 있는 창으로 열렸다(Pixel 7, y=72).
- 같은 휴대폰에서 편집기는 터미널 영역을 채운다.

**원인**
- `useFileExplorerWindows` 가 화면 크기와 상관없이 항상 `floating` 으로 열었다.
- 휴대폰을 구분하는 분기는 편집기의 `resolveEditorWindowPlacementMode` 에만 있었다.

**해결**
- `fileExplorerPlacement.ts` 의 `resolveFileExplorerWindowLayout` 이 다음 세 가지를 함께 정한다.
  - 터미널 영역을 채울지
  - 끌어 옮기기와 크기 조절을 허용할지
  - 최대화 버튼을 보일지
- 휴대폰에서는 항상 터미널 영역을 채운다. 저장된 배치는 바꾸지 않으므로 데스크톱에서는 예전 배치로 돌아온다.

**커밋**: `cfefd576`

## 2. #153 — 새 파일

**서버** (`POST /api/sessions/:id/files/create`)
- `wx` 플래그로 배타적으로 만든다.
- 같은 이름의 파일이나 폴더가 이미 있으면 409 `FILE_ALREADY_EXISTS` 로 거부하고, 기존 항목은 건드리지 않는다.
- 이름과 경로는 mkdir 과 같은 규칙으로 검사한다.

**프런트엔드**
- 메뉴 위치: 컨텍스트 메뉴와 휴대폰 더보기 시트에서 **새 폴더** 바로 위에 **새 파일**을 둔다.
- 창: 탐색기 창 안에 `NewFileDialog` 를 띄운다.
- 이름 확인: 입력할 때마다 다음을 확인한다.
  - 비었거나 공백뿐인 이름
  - `/` 나 `\` 가 들어간 이름, `.`, `..`
  - 그 폴더 목록에 이미 있는 이름(정확히 같을 때)
- 서버가 거부하면 창을 닫지 않고 이유를 보여 준다.
- 만든 뒤에는 업로드 도착 경로를 그대로 써서 새 파일을 선택하고 화면에 보이게 한다.

**커밋**: `eba56e54`

## 3. #154 — 끌어서 이동·복사

**판정 모델** (`fileExplorerDragModel.ts`)
- 무엇을 끄는지: 선택된 행을 끌면 선택 전체, 선택되지 않은 행을 끌면 그 행만 끈다.
- 이동과 복사: 기본은 이동이고, Ctrl(macOS 는 Option)을 누르고 놓으면 복사다.
- 놓을 곳: 폴더 행, 목록의 빈 곳(보고 있는 폴더)에 놓을 수 있고, 파일 행에는 놓을 수 없다.
- 거부: 끄는 항목 자신, 끄는 폴더의 하위, 항목이 이미 있는 폴더.
- 작업 요청: `buildPasteJobRequest` 와 같은 요청을 만든다.

**탐색기 창 연결**
- 기존 OS 파일 드롭 처리기에 내부 끌기 분기를 더했다.
- 경로 막대의 폴더 이름(`data-drop-dir`)에도 놓을 수 있다.
- 탭 위에 머무르면 탭이 바뀐다(0.5초).
- 폴더 위에 머무르면 그 폴더로 들어간다(0.7초).
- 아래쪽 칩에 "이동 → 폴더", "복사 → 폴더" 또는 놓을 수 없는 이유가 나온다.
- 터치 화면(모바일 레이아웃 또는 `pointer: coarse`)에서는 `draggable` 을 끈다.

**커밋**: `475a1cca`
