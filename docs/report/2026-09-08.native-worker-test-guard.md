## Scope of the correction

The permitted IPC is the output-forwarding Worker created by node-pty's `windowsConoutConnection.js`, with entry `lib/worker/conoutSocketWorker.js`. Its request must be the exact `workerData.conoutPipeName + '-worker'`. It is allowed only for Windows, the frozen app profile and an actual Worker whose real entry path matches this checkout's installed dependency. Main threads, other entries, fixture profile, mismatched pipes and descriptor/path/handle overloads remain denied. TCP restrictions are unchanged. Accepted Worker IPC has a distinct audit event.

WinPTY names use the native agent PID, increasing counter, FILETIME hex and optional random suffix (`deps/winpty/src/shared/GenRandom.cc`). The native agent PID is not the Node PID. ConPTY names use the canonical numeric output of `Math.random()*10000000`, followed by `-out` (`windowsPtyAgent.js`, `src/win/conpty.cc`). Both existing backend paths are covered.

Worker entry checks run at the listen boundary: the captured no-bind diagnostic `C:/Users/beom/AppData/Local/Temp/buildergate-worker-context.jsonl` shows that Node's preload stage has only the executable in argv, while the actual Worker entry is populated afterward. The profile remains frozen at preload.
