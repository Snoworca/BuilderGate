# MCP 로 편집기 열기, 이미지 뷰어 ‹ › 이동

- 날짜: 2026-10-16
- 요구사항: FR-MCP-012 (MCP 편집기 도구), FR-MDE-027 (이미지 뷰어 이동)

## 요청

- MCP 로 마크다운 편집기를 띄운다. 파일 경로를 넘기는 방식과 텍스트를 직접 넘기는 방식을 모두 지원한다.
- 소스코드 파일도 MCP 로 편집기에 띄운다. 단, 디스크에 저장된 파일만 연다.
- 이미지 파일도 MCP 로 연다.
- 이미지 뷰어에 ‹ › 버튼을 두어, 같은 디렉터리의 다른 이미지로 이동한다.

## 설계

### MCP 도구 세 개 (FR-MCP-012)

| 도구 | 받는 것 | 규칙 |
|---|---|---|
| `buildergate.editor.open_markdown` | `filePath` 또는 `content` (+ `title`, `overwrite`) | `.md`/`.markdown` 만 받는다. `content` 만 주면 `.buildergate/mcp-docs/<yyyyMMdd-HHmmss>[-<제목 slug>].md` 에 저장하고 연다. 있는 파일에 쓰려면 `overwrite: true` 가 필요하다(없으면 `FILE_EXISTS`). |
| `buildergate.editor.open_code` | `filePath` | 이미 있는 파일만 연다(`FILE_NOT_FOUND`). `content` 는 거부한다. 이미지는 `open_image` 로 안내한다. |
| `buildergate.editor.open_image` | `filePath` | 이미 있는 이미지 파일만 연다(png, jpg, jpeg, gif, webp, bmp, ico, avif, svg). |

- **경로 규칙**: 터미널 세션의 현재 작업 디렉터리를 기준으로 파일 API 와 같은 검사를 한다(`PATH_TRAVERSAL`, `PATH_BLOCKED`). 편집기가 그 세션으로 파일을 읽고 저장하기 때문이다.
- **대상 터미널**: `terminal.read` 와 같은 방식으로 지정한다. 세션 에이전트는 터미널을 생략할 수 있고, 그러면 자기 터미널이다. 다른 터미널은 지정할 수 없다(`INVALID_SCOPE`). `mcp:terminals.exec` 를 가진 고정 키는 어느 터미널이든 지정할 수 있다.
- **권한**: 새 scope `mcp:editor.open`. 세션 에이전트와 고정 액세스 키가 모두 가진다.
- **브라우저 전달**: 서버가 `editor:open {workspaceId, terminalId, filePath, kind}` 를 모든 브라우저에 보낸다. 브라우저는 그 워크스페이스로 전환한 뒤, 세션 경로 메뉴와 같은 경로로 파일을 연다. 이미 열려 있으면 그 탭을 앞으로 가져온다.
- `WsRouter.ts` 는 봉인된 소스라 고치지 않았다. 그래서 응답에는 "몇 개 브라우저에 보냈는지"가 없다.

### 이미지 뷰어 이동 (FR-MDE-027)

- 툴바 왼쪽에 `‹ n / m ›` 를 둔다. 같은 디렉터리의 이미지 파일을 이름순(활성 UI 언어, 숫자 인식)으로 센다.
- 양 끝에서는 해당 버튼이 꺼진다. 뷰어에 포커스가 있으면 ←/→ 키로도 이동한다.
- 이동하면 **같은 탭 자리**에서 파일이 바뀐다. 탭이 늘어나지 않는다. 대상이 이미 열려 있으면 그 탭을 선택한다.
- SVG 소스에 저장하지 않은 변경이 있으면 버튼이 꺼진다. 이동이 편집 내용을 버리지 않게 하려는 것이다.

- **TDD**: `McpEditorTools.test.ts` 9건이 구현 전에 모두 실패하는 것을 확인했다. 프런트 순수 모델 테스트와 `FileServiceEditorOpen.test.ts` 는 구현과 같이 썼다(실패 단계를 따로 보지 않았다).
- **회귀 확인**:
  - 모놀리식 러너 533개 통과
  - `TerminalResourcePolicy` 21/21 (재봉인 뒤)
  - `test:release-pipeline` 통과 (소비자 매니페스트 검사 포함)
  - MCP·FileService 관련 node:test 전부 통과
  - 서버 `tsc`, 프런트 app/editor/test 프로젝트 `tsc` 통과
  - i18n 가드 통과
- **실제 실행**: 2222 테스트 서버(MCP 는 3334, 운영 데몬은 3333 유지)에서 headless Edge 로 로그인한 뒤 MCP 를 호출했다.
  - `open_markdown(content)` 를 부르자 파일이 생기고, 브라우저가 해당 워크스페이스로 전환해 그 텍스트를 보여 주었다.
  - `open_markdown(path)` 와 `open_code(app.ts)` 는 탭을 열었다.
  - 오류 경우 4건은 기대한 코드를 냈다.
  - 이미지 2/3 에서 › 를 누르면 3/3 이 되고 › 가 꺼졌다. ← 를 두 번 누르면 1/3 이 되고 ‹ 가 꺼졌다. 탭 수는 4 로 그대로였다.
  - 스크린샷은 `.playwright-mcp/mcp-editor-*.png` 에 있다.
- **실행 중 고친 결함**: 키보드로 한 번 이동하면 뷰어가 다시 마운트되면서 포커스를 잃었다. 그래서 두 번째 ← 가 먹지 않았다. 이동으로 생긴 뷰어가 마운트될 때 포커스를 가져가도록 고쳤다.
- **정리**:
  - 테스트 워크스페이스는 정확한 id 로 지웠고, 남은 것이 0개인 것을 확인했다.
  - 2222 테스트 서버는 명령줄로 이 체크아웃 소유임을 확인한 뒤 그 PID 하나만 종료했다.
  - MCP 설정 파일은 백업본으로 되돌렸다. 운영 데몬(2001/2002/3333)은 같은 PID 로 그대로 떠 있다.

## 남은 것 / 범위 밖

- `cmd.exe` 에서 `npm run build`(frontend) 를 그냥 돌리면 postbuild 가 상속된 `BUILDERGATE_WEB_ROOT`(설치본)를 대상으로 잡는다. 이번에는 설치본 폴더가 읽기 전용이라 바뀐 것이 없었다(파일 날짜·번들 이름으로 확인). 대신 이 체크아웃의 `server/dist/public` 도 갱신되지 않았고, 테스트 서버가 옛 화면을 냈다. `BUILDERGATE_*` 를 지운 환경에서 다시 스테이징해 해결했다.
- 프런트 단위 전수에서 이번 작업과 무관한 선재 실패 3건이 보였다.
  - `apiErrorMessages` FR-I18N-007 AC-1: `LOCAL_LOGIN_*` 코드가 표에 없다.
  - `editorPortContract`: 27 대신 28 파일.
  - `tsconfigTestMembership`: `editorBoldToggle`, `editorCodeBlockLanguages` 가 미등재.
- FR-MDE-027 AC-3(이미 열린 대상 선택)과 AC-4(SVG 미저장 시 비활성)는 단위 테스트로만 확인했다. 실제 브라우저에서는 보지 않았다.
