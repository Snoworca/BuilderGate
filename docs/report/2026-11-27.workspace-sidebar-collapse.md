# 워크스페이스 사이드바 접기와 원 아이콘 목록 (FR-UIDS-016)

## 이슈 설명

데스크톱 워크스페이스 목록 영역이 220px 로 고정되어 있어 넓고, 화면을 많이 차지한다. 버튼으로 목록을 접고 다시 펼칠 수 있어야 한다는 요청이다.

- 헤더 옆에 햄버거 버튼을 두고, 이 버튼으로 접기와 펼치기를 한다.
- 접은 상태에서는 각 워크스페이스를 원 안의 한 글자로 보여 준다.
- 질문(대기)과 동작(실행) 표시는 원의 왼쪽 위와 오른쪽 위에 둔다.

## 문제 원인

- 데스크톱 사이드바는 `frontend/src/App.tsx` 에서 `style={{ width: '220px', flexShrink: 0 }}` 로 폭이 고정돼 있었고, 접는 기능이 없었다 (변경 전 `git show 95eaaeb1^:frontend/src/App.tsx` 1239행).
- 모바일 드로어(`frontend/src/App.tsx` 1259행)가 같은 `sidebarContent`(`WorkspaceSidebar`)를 재사용한다. 접기를 넣으면 모바일 목록도 접힐 수 있으므로, 모바일에서는 접기를 끄는 장치가 필요했다.

## 해결 방법

- `WorkspaceSidebar` 에 `collapsible`, `collapsed`, `onCollapsedChange` 를 추가했다. 헤더 옆 햄버거 버튼은 `aria-expanded` 를 갖고, 라벨은 `workspace.sidebar.collapse` / `workspace.sidebar.expand` 키로 i18n 을 거친다 (`frontend/src/components/Workspace/WorkspaceSidebar.tsx` 102~105행).
- 접힘 폭은 56px 다 (`frontend/src/components/Workspace/workspaceSidebarStore.ts` 13행).
- 접힌 행은 원 안에 이름의 첫 grapheme 을 보여 준다. `workspaceInitial.ts` 가 `Intl.Segmenter` 로 자르고, NFC 로 정규화한 뒤 대문자로 바꾼다. 원의 `title` 과 `aria-label` 에는 전체 이름을 둔다 (`frontend/src/components/Workspace/WorkspaceItem.tsx` 102행).
- 활성 워크스페이스 원에는 accent 색 테두리를 둔다. 대기 배지는 왼쪽 위, 실행 배지는 오른쪽 위에 둔다.
- 접힌 동안에는 헤더의 햄버거만 남기고, 사용량 패널(`UsageLimitsPanel`)과 버전 줄을 숨긴다 (`frontend/src/components/Workspace/WorkspaceSidebar.tsx` 147~158행).
- 접힘 상태는 localStorage 키 `buildergate.workspaceSidebar.collapsed` 에 저장한다. 저장된 값이 정확히 `'true'` 일 때만 접히고, 값이 없거나 다른 값이거나 저장소가 예외를 던지면 펼친다 (`workspaceSidebarStore.ts` 27~30행).
- 모바일은 `collapsible={!isMobile}` 로 항상 펼친 상태를 유지한다 (`frontend/src/App.tsx` 1203행).
- 접힌 상태에서 이름 바꾸기를 시작하면 먼저 사이드바를 펼친 뒤 편집한다.
- 요구사항 FR-UIDS-016 을 `docs/spec/44.ui-design-system.srs.md` 1026행에 추가했고, status 는 implemented 다.

## 남은 한계

- 기본 이름 `Workspace-N` 은 첫 글자가 모두 `W` 라서, 접힌 원만으로는 구분할 수 없다. 전체 이름은 툴팁으로 확인한다.
- 스크롤바가 있을 때 두 자리 배지끼리 약간 겹칠 수 있다. 기본 탭 한도 8 에서는 배지가 한 자리라 겹치지 않는다.
- 접힌 상태에서 끌면 드래그 고스트에 보이는 이름이 잘린다.
- 접힌 행의 드래그 재정렬과 탭 드롭은 브라우저에서 실측하지 않았다. 코드 리뷰로만 확인했다.
- 작업 중 사고 (시험 환경): 시험 서버가 MCP 포트 `127.0.0.1:3333` 도 함께 열어, 약 17분 동안 로컬 MCP 연결이 시험 서버로 붙었다 (응답 `INVALID_TOKEN`). 시험 서버 프로세스만 종료해 복구했고, 운영 프로세스에는 영향이 없었다 (구현 세션 기록). 다음 시험 서버부터는 `BUILDERGATE_MCP_PORT` 로 다른 포트를 지정한다.
