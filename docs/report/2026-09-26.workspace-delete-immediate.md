# 터미널이 여러 개인 Workspace 즉시 삭제

- 날짜: 2026-09-26
- 요구사항: PERF-BGSTAB-015 (신규, `docs/spec/30.buildergate-stability.srs.md`)
- 커밋: `1c348e3d`

## 이슈

Workspace에 터미널이 2개 이상 있으면, 삭제를 확인한 뒤에도 한참 기다려야 삭제되었다.

## 원인

- 서버의 `terminateMultipleSessions`가 탭마다 검증된 프로세스 트리 종료를 차례로 기다렸다. Windows에서는 한 번에 PowerShell identity 조회, 트리 종료, 정착 확인이 들어 약 2초가 걸리고, 이 시간이 탭 수만큼 쌓였다.
- 화면은 서버가 답할 때까지 확인창을 닫지 않았고, 목록에서도 빼지 않았다.

## 해결

| 위치 | 변경 |
|---|---|
| `server/src/services/SessionManager.ts` | `terminateMultipleSessions`가 세션 종료를 동시에 실행한다. 한도는 8개로, `maxTabsPerWorkspace` 기본값과 같다. 결과는 입력 순서로 모으므로 `missing` 순서와 자손 합계는 이전과 같다. graceful shutdown의 `terminateAllSessions`도 이 경로를 쓴다. |
| `frontend/src/hooks/useWorkspaceManager.ts`, `workspaceRemoval.ts` | 확인하면 Workspace, 탭, 그리드 배치를 먼저 화면에서 뺀 뒤 서버에 요청한다. 서버가 거절하면 모두 되돌리고, 원래 선택을 복원하고, 오류를 보여 준다. 로컬 배치와 스냅샷은 서버가 성공한 뒤에만 지운다. |
| `frontend/src/App.tsx` | 확인창이 삭제를 기다리지 않고 바로 닫힌다. |

## 남은 것

- 세션 하나를 닫는 비용(약 1.5~2초, PowerShell 두 번)은 그대로다. PERF-BGSTAB-013/014의 범위다.
- 화면에서 뺀 뒤 서버가 세션을 종료한 다음 저장에 실패하는 드문 경우, 되돌아온 탭은 끊긴 세션으로 보인다.
