# MCP 로 사용자 브라우저에 알림 보내기 (FR-MCP-012)

## 요청

MCP 로 브라우저 알림을 보낸다. 원격 접속에서도 동작해야 한다.

## 원인

- 에이전트가 사용자의 주의를 끌 수단이 없었다.
- 서버에서 브라우저로 이벤트를 보내는 방송 경로(`wsRouter.broadcastAll`)는 이미 있었다. 하지만 브라우저 알림(Notification API)은 어디에서도 쓰지 않았다.
- 원격 접속에서 자체 서명 인증서를 쓰면, 브라우저가 시스템 알림을 막을 수 있다.

## 해결

### 서버

- **새 MCP 도구**: `buildergate.notify`
  - 인자: `title`(1~100자), `body`(최대 500자), `level`(info, success, warning, error)
  - 동작: 연결된 모든 브라우저 페이지에 `notification:show` 이벤트를 보낸다.
  - 응답: `notificationId` 와 `deliveredTo`(그 순간 연결된 브라우저 연결 수)
- **보낸 쪽 정보**: 인증된 호출자 정보로 서버가 채운다(별칭, sessionKey, workspaceId, tabId). 고정 키로 보내면 보낸 쪽은 비어 있다.
- **호출 제한**: 같은 호출자는 60초에 6회까지 보낼 수 있다. 초과하면 `RATE_LIMITED` 를 돌려준다.
- **새 권한**: `mcp:notify`. 고정 키와 기본 세션 actor 모두에게 준다. 이것은 SEC-MCP-004 의 권한 목록을 확장하므로, SEC-MCP-004 에 변경 노트를 남겼다.

### 브라우저

브라우저는 상황에 따라 알림을 다르게 보여 준다.

- **페이지가 가려져 있고 알림을 허용한 경우**
  - 시스템 알림을 띄운다. 알림 id 를 tag 로 쓰므로, 페이지를 여러 개 열어 두어도 알림은 한 번만 뜬다.
  - 알림을 누르면 창이 앞으로 오고, 보낸 세션의 워크스페이스와 탭이 열린다.
- **그 밖의 경우**(페이지를 보고 있거나, 권한이 없거나, 브라우저가 알림을 막은 경우)
  - 페이지 안 오른쪽 위에 알림을 띄운다. 사용자가 닫거나 누를 때까지 남는다.
  - 페이지가 가려져 있는 동안에는 탭 제목에 읽지 않은 알림 개수를 붙인다(예: `(1) BuilderGate`).
  - 원격 접속에서 시스템 알림이 막혀도, 이 방식으로 알림을 받을 수 있다.
- **설정 화면**: "브라우저 알림" 카드를 추가했다. 카드에는 현재 상태, 알림 허용 버튼, 테스트 알림 보내기 버튼이 있다.
- **그 밖의 변경**: MCP 감사 로그 라벨과 i18n(영어, 한국어) 문자열을 추가했다.

## 검증

- **새 테스트**: 서버 6건(`McpNotify.test.ts`)과 프런트 6건(`browserNotifications.test.ts`)을 추가했다. 모두 구현 전에 실패하는 것을 먼저 확인했다.
- **기존 테스트 수정**: 권한 목록을 정확히 비교하던 테스트 5곳에 `mcp:notify` 를 추가했다. 권한 목록이 바뀌는 것이 의도한 변경이기 때문이다.
- **회귀 확인**: 아래가 모두 통과했다.
  - MCP 스위트 44건
  - 모놀리식 러너 533개
  - `TerminalResourcePolicy` 21/21
  - `test:release-pipeline`
  - 타입 검사, i18n 가드, 빌드
- **실제 브라우저 확인**: 2222 테스트 서버, MCP 3334(운영 데몬은 3333 유지), Edge 로 확인했다.
  - 페이지를 보고 있을 때: 페이지 안 알림이 떴다.
  - 권한을 허용하고 페이지가 가려졌을 때: 시스템 알림이 생성됐다. 알림을 누르자 보낸 세션의 워크스페이스(`bg-notify-probe`)로 이동했다.
  - 권한이 없고 페이지가 가려졌을 때: 페이지 안 알림이 뜨고 탭 제목이 `(1) BuilderGate` 가 됐다. 페이지로 돌아오자 제목이 원래대로 돌아왔다.
  - 설정 카드가 상태를 올바르게 표시했다("아직 묻지 않음", "허용됨").
  - 7번째 호출은 `RATE_LIMITED` 를 돌려받았다.
  - 스크린샷: `.playwright-mcp/notify-*.png`
- **정리**: 테스트 워크스페이스는 정확한 id 로 지웠다. MCP 설정 파일은 백업본으로 되돌렸다. 테스트 서버를 종료했다.

## 한계

- **가려진 상태는 흉내 냈다**: Playwright 는 모든 페이지를 보이고 포커스된 상태로 유지한다. 그래서 `visibilityState` 와 `hasFocus` 를 페이지 안에서 덮어써서 가려진 상태를 만들었다. 이 두 값 외에 판정, 알림 생성, 이동은 실제 코드가 실행했다.
- **OS 알림 창은 직접 보지 않았다**: 알림 생성자 호출을 기록해서 확인했다. OS 화면에 알림 창이 실제로 뜨는지는 확인하지 않았다.
- **원격 PC 에서는 시험하지 않았다**: 원격 PC 에서 설정의 "테스트 알림 보내기"로 확인할 수 있다.
- **이미 연결된 세션 에이전트는 바로 쓸 수 없다**: 새 권한을 받으려면 세션 토큰을 다시 받아야 한다(다시 연결하거나 다시 claim).
- **브라우저를 닫으면 알림을 받을 수 없다**: BuilderGate 탭이 하나도 열려 있지 않으면 알림이 전달되지 않는다. 이를 해결하려면 Web Push 가 필요하며, 이번 범위에 넣지 않았다.
