# 편집기 대기 알림과 탭 보기 다시 그리기 (FR-ARCH-014, REL-BGSTAB-050)

## 이슈 설명

BuilderGate 2222 서버의 Claude Code 세션 하나가 멈춘 것처럼 보였다. 새로고침해도 화면이 스크롤되지 않았고, 창 안에 전부 보이지 않았다.

조사 결과 세션 안의 Claude Code 가 서버 PC 에서 메모장을 띄우고 그 종료를 기다리고 있었다. 사용자는 이런 멈춤을 모바일에서도 알아볼 수 있고 직접 풀 수 있기를 원했다. 그래서 다음 두 가지 개선을 골랐다.

- 편집기를 기다리는 세션을 앱이 알리고, 그 편집기를 닫는 버튼을 제공한다.
- 탭 보기에서도 화면을 실제 크기로 다시 그린다.

## 문제 원인

원인 분석은 2026-10-21 에 실측으로 확인했다. 근거는 2222 데몬 로그(`runtime/buildergate-daemon.log`)의 resize·snapshot 이벤트, 브라우저 터미널 디버그 캡처, 프로세스 트리 조회다.

1. 세션 안의 Claude Code 가 11:27 KST 에 `start /wait notepad` 로 서버 PC 바탕화면에 메모장을 띄웠다. 메모장은 2시간 반 동안 닫히지 않았다. 외부 편집기로 프롬프트를 편집하는 기능(Ctrl+G)으로 보인다. 사용자가 직접 누른 것인지는 확인하지 못했다.
2. 그 직전 휴대폰 접속이 PTY 를 43열로 바꾸었다. 앱은 43열 기준으로 화면을 그렸다. 이후 데스크톱이 208열로 되돌렸지만, 앱은 대기 중이라 다시 그리지 않았다.
3. 대기 중에는 마우스 보고가 none 이었고 활성 버퍼가 alternate 였다. 그래서 휠 스크롤이 동작하지 않았다.
4. 메모장을 닫은 뒤에도 앱은 43열 화면을 유지했다. 새로고침은 같은 크기의 resize 를 서버가 건너뛰었다(resize_skipped). 그래서 앱에 다시 그리라는 신호가 가지 않았다. 브라우저 창 크기를 실제로 바꾸자 앱이 즉시 전체 폭으로 다시 그렸다.
5. 탭 보기에는 화면을 복구하는 수단이 없었다. REL-BGSTAB-047 은 같은 문제를 그리드 칸에서 푼 요구사항이다. 그 "한 줄 줄였다가 복원" 동작은 그리드 칸에만 적용되어 있었다.

현재 SRS 기준으로는 BuilderGate 의 결함이 아니라 요구사항 공백으로 판정했다. 편집기 대기 감지와 탭 보기 복구가 요구사항에 없었기 때문이다.

## 해결 방법

### FR-ARCH-014: 편집기 대기 알림과 닫기

- 서버가 20초마다 세션 셸의 하위 프로세스를 조회한다. GUI 편집기(notepad.exe, notepad++.exe, code.exe 등)가 있으면 `session:editor-wait` 메시지로 알린다.
- 세션이 없으면 조회하지 않는다. 조회가 겹쳐 실행되지 않는다. 조회가 실패하면 이전 판정을 유지한다.
- 터미널 위에 안내 문구와 "편집기 닫기" 버튼을 표시한다.
- 닫기는 편집기의 PID 와 생성 시각을 새 프로세스 목록으로 다시 확인한 뒤, 그 프로세스 하나만 종료한다. 다른 프로세스는 건드리지 않는다.
- 늦게 붙은 터미널은 마운트할 때 `GET /api/sessions/:id/editor-wait` 로 현재 상태를 읽는다. WsRouter.ts 는 봉인된 authority 소스이므로 구독 경로를 바꾸지 않았다.
- FR-ARCH-014 AC-2 의 문구는 "구독 시점의 현재 상태를 받는다"이다. 구현은 구독 메시지 대신 마운트 시 REST 조회로 같은 결과를 낸다. 이 차이는 SRS 증거 비고(VE-2)에 적었다.
- 확인과 종료 사이에 편집기가 먼저 끝나면(ESRCH) `EDITOR_WAIT_GONE` 을 돌려준다. 그 밖의 예외는 500 으로 응답한다. Express 4 는 async 함수의 예외를 자동으로 잡지 않으므로 라우트에서 직접 처리했다.

### REL-BGSTAB-050: 탭 보기 다시 그리기

- 탭 보기의 터미널이 보이게 될 때(새로고침 포함)와 탭 또는 그리드 전환 때, PTY 를 한 줄 줄였다가 되돌린다. 그러면 터미널 안 프로그램이 실제 크기 변경 신호를 받고, 실제 크기로 화면을 다시 그린다.
- 터미널 메뉴(PC 우클릭, 모바일 길게 누르기)에 "화면 다시 그리기" 항목을 넣었다.
- 그리드의 가운데 클릭 복구 동작은 그대로 둔다.
- 요구사항 번호: 이 작업은 처음에 REL-BGSTAB-049 로 썼다. 그런데 main 이 같은 번호를 먼저 썼다. 그래서 speckiwi 의 repair requirement-id-collisions(diagnose, plan, apply) 절차로 REL-BGSTAB-050 으로 바꾸었다.
