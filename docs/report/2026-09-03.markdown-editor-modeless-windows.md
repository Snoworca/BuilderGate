# 마크다운 편집기와 모달리스 창 시스템

- **커밋**: `a681cb1 feat(editor): add a modeless markdown editor over a two-band dialog stack`
- **요구사항**: `FR-MDE-001`~`009` · `CON-MDE-001`·`002` · `IR-MDE-001` (12건, AC 97개)
- **상태**: 12건 전부 `planned` → `implemented`, 검증 증거 부착

## 1. 이슈

DocuLight2.0 의 마크다운 편집기를 BuilderGate 로 이식하고, 그것을 담을 모달리스 창 시스템을 만드는 작업이다. 요구는 셋이었다.

1. 여러 개를 띄우고 클릭으로 앞뒤를 정하며 닫기·최소화·최대화가 되는 창. **최대화해도 좌측 워크스페이스 창과 상단 작업 표시줄을 가리지 않아야 한다.**
2. 편집기를 그 창에 결합.
3. 세션 경로 우클릭으로 `CLAUDE.md`·`CLAUDE.local.md`·`AGENTS.md` 를 편집. 파일이 없으면 생성을 묻고, 미저장이면 제목에 `*`, `Ctrl+S` 로 저장하면 사라진다.

추가로 확정된 것은 **설정 다이얼로그는 모달이고 편집기는 모달리스**라는 점, 그리고 **100KB 를 넘는 문서도 저장되어야 한다**는 점이다.

## 2. 문제 원인

### 2.1 편집기를 띄울 표면이 없었다

기존 `WindowDialog` 는 모달 하나만 가정해 스택이 단일했다. 편집기를 그 위에 올리면 설정 다이얼로그와 z 축을 다투게 되고, "설정 중에는 편집기를 조작할 수 없다"는 요구를 표현할 수단이 없다.

### 2.2 서버가 열 수 있는 파일을 저장하지 못했다

`server/src/index.ts` 의 `express.json()` 이 `limit` 없이 등록되어 요청 본문이 body-parser 기본값인 **100KB** 로 묶였다. 그런데 `config.schema.ts` 의 `maxFileSize` 기본값은 **1MB** 다.

그래서 100KB 를 넘고 1MB 이하인 파일은 **읽기로는 열리지만 저장할 수 없었고**, 그 실패가 크기 초과를 알리는 413 이 아니라 **500** 으로 나갔다. 사용자는 왜 실패했는지 알 수 없다.

## 3. 해결

### 3.1 스택을 두 밴드로 나눴다

`dialogStack.ts` 가 `modal` 과 `modeless` 스택을 따로 들고, 모달은 3000 대가 아니라 5000 대 밴드에 선다. 설정은 입력을 막고 편집기는 막지 않는다.

기존 모달 여섯(`CommandPresetDialog`·`MessageBox`·`McpControlDialog`·`RecoveryOptionDialog`·`TerminalShortcutDialog`·`WorkspaceMoveDialog`)의 쌓임 순서·Escape 처리·Tab 가둠은 그대로다. 그것을 `markdown-editor-modal-regression.spec.ts` 19건이 고정한다.

### 3.2 계단식 단계를 저장하지 않는다

창은 `floating`·`docked`·`stage` 세 배치 상태를 갖고, `docked` 진입 시 계단식 단계 `k` 를 **그때 다시 계산한다.**

저장하면 안 되는 이유가 있다. 단계를 저장해 두고 복원하면 재계산 규칙이 무력화되어, 한쪽이 움직였다 돌아온 뒤에는 **새로고침 전에 어긋나 있던 두 창이 정확히 겹쳐 돌아온다.** 그리고 단계는 창의 개수가 아니다 — 0·1·2 중 1 의 창이 닫히면, 개수로 세는 구현은 다음 창에게 이미 점유된 2 를 준다.

### 3.3 영속화에서 본문과 측정 rect 를 뺐다

`window_state_<workspaceId>` 에 탭 ID·파일 경로·배치 상태·최소화 여부·스택 위치만 담는다. 문서 본문은 담지 않고 디스크에서 다시 읽는다.

`docked` 와 `stage` 의 rect 도 담지 않는다 — **매번 측정되므로** 저장하면 낡은 사본이 살아 있는 측정과 어긋날 뿐이다. 다만 사용자가 끌어 놓은 `floatingRect` 는 배치 상태와 무관하게 담는다. `fillTerminal` 과 `toggleMaximize` 가 그것을 **일부러 보존하는 복귀 지점**이라, 떨어뜨리면 그 창은 새로고침 후 돌아갈 자리를 잃는다.

### 3.4 전송 한도를 같은 값이 아니라 파생값으로 맞췄다

`requestBodyLimit.ts` 를 새로 만들어 `max(1048576, maxFileSize * 6 + 8192)` 를 쓴다.

두 한도를 **같게** 맞추지 않은 이유가 있다. JSON 봉투는 `24 + 경로 길이` 이고 본문은 이스케이프로 팽창하는데, `isBinaryFile` 이 앞 8KB 에서 `0x00` 만 표본하므로 **읽기 경로가 6.00배 팽창하는 파일을 실제로 내준다.** 한도를 같게 두면 방금 연 파일을 저장할 수 없다.

`writeFile` 에는 읽기 경로가 이미 밟는 세 검사(`assertSessionExists` → `resolveAndValidate` → `isBlockedExtension`)를 같은 순서로 붙이고, 디코드된 본문이 `maxFileSize` 를 넘으면 거절한다.

### 3.5 결속된 탭이 닫혀도 본문을 잃지 않는다

탭이 닫히면 그 창은 사라지지 않고 `floating` 으로 옮겨 가며 미저장 본문을 유지한다. 저장할 곳이 없으므로 닫기 확인은 "저장하시겠습니까"가 아니라 **"저장할 수 없습니다. 그래도 닫으시겠습니까"** 라는 다른 질문을 띄운다. 같은 확인에서 저장 갈래만 비활성화한 것이 아니다.

## 6. 남은 사항

### 6.1 어느 AC 도 요구하지 않아 구현하지 않은 것 둘

- **복원 재시도 경로가 없다.** `fileApi.readFile` 에 타임아웃이 없어, 페이지 로드 시점에 세션이 아직 붙지 않은 탭의 편집기 창은 새로고침 전까지 돌아오지 않는다.
- **`clearWindowStateForWorkspace` 가 없다.** mosaic 선례에는 있고 `workspace:deleted` 에서 불린다. 지금은 워크스페이스를 지워도 저장 키가 남는다.

### 6.2 red 기록이 없는 Task 셋

`T-PH001-05` · `T-PH007-01` · `T-PH007-03` 의 red 증거가 없다. 담당 레인이 세션 기록을 남기지 않았고, 지금 재현하려면 구현을 되돌려야 한다.

짝이 되는 green Task 에는 증거가 있고 대조표도 해당 AC 를 통과로 적으므로 **통과 판정 자체는 흔들리지 않는다.** 다만 그 red 들이 실제로 빨갰다는 기록은 남아 있지 않다.

### 6.3 이번 작업 범위 밖에서 확인된 것

**`CLAUDE.md` 의 테스트 표가 실제와 다르다.** 전부 실측이다.

| 위치 | 문서 | 실제 |
|---|---|---|
| `server/src/**/*.test.ts` | 37 | **59** |
| `tools/daemon/*.test.js` | 19 | **20** |
| `frontend/tests/unit/` | 56 | **92** |
| `tests/e2e/*.spec.ts` | 30 | **37** |
| Playwright 3종 수집 | 465 | **651** (`Desktop Chrome` 단독 217) |
| SplitHandshake 진단 | `✖` 목록과 대조 | 항목은 **`⚠`** — `✖` 는 절 제목 1줄뿐이라 그 지침대로는 0건이 잡힌다 |

`tests/benchmarks/` 2개만 정확했다.

**타입 검사가 테스트 82개에 닿지 않는다.** `tsc -b` 의 참조는 `editor`/`app`/`node` 뿐이라 테스트 파일을 하나도 보지 않고, `tsconfig.test.json` 은 허용목록이며 47개만 담는다(`tests/e2e` 는 0개). 결과적으로 e2e 37개 전부와 단위 92개 중 45개가 검사 밖이다.

단 **그 미등재는 의도된 선택**이다 — 파일 주석이 "Deliberately NOT listed" 라고 적고 있고, 테스트 전용 타입 오류가 `npm run build` 와 CI 를 깨뜨리지 않게 하려는 것이다. solution 에 그냥 등재하면 빌드가 깨진다.

**`WorkspaceService.flushToDisk` 의 동시 진입 — 확인했고 고쳤다.** 커밋 `3adda52`, 요구사항 `REL-BGSTAB-020`.

재현했다. 탭 200개 상태에서 즉시 저장 2회를 동시에 부르면 **20회 중 15회** 실패하고, 5회면 20/20 이다. 오류는 `EPERM`/`EBUSY` 가 아니라 **`ENOENT: rename 'workspaces.json.tmp' -> 'workspaces.json'`** — 두 flush 가 같은 임시 파일을 쓰고 먼저 도착한 rename 이 그것을 옮겨버려 두 번째가 원본을 잃는다. 빈 상태에서 2회가 통과하는 것은 페이로드가 작아 두 쓰기가 한 틱에 끝나기 때문이고, 그래서 **깨끗한 픽스처에서는 드러나지 않는다.**

겹칠 창은 우연이 아니었다. `index.ts:1461-1465` 가 **30초마다** `snapshotAllCwds()` 뒤에 `forceFlush()` 를 부르고 실패를 `.catch` 로 삼킨다. 디바운스가 아니라 즉시 경로이므로 **서버가 사는 내내 30초 주기로 창이 열리고, 그 안에 요청이 들어가느냐만 무작위다.** "인스턴스가 노후하면 500 이 난다"고 읽히던 것은 **오래 돌수록 그 창을 더 많이 가로지르는 것**이었다.

종료 경로도 이미 잃고 있었다. `gracefulShutdown.ts:250` 이 CWD 를 스냅숏하고 `:251` 이 `forceFlush()` 를 기다리는데, **타이머는 `:259` 에서야 꺼진다.** 첫 강제 flush 가 살아 있는 타이머와 경합해 던지면 `index.ts:234` 에 try/catch 가 없어 **세션 정리 전에 종료가 중단된다.**

고친 형태는 `flushToDisk` 안의 promise 체인이다. `save(true)` 20곳·`forceFlush` 3곳·`initialize` 3곳이 전부 그 하나를 지나므로, **`save` 에 두었다면 뒤의 여섯이 보호 밖에 남았을 것이다.** 페이로드는 큐에 넣을 때가 아니라 **실행될 때** 직렬화되므로 호출자의 완료가 자기 변경의 디스크 도달을 함의한다.

**기각된 대안 — in-flight promise 재사용.** 이것을 제안했으나 `flushToDisk` 가 진입 시점에 동기 직렬화한다는 사실이 그것을 막는다. 진행 중인 flush 에 올라탄 호출자는 **자기 변경이 담기지 않은 쓰기의 완료**를 받으므로, 눈에 보이는 거부가 조용한 유실로 바뀐다. 이것을 대조 뮤턴트로 세워 확인했다 — **그 대안은 AC-1 과 AC-2 의 "거부되지 않는다" 절반을 전부 통과하고, 디스크에서 변경을 되읽는 단언 하나에만 걸린다.** AC 문면에 그 절반이 없었다면 잘못된 구현이 통과했을 것이다.

**여전히 남은 것 셋.** 전부 이번 범위 밖이며 고치지 않았다.

- **`gracefulShutdown.ts` 의 타이머 정리(`:259`)가 첫 강제 flush(`:251`) 뒤에 있다.** 직렬화가 증상을 없애지만 순서 자체는 그대로다. 두 변경을 함께 하면 어느 쪽이 증상을 없앴는지 판정할 수 없어 제외했다. `index.ts:234` 에 try/catch 가 없다는 사실도 남는다.
- **`addTab` 이 PTY 를 먼저 만들고 나중에 저장한다.** `createSession`(`:562`)이 `save(true)`(`:614`)보다 앞이라, 저장이 거부되면 **PTY 는 살아 있고 탭은 메모리에 남는데 클라이언트만 500 을 받는다.** 이번 수정으로 그 거부를 만들던 트리거는 사라졌지만 순서는 그대로이고, 진짜 I/O 실패에서는 여전히 성립한다.
- **`migrateGridLayouts`(`:1616`)의 `this.save(true)` 가 await 되지 않는다.** 거부되면 unhandled rejection 이 된다. `index.ts:187` 의 핸들러가 로그만 찍고 넘어가므로 **프로세스가 죽지는 않지만**, 레거시 GridLayout 마이그레이션 결과가 저장되지 않아도 호출자는 성공으로 진행하고 아무도 모른다.

**죽은 UI 를 겨냥한 spec 이 남아 영구히 빨갛다.** `pane-keyboard` 3건과 `pane-persistence` 2건이 `src` 에 존재하지 않는 선택자를 기다린다 — `.pane-leaf` 는 0건이고 `.status-prefix` 는 렌더 트리에 연결되지 않은 `StatusBar/` 에만 있다.
