## 1. 이슈

터미널 출력을 JSON 에서 바이너리 WebSocket 프레임으로 전환하는 작업에서, 프레임이 end-to-end 로 흐르지 않았다. 코덱 자체(인코더·디코더·골든 벡터)는 이미 있었으나 그것을 실제 경로에 잇는 조각이 없었다.

## 2. 문제 원인

착수 전 실측으로 확인한 공백은 다섯 가지였다.

| 2 | 서버에 채널 할당자 없음 | `grep -rn channelId server/src` 가 타입 선언 1건만 반환 |

## 3. 해결 방법

### 3.1 `:3299` 정책 — 가드를 추가하지 않는다

세 가지를 추적해 결정했다.

1. 수렴 상태의 `replayToken` 은 옵셔널이 아니고(`:218`·`:234`), 상태는 `:2288` 에서 서버가 준 구체적 토큰이 있을 때만 성립한다. 즉 이 자리에서 토큰의 부재는 "모름"이 아니라 "기다리는 그 재생물이 아님"이다.
2. 저장소 키는 `${wsConnectionGeneration}:${sessionGeneration}`(`:350`)이고, `:3295` 의 `isCurrentCompatibilityPostAckState`(`:1404-1411`)가 **같은 세대쌍**을 `:3299` 보다 먼저 검사한다. 세대가 밀리면 `:3299` 에 도달하지 않는다.
3. `forget` 호출 3곳(`:1116`·`:1129`·`:1723`)이 각각 떠나는 세션 id 를 쓰거나, 같은 effect 의 `:1136` 이 수렴을 `null` 로 만들거나, 직후 `:1724` 가 다시 기록한다.

따라서 `:3299` 에서 `undefined` 는 저장소 경로로 도달하지 않는다. 가드는 도달 불가능한 경우를 지키면서 수렴의 증명 기능만 약화시킨다.

⚠️ **이 판단은 독립 검증을 받지 못했다.** 반박 전용 서브에이전트를 2종 띄웠으나 3회 요청 모두 판정 없이 유휴로 종료했다. 위 사실 확인은 전부 작성자가 직접 명령을 실행해 대조한 것이다.

### 3.3 기본값이 전부를 가둔다

`realtime.terminalWireFormat` 의 기본값은 `json` 이다. 이 값에서는 `isBinaryNegotiable` 이 거짓이고, 그룹은 채널을 열지 않으며, `subscribed` 메시지는 오늘과 동일한 4개 키만 싣는다. `WsRouterBinaryChannels.test.ts` 가 그 키 집합을 직접 단언한다.

## 4. 뮤테이션이 잡아낸 결함 4건

뮤테이션은 이번 작업에서 네 번 실제 결함을 잡았다. 전부 테스트가 green 인 상태에서였다.

1. **`binaryFrameIntake`** — opcode `0x03`·`0x06`·`0x07` 은 `prologueBytes` 가 0 이라 `parseFrameMessage` 가 `undefined` 를 반환하는데, 구현이 그것을 **진단 없이 건너뛰고** 있었다. 세 opcode 모두 프레임으로 정상 디코드되므로 도달 가능한 무성 소실이었다. `unhandledOpcodes` 에 기록하도록 고치고 회귀 뮤턴트를 추가했다.
2. **`terminalChannelAllocator`** — 「유예가 지났지만 아직 `sweep` 을 돌리지 않은 구간」이 통째로 미검증이었다. `lifecycle`·`sessionOf` 가 표가 아니라 시계로 계산하는 이유가 정확히 그 구간이므로, 두 함수의 존재 이유가 검증되지 않은 상태였다.
3. **`terminalOutputWireAdapter`** — 세그먼트의 `screenSeq` 상속은 테스트했으나 `authorityRevision` 상속이 빠져 있었다.
4. **`terminalBinaryNegotiationClient`** — `asRecord` 가드 완화 뮤턴트가 살아남았다. 두 판본을 나란히 실행해 갈리는 입력이 `type` 속성을 가진 배열 하나뿐임을 확인했고(`JSON.parse` 로는 생성 불가), 진입점이 `unknown` 을 받으므로 그 입력을 테스트로 고정했다.

## 5. 타입체크가 공허했던 두 지점

- **프론트** — `frontend/tsconfig.test.json` 의 `files` 허용목록에 `wsFrameDispatch.test.ts` 와 `terminalOutputDeliveryBinary.test.ts` 가 빠져 있었다. 두 파일은 `tsc` 를 아예 통과하지 않고 있었다. 목록에 넣자 그 둘은 깨끗했으나, 새로 작성한 테스트에서 즉시 실제 오류가 나왔다(`whole.data` 가 `string | Uint8Array` 인데 좁히지 않고 `byteLength` 접근).
- **서버** — `tsx --test` 는 타입을 검사하지 않는다. 협상 테스트 21건이 전부 green 인 상태에서 `tsc` 를 돌리자 유니온 타입 접근 오류 10건이 나왔다. 판별자를 런타임에 확인하는 단언 함수로 고쳤고, 그 과정에서 치환이 함수 본문까지 바꿔 무한 재귀를 만든 것을 테스트 실행으로 잡았다.

## 7. 하지 않은 것과 그 이유

**`WsRouter.ts` · `SessionManager.ts` 배선에 착수하지 않았다.**

`subscribed` 행에 채널 정보를 실으려면 세션별 `streamEpoch` 이 필요하다. 그런데 `SessionManager.ts:1076` 의 `retainedTerminalStreamEpochCounter` 는 세션별이 아니라 **전역** 카운터다. 사양(`01:462`)은 이것을 세션 소유로 승격하라고 요구하며, 그 승격은 §4 롤백의 전제("epoch 을 올리면 클라이언트가 구 스트림을 자동 폐기")를 건드리는 의미론적 변경이다.

대신 그 승격의 대상이 될 원장을 순수 모듈(`terminalStreamEpoch.ts`)로 먼저 만들었다. `SessionManager` 쪽은 위임 몇 줄이 되며, 그 결정은 사용자 확인을 받는 편이 낫다고 판단했다.

## 8. 커밋하지 않은 이유

1. **부분 커밋이 CI 를 깬다.** `binaryFrameIntakeWiring.test.ts` 는 미커밋 상태인 `WebSocketContext.tsx`·`TerminalContainer.tsx` 의 내용을 검사한다.
2. **전부 커밋하면 남의 작업을 쓸어간다.** 공유 워킹트리이고 `git status --porcelain` 이 402 엔트리를 낸다 (2026-08-27 실측). 두 파일이 각각 1,154줄·1,952줄의 남의 미커밋 델타를 안고 있어 파일 단위로 갈라지지 않는다.
3. 되돌리기 어려운 행동이며, 기다려서 잃는 것이 없다.

## 9. 검증 한계 — 반드시 읽을 것

**이 작업은 독립 검증을 받지 못했다.** 서브에이전트를 총 6종(반박 2, 검증 1, 결정 위원회 3) 띄웠고, 재요청을 포함해 **모든 요청이 판정 없이 유휴로 종료**했다. 위 검증 결과는 전부 작성자가 직접 명령을 실행해 얻은 것이며, **기계적으로 확인 가능한 축**(테스트 수, 뮤턴트 생존 여부, 타입체크 exit code, 실패 집합 대조, 대조군 실행)에 한정된다.

검증되지 않은 것은 판단이 필요한 축이다 — 각 모듈의 설계가 옳은지, `:3299` 정책 결정이 타당한지, `wsTransportMode === 'unified'` 제약과 미지 `reason` 의 fail-safe 방향이 적절한지. 다음 세션은 이 축들을 사실로 받지 말고 처음 부딪히는 지점에서 재확인해야 한다.

**결정 위원회도 성립하지 않았다.** 사용자가 지시한 3인 위원회는 3인 전원이 기권했고, 두 결정(다음 구현 대상, 커밋 여부)은 작성자가 자체 조사로 내렸다.
