# 좁은 탭의 긴 질문 선택지와 작업 목록 패널에서 입력 대기 표시(?)가 뜨지 않는 문제 수정 (FR-AITUI-024 AC-1, #249)

## 이슈

og-flow 2289 탭에서 Claude Code가 질문 선택지를 띄웠는데도 탭에 입력 대기 표시(?)가 뜨지 않는 이유를 묻고, 고쳐 달라는 요청.

## 문제 원인

그 탭(43열, 휴대폰 폭)의 화면을 2002에서 캡처해 판정 함수에 넣어 보았다. 입력 대기 판정(`isAgentChoicePrompt`)은 화면 맨 아래 줄부터 위로 올라가며 메뉴 안내 줄(`Enter to select · …`)을 찾고, 찾으면 그 위에 커서(`❯`)가 붙은 선택지가 있는지 본다. 이 화면에서는 두 단계가 모두 빗나갔다.

1. 안내 줄 아래에 작업 목록 패널(`◼ …`, `✔ …`, `… +N`, `N/M tasks done`)이 붙어 있었다. 판정은 이 줄들을 「안내 줄 아래의 줄」로 세었고, 허용한 줄 수를 넘자 안내 줄을 찾기 전에 탐색을 멈췄다.
2. 선택지 설명이 좁은 폭 때문에 여러 줄로 접혀, 커서가 붙은 선택지 줄이 화면 위로 밀려났다. 판정은 화면만 읽고 scrollback은 읽지 않으므로, 안내 줄 위에서 커서 선택지를 찾지 못했다.

## 해결 방법

- 작업 목록 패널 줄(`TASK_PANEL_ROW`)은 안내 줄 아래 줄 수에 넣지 않는다. 패널이 아닌 줄은 지금처럼 센다.
- 안내 줄 위에 커서 선택지가 없더라도, 질문 메뉴의 고정 선택지(`N. Type something.`, `N. Chat about this`, `QUESTION_MENU_OPTION`)가 있으면 입력 대기로 본다. 이 두 선택지는 Claude Code 질문 메뉴에 항상 붙고, 일반 번호 목록에는 나오지 않는다.
- 커서 줄을 만나면 지금처럼 탐색을 멈춘다(입력 중인 프롬프트는 대기로 보지 않는다).

## 검증

- 2289 탭의 화면 캡처를 `claudeAskUserQuestionCursorAboveScreenTaskPanel` 픽스처로 넣고, 수정 전에 실패하는 것을 먼저 확인했다.
- 단위 테스트 4건을 더했다: 작업 목록 패널, 화면 위로 밀린 커서 줄, 패널이 아닌 줄이 쌓이는 경우(대기 아님), 고정 선택지가 없는 번호 목록(대기 아님).
- `agentChoicePrompt.test.ts` 58건 통과, 서버 `tsc --noEmit` 오류 없음.
- 실제 앱(2026-11-21): 깨끗한 워크트리에서 `de386403` 을 빌드해 2222로 띄우고 ego 브라우저로 열었다. 실제 PTY(PowerShell)에 2289 탭 캡처 화면을 화면 맨 아래 줄에 맞춰 출력하자, 1.0초 뒤 탭과 워크스페이스에 ? 표시가 떴다. 수정 전인 2002(0.11.9)에서는 같은 화면에 ? 표시가 뜨지 않았다. SRS VE-19.
