# macOS 에서 세션 터미널이 생성되지 않던 문제 수정

- 일자: 2026-10-03
- 요구사항: OPS-BGSTAB-017 AC-7 (신설, 체크됨, VE-5·VE-6)
- 커밋: 미커밋 (작업 트리에 변경만 남김)

## 1. 이슈

macOS(arm64)에서 워크스페이스에 터미널을 추가하면 세션이 만들어지지 않았다. Windows 에서는 같은 동작이 정상이다.
설치된 0.10.8 앱의 데몬 로그(`runtime/buildergate-daemon.log`)에 세션 생성마다 아래 오류가 남아 있었다.

```
[WorkspaceRoutes] Unexpected error: Error: posix_spawnp failed.
    at new UnixTerminal (/snapshot/BuilderGate/server/node_modules/node-pty/lib/unixTerminal.js:92:24)
    at SessionManager.createSession (...)
```

`npm ci` 직후의 소스 체크아웃에서 `pty.spawn('/bin/zsh', ...)` 한 줄로도 같은 오류가 재현됐다.

## 2. 원인

macOS 의 node-pty 는 PTY 를 만들 때마다 `prebuilds/darwin-<arch>/spawn-helper` 라는 별도 실행파일을
`posix_spawn` 으로 실행한다(`src/unix/pty.cc` 의 `__APPLE__` 분기). Windows(ConPTY/winpty)와 Linux(직접 fork)에는
이 헬퍼가 없으므로 macOS 에서만 생기는 문제다. 이 헬퍼가 실행 불가능한 이유가 두 겹으로 있었다.

1. **node-pty 1.1.0 이 헬퍼를 실행 권한 없이 배포한다.** `npm ci` 로 받은 파일이 `-rw-r--r--` 이다.
   소스에서 서버를 띄워도 모든 세션 생성이 실패한다.
2. **패키지된 앱(pkg)에서는 헬퍼 경로가 `/snapshot/...` 가상 경로다.** node-pty 는 헬퍼 경로를 자기 `__dirname`
   기준으로 모듈 로드 시 한 번 계산하는데, pkg 실행파일 안에서는 그것이 실행파일 내부 가상 파일시스템 경로라
   커널이 실행할 수 없다. 실행 권한이 있어도 실행되지 않는다.

`OPS-BGSTAB-017` VE-4 에 "macOS is build-only here; no macOS host was available" 로 남아 있던 그 공백이다.

## 3. 해결

`server/src/utils/nodePtySpawnHelper.ts` 를 추가했다.

- `installNodePtySpawnHelperGuard()` — node-pty 네이티브 모듈의 `fork` 를 감싸, 10번째 인자(헬퍼 경로)가
  항상 실행 가능한 실제 파일을 가리키게 한다. **macOS 에서만** 설치되며 Windows·Linux 에서는 아무 일도 하지 않는다.
  중복 설치되지 않는다.
- `resolveExecutableSpawnHelper()` — 헬퍼가 실행 가능하면 그대로, 실제 파일인데 권한이 없으면 제자리에서
  `chmod 755`, 그것이 불가능하거나(읽기 전용 설치) `/snapshot` 경로면 내용 해시로 키를 단 실행 가능 사본을
  `$TMPDIR/buildergate-node-pty/<hash>/spawn-helper` 에 만든다. 사본은 재사용하며, OS 가 임시 디렉터리를
  정리하면 다시 만든다. 어떤 단계든 실패하면 원래 경로를 돌려줘 node-pty 자신의 오류가 그대로 보이게 한다.
- `SessionManager` 생성자에서 실제 `pty.spawn` 을 쓸 때(테스트 주입이 아닐 때) 가드를 설치한다.

node_modules 를 직접 패치하지 않은 이유: `npm ci` 를 다시 하면 패치가 사라지는데 기존 `dist/` 는 재빌드 없이
그대로 기동되므로, 조용히 다시 깨지는 경로가 생긴다. 런타임 래핑은 설치 상태와 무관하게 동작한다.

### 함께 고친 macOS 전용 테스트 결함 (제품 코드 무관)

- `tools/build-portable-runtime-evidence.test.mjs` — 픽스처를 `os.tmpdir()` 아래 만들었는데 macOS 에서는
  `/var → /private/var` 심볼릭 링크라 검증기의 "심볼릭 링크 조상 금지" 규칙에 걸려 6건이 실패했다.
  `realpathSync(tmpdir())` 로 바꿨다. 검증기 자체는 그대로다.
- `server/src/test-runner.ts` 의 "configured host shell is unavailable" 테스트 — `platform: 'linux'` 로 고정하고
  zsh 가 없다고 전제했지만 명령 탐지를 주입하지 않아 실제 호스트의 `which zsh` 를 물었다. macOS 에는 항상
  `/bin/zsh` 가 있어 실패했다. `isCommandAvailableFn` 을 주입해 전제를 명시했다. 단언은 바꾸지 않았다.
- `tools/wave3/terminal-resource-consumer-manifest.test.mjs` — 하위 실행 출력을 spec 리포터 형식(`ℹ pass N`)으로
  파싱하는데 Node 22 는 TTY 가 아닐 때 TAP 를 낸다. `--test-reporter=spec` 을 명시했다.
  이 파일과 `SessionManager.ts` 가 봉인 대상이라 소비자 매니페스트를 재봉인했다(드라이런에서 tuples·classifications
  `unchanged`, 변한 것은 두 파일의 해시뿐임을 확인).

## 6. 남은 것 (범위 밖)

- zsh 의 CWD 추적 훅이 `precmd() { ... }` 를 터미널에 직접 입력한다. 화면에 한 줄 보이고, 사용자가 `.zshrc` 에서
  정의한 `precmd` 함수를 덮어쓴다. Windows 의 bash/WSL 경로도 같은 방식으로 훅을 입력하므로 macOS 회귀는 아니며,
  Linux zsh 에도 영향이 있어 이번 범위에서 바꾸지 않았다.
- 기존 설치본(0.10.8 앱)은 이 수정이 들어간 새 빌드로 교체해야 고쳐진다.
