# 서브에이전트를 기다리는 Claude Code의 실행 중 표시

- 날짜: 2026-09-26
- 요구사항
  - FR-AITUI-010 (신규): AI TUI 작업 중 상태 유지
  - REL-BGSTAB-022 (신규): Windows 트리 종료 안전 가드
  - FR-AITUI-009 AC-6 (추가): 세션 저장 후보 즉시 갱신
- 커밋: `f01ad97f`

## 이슈

Claude Code가 서브에이전트로 작업하는 동안 세션이 busy(실행 중)로 표시되지 않았다.

## 원인

- 서브에이전트를 기다리는 동안 Claude Code 화면에서 바뀌는 것은 스피너와 경과 시간뿐이다.
- Claude Code 2.1.281 번들을 읽어 확인한 스피너 동작
  - 글리프 `· ✢ * ✶ ✻ ✽`를 2초 코사인 주기로 오간다.
  - 끝 프레임은 약 0.4초 머문다.
  - 시간 표시는 1초마다 바뀐다.
- 분류기의 판정
  - `·` 프레임과 `12s` 같은 시간 틱은 `repaint_only`로 분류된다.
  - `deriveDisplayStatus`는 `repaint_only` 한 번에 곧바로 idle을 낸다.
- `idleDelayMs` 200ms가 프레임 간격(최대 약 0.4초)보다 짧았다.
- 2222에서 같은 주기를 재현하자 24개 표본 중 13개가 "대기"였다. 실행 중과 대기를 오가며 깜빡였다.

## 해결 (FR-AITUI-010)

- 이미 실행 중인 AI TUI의 `repaint_only` 출력은 idle로 바꾸지 않고 idle 타이머를 뒤로 미룬다.
  - 마지막 busy 출력 뒤 3초 안에만 적용한다.
  - 스피너의 busy 프레임은 2초마다 한 번 이상 나온다.
- repaint만으로는 실행 중이 시작되지 않는다. AI 프롬프트에 입력하면 idle이 되는 기존 동작은 그대로다.
- 실행 중인 AI TUI는 출력이 1.5초 끊겨야 idle이 된다. 일반 셸은 200ms 그대로다.
- 상태줄이 주기적으로 스스로 다시 그려지더라도, 3초 창이 지나면 실행 중을 붙잡지 않는다. 단위 테스트에서 약 3.1초에 끝났다.

## 함께 고친 것

### Windows 트리 종료 가드 (REL-BGSTAB-022)

- 상황: E2E 도중 2222 서버가 로그 없이 두 번 사라졌다.
- 코드를 읽어 찾은 두 위험을 막았다. 둘 다 죽이는 범위를 좁히기만 한다.
  1. 트리 걷기가 부모 PID만 본다. 서버를 띄운 PowerShell이 끝난 뒤 그 PID가 탭 셸에 재사용되면, 서버가 그 탭의 자식으로 보일 수 있다.
     - 이제 부모보다 먼저 생긴 프로세스와 시작 시각을 읽을 수 없는 프로세스는 걷지도 죽이지도 않는다.
     - 서버와 스크립트 자신의 PID는 보호한다.
     - 건너뛴 PID는 경고로 남긴다.
  2. node-pty ConPTY `kill()`은 셸 PID의 콘솔에 붙어 그 콘솔의 모든 프로세스를 서버에서 죽인다. 셸이 이미 죽고 PID가 서버의 도우미 PowerShell에 재사용되면 목록에 서버가 들어갈 수 있다.
     - 이제 그 목록에서 서버와 부모 PID를 뺀다.
- 두 번의 소실 원인은 확정하지 못했다.
  - 가드를 넣은 뒤 7회, 가드를 뺀 대조군 3회 모두 서버가 살아 있었다.
  - 가드 경고는 한 번도 찍히지 않았다.
- 종료 코드 감시기(`watch-2222.ps1`)로 다음 소실 때 원인을 가를 수 있다. 종료 코드 1은 node-pty의 `process.kill`, -1은 .NET `Kill`, `0xC0000xxx`는 크래시다.

### 세션 저장 후보 즉시 갱신 (FR-AITUI-009 AC-6)

- 문제: 헤더 버튼의 후보 수가 15초 주기로만 갱신되었다. 방금 AI 탭이 된 탭이 있어도 버튼이 비활성이라 누를 수 없었다. E2E도 이 때문에 두 번 실패했다.
- 이제 탭의 `recoveryCommand`가 바뀌면 후보를 바로 다시 읽는다.
