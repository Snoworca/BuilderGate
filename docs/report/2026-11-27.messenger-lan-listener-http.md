# 메신저 사내망 수신 리스너: HTTP 기본, HTTPS 선택, 접근 허용 목록 설정 (#270)

## 이슈

사용자 요청(2026-11-27):

- 대화방 사내망 수신 리스너도 HTTP 로 연다.
- HTTPS 도 지원하되, 옵션에서 고르게 한다.
- 접근 제한은 설정에서 바꿀 수 있게 하고, 기본값은 내부망으로 한다.

요구사항: FR-MSG-014 AC-3·AC-4·AC-5(신규), FR-MSG-008 AC-4·AC-5(수정)·AC-7(신규), FR-MSG-009 AC-1(수정).

## 원인

- 사내망 수신 리스너는 항상 직접 TLS 로만 열렸다. 인증서를 읽지 못하면 아예 켜지지 않았다(`LAN_TLS_UNAVAILABLE`). 팀원들이 연락처를 등록하지 못한 원인 후보 중 하나다(#266).
- 연락처 등록 요청, 연결 코드, 입장권, 피어 링크가 모두 `https`·`wss` 와 인증서 해시를 전제했다.
- 접근 허용 목록은 코드에 고정되어 있었다(루프백과 사설 IPv4 대역).

## 해결

- **프로토콜:** 연락처 창에서 HTTP 와 HTTPS 중 고른다. 새 설치는 HTTP 로 시작한다. 이 선택이 생기기 전에 저장된 설정은 HTTPS 를 유지한다. 그래서 다른 PC 들이 저장해 둔 `wss://` 연락처와 방 링크가 끊기지 않는다. HTTP 는 인증서 없이 켜진다.
- **접근 허용 목록:** 연락처 창에서 고친다.
  - 형식은 IPv4, IPv4/CIDR, `*` 다. `0.0.0.0/0` 은 거부한다.
  - 기본값은 내부망(10/8, 172.16/12, 192.168/16)이고, 루프백은 목록과 상관없이 받는다.
  - 피어 업그레이드, `/mcp/contact-request`, hello 인증이 모두 요청마다 현재 목록을 읽는다. 목록을 바꿔도 리스너를 다시 열지 않는다.
- **주소와 인증서:** 연결 코드와 입장권은 프로토콜에 따라 `ws://` 나 `wss://` 를 담는다. 인증서 해시는 HTTPS 일 때만 담는다.
- **주소로 추가:** `http://` 나 `https://` 를 적으면 그것만 쓴다. 생략하면 http 로 먼저 시도하고, 닿지 않으면 https 로 다시 시도한다. https 로 다시 시도할 때는 새 secret 을 쓴다. 이후의 확인 요청과 링크도 찾은 프로토콜을 따른다.
- **화면:**
  - HTTP 를 고르면 "키가 암호화 없이 전송됩니다" 안내가 뜬다.
  - 목록에 `*` 가 있으면 경고가 뜬다.
  - 켜기·끄기 버튼은 아직 적용하지 않은 설정을 보내지 않는다. 설정 변경은 "설정 적용" 버튼으로만 보낸다.
  - 켜진 상태에서 프로토콜을 바꾸면 연결 코드를 새로 만든다.
- **설정 위치:** 사용자는 "대화방 설정"이라고 했다. 하지만 이 설정은 방마다가 아니라 PC 전체에 걸리는 값이어서, 기존 "사내망 연결 받기" 스위치가 있는 연락처 창에 두었다.

## 검증

- 모든 동작 변경은 실패하는 테스트를 먼저 쓰고 구현했다.
- 서버 메신저·피어·라우트 테스트 231/231, 모놀리식 러너 533/533, `TerminalResourcePolicy.test.ts` 21/21.
- 프런트 메신저·i18n 테스트 96/96, 서버 `tsc`, 프런트 `tsc -b` 통과.
- 독립 서브에이전트 리뷰를 1회 받았다. 보안 회귀(주소 검사 우회)는 없었다. 리뷰 지적은 모두 반영했다.
  - 높음 H1: 기존 설치가 업데이트 뒤 HTTP 로 바뀌는 문제
  - 중간 M1: 켜기·끄기가 적용 전 설정까지 보내는 문제
  - 낮음 L1·L3·L4·L5
- 소비자 매니페스트는 `server/src/index.ts` 해시만 다시 봉인했다. 정확한 소비자 튜플과 분류는 바뀌지 않았다.

## 남은 점

- **원래 있던 실패:** `npm run check:consumer-manifest` 의 differential GREEN 스냅샷 단언(`actualConsumers.disabledSha256`)이 실패한다.
  - 이번 변경 전 HEAD `bbb2b4e1` 에서도 같은 해시로 실패하는 것을 측정했다(2026-11-27, WSL).
  - `--rerun-differential` 로 다시 기록할지는 사람이 결정할 일이라 건드리지 않았다.
- **E2E:** 실제 브라우저로 화면을 확인하지 않았다. 2222 서버를 띄우는 E2E 는 돌리지 않았다.
- **기존 설치를 HTTP 로 옮길 때:** 연락처 창에서 프로토콜을 바꾸면 된다. 이때 그 PC 를 `wss://` 로 저장한 상대는 연락처를 다시 추가해야 한다.
