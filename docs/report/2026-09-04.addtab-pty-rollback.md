## 이슈: addTab이 저장에 실패하면 PTY가 고아 프로세스로 남는다

### 문제
- `WorkspaceService.addTab`이 `createSession`으로 PTY를 생성한 후 `await this.save(true)`로 저장하는 중간에 `try`/`catch` 블록이 없음
- 저장이 실패하면 (예: ENOENT—경로 불존재) PTY 프로세스는 계속 실행되고 탭은 메모리에 남음
- 호출자만 오류를 받으며, 아무도 소유하지 않는 고아 PTY 프로세스가 서버에 남음

### 원인 분석
- `createSession` (line:xxx) 내에서 sessionDTO를 생성하고 반환
- `addTab` (line:yyy) 에서 sessionDTO로 탭을 추가한 후 `await this.save(true)` 호출
- 저장이 ENOENT 등으로 거부되면 `catch` 블록이 없어 탭과 sessionDTO는 메모리에 남음
- 재연결 시도 시 `currentSessionId`가 같은 상태로 유지되어 MCP 경로에서 재시도 시 새 탭이 이전 시도의 타이틀을 물려받음 (예: "Terminal-1" → 실패한 시도의 타이틀로 변경)

### 재현 (수정 전 검증)
- dataFilePath를 존재하지 않는 디렉터리로 설정하여 `save(true)`가 ENOENT로 거부되도록 강제
- 신규 테스트 스위트 8개 케이스 중:
  - 6개 케이스 fail (수정 전)
  - 그 중 2개의 실패 메시지:
    - "the PTY created by the failed addTab is still running"
    - "the tab from the failed addTab is still in the in-memory state"

### 해결
addTab의 저장 호출을 `try`/`catch`로 감싸고, 실패 시 다음을 순차 실행:

1. **탭 제거** (ID 기반): state에서 해당 탭을 삭제
2. **활성 탭 재선택**: 
   - 삭제 전 activeTabId가 그 탭을 가리키면 남은 탭 중 하나를 활성으로 지정
   - 방식은 deleteTab과 동일 (공유 상태 구조 유지)
3. **보류 중인 타이틀 취소**: `cancelPendingTerminalTitle` 호출
4. **세션 종료**: `terminateSession(sessionDTO.id, { reason: 'tab-delete' })` 호출
   - 정리 실패는 console.warn으로 삼킴 (부분 실패 방지)
5. **원래 오류 재발생**: catch 블록에서 예외 다시 던짐

### 검증 중 발견·수정된 사항 (서브에이전트 뮤턴트 검증)

**1. 이웃 탭 없이 통과하는 문제**
- 초기 테스트 픽스처에 이웃 탭·세션이 없어, 모든 탭을 지우거나 모든 세션을 종료하는 구현도 통과
- **수정**: 이웃 탭 둘(둘째를 활성으로) 추가하여 선택성 검증

**2. 공유 상태 간섭**
- 초기 구현은 실패 전 activeTabId·colorCounter·updatedAt을 스냅숏으로 되돌림
- 동시 호출이 그 사이에 한 일(색상 할당, 시각 갱신)이 지워짐
- **수정**: 스냅숏 버리고 남은 탭에서 활성 탭을 다시 선택하는 방식으로 변경, 공유 카운터는 건드리지 않음

**3. 타이틀 누수**
- 롤백이 `cancelPendingTerminalTitle` 호출 누락
- MCP 경로에서 같은 `currentSessionId`로 재시도 시 새 탭이 실패한 시도의 타이틀을 물려받음 (실측: 탭 이름 "Terminal-1" → 이전 시도의 타이틀로 변경)
- **수정**: 롤백 시 `cancelPendingTerminalTitle` 호출 추가

## 범위 밖으로 남긴 사항

`flushToDisk`가 쓰기를 직렬화하므로, 실패한 쓰기 뒤에 대기하던 쓰기가 롤백 실행 **전에** 상태를 스냅숏합니다. 그 결과 롤백된 탭이 디스크에 남을 수 있습니다.

다만 **수정 전에도 같은 탭이 디스크에 남았으므로** 새로 생긴 문제는 아닙니다. 새로운 현상은 다음 성공 저장 전까지의 메모리·디스크 불일치입니다.

요구사항 statement에 "Out of scope" 로 기록했으며, 이후 별도 요구사항으로 추적할 수 있습니다.
