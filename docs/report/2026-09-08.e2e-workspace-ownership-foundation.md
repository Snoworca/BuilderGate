# E2E workspace ownership foundation

Requirement: REL-BGSTAB-001. This is the core/fixture implementation checkpoint for [B2](../plan/2026-09-08.e2e-workspace-ownership.design.md), not completion of the spec migration or actual browser validation. No SRS lifecycle or AC promotion.

## Change and test-first evidence

The previous global hooks treated after-minus-before workspace IDs as owned, swallowed authentication/list failures, and discarded failed cleanup records. Three tests executed those actual hooks with controlled fetch and observed deletion attempts against concurrent or pre-existing user workspaces. These were fake requests only; no live workspace was deleted.

The replacement initializes a new run only after successful preflight. A validated successful POST response establishes an immutable per-ID ownership record. Complete files are published without replacement, so concurrent writers cannot overwrite another owner or expose an unfinished final record. Cleanup validates the registry and list, preserves user/sibling resources, separates confirmed deletion from absence, and retains failed IDs. The single-ID API never expands a request into an owner-wide sweep.

The thin Playwright fixture observes creation requests and their real loopback responses, waits for request/body/publication completion, and reports failures. The API adapter preserves caller POST options and publishes ownership before returning. Read-only owner/run validation precedes POST and auto-fixture use. Cleanup failures survive alongside a failed test body, and listeners are removed after drains. Mock-only specs remain separate.

Independent review found and test-first fixes addressed explicit null setup fallback, overlapping TLS restoration and API preflight ordering. Every change followed its failing test; no fixture or registry test used a real network endpoint. The actual fixture module and registry code were executed with controlled transport ports and real temporary files.
