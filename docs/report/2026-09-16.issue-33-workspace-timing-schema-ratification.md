## 4. 이슈가 지적한 일반 문제 — unknown key 무음 strip

이슈 말미의 지적은 **여전히 유효하며 이 이슈의 범위 밖이다.**

`server/src/schemas/config.schema.ts` 의 섹션 13개 중 `.strict()` 인 것은 셋뿐이다.

| strict (오타를 거부) | loose (오타를 조용히 버림) |
| --- | --- |
| `realtimeSchema`, `resourceLimitsSchema`, `stabilityModesSchema` | 최상위 `configSchema`, `serverSchema`, `ptySchema`, `sessionSchema`, `sslSchema`, `securitySchema`, `twoFactorSchema`, `bootstrapSchema`, `authSchema`, `fileManagerSchema`, `workspaceSchema` |

### 권고: `.strict()` 확대는 안 된다. warn 경로여야 한다

`.strict()` 를 최상위와 나머지 10개 섹션에 확대하면 **현재 정상 로드되는 설정이 거부된다.**
`ed03769` ("구설정 호환성을 유지하며 미사용 설정 제거") 가 세운 `FR-BGSTAB-025` 계약이
바로 그 반대를 단언한다 — `server/src/schemas/config.schema.test.ts:32-58` 의 13개 케이스는
은퇴한 키(`logging.level`, `bruteForce.*`, `auth.maxDurationMs` 등)를 담은 설정이
**파싱에 성공하고 그 키만 사라질 것**을 요구한다. strict 로 바꾸면 이 13개가 전부 red 가 되고,
기존 사용자의 `config.json5` 가 부팅을 막는다.

따라서 권고하는 형태는 **거부가 아니라 경고**다.

1. 로더(`loadConfigFromPath` / `loadConfigFromPathStrict`)에서 parse 전후 raw 키와
   validated 키를 비교해 사라진 키를 수집한다.
2. `FR-BGSTAB-025` 의 은퇴 키 목록에 있으면 "은퇴한 설정" 으로, 없으면 "알 수 없는 키(오타 가능)" 로
   구분해 `console.warn` 한다.
3. 값은 로그에 쓰지 않는다(비밀값 노출 방지). 경로만 쓴다.

이는 로더 동작 변경이므로 자체 요구사항이 필요하다. `FR-BGSTAB-026` 에 끼워 넣지 않는다.
별도 결함으로 오케스트레이터에 보고했다.
