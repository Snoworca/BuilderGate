# 원격 연결 간소화 (FR-MCP-024)

## 이슈

- 원격 BuilderGate 에 연결하면 `DEPTH_ZERO_SELF_SIGNED_CERT` 로 끊겼다.
- 연결하려면 세 가지를 직접 맞춰야 했다.
  - `wss://호스트:포트/mcp/peer` 주소를 직접 조립한다.
  - `openssl` 로 인증서 지문을 뽑아 넣는다.
  - 고정 인증키는 생성할 때 한 번만 보이므로 그때 복사해 둔다.
- 사용자 요청은 세 가지다. MCP 키 하나로 연결하고, 키를 다시 볼 수 있게 하고, MCP 주소를 넣으면 알아서 변환되게 한다.
- 설계 시안: `design/html/2026-11-10.peer-link-simple-connect.html`

## 원인

- `peerWsTransport.ts` 는 지문이 없는 링크에 일반 CA 검증(`rejectUnauthorized: true`)을 적용했다. 그래서 자체 서명 인증서는 지문을 수동으로 넣지 않는 한 연결되지 않았다.
- 링크 주소는 `isAllowedPeerUrl` 로 형식만 검사하고 변환하지 않았다.
- 고정 키는 SHA-256 해시만 저장했다(SEC-MCP-002 AC-10).

## 해결

- **주소 변환:** `normalizePeerAddress` 가 MCP 주소, `호스트:포트`, 호스트만 적은 경우, `wss://` 를 `wss://호스트:포트/mcp/peer` 로 바꾼다.
  - 적은 포트는 443 이어도 그대로 쓴다.
  - 포트가 없는 MCP 주소나 호스트에는 3333 을 쓴다.
  - 포트가 없는 링크 주소는 기존처럼 그 방식의 기본 포트를 쓴다.
  - 루프백이 아닌 HTTP 주소는 「HTTPS 를 켜라」는 칸 오류로 거부한다.
- **인증서를 처음 연결할 때 기억(TOFU):**
  - 지문이 없는 링크는 업그레이드 응답에서 인증서 지문을 hello(키를 싣는 메시지)보다 먼저 기억하고, 그 값을 링크에 저장한다. 저장해도 다시 연결하지 않는다.
  - 기억한 지문과 다른 인증서가 오면 키를 보내지 않고 `PEER_TLS_FINGERPRINT_MISMATCH` 로 끊는다. 화면에는 「새 인증서 신뢰」 버튼이 뜬다(`POST /api/mcp-control/peers/:name/trust-certificate`).
  - 저장할 때 지문 필드를 빼면 주소가 같은 동안 기억한 지문을 유지한다.
- **MCP 키 다시 보기:**
  - `McpFixedAccessKeyVault` 가 해시와 함께, 이 PC 키로 암호화한 키를 저장한다.
  - `GET /api/mcp-control/access-key` 로 로그인한 사용자가 키를 다시 볼 수 있다. 응답에는 `Cache-Control: no-store` 를 붙인다.
  - 해시만 있는 이전 키는 `MCP_FIXED_ACCESS_KEY_NOT_REVEALABLE` 을 돌려준다.
  - 화면은 키를 가린 채 「보기」「숨기기」「복사」를 제공하고, 이름을 「MCP 키」로 바꿨다.
- **독립 리뷰에서 나온 결함 수정:**
  - H1: `:443` 이 3333 으로 바뀌던 문제
  - M2: 주소를 바꾸는 중에 이전 주소의 인증서가 기억되던 문제
  - M3: 지문보다 먼저 큐에 들어간 저장 때문에 연결이 다시 시작되던 문제
  - L5: 다른 탭에서 키를 바꾸면 이전 키를 보여 주던 문제
- **SRS:** FR-MCP-024 를 새로 만들었다. FR-MCP-016 AC-1·AC-2, FR-MCP-020 AC-1 의 지문 수동 입력과 SEC-MCP-002 AC-10 의 「해시만 저장」을 승계한다고 각 요구사항에 기록했다.

## 남은 한계

- 실제 두 PC 사이의 연결과 브라우저 화면은 아직 확인하지 않았다. 2222 에서 E2E 를 돌리지 않았다.
- L4: 지문 저장에 실패하면 메모리에서만 유지되므로, 재기동하면 처음 연결 때처럼 다시 기억한다.
- L6: 업데이트 전 화면이 캐시에 남아 있으면 저장할 때 지문을 지울 수 있다. 일시적인 문제다.
- 처음 연결하는 순간에는 중간자 공격을 막지 못한다. TOFU 방식의 본질적인 한계다.
