# PTY 기본값을 플랫폼 네이티브 의사 터미널로 (CON-BGSTAB-002)

## 요청과 그 과정

사용자 지시로 시작했다. 처음 지시는 두 개였다 — `pty.useConpty` 기본값 `true`,
`pty.windowsPowerShellBackend` 기본값 `winpty`. 구현 후 *"linux 도 pty 가 있나요?"* 라는
질문이 왔고, 그 답을 만들다가 **배너 결함**이 드러났다. 이어서 *"리눅스든 맥이든 윈도우든
기본은 PTY 로 가자"* 로 방향이 정해졌고, 이것이 앞 지시를 뒤집는지 확인한 뒤
**ConPTY 로 통일**을 채택했다.

중간 방향(PowerShell 만 winpty)은 **철회**했다. 기록을 남기는 이유는 철회 근거가 실측이기
때문이다: `windowsPowerShellBackend` 를 `winpty` 로 기본값에 두면 신규 Windows 설치가
**동작하는 winpty 를 전제**하게 된다. `resolveWindowsPtyBackend` 가
`assertPowerShellWinptyAvailable()` 을 호출하고, 실패 시 `CONFIG_ERROR` 로 PowerShell
세션이 아예 뜨지 않는다. 현재 기본값(`inherit`)에서는 그 프로브를 아예 타지 않는다.

## 왜 ConPTY 가 "PTY" 인가

| 플랫폼 | 기구 | 성격 |
|---|---|---|
| Linux / macOS | 커널 PTY (`/dev/ptmx`, `forkpty`) | 수십 년 된 네이티브 의사 터미널. node-pty 가 직접 사용하며 **대안이 없다** |
| Windows | **ConPTY** | Microsoft 의 네이티브 의사 콘솔. Unix PTY 와 같은 계열 |
| Windows | winpty | 숨은 콘솔 창을 띄워 **스크래핑하는 shim**. ConPTY 이전에 Windows 에 PTY 가 없어서 존재 |

즉 "세 플랫폼 공통의 기본값" 을 말할 수 있는 것은 네이티브 의사 터미널이고, Windows 에서
그것은 ConPTY 다. winpty 는 이 기준에서 빠진다.

## 변경

**기본값** (`server/src/utils/ptyPlatformPolicy.ts`)

- win32: `useConpty: true`, `windowsPowerShellBackend: 'inherit'`
  (`useConpty` 는 이미 `true` 였고, PowerShell 을 분리하지 않는다는 점을 명시적으로 굳혔다)
- 그 외: `useConpty: false`, `windowsPowerShellBackend: 'inherit'` — 변화 없음

**강제가 아니라 기본값이다.** `windowsPowerShellBackend` 는 세 선택지를 유지하고, 명시적으로
`winpty` 를 설정한 배포는 그대로 winpty 를 쓴다(AC-2 가 그것을 고정한다).

**배너 결함** (`server/src/index.ts`)

기동 배너가 `config.pty.useConpty ? 'ConPTY' : 'winpty'` 였다. **Windows 백엔드 둘 중 하나를
모든 플랫폼에서** 찍는 2분기다. 비-Windows 에서 `useConpty` 는 강제로 `false` 이므로
Linux 기동은 **항상 `Global PTY: winpty`** 를 출력했다 — winpty 가 존재하지도 않는 호스트에서.

이 줄은 이 세션의 WSL 실행 보고서에 **사실처럼 옮겨 적혔다.** 그것이 이 항목이 결함인 이유다.

- `describeGlobalPtyBackend(platform, useConpty)` 신설. 비-Windows 는 `pty (native)` 를
  반환하고 `useConpty` 를 **무시한다** — 그 플래그는 Windows 기구의 이름이므로 거기서는
  발언권이 없다(테스트가 직접 고정).
- `[PTY] Global Windows backend default: …` 와 `[PTY] Effective PowerShell backend default: …`
  두 줄은 win32 로 게이트했다. Linux 에서 *"Global **Windows** backend default"* 를 찍고
  있었다.

실측 (Linux, 2222):

```
변경 전   ║  Global PTY:   winpty
          [PTY] Global Windows backend default: winpty
          [PTY] Effective PowerShell backend default: winpty (policy: inherit)

변경 후   ║  Global PTY:   pty (native)
          (Windows 백엔드 줄 없음)
```

## 검증

단위 9/9(`ptyPlatformDefaults` 6, `ptyBackendLabel` 3). 회귀: server monolithic runner
542 PASS exit 0, release pipeline 19/19, 소비자 매니페스트 검증기 exit 0(재봉인 diff 4줄,
`exact consumer tuples`·`classifications` 불변).

선재 테스트 3건이 중간 방향에서 빨개졌었고(옛 기본값 `inherit` 을 고정), 최종 방향이
`inherit` 이므로 원래 단언으로 되돌아왔다 — 순 변화는 주석 2줄뿐이다.

## 범위 밖 — 한 줄로 남긴다

`loadConfigFromPath` 의 마지막 fallback `configSchema.parse({})` 는 ZodError 를 던진다.
설정 생성과 읽기가 모두 실패했을 때만 닿는 경로이고 "Using default configuration" 이라는
로그와 달리 기본값을 반환하지 못한다. 이번 변경과 무관한 선재 결함이라 손대지 않았다.

## Windows 실측 한계

AC-4 의 Windows 쪽은 단위 단언으로만 덮였다. 이 변경을 위해 Windows 서버를 띄우지 않았다.
