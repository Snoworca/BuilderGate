# 그리드↔탭 전환·탭 이동 뒤 터미널 렌더링 깨짐

- 날짜: 2026-09-29
- 요구사항: REL-BGSTAB-038 (보이는 터미널의 크기는 컨테이너에 수렴한다), 타깃 `terminal-fit-convergence`. 겹치는 부분은 REL-BGSTAB-017에 Change Note로 남겼다.
- 커밋: (미커밋)

## 이슈

사용자 보고: 그리드 모드에서 탭 모드로 바꾸거나 탭끼리 이동할 때, 렌더링이 완전히 깨진 채 나오는 일이 상당히 자주 있다. 브라우저를 새로고침하면 제대로 그려진다.

스크린샷(`탭모드깨짐.png`)의 모습:
- 탭 모드의 넓은 칸에 Claude Code 화면이 왼쪽 위 약 420px 폭으로만 그려져 있다.
- 그 위에 가로줄 여러 개가 겹쳐 있다.
- 즉 터미널의 cols/rows(와 PTY 크기)가 그리드 칸 크기에 머물렀고, TUI가 좁은 폭으로 여러 번 다시 그린 흔적이 남았다.

## 원인

터미널 크기 맞춤(fit)은 한 번 실패하면 다시 시도되지 않았다. 실패하는 경우는 세 가지다.

1. 보이게 된 직후 한 프레임에서 컨테이너가 아직 0×0이면 건너뛴다(`fit_skipped_non_renderable`).
2. `isVisibleRef`가 아직 false일 때 ResizeObserver가 울리면 건너뛴다.
3. 스냅샷 복원·복구가 진행 중이면 쓰기 조정자(write coordinator)가 fit을 거절한다. 사유는 `fresh-checkpoint-required`, `recovery-required`, `stale-view-generation`이다. 탭 전환·뷰 전환 직후가 정확히 이 구간이다.

어느 경우든 복구는 "나중에 다른 레이아웃 변화가 ResizeObserver를 한 번 더 울려 주는 우연"에만 기대고 있었다.

실측(https://localhost:2222, 출력이 흐르는 탭 3개, 그리드→탭 30회):
- 30회 중 2~3회, 전환 직후 탭 화면이 폭 31%(그리드 칸의 52열)로 남았다.
- 복구는 약 0.8~1.1초 뒤 ResizeObserver가 다시 울렸을 때만 일어났다.
- 그 재발화가 오지 않으면 새로고침 전까지 영구히 깨진 채 남는다. 사용자 스크린샷이 그 모습이다.

## 해결

- `frontend/src/utils/terminalGeometryConvergence.ts`(신규)
  - `decideGeometryConvergence`는 보임 여부, 컨테이너 크기, `FitAddon.proposeDimensions()`, 현재 cols/rows를 보고 `fit` / `in-sync` / `not-renderable` / `unmeasurable` 중 하나를 판정한다.
  - `createGeometryConvergenceLoop`는 주기 점검(700ms)과 레이아웃 변화 직후의 추가 점검(60/250/700ms)을 돌린다. `stop`은 모든 타이머를 지운다.
- `TerminalView.tsx`
  - 터미널이 보이는 동안만 루프를 돈다. 가려지거나 언마운트되면 멈춘다.
  - 크기가 어긋나면 fit을 제출하고, 적용되면 서버에 resize를 보낸다(reason `geometry-convergence`).
  - 이미 대기 중인 fit이 있으면 중복 제출하지 않는다.
  - ResizeObserver 콜백과 보임 전환 때 추가 점검을 건다.
  - 크기가 맞으면 아무것도 하지 않는다.

## 검증

- **단위 테스트**: `tests/unit/terminalGeometryConvergence.test.ts` 6/6 통과(테스트를 먼저 작성해 실패를 확인했다).
- **프런트 전체**: 2108/2111. 실패 3건은 전용 러너가 필요한 terminal-view 파일로 예상된 것이다.
  - `npm run test:unit:terminal-view-behavior`는 `act is not a function`으로 19/20 실패한다. TerminalView.tsx를 HEAD로 되돌려도 똑같이 실패하므로 이번 변경과 무관하다.
  - 작업 트리에 커밋되지 않은 `package.json`/`package-lock.json` 변경이 있다(이번 작업이 만든 것이 아니다).
- **실측**(2222, 소유 Workspace를 만들어 정확한 id로 삭제)
  - **고장 주입**: 페이지의 ResizeObserver를 꺼 fit 누락을 극단으로 재현했다. 그리드↔탭 12회 모두 1.5초 뒤 컨테이너를 채웠고(stuck 0/12), 그중 11건의 fit을 새 점검이 수행했다(`fit_completed:geometry-convergence` 11). 다른 경로로는 일어나지 않았을 fit이다.
  - **정상 실행 30회**: stuck 0/30. 크기가 맞을 때 새 점검은 fit을 요청하지 않았다.
  - 전환 직후 약 0.8초의 좁은 순간은 탭이 스냅샷 크기(52열)로 먼저 복원되는 흐름이며, 곧바로 맞춰진다.
- **기타**: 소비자 매니페스트 재봉인(튜플·분류 불변, 해시 1건), 릴리즈 파이프라인 통과, `TerminalResourcePolicy.test.ts` 21/21.

## 한계

- 사용자 환경의 "영구히 깨진" 상태 자체는 재현하지 못했다. 그 상태로 가는 공통 경로인 누락된 fit을 고장 주입으로 만들고, 새 점검이 그것을 복구함을 보였다.
- 최악의 경우 복구까지 약 0.7초가 걸린다(주기 점검 간격).
- TUI가 좁은 폭에서 그린 흔적(가로줄)은 스크롤백에 남을 수 있다. 화면은 크기가 맞춰진 뒤 에이전트가 다시 그린다.
