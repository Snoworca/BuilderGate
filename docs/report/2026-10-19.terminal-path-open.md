# 터미널 출력의 파일 경로 바로 열기 (FR-ARCH-012, FR-ARCH-013, #146)

## 요청

코딩 에이전트가 터미널에 출력한 파일 경로를 파일 탐색기를 거치지 않고 바로 열고 싶다는 요청이었다. 특히 HTML 시안과 SVG 를 빨리 확인하는 것이 목적이었다.

논의를 거쳐 다음과 같이 정했다.

- PC 에서는 Ctrl+클릭(macOS 는 Cmd+클릭)으로 연다.
- 모바일에서는 짧은 탭이 키보드를 여는 동작이므로(FR-ARCH-010), 길게 누르기 메뉴를 쓴다.
  - 누른 자리 근처의 경로를 메뉴 맨 위 "열기" 항목으로 보인다.
  - "화면의 파일" 하위 메뉴에 보이는 화면의 경로를 나열한다.
- URL 은 이번 범위에서 뺐다. 원격 접속에서는 `localhost` 주소가 접속한 기기 자신을 가리켜 열리지 않기 때문이다. 포트 전달과 함께 따로 다룬다.

이슈 #146 을 먼저 발행한 뒤 작업했다.

## 요구사항

- 새 target `terminal-path-open` 을 등록했다. 커밋 전에 Active target 을 원작자 값 `file-transfer` 로 되돌렸다.
- `FR-ARCH-012` 는 터미널 출력의 파일 경로를 Ctrl/Cmd+클릭으로 연다. AC-1~AC-8 을 담는다.
- `FR-ARCH-013` 은 터미널 메뉴에서 출력에 나온 파일을 연다. AC-1~AC-7 을 담는다.
  - AC-7(파일 이름 아래에 폴더를 두 줄로 표시)은 iPhone 확인 뒤 추가했다.
- 두 요구사항은 `docs/spec/10.product-architecture.srs.md` 에 있다. Stability 는 evolving, Status 는 implemented 이다.
- 증거 10건(단위 테스트 7건, 실기기 확인 3건)을 기록했다. 자동화된 E2E 가 없으므로 verified 로 올리지 않았다.

## 구현

### 경로 인식 (`frontend/src/utils/terminalPathDetection.ts`)

- xterm 에 의존하지 않는 순수 함수다.
- 상대 경로, 절대 경로(`C:\…`, `/…`), 열 수 있는 확장자를 가진 파일 이름을 찾는다. 열 수 있는 형식은 파일 탐색기 더블클릭과 같은 기준(`isOpenableFile`)을 쓴다.
- 다음을 처리한다.
  - `:42`, `:42:7` 같은 줄 번호 접미사
  - 따옴표, 백틱, 괄호, 끝의 마침표·쉼표·콜론
  - 경로 바로 뒤의 한국어 조사(`a.html을`)
  - URL 제외
  - 자동 줄바꿈된 경로
  - 한글처럼 두 칸을 차지하는 글자의 열 위치
- Claude Code 는 휴대폰 폭에서 긴 경로를 잘라 줄마다 들여쓰기 공백을 붙인다. 윗줄이 오른쪽 끝까지 경로 문자로 차 있고 아랫줄이 공백 1~4칸 뒤에 경로 문자로 시작하면 이어 붙인다. 원래 조각은 대안으로 남긴다.

### PC 링크 (`frontend/src/utils/terminalPathLinks.ts`)

- xterm 의 `registerLinkProvider` 로 링크를 등록한다. Ctrl/Cmd 를 누른 클릭만 연다.
- 밑줄은 Ctrl/Cmd 를 누른 동안만 보인다.
- 마우스가 있는 줄의 앞뒤 4줄을 함께 읽어, 들여쓰기로 잘린 경로도 하나의 링크로 만든다.

### 메뉴 (`frontend/src/utils/contextMenuBuilder.ts`, `App.tsx`, `MosaicContainer.tsx`)

- 탭 모드와 그리드 모드 모두에 적용했다.
- 누른 줄을 먼저 보고, 그다음 위아래 줄을 본다. 같은 줄에서는 누른 열에 가까운 경로를 고른다.
- "화면의 파일"은 아래쪽(최근 출력)부터 중복 없이 최대 10개를 나열한다.
- 메뉴 항목에 둘째 줄(`ContextMenuItem.description`)을 추가했다. 첫 줄은 파일 이름을 자르지 않고 표시하고, 둘째 줄은 세션 폴더 기준 폴더를 작게 표시한다. 폴더가 길면 앞쪽을 "…"로 줄인다.

### 열기 전 확인 (`frontend/src/utils/terminalPathOpen.ts`)

- 서버의 `GET /files/stat` 으로 세션 폴더 기준 해석과 파일 API 규칙을 거친다.
- 파일이 없거나, 폴더이거나, 세션 폴더 밖이거나, 열 수 없는 형식이면 편집기 창도 새 파일 생성 확인도 띄우지 않는다. 대신 `MessageBox` 로 이유를 보인다.
- 이어 붙인 경로가 없으면 원래 조각을 차례로 시도한다.

### 봉인 파일

- `TerminalView.tsx` 에 링크 등록 한 줄과 `getPathsAt` 핸들을 더했다. `TerminalContainer.tsx` 는 그 핸들을 넘긴다.
- 커밋 직전에 소비자 매니페스트를 재봉인했다. 바뀐 것은 두 파일의 해시뿐이고, exact tuples 와 classifications 는 그대로다.

## 작업 중 발견한 문제

### Ctrl 을 눌러도 밑줄이 생기지 않음

- 원인: xterm 6 의 Linkifier 는 hover 때 `link.decorations` 를 자기 상태로 복사하고, `hover` 를 부른 뒤, `link.decorations` 를 setter 가 있는 새 객체로 바꾼다. 코드는 처음 만든 객체를 계속 고쳐서 화면에 반영되지 않았다.
- 단위 테스트의 가짜 터미널이 이 교체를 흉내 내지 않아서 테스트는 통과했다.
- 수정: 그 시점의 `link.decorations` 로 고치고, 들어갈 때의 설정은 교체 직후에 적용한다. 가짜 터미널도 xterm 과 같은 순서로 동작하게 고쳤고, 고친 테스트가 실제 증상 지점에서 실패하는 것을 먼저 확인했다.

### 모바일에서 "경로를 찾을 수 없습니다"

- 원인: Claude Code 가 휴대폰 폭에서 긴 경로를 잘라 들여쓰기를 붙였다. 마지막 조각(`cement-class-deny.html`)만 경로로 잡혔다.
- 첫 수정은 xterm 이 자동 줄바꿈으로 표시한 줄만 이어 붙였다. ConPTY 는 화면을 다시 그려 보내므로 이 표시를 믿을 수 없어서, 윗줄이 끝까지 찬 경우로 조건을 넓혔다.

### 빈 "화면의 파일"이 사라짐 (AC-4)

- 메뉴 정규화(`normalizeContextMenuItems`)는 동작도 하위 항목도 없는 항목을 지운다. 그래서 경로가 없을 때 비활성 항목 대신 항목이 사라졌다. 빈 동작을 붙여 비활성으로 남게 했다.

### 렌더 테스트 35개 실패

- 렌더 테스트의 가짜 xterm 에 `registerLinkProvider` 가 없었다. 메서드가 없으면 등록을 건너뛰게 했다.

### 테스트 파일의 역슬래시

- 이 환경의 heredoc 이 역슬래시를 절반으로 줄여서, Windows 경로를 다루는 테스트 두 곳이 엉뚱한 값으로 통과하거나 실패했다. lint 가 잡았고, 이후로는 역슬래시가 있는 파일을 편집 도구로만 썼다.

### `~\…` 경로와 세션 폴더 밖의 파일

- `~`(홈 폴더)를 풀지 않아서 `~\VSCodeProjects\…` 경로는 항상 "경로를 찾을 수 없습니다"가 된다.
- 세션 폴더의 형제 폴더에 만든 worktree 의 파일은 서버 파일 API 가 세션 폴더 밖이라 거부한다(`PATH_TRAVERSAL`). 이것은 의도된 보안 경계다.
- 같은 저장소의 worktree 를 읽기 전용으로 허용하자는 제안을 이슈 #150 으로 원작자에게 올렸다. `~` 처리와 안내 문구 개선은 아직 하지 않았다.
