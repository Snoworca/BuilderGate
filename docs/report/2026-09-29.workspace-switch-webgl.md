# 워크스페이스 전환 때의 끊김

- 날짜: 2026-09-29
- 요구사항: PERF-BGSTAB-020 (숨긴 터미널은 페이지 전체 예산 안에서 WebGL 컨텍스트를 유지한다), 타깃 `workspace-switch-webgl`
- 관련: PERF-BGSTAB-017 AC-1을 완화했고, 그 내용을 Change Note로 남겼다.
- 커밋: (미커밋)

## 이슈

사용자 보고: 워크스페이스 사이를 이동할 때 약간씩 불편한 딜레이가 있다.

처음에는 기각을 검토했다. 터미널이 1~3개이고 셸만 도는 워크스페이스에서는 전환이 13~33ms(1~2프레임)라 재현되지 않았다.

사용자 지시에 따라 조건을 바꿔 다시 쟀다. 그리드 모드, 워크스페이스마다 세션 3개, 세션마다 Claude Code를 실행했다. 이 조건에서 재현됐다.

## 원인

실측(https://localhost:2222, 소유 Workspace 2개 × Claude 세션 3개, 헤드리스 Chromium, 전환 8회):
- 화면은 약 40ms에 바뀐다.
- 그 직후 매번 127~154ms짜리 긴 작업(long task)이 메인 스레드를 막았다. 첫 전환은 85·57·245ms였다.
- 가장 긴 프레임 간격은 127~246ms였다.

CPU 프로파일은 소스맵 빌드로 뜨고 원본 위치로 되돌려 읽었다. 시간은 대부분 `terminalWebglRenderer.ts`의 `sync` 아래 `WebglAddon` 활성화에서 썼다. 내역은 xterm 글자 측정 `_measure`(4회 전환에 자기 시간 121ms), `getContext`, 셰이더 컴파일, 글리프 아틀라스 `texImage2D`였다.

- PERF-BGSTAB-017 AC-1(#15)은 숨긴 터미널의 WebGL 컨텍스트를 즉시 반납하고, 다시 보일 때 렌더러를 처음부터 만들게 했다.
- 터미널 하나에 약 40ms가 든다. 그리드 3개면 전환할 때마다 약 130~150ms가 걸렸다.

## 해결

`frontend/src/utils/terminalWebglRenderer.ts`
- `createWebglContextPool`을 추가했다. 페이지 전체의 WebGL 컨텍스트를 관리한다.
  - 숨긴 터미널은 컨텍스트를 최대 5분 유지하고, 그 전에 다시 보이면 그대로 쓴다.
  - 보이는 것과 유지 중인 것을 합쳐 12개를 넘으면, 가장 오래전에 숨긴 것부터 반납한다. Chrome의 페이지당 한도는 16개다.
  - 보이는 터미널의 컨텍스트는 예산 때문에 반납하지 않는다.
- 렌더러는 붙을 때·숨을 때·다시 보일 때 풀에 알린다.
  - 컨텍스트 소실·dispose는 기존처럼 처리하고 풀에서도 뺀다.
  - 공개 API `sync(isVisible)`는 바뀌지 않아 `TerminalView.tsx`는 고치지 않았다.

## 검증

- **단위 테스트**: `frontend/tests/unit/terminalWebglRenderer.test.ts` 12/12. 먼저 실패를 확인했다.
  - 기존 #15 케이스 8개는 유지 시간 0(숨기면 즉시 반납)으로 그대로 돈다.
  - 새로 넣은 4개: 시간 안의 재사용, 시간 초과 반납, 예산 초과 시 오래된 것부터 반납(보이는 것은 유지), 소실·dispose 뒤 풀에서 빠짐.
- **프런트 단위 전체**: 2116/2119. 실패 3건은 전용 러너가 필요한 terminal-view 렌더 파일이다.
- **실측**(같은 조건, 수정 후):
  - 화면이 6~8ms에 바뀐다.
  - 8회 중 7회는 긴 작업이 없었고 1회만 56ms였다.
  - 가장 긴 프레임 간격은 27~36ms(1회 57ms)였다.
  - 8번째 전환 뒤 스크린샷(`.playwright-mcp/ws-switch-grid-7.png`)에서 세 터미널이 모두 정상으로 그려졌다.

## 한계

- 헤드리스 Chromium(소프트웨어 GL) 측정이다. 실제 GPU에서는 절대 시간이 다를 수 있다.
- 한 번에 13개 이상 보이는 그리드에서는 유지할 여유가 없어, 전과 같이 매번 다시 만든다.
- 5분 넘게 숨겨 둔 워크스페이스로 돌아가면 첫 전환은 전과 같이 렌더러를 다시 만든다.
- 실제 컨텍스트 소실(`WEBGL_lose_context`) 브라우저 검증은 다시 돌리지 않았다. 유지 중 소실은 단위 테스트로 확인했다.
