# 터미널 붙여넣기 롤백 런북 (#18 완료 조건 12)

> 대상: `SEC-BGSTAB-001`, `REL-BGSTAB-028` 가 도입한 붙여넣기 경로
> 작성 근거: GitHub issue #18 완료 조건 12 — "rollback은 신규 paste admission 중단 →
> pending operation을 accepted/rejected/unacked/unknown으로 명시 수렴 → 검증된
> `pasteInput` safe adapter 전환 순서다. context-menu direct `sendInput` 우회는 복원하지 않는다."

## 0. 먼저: `pasteInput` 은 존재하지 않는다

완료 조건 12 가 이름을 대는 `pasteInput` API 는 **이 코드베이스에 없다.**
실측 2026-09-19 — `frontend/src` 와 `server/src` 전체에서 0건이고,
`frontend/tests/unit/terminalClipboardAdapterContract.test.ts` 가 그 이름의 재등장을
막는다(같은 파일 주석: "`pasteInput` occurs nowhere in the repository").
조건문은 그 이름이 아직 있던 시점에 쓰였다.

**조건문 문구는 그대로 두고, 아래에 실제 대상 API 이름을 적는다.**
`pasteInput` 을 되살리는 것은 금지다 — 계약 테스트가 곧바로 빨개진다.

## 1. 지금의 "검증된 safe adapter" 가 무엇인가

실측한 붙여넣기 경로는 하나로 수렴한다.

```
  탭 컨텍스트 메뉴 ┐
  그리드 컨텍스트 메뉴 ├─→ clipboardCoordinator.pasteClipboard(source)
  커맨드 프리셋     ┘        clipboardCoordinator.pasteText(text, source)
  키보드 Ctrl+V   ──────→          │
                                   ↓  options.admitPaste
                          submitProgrammaticPaste(text, source)
                                   │  sanitize → 크기 상한 → 여러 줄 가드
                                   ↓
                             term.paste(text)   ← xterm 이 bracketed paste 로 감쌈
                                   ↓  onData
                            submitCapturedInput → onInput
                                   ↓
                          TerminalInputSequencer  ← operation id / seq range 부여
                                   ↓
                            transmitSequencedInput → WS `input`
```

따라서 롤백 3단계가 말하는 **"검증된 safe adapter" 는 두 층 중 하나**다.

| 층 | 실제 이름 | 무엇을 보장하나 |
| --- | --- | --- |
| 상위 (권장) | `createTerminalClipboardCoordinator` 의 `pasteClipboard` / `pasteText`<br>`frontend/src/utils/terminalClipboardCoordinator.ts` | FR-BGSTAB-021 generation guard, 관측 채널, payload 미기록 |
| 하위 | `submitProgrammaticPaste`<br>`frontend/src/components/Terminal/TerminalView.tsx` | ESC sanitize, 크기 상한, 여러 줄 가드 |

**롤백 대상이 키보드 Ctrl+V 를 포함하면 상위 층으로 되돌린다.** 키보드 경로는
capture 단계 `paste` 리스너에서 `clipboardCoordinator.pasteText(..., 'keyboard')` 로
들어가므로, 그 리스너를 이전 상태로 되돌리는 것이 곧 키보드 경로의 롤백이다.

## 2. 순서 (이 순서가 조건이다)

순서를 바꾸면 롤백 도중에 애매한 operation 이 **새로** 생긴다. 그것이 이 조건이
순서를 명시하는 이유다.

### 2.1 신규 paste admission 중단

`terminalClipboardCoordinator` 의 `dispose()` 를 호출한다.
`disposed = true` 와 `lifecycleGeneration += 1` 이 함께 일어나므로,

- 이후의 `pasteClipboard` / `pasteText` / `copyText` 는 `captureTarget()` 단계에서
  `context-changed` 로 거절된다.
- **이미 비동기로 진행 중이던 것**(클립보드 읽기 대기 중)도 `isCurrent()` 의
  generation 비교에서 걸러진다 — 이것이 "중단" 이 경합 없이 성립하는 근거다.

> 확인: `frontend/tests/unit/terminalClipboardCoordinator.test.ts` 의
> "disposed coordinator" 케이스들이 이 성질을 고정한다.

### 2.2 pending operation 을 명시 상태로 수렴

중단 이후 **남아 있는 것이 없어야** 3단계로 넘어간다. 수렴시킬 큐가 둘이다.

1. **프런트엔드 pending input queue** — `rejectPendingInputQueue(reason)`
   (`TerminalView.tsx`). TTL 만료 시 `timeout` / `timeout-enter-safety` 로,
   명시 중단 시 주어진 사유로 각 항목을 거절한다. 거절은 `input:rejected` 와
   같은 discard 표면으로 사용자에게 보인다.
2. **서버 dedup ledger** — 수렴시킬 "대기" 가 없다. ledger 는 판정만 하고
   결과를 보관하지 않는다. 재전송은 다음 넷 중 하나로 **이미** 명시 수렴한다:
   `duplicate-operation`(PTY 도달함) · `expired-operation` · `unknown-operation` ·
   `payload-mismatch`(모두 PTY 미도달).

**`unacked` 는 이 코드베이스에 없다.** 일반 입력에 acceptance ACK 프로토콜이
없기 때문이다(#18 완료 조건 4, 미구현). 따라서 2단계의 수렴 집합은 실제로는
`accepted / rejected / expired / unknown` 넷이며, `unacked` 를 기다리는 단계를
런북에 넣으면 **영원히 끝나지 않는 절차**가 된다. 조건 4 가 구현되면 이 절을
갱신한다.

### 2.3 검증된 adapter 로 전환

1 절의 표에서 고른 층의 **직전 검증된 커밋 상태**로 되돌린다.
되돌린 뒤 반드시 확인할 것:

- `npm run test:unit:clipboard`
- `npm run test:unit:terminal-view-behavior`
- `frontend/tests/unit/terminalClipboardAdapterContract.test.ts`

## 3. 복원하지 않는 것

- **context-menu direct `sendInput` 우회.** 이미 제거되어 있다 — 실측 2026-09-19,
  그리드 컨텍스트 메뉴는 `pasteTerminalClipboard` / `pasteTerminalText` 로만
  붙여넣으며 `sendTerminalInput` 을 쓰지 않는다. 되살리면 generation guard 와
  sanitize 를 동시에 우회한다.
- **`pasteInput`.** 0 절 참조.

> 남아 있는 `sendInput`(`App.tsx` 의 `sendTerminalInput` → `CommandPresetDialog`,
> `TerminalShortcutDialog`)은 붙여넣기 경로가 **아니다.** 프리셋 실행과 단축키
> 시퀀스 전송용이며, 이 금지 대상과 혼동하지 않는다.

## 4. 이 런북이 보증하지 않는 것

- 실제 롤백을 수행한 기록이 아니다. 각 단계는 현재 코드에서 **수행 가능함을 확인한**
  절차이며, 2.2 의 `unacked` 부재처럼 수행할 수 없는 단계는 수행할 수 없다고 적었다.
- 서버 측 되돌리기(예: wire 사유 축소)는 다루지 않는다. 사유를 줄이면 구형
  클라이언트가 아니라 **신형 클라이언트**가 모르는 사유를 받게 되므로 별도 판단이 필요하다.
