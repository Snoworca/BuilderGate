# 에이전트 세션 ID 를 hook 없이 얻기 — 재시작 복구용 연구

작성일: 2026-09-26
대상: Claude Code 2.1.281 · Codex CLI 0.157.1(WSL, 0.155.1 에서 업데이트) / 0.157.0(Windows) · Hermes Agent v0.21.5(2026.9.24, v0.10.0 에서 업데이트, Python 3.14) · OpenCode 1.3.13
방법:
- 로컬 설치본의 `--help` 와 공개 소스(codex `rust-v0.155.1`, opencode `v1.3.13`, hermes 로컬 체크아웃)를 읽었다.
- Claude 2.1.281 실행 파일 안의 JS 코드와 이 PC 에서 실행 중인 프로세스·데이터 파일(키·스키마·ID·시각만)을 읽었다.
- 에이전트를 모델 호출로 실행하지 않았고 사용자 설정을 바꾸지 않았다.
관련 요구사항: 없음 (구현하려면 새 SRS 요구사항이 필요하다).
전제:
- "복구" 는 BuilderGate 서버 재시작 뒤 고아 탭을 되살리는 흐름이다(FR-AITUI-004).
- 재시작하면 PTY 와 그 안의 에이전트가 함께 끝난다.
- **hook 계열은 배제한다**(사용자 지시).

## 0. 결론

- **hook 없이 가능하다.** 주 경로는 **실행 중 읽기**다. 에이전트가 스스로 남기는 파일에서 지금 쓰는 세션 ID 를 읽는다.
- **저장은 에이전트를 멈추지 않는다** (2026-09-26 사용자 결정). 사용자가 "세션 저장" 버튼을 누르면 실행 중 읽기로 ID 를 찾아 저장본에 기록하고, 에이전트는 그대로 둔다. 그래서 종료할 때 찍히는 재개 명령(§4)은 저장 수단으로 쓰지 않고, 사용자가 직접 에이전트를 종료할 때 보조로만 읽는다.
- **재시작 전에 저장해 두어야 한다.** 고아 탭 복구 때 `--continue` / `resume --last` 대신 저장본의 ID 로 재개한다.

| 에이전트 | 실행 중 읽기 (저장 수단) | 종료 시 출력 (보조) | 재개 명령 |
|---|---|---|---|
| Claude | `sessions/<pid>.json` — 정확 | ` Resume this session with: claude --resume <id>` | `claude --resume <id>` |
| OpenCode | 프로세스별 로그 `log/<시작시각>.log` 의 `session.prompt session.id=` — 정확 | `Continue  opencode -s <id>` | `opencode --session <id>` |
| Codex | 잠긴 `thread-writer-locks/<id>.lock`(살아 있는 스레드) × `threads.cwd`, 겹치면 시각 대조 — 대부분 정확 | `To continue this session, run:` / `  codex resume <id>` | `codex resume <id>` |
| Hermes | `state.db` `sessions.cwd`·`started_at`·`last_activity_at` 대조(v0.21) + 화면 배너 — 추정 | `Resume this session with:` / `  hermes [--tui ]--resume <id>` | `hermes --resume <id>` |

- **확실도**: Claude·OpenCode 는 정확, Codex 는 잠금 파일 + cwd 로 대부분 정확, Hermes 는 cwd·시각 대조로 추정이다. 저장본에 확실도를 함께 기록하고, 이어하기 창에서 추정 ID 는 기본으로 체크하지 않는다.
- **저장하지 않고 재시작하면**(크래시 포함) 저장본이 없으므로 기존 `--continue` / `resume --last` 로 돌아간다.
- **처음 배포하는 재시작은 못 잡는다.** 그 재시작의 종료 절차는 옛 코드가 돈다.

## 1. 배제한 것

hook 이거나 에이전트 쪽에 코드를 심어 실행하는 방식은 모두 뺀다.
- Claude: hooks(SessionStart 등), statusLine 명령, `--settings` 로 hook 주입
- Codex: hooks(`hooks.json`, `-c hooks...`), `notify`
- Hermes: shell hook(`config.yaml` `hooks:`), plugin hook
- OpenCode: server/TUI plugin(`OPENCODE_CONFIG_DIR`, `OPENCODE_TUI_CONFIG`)
- Orca 방식(§6): 전부 hook 기반이라 채택하지 않는다.

hook 이 아닌 **실행 인자**는 남긴다. BuilderGate 가 직접 띄우는 경우에만 쓴다.
- Claude `--session-id <uuid>`: ID 를 미리 정한다.
- Codex `-c tui.terminal_title=["thread-id"]`: OSC 0 제목에 ID 를 싣는다. 32자에서 잘리고 사용자 제목 설정을 덮으므로 선택 사항이다.

## 3. 에이전트별 — 실행 중 읽기

### 3.1 Claude Code — PID 파일 (정확)

- **위치**: Windows `%USERPROFILE%\.claude\sessions\<pid>.json`, WSL `~/.claude/sessions/<pid>.json`.
- **필드**: `pid`, `sessionId`, `cwd`, `startedAt`(ms), `procStart`, `status`(idle/busy/waiting/shell), `version`, `pidDomain`.
- **실측**: Windows 에서 살아 있는 `claude.exe` 15개 모두 파일이 있었고, 죽은 PID 의 잔여 파일은 0개였다.
- **동작** (실행 파일 코드 `concurrentSessions`):
  - 시작할 때 쓴다.
  - 세션이 바뀌면 구독 콜백이 `sessionId` 를 덮어쓴다(`$t({sessionId:P, …})` → `updatePidFile`). cwd 가 바뀌면 `cwd` 를 덮어쓴다.
  - `process.on("exit")` 에서 지운다.
- **PTY → claude PID**: Windows 프로세스 트리로 이어진다.
  - 실측 경로: `claude.exe ← cmd.exe ← powershell.exe(PTY 셸) ← node.exe(BuilderGate)`
  - 비용: `Get-CimInstance Win32_Process` 전체 조회에 2.4초(1,181 프로세스). 필요할 때만 조회한다.
- **트리 없이 대조**: `cwd` + `startedAt` 을 BuilderGate 가 본 실행 시각과 맞춘다.
  - cwd 만으로는 안 된다. 실측에서 살아 있는 세션 4개가 같은 cwd 였다.
- **WSL 에서 도는 claude**: Linux PID 를 Windows 에서 모르므로 `\\wsl.localhost\<distro>\home\<user>\.claude\sessions` 를 cwd·시각으로 대조한다.
- **실행 인자**: BuilderGate 가 띄우는 새 세션은 `--session-id <uuid>` 로 미리 정한다. 재개(`--resume <id>`)는 ID 를 유지한다.

### 3.2 OpenCode — 프로세스별 로그 (정확)

- **위치**: `~/.local/share/opencode/log/<UTC 시작시각>.log` (Windows `C:\Users\<u>\.local\share\opencode\log`). 프로세스마다 한 파일이다.
- **내용**: 프롬프트마다 `service=session.prompt session.id=ses_…` 가 남는다. Windows·WSL 로그 모두에서 형식을 확인했다.
- **찾는 법**: opencode 프로세스의 시작 시각과 가장 가까운 파일 이름을 고른다. 그 파일의 마지막 `session.prompt` 가 현재 세션이다.
- **보조**: `opencode.db` 의 `message(session_id, time_created)`, `session(directory)`.
- **ID 가 바뀌는 경우**:
  - 첫 프롬프트 전에는 세션이 없다.
  - `/new` 뒤에는 다음 프롬프트에서 새 ID 가 생긴다.
  - `/sessions` 전환은 다음 프롬프트에서 로그에 드러난다.

### 3.3 Codex — 잠금 파일 + cwd (대부분 정확)

- **PID 로 찾을 수 없다.** 실측: BuilderGate(2222) 안의 Codex TUI(PID 111032)는 스레드를 공유 app-server daemon 에서 돌린다.
  - `logs_2.sqlite` 의 `process_uuid` 는 `pid:<pid>:<uuid>` 형식이다(`state/src/log_db.rs:441-442`).
  - TUI 의 로그 행 284개는 `thread_id` 가 모두 비어 있다. 그 스레드의 로그는 daemon PID 로 남는다.
  - daemon 은 세션 도중 자동 업데이트로 교체되었다(11:12, 새 PID 32636).
- **대조**
  - TUI 프로세스 생성 06:36:06 ↔ `state_5.sqlite` `threads.created_at` 06:36:07 (새 스레드).
  - `threads(id, cwd, created_at, updated_at, source)` 와 `history.jsonl {session_id, ts(초)}` 를 쓴다. `history.jsonl` 은 프롬프트마다 제출 시점에 기록된다.
  - BuilderGate 가 그 탭에서 Enter 를 본 시각과 cwd 로 맞춘다.
- **살아 있는 스레드 = 잠긴 lock 파일**
  - 동작: 스레드마다 `$CODEX_HOME/thread-writer-locks/<thread-id>.lock` 을 독점 잠금(`try_lock`)으로 잡고, 닫히면 `Drop` 에서 지운다(`rollout/src/writer_lock.rs:17-186`, 0.155.1·0.157.1 동일).
  - 실측: Windows 에 lock 파일은 하나(`01a0da7f…`)뿐이었고, 읽으려 하면 I/O 오류가 났다(잠김). 그 스레드가 BuilderGate 안 TUI 의 스레드였다.
  - 살아 있는 스레드 목록과 `threads.cwd` 가 탭 cwd 에서 하나로 겹치면 정확하다.
  - 여럿이면 `created_at`·`updated_at`·`history.jsonl` 시각으로 가른다.
  - Linux 는 권고 잠금이라 읽기로는 판별되지 않는다. `flock -n` 으로 확인해야 한다.
- **보조**
  - TUI 명령줄이 `resume <id>` 였다면 거기서 바로 얻는다.
  - 0.157 의 새 `codex agents` 는 사람이 보는 TUI 목록이라 기계가 읽을 수 없다.
  - daemon 프로토콜의 `thread/loaded/list` 는 로드된 스레드 ID 만 준다(`app-server-protocol/src/protocol/v2/thread.rs:1637`). lock 파일로 같은 정보를 더 싸게 얻는다.
- **ID 가 바뀌는 경우**: `/new`·`/clear`·`/fork` 는 새 ID, `resume` 은 유지.

### 3.4 Hermes — DB cwd·시각 + 화면 (추정)

- **v0.21.5 에서 DB 가 좋아졌다.**
  - `sessions` 에 `cwd`, `git_branch`, `git_repo_root`, `last_activity_at`, `title` 등이 추가되었다(`hermes_state_common.py:377` 부근 스키마).
  - `--resume` 은 기본으로 그 cwd 로 되돌아간다(`--no-restore-cwd`, `--in DIR` 신설).
  - 그래서 cwd + `started_at`/`last_activity_at` 으로 Codex 처럼 대조할 수 있다.
  - PID 는 여전히 없다. 프로세스별 등록 파일도 없다.
- **옛 DB 의 한계**(v0.10 에서 쌓인 행)
  - cwd 가 없다.
  - `ended_at IS NULL` 인 cli 세션이 131개였다. 강제 종료된 세션이 닫히지 않은 채 남는다.
  - `messages.timestamp` 는 제출 시각이 아니라 기록(flush) 시각이다.
- **새로 생긴 `HERMES_SESSION_ID`**: 프로세스 안에서 설정되고 압축 때 갱신되어 Hermes 의 자식 프로세스에 전달된다(`agent/agent_init.py:1169`, `agent/conversation_compression.py:1653`). BuilderGate 는 부모 쪽이라 읽을 수 없다.
- **기본 UI**: 여전히 클래식 CLI 다. `--tui` 나 `display.interface: tui` 일 때만 새 TUI 가 뜬다(`hermes_cli/main_tui_launch.py:482-500`).
- **화면 출력**: 시작 배너 `Session: <id>`(80열 이상, compact 아님, `hermes_cli/banner.py:638`), `↻ Resumed session <id>`, `/status` 의 `Session ID:`. BuilderGate 스크롤백에 남아 있으면 읽는다.
- **ID 가 바뀌는 경우**
  - `/new` 는 `(^_^)v New session started!` 만 찍는다. 그 뒤 첫 제출 이후 `started_at` 이 가장 가까운 cli 세션을 고른다.
  - 압축으로 자식 ID 가 생겨도 `hermes -r <부모 id>` 가 최신 후손으로 이어 준다.
- **위치**: 이 PC 에서는 WSL 에만 있다. Windows 서버는 `\\wsl.localhost\<distro>\home\<user>\.hermes\state.db` 로 읽는다.

## 4. 종료 시 출력되는 재개 명령 (보조)

> 2026-09-26 사용자 결정으로 저장은 에이전트를 종료하지 않는다. 아래 방식을 "저장할 때 에이전트를 종료시키고 읽는" 용도로는 쓰지 않는다. 사용자가 **직접** 에이전트를 종료했을 때 PTY 출력에서 이 줄을 읽어, 마지막으로 끝난 세션 ID 를 보조로 기록하는 데만 쓴다.

네 에이전트 모두 정상 종료할 때 재개 명령을 PTY 에 찍는다. 공식 출력이라 **그 순간 세션의 정확한 ID** 를 준다.

| 에이전트 | 출력 | 조건 | 근거 |
|---|---|---|---|
| Claude | ` Resume this session with: claude [--worktree <w> ]--resume <id>` | 세션에 기록이 있을 때. **이름 붙은 세션은 `"<이름>"` 이 찍힌다**(`--resume` 은 이름도 받는다) | 실행 파일 코드 `resumeHintPrinted` |
| Codex | `To continue this session, run:` / `  codex resume <thread_id>` (보관된 스레드는 `Session archived: <id>`) | `resume_hint` 가 있을 때 | `tui/src/app/exit_summary.rs:134-145` |
| Hermes | `Resume this session with:` / `  hermes --resume <id>` (TUI 는 `  hermes --tui --resume <id>`, 제목이 있으면 `  hermes -c "<title>"`) | 메시지가 1개 이상 | v0.21.5 `hermes_cli/cli_session_mixin.py:1173`, `hermes_cli/main_tui_launch.py:62` |
| OpenCode | `Continue  opencode -s <id>` | 세션 화면에 있을 때 | `cli/cmd/tui/routes/session/index.tsx:254` |

- **장점**
  - 설치가 필요 없다.
  - `/clear`·`/new`·전환 뒤에도 그 순간의 ID 가 나온다.
  - 에이전트가 기록을 정리하고 끝나므로 강제 종료보다 재개 품질이 좋다.
- **한계**
  - 정상 재시작(`stop.bat`, UI 재시작)에서만 된다. 크래시·정전에는 없다.
  - 진행 중인 턴은 중단된다. 어차피 재시작으로 끝날 턴이다.
  - 탭마다 수 초의 대기 예산이 필요하다.
- **종료 키**: 에이전트마다 다르고 상태(턴 진행 중, 입력 중)에 따라 다르다. 예를 들어 Ctrl+C 두 번, Ctrl+D, `/exit`. **실측 검증이 필요하다.**
- **평소에도 쓸 수 있다.** 사용자가 직접 에이전트를 종료할 때도 같은 줄이 찍힌다. BuilderGate 가 항상 이 줄을 파싱해 두면 "마지막으로 끝난 세션 ID" 를 공짜로 얻는다.

## 6. Orca 는 어떻게 하는가 (참고, 채택 안 함)

`/tmp/orca` @ `9ab0a18e82`, 경로는 `src/` 기준.
- **자기 hook 으로만 얻는다.**
  - Claude: 사용자 `~/.claude/settings.json` 에 hook 을 쓴다.
  - Codex: 전용 `CODEX_HOME` 의 `hooks.json` 에 쓰고 trust 해시를 기록한다.
  - OpenCode: PTY 별 플러그인을 `OPENCODE_CONFIG_DIR` 로 붙인다.
  - Hermes: 플러그인을 설치한다.
  - 전달: PTY 에 `ORCA_PANE_KEY` 를 넣고, hook 이 loopback HTTP 로 보낸다. 서버가 꺼져 있으면 스풀 파일에 쌓는다.
- **hook 없이 이미 돌던 에이전트는 복구하지 않는다.**
  - 프로세스 검사는 종류·생존만 본다(`agent-process-recognition.ts:279-315`).
  - Codex `/status` 파싱 함수는 테스트에서만 호출된다(`codex/codex-tui-rollout-proof.ts:160`).
- **ID 가 없으면 `--continue` 로 가지 않고 셸만 복원한다.** Hermes 는 재개 대상이 아니다(`shared/agent-session-resume.ts:238-242`).
- **가져올 만한 것**(hook 과 무관)
  - ID 검사: 빈 값, 512자 초과, `-` 시작, 제어문자를 거부한다(`shared/agent-session-resume.ts:74-100`).
  - Claude 재개 명령 정리: 저장된 명령의 `--resume/--continue/-r/-c` 를 지우고 하나만 붙인다(`shared/agent-resume-launch-command.ts:9-21`).
  - 셸별 인용(`:65-70`).

## 7. BuilderGate 흐름 제안

1. **기록**: 탭마다 에이전트 종류(opencode 추가), 실행 시각(AI TUI 명령 제출), AI 포그라운드 중 Enter 시각, cwd 를 기록한다.
2. **실행 중 읽기**: Enter 몇 초 뒤(디바운스) 에이전트별 resolver 를 돌린다. 결과로 `agentSessionId`, 얻은 수단, 신뢰도를 `workspaces.json` 에 저장한다.
   - Claude: PID 파일
   - OpenCode: 프로세스별 로그
   - Codex·Hermes: 대조
3. **세션 저장 버튼**: 누르면 2단계 resolver 를 즉시 돌려 저장본을 쓴다. 에이전트는 멈추지 않는다. 헤더 버튼은 "저장됨 · 시각" 으로 바뀌고, 다시 누르면 최신 값으로 덮어쓴다.
4. **출력 파싱(보조)**: 사용자가 직접 에이전트를 종료할 때 찍히는 §4 의 재개 명령을 읽어 그 탭의 값으로 기록한다.
5. **복구**: 고아 탭에 ID 가 있으면 ID 로 재개하고, 없으면 기존 옵션을 그대로 쓴다.
   - 사용자 정의 옵션(`claudep` 등)은 인자만 바꾼다: `--continue` → `--resume <id>`, `resume --last` → `resume <id>`.
6. **ID 검증**: ID 는 셸에 입력되므로 형식을 엄격히 검사한다.
   - Claude/Codex: UUID. Claude 는 이름일 수 있으니 따옴표 인용하고 제어문자를 거부한다.
   - Hermes: `^\d{8}_\d{6}_[0-9a-f]{6}$`
   - OpenCode: `^ses_[0-9a-f]{12}[0-9A-Za-z]{14}$`
7. **실패 처리**: 전부 문서에 없는 내부 형식이다(종료 출력 문구 포함). resolver·파서는 실패하면 조용히 기존 동작으로 돌아간다.

## 8. 미확인·위험

- Claude PID 파일의 세션 전환 갱신은 코드로 확인했고 실제 `/clear` 로 확인하지 않았다.

- 내부 파일(`sessions/*.json`, `state_5.sqlite`, `logs/*.log`, `state.db`)과 종료 문구는 버전마다 바뀔 수 있다.
- 이 PC 에 떠 있는 opencode·hermes 프로세스가 없어서, 그 둘은 파일 형식만 확인했고 실행 중 대조는 확인하지 않았다.

- Windows Codex 는 0.157.0 그대로다. BuilderGate(2222) 탭에서 실행 중인 Codex(PID 111032)가 npm 설치본의 exe 를 잡고 있어 업데이트를 보류했다.
- Hermes 는 Python 3.14 전용이 되었다. v0.10 계열 설치에서 옛 업데이트 도구로 코드만 바뀌면 실행되지 않는다(`ruamel` 없음). 이때는 `python -m pm.cli install` 로 복구한다(2026-09-26 이 PC 에서 겪고 복구함).
