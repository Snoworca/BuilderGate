# i18n 연구 — 영어·한국어 지원 (2026-09-27)

## 결론

- **프런트엔드에서 구현한다.** 언어는 브라우저의 `navigator.language` 하나로 정한다. 한국어(`ko`, `ko-KR` 등)면 한국어, 아니면 영어다(사용자 규칙 그대로).
- **사전은 서버의 JSON 파일이다.** `frontend/public/locales/messages.{언어}.json` 은 빌드 후 서버 웹 루트의 `/locales/` 에 놓인다. 브라우저는 고른 언어의 파일 **하나만** 받아(실패하면 en 을 한 번 더) `Map<언어, Map<키, 문구>>` 에 올린 뒤 첫 렌더를 한다.
- **1차(단계 0~4)는 서버 코드를 바꾸지 않는다.** 정적 파일 서빙이 이미 인증 없이 열려 있고, 단일 실행파일 빌드도 `web/` 폴더를 그대로 싣는다.
- 옮길 문구는 **실행 경로의 한국어 문자열 958개(중복 제외 744개, 84개 파일)** 와 지금 영어로 나오는 편집기 문구(벤더 표 메뉴 6개·검색 패널 10개, CodeMirror 내장 패널)다. 서버에는 한국어 문구가 없다. 서버 오류 메시지는 영어이며 지금도 영어로 보인다.
- **`t()` 는 모듈 로드 중에 부르지 않는다**(모듈 최상위와 로드 때 즉시 도는 함수 본문). `main.tsx` 가 `App` 을 정적으로 import 해 모든 모듈의 최상위 코드가 사전보다 먼저 돈다. 958개 중 165개가 그 자리에 있다(§3.4).
- **가장 큰 비용은 테스트다.** E2E 71개 파일 중 38개가 한국어 문구로 요소를 찾거나 단언한다. `@playwright/test` 기본 로캘이 `en-US` 라서 **로캘을 `ko-KR` 로 고정하지 않으면 이 38개가 깨진다.** 단위 테스트는 소스 텍스트의 한국어를 단언하는 43개 파일과, 모델 함수가 돌려준 한국어를 단언하는 파일(최대 23개)이 영향을 받는다. 후자는 node 테스트에 ko 사전을 올려야 한다.
- **SRS 충돌이 있다.** FR-UIDS-003 은 요구 문장 자체가 "모든 UI 문구를 한국어로" 이고 AC-4 가 "i18n 은 만들지 않는다" 다. FR-UIDS-004 AC-6 은 터미널 영역의 문구 변경을 "영어→한국어" 로만 허용한다. 새 scope 를 만들고 두 요구사항을 승계해야 한다(§8).

### 2.2 서버 문구가 화면에 오는 경로

- `frontend/src/services/apiError.ts` 의 `parseApiErrorPayload` 가 서버의 `error.message`(없으면 최상위 `message`)를 그대로 화면 문자열로 만든다. 코드(`error.code`, 없으면 최상위 `code`, `:5-6`)가 메시지와 다르면 괄호 안에 덧붙인다. 그래서 **지금도 한국어 화면에 "Session not found" 같은 영어가 나온다.**
- 서버 오류는 대부분 코드를 갖는다: `AppError` 를 던지는 곳 153곳, 응답에 `{ error: { code } }` 를 쓰는 곳 12곳, 코드 없이 `{ error: '...' }` 문자열만 쓰는 곳 16곳. MCP 제어 라우트(`/api/mcp-control/*`)는 최상위 `{ ok: false, code, message }` 로 보낸다(`server/src/index.ts:355-371`, `server/src/services/McpControlRouteResult.ts:13-19` 가 서비스의 `code` 를 그대로 싣는다).
- 코드 수(테스트 제외, 리터럴로 셀 수 있는 것만): `ErrorCode` 열거형(`server/src/utils/errors.ts`) 52 + 열거형 밖 63 = **115종**. 열거형 밖은 `code: '…'` 리터럴 47종(`TARGET_NOT_FOUND`, `AGENT_PROFILE_NOT_FOUND`, `WEBHOOK_KEY_INVALID`, `CLOSE_CONFIRMATION_REQUIRED`, `MCP_LISTENER_ONLY` 등)과 선언된 목록(`McpSecurityContract.ts` 의 `MCP_DENIAL_CODES`, `SessionInputGateway.ts` 의 `INPUT_GATEWAY_DENIAL_CODES`, `fileJobManager.ts:105` 의 `FileJobManagerErrorCode` 5개)이다. `code: <변수>` 61곳은 세지 않았다. `McpToolService.ts` 의 JSON-RPC 응답은 에이전트가 받으므로 115종이 모두 브라우저에 오지는 않는다. 코드별 도달 경로는 추적하지 않았다.
- 그러므로 서버 문구는 **서버를 번역하지 않고** 프런트엔드가 `error.code` → 키 매핑 표로 `apiError.<CODE>` 를 고르면 된다. 표에 없으면 서버 메시지를 그대로 보인다. 표의 범위(브라우저가 받는 코드)는 단계 5 첫 작업으로 도출한다. 이 작업은 2차(단계 5)다.

### 2.5 기타

- 한국어 정렬이 두 곳에 하드코딩돼 있다: `new Intl.Collator('ko')`(`frontend/src/components/fileExplorer/fileListView.ts:124`), `localeCompare(b.label, 'ko')`(`frontend/src/utils/contextMenuBuilder.ts:191`). 활성 언어를 쓰도록 바꾼다(단계 6). `fileListView.ts:124` 는 모듈 최상위 상수라 §3.4 규칙대로 쓰는 시점에 만든다. `toLocaleString()` 은 이미 브라우저 로캘을 따른다.
- `frontend/index.html` 은 `<html lang="en">` 이다. 활성 언어로 바꾼다(스크린리더·글꼴 선택).
- 한글이 든 정규식이 2개 있다(TSV 종류 `regex`). `frontend/src/components/SessionSave/sessionSnapshotModel.ts:142` 는 `formatSavedAt()`(`:114-120`) 결과에서 `.replace(/^오늘 /, '')` 로 앞머리를 잘라 낸다. 번역하면 en 의 "Today " 는 잘리지 않는다 → 단계 2 에서 `formatSavedAt` 에 "오늘이면 시각만" 선택 인자를 두고 `:142` 가 그것을 쓴다(단계 2 의 유일한 로직 변경, ko 결과는 같다). `frontend/src/components/ui/uiClasses.ts:29` `containsHangul` 의 문자 범위는 문구가 아니라 판별 도구라 가드 3 이 이름으로 허용한다.

```
  catalog.ts            순수 함수: JSON → Map, 자리표시자 치환, 복수형 범주
  i18n.ts               실행부: 목록·사전 fetch, installCatalog(), t(), tn(), activeLanguage()
  keys.ts               type MessageKey·PluralKey (en JSON 에서 타입만 추론)
frontend/tests/unit/

```

사전은 **평면(flat) JSON** 이다. 한 줄이 곧 `"키": "문구"` 이고, 그대로 `Map<키, 문구>` 가 된다.

```json
{
  "common.cancel": "취소",
  "common.close": "닫기",
  "preset.delete.confirm": "'{label}' 항목이 목록에서 삭제됩니다. 이미 터미널에 보낸 내용은 그대로 남습니다.",
  "fileExplorer.selection.count.other": "{count}개 선택됨"
}
```

```json
{ "default": "en", "languages": { "en": "English", "ko": "한국어" } }
```

- 다른 언어를 붙일 때는 `messages.ja.json` 을 추가하고 `languages.json` 에 한 줄을 넣는다. 코드와 빌드는 바꾸지 않는다.
- 중첩 JSON(`{ "common": { "cancel": … } }`)은 쓰지 않는다. 평면이어야 키로 grep 할 수 있고 Map 과 1:1 이다.

### 3.2 언어 결정 (브라우저)

```ts
// negotiate.ts — 순수 함수, node --test 로 검증한다
export function pickLanguage(tag: string | undefined, supported: ReadonlySet<string>, fallback: string): string {
  const primary = (tag ?? '').split(/[-_]/)[0].toLowerCase();   // 'ko-KR' → 'ko'
  return supported.has(primary) ? primary : fallback;          // 그 밖은 'en'
}
// 호출: pickLanguage(navigator.language, supported, manifest.default)
```

- `navigator.language` 하나만 본다. 사용자 규칙 "한국어면 한국어, 아니면 영어" 를 그대로 옮긴 것이다. 언어가 늘면 "그 언어면 그 언어, 아니면 영어" 로 넓어진다. `navigator.languages` 를 순서대로 훑어 첫 지원 언어를 고르는 방식은 D3 대안이다.
- 결정은 페이지를 불러올 때 한 번만 한다. 실행 중 전환은 없으므로 React Context·재렌더 배선이 필요 없다(§3.4).

### 3.3 로딩 순서 (첫 렌더 전)

```
main.tsx
  1. GET /locales/languages.json                      (수백 바이트)
  2. lang = pickLanguage(navigator.language, …)
  3. GET /locales/messages.{lang}.json                (고른 언어 하나만)
  4. installCatalog(lang, json)                       (catalogs.set(lang, new Map(Object.entries(json))))
  5. document.documentElement.lang = lang
  6. createRoot(...).render(<App/>)
```

- 실패하면 `en` 으로 한 번 더 시도한다. 그것도 실패하면 키 이름을 그대로 보이며 렌더한다. 서버가 없으면 앱이 어차피 동작하지 않으므로 사전을 번들에 넣어 두지 않는다.
- 로그인 화면도 첫 렌더 뒤에 나오므로 번역된다. 두 요청은 인증 없이 받을 수 있는 정적 파일이다.
- 캐시: `express.static` 기본값이 ETag 재검증이다. 사전을 고친 뒤에는 304 가 아니라 새 내용이 온다.
- `main.tsx:4` 는 `App` 을 정적으로 import 한다. 그래서 1~4 보다 **모든 모듈의 최상위 코드가 먼저 돈다.** 이 순서가 §3.4 의 모듈 로드 중 호출 금지 규칙의 근거다.

### 3.4 번역 API

```ts
// keys.ts — 타입 전용 import 라 번들에 들어가지 않는다
type EnKey = keyof typeof import('../../public/locales/messages.en.json');
export type PluralKey = EnKey extends infer K ? K extends `${infer B}.other` ? B : never : never;  // 'fileExplorer.selection.count'
export type MessageKey = Exclude<EnKey, `${PluralKey}.${string}`>;                                    // t() 가 받는 키

// i18n.ts
const catalogs = new Map<string, Map<string, string>>();   // 사용자가 권장한 구조
let activeLang = 'en';
let active = new Map<string, string>();

export function installCatalog(lang: string, json: Record<string, string>): void {   // main.tsx 초기화·테스트 로더가 부른다
  catalogs.set(lang, new Map(Object.entries(json)));
  activeLang = lang;
  active = catalogs.get(lang)!;
}
export function t(key: MessageKey, params?: Params): string {
  const template = active.get(key);
  if (template === undefined) { warnOnce(key); return key; }
  return fill(template, params);   // template.replace(/\{(\w+)\}/g, (m, n) => (params && n in params ? String(params[n]) : m))
}
export function tn(key: PluralKey, count: number, params?: Params): string {
  const full = `${key}.${new Intl.PluralRules(activeLang).select(count)}`;   // 키 조립은 여기 한 곳뿐
  const template = active.get(full);
  if (template === undefined) { warnOnce(full); return full; }
  return fill(template, { count, ...params });
}
```

- **모듈 단일 인스턴스**다. 언어가 렌더 전에 정해지고 바뀌지 않으므로 React 밖의 모델 파일(`mcpControlDialogModel.ts`, `workspaceDeleteFlow.ts`, `contextMenuBuilder.ts` 등)도 `t()` 를 부를 수 있다. **단 모듈 로드가 끝난 뒤 도는 함수 안에서만 부른다.** 모듈 최상위(최상위 문장, 최상위 상수의 초기화식)와 로드 때 즉시 도는 함수 본문(최상위 IIFE, 최상위에서 `Array.from`·`.flatMap` 등에 넘긴 콜백 — 지금 6곳, 예: `fileListView.ts:68`, `settingsDraftHelpers.ts:102`)에서 평가된 `t()` 는 사전이 오기 전이라 키를 돌려준다(§3.3). 현재 한국어 리터럴 165개(20개 파일)가 그 자리에 있다: `mcpControlDialogModel.ts` 57 · `settingsDraftHelpers.ts` 28 · `McpControlDialog.tsx` 18(`:67-97` 의 `TAB_DEFINITIONS`·라벨 표 4개) 등. 이런 표는 문구 대신 `MessageKey` 를 담고, 화면에 쓰는 곳에서 `t()` 한다. 호출 위치 가드(§4 가드 4)가 지킨다.
- **키 타입 검사**: 없는 키는 `t()` 에서, 복수형이 아닌 키는 `tn()` 에서, 복수형 키(`….one`)는 `t()` 에서 컴파일 오류다. frontend 의 TS 5.9.3 과 `tsconfig.app.json` 과 같은 컴파일 옵션(`moduleResolution: bundler`, `resolveJsonModule` 미지정)으로 세 경우 모두 TS2345 가 나는 것을 실측했다.
- **키는 리터럴로만 쓴다**: `t()`·`tn()` 의 리터럴 인자, 또는 `satisfies Record<…, MessageKey>` 매핑 표의 리터럴 값이다. 열거값 → 표시명은 이 매핑 표로 옮긴다(현재 "그 밖의 객체 속성" 104개가 이 모양이다). `` t(`mcp.mode.${mode}`) `` 처럼 조립하면 사용 여부 가드를 빠져나간다. 조립은 `tn()` 내부의 복수형 선택 하나뿐이다. 서버 오류 코드도 조립하지 않고 `error.code` → `apiError.<CODE>` 매핑 표로 고른다(단계 5).
- **복수형**: 영어에 필요하다. 필요한 키만 `{key}.one`/`{key}.other` 로 나누고 `tn()` 으로 부른다. 각 사전은 **자기 언어의 범주만** 둔다: `new Intl.PluralRules(lang).resolvedOptions().pluralCategories` 가 en 은 one·other, ko 는 other 다. 동등성 가드는 이 범주로 비교한다(§4 가드 1).
- **CodeMirror 문구**: 라이브러리 내장 패널은 `state.phrase('<영어 원문>')` 으로 그린다. 벤더 표 메뉴 6개와 벤더 검색 패널 10개(§2.1)도 단계 3 에서 같은 줄 안에서 이 방식으로 바꾼다. 호스트가 `EditorState.phrases.of({ 'Find': t('editor.cm.find'), … })` 확장을 함수 안에서 만들어(가드 4) 코드 편집기 확장(`codeEditorExtensions.ts`)과 벤더 편집기의 `extensions` prop(FR-MDE-005 가 `useMemo` 로 고정)에 넣는다. 표에 없는 원문은 영어 그대로 나온다.
- 라이브러리(i18next 등)는 쓰지 않는다. 언어가 고정이고 기능이 치환·복수형·없는 키 셋뿐이라 자체 구현이 100줄 안쪽이며, 요구된 Map 구조를 그대로 쓸 수 있다.

### 3.5 키 이름 규칙

`{영역}.{대상}.{용도}`. 소문자 camelCase 세그먼트를 점으로 잇는다. 마지막 세그먼트 `zero`·`one`·`two`·`few`·`many`·`other` 는 복수형 키에만 쓴다. 복수형 기본 키(예: `x.count`) 아래에는 범주 키만 둔다 — `x.count.hint` 같은 키는 §3.4 의 `Exclude` 로 `MessageKey` 에서 빠져 `t()` 가 컴파일 오류를 낸다.

| 영역 | 예 |
|---|---|
| `common.*` | `common.cancel`, `common.close`, `common.unknown`, `common.delete` |
| 화면별 | `mcp.security.mode.loopback`, `settings.section.cors.title`, `sessionSave.restore.confirm` |
| `apiError.<CODE>` | `apiError.SESSION_NOT_FOUND` (2차. 마지막 세그먼트만 예외로 서버 응답 코드 그대로 대문자) |

받침에 따라 모양이 바뀌는 조사(을/를, 이/가, 은/는, 와/과, (으)로)는 자리표시자 바로 뒤에 붙이지 않는다(`'{label}' 항목이` 처럼 명사를 끼운다). 에·의·도·입니다처럼 모양이 하나인 조사는 괜찮다. 단계 2 는 ko 값을 바꾸지 않으므로(FR-I18N-003 AC-2) 이 규칙은 단계 3 이후 새로 쓰거나 고치는 문구에 적용한다. 지금 어긋나는 것은 `{…}로` 3개(`SettingsPage.tsx:273`·`:276`, `TerminalShortcutDialog.tsx:327`)이며, 자리표시자 값이 `conpty`·`winpty`·프로필 이름 같은 정해진 목록이라 그대로 옮긴다.

2. **사용**: en 의 모든 키(복수형은 기본 키)가 `src` 에 문자열 리터럴로 나온다(죽은 키 금지). 코드가 쓰는 키가 en 에 있는지는 `tsc` 가 본다(§3.4).

5. **en 값**: `messages.en.json` 의 값에 한글이 없다. 단계 2 의 임시 값이 남지 않게 하며, 단계 3 부터 켠다.

## 5. 위험

| 위험 | 대응 |
|---|---|
| 첫 렌더 전 요청 2개(순차) | 정적 파일이고 수 KB 다. 로컬·LAN 에서는 무시할 수준이다. 원격이면 1 RTT 가 늘어난다. 필요하면 나중에 `languages.json` 을 빌드에 넣어 1개로 줄인다 |
| 영어 번역 품질 | 초안은 작성하되 검토가 필요하다. 추출한 한국어 값은 바꾸지 않으므로 1차에서 한국어 화면이 바뀌는 것은 지금 영어로 나오는 편집기 문구(§2.1)와 `<html lang>`(en→ko, 글꼴 선택·스크린리더) 둘이다. 2차는 서버 오류 문구를 더한다 |
| 문구 추출 중 동작 회귀 | 문구만 옮기고 로직은 건드리지 않는다(예외: `formatSavedAt` 선택 인자, §2.5). 단계 2 동안 en 에 임시 값을 함께 써서 빌드가 살아 있고, ko 로캘로 고정한 E2E 가 기존 셀렉터 그대로 회귀를 잡는다 |
| 모듈 로드 중 `t()` | 화면에 키가 보인다. 가드 4 가 막는다 |
| 영어 화면 E2E 부재 | 로그인→주요 창 열기 정도의 영어 로캘 스모크 1개를 추가한다(단계 4) |
| 다른 레인과 충돌 | 84개 파일을 건드린다. 활성 target 인 ui-design-system 이전 작업(FR-UIDS-004)과 같은 파일이 겹친다. 순서를 정해야 한다. 단계 0 의 `set-active-target i18n --create` 는 Active Target 을 ui-design-system 에서 i18n 으로 바꾼다. `settingsDraftHelpers.ts`·`TerminalView.tsx` 편집은 이미 낡은 consumer 매니페스트에 드리프트를 더한다 → 재봉인은 i18n 이 하지 않는다(단계 2-s, D7) |

## 7. 버린 대안

- **서버 OS 언어로 결정** (처음 지시). 실측으로는 동작했다: Windows node 24.16.0(full-icu), 설치본 node.exe, 단일 실행파일에 쓰는 pkg 기반 node 22.22.2 모두 `Intl.DateTimeFormat().resolvedOptions().locale` 이 `ko-KR` 이었다. 다만 pkg 기반 node 는 **small-icu** 라 `supportedLocalesOf(['ko-KR'])` 가 `[]` 이고 한국어 월 이름이 `M01` 로 나온다. Git Bash 가 Windows 에 `LANG=en_US.UTF-8` 을 넣을 수 있다는 점과 macOS launchd 에 `LANG` 이 없다는 점도 걸렸다(둘 다 미실측). 원격 사용자에게 서버 기계의 언어를 강요한다는 점과 함께, 2026-09-27 사용자 결정으로 브라우저 언어로 바꿨다.
- **`key="value"` 텍스트 파일** (처음 지시). 값을 JSON 문자열로 해석하는 파서로 프로토타입을 만들어 통과했지만, JSON 으로 저장하라는 결정으로 대체했다. 평면 JSON 은 한 줄이 `"키": "문구"` 라 같은 편집성을 가진다.
- **i18next 같은 라이브러리**: 실행 중 언어 전환·네임스페이스·백엔드 플러그인이 필요 없다. 요구된 Map 구조와도 맞지 않는다.
- **사전 로드 뒤 `import('./App')`**: 모듈 최상위 `t()` 도 동작하게 되지만, node 테스트는 모델 모듈을 import 하는 순간 최상위 `t()` 가 돌아 로더를 import 순서보다 앞세워야 하고, `main.tsx` 에 정적 import 가 하나 늘면 조용히 키가 보인다. 최상위 호출 금지와 가드 4 를 택했다.

## 8. SRS 초안 (IEEE 29148 형식, 미등록)

등록 위치 제안은 `docs/spec/45.i18n.srs.md`, prefix `I18N`, 새 target `i18n` 이다. 모두 CLI 로 하고 `--root .` 를 준다(MCP mutation 금지, CLAUDE.md).

1. target: `speckiwi set-active-target i18n --create` (scaffold-scope 는 target 을 만들지 않는다. Active Target 도 i18n 으로 바뀐다, §5) → `speckiwi set-target-goal i18n --goal "…"`
2. scope: `speckiwi scaffold-scope I18n:I18N --apply`
3. 새 요구사항: `speckiwi add-requirement --scope I18N --target i18n …`
4. 승계: `speckiwi supersede --old FR-UIDS-003 --scope I18N --target i18n …`, `speckiwi supersede --old FR-UIDS-004 --scope UIDS --target ui-design-system …`. `--target` 을 빼면 Active Target 으로 간다
5. 3·4 의 결과는 `Stability=draft` 다. 사용자 승인 뒤 `speckiwi update-stability <ID> evolving --reason "…"`
