# Design — mobile terminal keyboard (epic #133)

Reference mock: `docs/design/mobile-terminal-keyboard.html`. Sub-issues: #134 encoder, #135 modifier latch, #136 accessory bar, #137 special keyboard, #138 numpad.

## Encoder

### Key-to-bytes mapping

- [D-001] The encoder MUST be a pure module that maps a key name plus a modifier state `{ctrl, alt, shift}` plus an `applicationCursor` flag to the exact byte string sent to the PTY.
- [D-002] Arrow keys without modifiers MUST encode as `ESC [ A..D` when `applicationCursor` is false and as `ESC O A..D` when it is true.
- [D-003] Arrows, Home and End with any modifier MUST encode as `ESC [ 1 ; m X` where `m = 1 + shift(1) + alt(2) + ctrl(4)`.
- [D-004] Home and End without modifiers MUST encode as `ESC [ H` / `ESC [ F`, and as `ESC O H` / `ESC O F` when `applicationCursor` is true, matching xterm.js hardware keys.
- [D-005] Insert, Delete, PageUp and PageDown MUST encode as `ESC [ n ~` with n = 2, 3, 5, 6, and as `ESC [ n ; m ~` when a modifier is active.
- [D-006] F1–F4 MUST encode as `ESC O P..S` and F5–F12 as `ESC [ 15~ 17~ 18~ 19~ 20~ 21~ 23~ 24~`.
- [D-007] Esc, Tab, Enter and Backspace MUST encode as `ESC`, `\t`, `\r` and `0x7f`, and Shift+Tab as `ESC [ Z`.
- [D-008] A single character with Ctrl MUST encode per the xterm table: `a`..`z` → `0x01`..`0x1a`; `@`, `2` and Space → `0x00`; `[` and `3` → `0x1b`; `\` and `4` → `0x1c`; `]` and `5` → `0x1d`; `^` and `6` → `0x1e`; `_`, `-` and `7` → `0x1f`; `?` and `8` → `0x7f`; any other character is sent unchanged.
- [D-009] Alt MUST prefix a single `ESC` only to keys without a modifier parameter form (single characters, Esc, Tab, Enter, Backspace, F1–F12); keys with the `ESC [ 1 ; m X` or `ESC [ n ; m ~` form carry Alt in `m` instead.
- [D-010] Shift on a single letter MUST upper-case it before Ctrl/Alt are applied.

### Injection

- [D-011] Encoded bytes MUST reach the server through the existing `TerminalHandle.sendInput` path, which ends in `submitCapturedInput`, so operation IDs, the input queue and the checkpoint barrier apply unchanged.
- [D-012] `TerminalHandle` SHALL expose `getApplicationCursorKeysMode()` that reads the live `term.modes.applicationCursorKeysMode`, forwarded by `TerminalContainer` like `getMouseTrackingActive`.

## Modifier latch

### States

- [D-013] Each of Ctrl, Alt and Shift MUST hold one of three states: `off`, `once` or `locked`.
- [D-014] A tap MUST move `off` → `once`, `once` → `off` and `locked` → `off`.
- [D-015] A press held for 1500 ms MUST move the key to `locked` at the 1500 ms mark, without waiting for release.
- [D-016] Releasing before 1500 ms MUST count as a tap; a `pointercancel` leaves every state unchanged.
- [D-017] After one encoded key is sent, every modifier in `once` MUST return to `off`, while `locked` modifiers stay `locked`.
- [D-018] Reaching `locked` MUST call `navigator.vibrate(25)` only when that function exists, so a browser without the Vibration API locks silently and raises no error.

### Applying the latch to system-keyboard input

- [D-019] When any modifier is not `off`, data from `term.onData` that is exactly one printable ASCII character (0x20–0x7E) MUST be re-encoded through the encoder before `submitCapturedInput`, inside the existing `onData` handler, whatever the IME composition flags say, because Android keyboards deliver Latin letters through composition.
- [D-020] The latch MUST NOT transform non-ASCII data (Hangul syllables and other IME commits), multi-character data, parser replies, focus reports or programmatic paste.
- [D-021] The latch state SHALL live in one module-level store with subscribe/getSnapshot, read by `TerminalView` and by every keyboard component.
- [D-022] The re-encoding MUST happen after the provenance counter has been consumed and after the query-reply and replay guards have passed, and applies to every non-programmatic-paste input whether or not a user-input permit is present, because Android IME commits arrive after the microtask permit expires.

### Lockable-key marking

- [D-023] Only Ctrl, Alt and Shift MUST be lockable, each showing a corner dot that is grey when `off`, blue when `once` and glowing orange when `locked`.
- [D-024] The `once` state MUST render as blue text with underline and no filled background, and `locked` as an orange tinted box with an orange border.
- [D-025] While a lockable key is pressed, a fill MUST rise from the bottom over 1500 ms, with the browser context menu, text selection and `contextmenu` propagation to the tab wrapper suppressed.

## Accessory key bar

### Content and placement

- [D-026] The bar MUST show, left to right: Esc, Tab, Ctrl, Alt, separator, ←, ↑, ↓, →, separator, Home, End, PgUp, PgDn, and a keyboard-switch button.
- [D-027] The bar MUST render only when `useResponsive().isMobile` is true and either a document-level `focusin` has landed on the active tab's `.xterm-helper-textarea` without a later `focusout`, or the special keyboard is open.
- [D-028] The bar MUST sit directly above the system keyboard, using `window.visualViewport` (height and offsetTop) to compute the keyboard inset.
- [D-029] While the bar is shown, the app root height MUST follow `visualViewport.height` (through a CSS variable on `.app`), so the whole layout including the terminal shrinks above the keyboard and the existing ResizeObserver re-fits xterm.
- [D-030] The bar MUST scroll horizontally when wider than the screen, with its scrollbar hidden.
- [D-031] Every key MUST be at least `--ctl-touch` (44 px) in its smaller tappable dimension in the special keyboard and 36 px high in the bar.

### Focus

- [D-032] Pressing any bar or panel key MUST NOT move focus away from the terminal while the system keyboard is shown (`preventDefault` on `pointerdown`/`mousedown`).
- [D-033] Win, AltGr, mouse and screenshot keys MUST NOT appear anywhere in the bar or panel.

## Special keyboard

### Switching

- [D-034] Tapping the keyboard-switch button while the system keyboard is shown MUST blur the terminal textarea through a new `TerminalHandle.blurInput()` and open the special keyboard panel in the same place.
- [D-035] The panel height MUST equal the last measured system-keyboard inset, with a 280 px default when none was measured.
- [D-036] Tapping the switch button while the panel is open MUST close the panel and call `TerminalHandle.focus()` synchronously inside the tap handler, so iOS and Android raise the system keyboard again.
- [D-037] While the panel is open the terminal textarea MUST stay blurred: the tab wrapper `onPointerDown → focusTerminal` (App.tsx), `TerminalView` `handleClick`, and the pending focus-restore path (`pendingFocusRestoreRef`) are all suppressed, and the blur clears `pendingFocusRestoreRef`.

### Layout

- [D-038] The panel MUST have a top row Esc, Tab, Ctrl, Alt, Shift and below it three 3×4 blocks: F1–F12; ⌫ / | ~ * - ` : + _ = Enter; and Home ↑ PgUp / ← (empty) → / End ↓ PgDn / Ins Del Numpad.
- [D-039] Every panel key MUST send through the encoder with the latch applied and consume `once` modifiers.

## Numpad

- [D-040] Tapping Numpad MUST replace only the right 3×4 block with `7 8 9 / 4 5 6 / 1 2 3 / 0 . Arrows`, leaving the other blocks in place.
- [D-041] Numpad digits and `.` MUST send as plain characters through the encoder with the latch applied.
- [D-042] The chosen right block SHALL persist per device in `localStorage`, read and written inside try/catch so storage failure changes nothing else.

## Cross-cutting

### Integration items

- [I-001] Every user-visible sentence (button titles, aria labels, the switch button label) MUST go through `t()` with keys in both `messages.{en,ko}.json`; key cap names (Ctrl, Esc, F1, PgUp, arrows) stay ASCII constants outside the catalogs.
- [I-002] Desktop behaviour MUST NOT change: no component of this feature renders when `isMobile` is false.
- [I-003] Each sub-issue #134–#138 MUST be closed only after its wave is merged and its requirements carry test evidence.
