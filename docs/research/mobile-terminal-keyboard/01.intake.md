# Intake — mobile terminal keyboard

- Source class: GitHub issue (`intake-issue`) — epic #133, sub-issues #134–#138 (`- [ ] #134` … `- [ ] #138` in the epic body, 5 linked sub-issues).
- Design mock: `docs/design/mobile-terminal-keyboard.html` (committed 5c2e7c3b). The mock is the visual and behavioural reference for every wave.
- Autonomy: `--auto` is active. Design questions not answered by the issues, the mock or the user's chat decisions are answered by the decision committee, not the user.

## Intent

Mobile users of the BuilderGate web terminal cannot type arrow keys, Esc, Ctrl or F keys because the phone's system keyboard has none. Provide, modelled on the Microsoft Remote Desktop app:

1. an accessory key bar pinned directly above the system keyboard;
2. a special keyboard panel that replaces the system keyboard (F1–F12, arrows, Home/End/PgUp/PgDn, Ins/Del) with a numpad variant;
3. modifier latching for Ctrl/Alt/Shift.

## Decisions already taken by the user (chat, 2026-10-17)

- Modifier latch: short tap = applies to the next single key only (blue text + underline, blue dot, no filled box); hold 1.5 s = lock (orange box + glowing orange dot, weak vibration `navigator.vibrate(25)`); tap while locked = release. The user confirmed this two-state model after the trade-off was explained.
- Only Ctrl, Alt and Shift are lockable; they are marked by a corner dot.
- Win, AltGr, mouse and screenshot keys from RD Client are excluded.
- Arrow sequences follow xterm's live application-cursor mode.
- Vibration only on Android Chrome; iOS shows light only, without error.
