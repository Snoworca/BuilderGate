## 2. 이미 있는 결함 (코드 모드와 무관하게 지금 발생)

### D1. 저장하면 CRLF 가 LF 로 바뀐다 — 실측

CodeMirror 6 은 줄 구분자를 정규화하고 `doc.toString()` 은 항상 `\n` 으로 잇는다. 편집기는 `update.state.doc.toString()` 과 `getMarkdown()` 에서 이 값을 그대로 저장한다.

```
입력                 "﻿a\r\nb\r\n"
doc.toString()       "﻿a\nb\n"          ← 현재 저장되는 값
lineSeparator('\r\n') 설정 + sliceDoc()   "﻿a\r\nb\r\n"   ← 보존됨
```

(`@codemirror/state` 로 직접 측정. BOM 은 문자로 남아 보존된다.)

귀결: CRLF 파일을 한 글자만 고쳐 저장해도 **모든 줄이 diff 에 잡힌다.** 이 저장소처럼 CRLF 파일이 섞인 곳에서 마크다운에도 이미 일어나는 일이며, 코드 파일로 넓히면 영향이 커진다.

### D2. UTF-8 이 아닌 파일은 저장하면 깨진다 — 코드 근거

서버가 CP949/EUC-KR 등을 UTF-8 로 디코드하면 잘못된 바이트는 U+FFFD 로 바뀐다. 편집기는 그 문자열을 그대로 보여 주고, 저장하면 U+FFFD 가 `EF BF BD` 로 기록되어 **원래 바이트를 복구할 수 없다.** 읽기에서 경고하지 않는다. 실파일로 재현하지는 않았다.

### D3. 코드 파일이 마크다운 편집기로 열린다

`.ts` `.py` `.sh` `.yaml` 이 허용 목록에 있어 지금도 열리지만 마크다운 모드다.

- `#` 주석이 제목으로, `*`·`_` 가 강조로, `|` 가 표로 렌더링되어 **원문이 가려진다.**
- 마크다운 입력 보조(`startAsteriskList`, `extendEmphasisPair`, `autoCloseCodeFence`, `*`·`_`·`` ` `` 자동 짝)가 코드 입력을 바꾼다.
- 줄 번호가 없고 줄 바꿈이 강제된다.

## 3. 설계 (A안)

### 3.1 모드 결정

순수 함수 하나로 파일 이름에서 모드를 정한다. 탐색기의 "열 수 있음" 판정과 아이콘도 같은 표를 쓰게 해 목록이 둘로 갈라지지 않게 한다.

```ts
type EditorMode =
  | { kind: 'markdown' }
  | { kind: 'code'; language: LanguageDescription | null }; // null = 일반 텍스트

function resolveEditorMode(fileName: string): EditorMode | null; // null = 열지 않음
```

판정 순서:

1. **정확한 파일명 표**: `Dockerfile` `Containerfile` `Makefile` `GNUmakefile` `CMakeLists.txt` `Jenkinsfile` `Vagrantfile` `Gemfile` `Rakefile` `Procfile` `Justfile` `.gitignore` `.gitattributes` `.gitmodules` `.editorconfig` `.npmrc` `.nvmrc` `.yarnrc` `.dockerignore` `.eslintignore` `.prettierignore` `.babelrc` `.prettierrc` `.eslintrc` `.htaccess` `.bashrc` `.zshrc` `.profile` `LICENSE` `README`
2. **접두사 규칙**: `.env`, `.env.*`
3. **마크다운**: `md` `markdown` `mdx` → `markdown`
4. **확장자 → 언어** (`LanguageDescription.matchFilename`)
5. **텍스트로 아는 확장자** (`txt` `log` `csv` `tsv` `lock` `conf` `cfg` 등) → 언어 없는 코드 모드
6. 그 밖의 것 → `null` (열지 않음. 흐리게 표시되는 지금 동작 유지)

5번을 넓혀 "모르는 확장자도 일단 텍스트로 시도하고 서버의 `BINARY_FILE` 거부를 안내" 할 수도 있다. 그러면 탐색기의 흐림 표시가 판정 근거를 잃으므로 1단계는 허용 목록 방식으로 둔다.

### 3.2 컴포넌트

벤더 파일(`AtomicCodeMirrorEditor.tsx`)에 모드 분기를 넣지 않는다. 벤더링된 사본과 원본의 차이가 커지고, 마크다운 전용 확장이 섞여 D3 이 되풀이되기 쉽다.

- 새 파일 `frontend/src/components/editor/CodeFileEditor.tsx`:
  - 마크다운 편집기와 **같은 모양의 핸들**(`getText` 또는 기존 이름 유지, `setReadOnly`, 포커스)과 **같은 마운트 시점 계약**(초기 본문은 controlled value 가 아님, `documentId` 로 정체성 부여 — FR-MDE-005)을 지킨다
  - 그래서 `EditorDocumentPanel` 과 `editorWindowSave` 는 "어느 컴포넌트를 마운트하는가" 한 줄만 바뀐다
- `EditorDocumentPanel` 이 `resolveEditorMode(filePath)` 로 둘 중 하나를 고른다.

### 3.6 줄바꿈·BOM·인코딩 (D1·D2 해결 — 마크다운 모드에도 적용)

1. **줄 구분자**:
   - 열 때 본문에서 첫 줄바꿈 종류(`\r\n` / `\n` / `\r`)를 감지해 `EditorState.lineSeparator` 로 고정한다.
   - 저장 본문은 `doc.toString()` 이 아니라 `state.sliceDoc()` 으로 만든다 (실측으로 보존 확인).
   - 섞인 파일은 다수 쪽으로 정한다.
   - 상태 표시줄 또는 탭 제목 툴팁에 `CRLF`·`LF` 를 표시한다.
2. **BOM**: 문자열 앞의 `﻿` 가 그대로 왕복하므로 추가 처리가 필요 없다. 다만 편집기에 보이지 않게 떼었다가 저장할 때 다시 붙이는 쪽이 커서·검색에 안전하다.
3. **인코딩**:
   - 서버 `readFile` 에서 `new TextDecoder('utf-8', { fatal: true })` 로 검증해 결과를 `encoding` 필드에 싣는다.
   - UTF-8 이 아니면 `encoding: 'unknown'` 으로 표시하고, 편집기는 **읽기 전용**으로 열어 "UTF-8 이 아닌 파일은 저장하면 손상되므로 읽기 전용으로 열었습니다" 를 보여 준다.
   - 거부 대신 읽기 전용을 고른 이유: 내용 확인은 여전히 쓸모 있다.
4. **바이너리 판정**: 지금의 NUL 10% 규칙은 NUL 이 드문 바이너리를 통과시킬 수 있다. 위의 UTF-8 fatal 검증이 대부분을 걸러 주므로 규칙 자체는 그대로 둔다.

### 3.7 크기

서버 한도가 기본 1 MiB 이고 CodeMirror 6 은 그보다 훨씬 큰 문서도 가상화로 다룬다. 1단계에는 별도 클라이언트 한도가 필요 없다. 운영자가 `maxFileSize` 를 크게 올리는 경우를 대비해 "문서가 N MiB 를 넘으면 문법 강조를 끈다" 규칙만 남겨 둔다(N 은 구현 시 측정).

### 3.8 번들 영향

- 새로 들어오는 상시 코드는 CodeMirror 기본 확장뿐이다: `lineNumbers`, `foldGutter`, `bracketMatching`, `autocompletion`, `lint`. 대부분 `@codemirror/view`·`language`·`autocomplete` 에 이미 포함되어 번들에 들어 있다.
- 문법은 `load: () => import(...)` 로 파일을 열 때만 받는다.
- 정확한 증가량은 구현 후 `vite build` 결과로 확인한다. 이 연구에서는 측정하지 않았다.

3단계(D1)와 4단계(D2)는 코드 모드가 없어도 지금 마크다운 편집기에서 사용자가 겪는 데이터 변형이다. 코드 모드보다 먼저 해도 된다.

## 5. SRS 영향

- `41.markdown-editor.srs.md` 에 새 요구사항이 필요하다:
  - 편집 모드 결정
  - 코드 모드 편집 기능
  - 줄바꿈·BOM 보존
  - 비 UTF-8 읽기 전용
  - 데이터 파일 검증
- 문서 제목·scope 이름이 "markdown-editor" 인 것은 그대로 두고, 요구사항 추가로 범위를 넓힌다.
- 같은 문서 §2 Out of Scope 의 "임의 파일을 고르는 파일 탐색기 UI … UI 진입점은 세 파일로 제한한다" 는 FR-MDE-012(편집기 파일 트리)와 파일 탐색기 에픽으로 이미 사실과 다르다. 새 요구사항을 넣을 때 함께 갱신 대상이다.
- `42.file-explorer.srs.md` FR-FEX-011 AC-6("열 수 있는지의 판정은 `viewableExtensions.ts` 의 확장자 집합을 재사용한다")은 1단계에서 판정 출처가 바뀌므로 승계(supersede)해야 한다.
