## 1. 검색 (버튼 + Ctrl+F)

| 항목 | 내용 |
|---|---|
| 진입 | 경로 바에 검색 버튼 추가, 탐색기 포커스 상태에서 `Ctrl+F` (macOS `Cmd+F`) |
| 범위 | 현재 경로 **하위 전체** (재귀) |
| 실행 | **비동기**. 서버가 결과를 스트리밍하고 브라우저는 도착하는 대로 목록에 추가 |
| 취소 | 진행 중 언제든 취소 버튼 / `Esc`. 취소 시 서버 탐색도 즉시 중단 |
| 진행 표시 | 탐색한 항목 수, 현재 탐색 중 경로, 찾은 개수 |
| 결과 | 이름·상대 경로. 클릭하면 해당 위치로 이동(디렉토리) 또는 편집기로 열기(파일) |
| 재사용 후보 | 기존 file-job 패턴(`POST /api/file-jobs` → WS `file-job:progress`/`done`, `DELETE` 취소). 검색은 새 job 종류 + 결과 스트림 이벤트가 필요 |
| 현재 코드 | 검색 엔드포인트 없음, Ctrl+F 바인딩 없음 (`fileExplorerShortcuts.ts:53-81`) |

## 2. 타이핑 필터 (Nautilus / macOS Finder 방식)

| 항목 | 내용 |
|---|---|
| 트리거 | 탐색기 본문에 포커스가 있을 때 인쇄 가능한 문자 입력 (단축키 조합 제외) |
| 표시 | 탐색기 상단에 입력한 단어가 보인다 |
| 동작 | 이름에 그 단어를 **포함**하는 디렉토리·파일만 보여준다 |
| 강조 | 일치하는 부분 문자열의 **배경색을 바꿔** 눈에 띄게 표시 |
| 범위 | **화면에 보이는 항목 기준**. 하위 경로를 새로 탐색하지 않는다. 트리 모드는 펼쳐진 항목까지만 |
| 해제 | `Esc`, 입력 지우기(Backspace 로 전부), 디렉토리 이동 시 |
| 기존 단축키와 충돌 | Ctrl/Cmd 조합·F2·Delete 는 기존대로 (`fileExplorerShortcuts.ts`) |
| 포커스 판정 | 기존 `bodyRef.current.contains(document.activeElement)` (`FileExplorerWindow.tsx:581`) |

## 3. 단일 경로 자동 확장 (목록·트리)

| 항목 | 내용 |
|---|---|
| 규칙 | 연 디렉토리의 자식이 **디렉토리 하나뿐**이면 그 안으로 계속 내려간다 |
| 종료 조건 | 자식이 **없거나**, 항목(파일 또는 디렉토리)이 **2개 이상**이거나, 유일한 자식이 **파일**일 때 |
| 목록 모드 | A 더블클릭 → A/B/C/D 로 바로 이동 |
| 트리 모드 | A 펼치기 → A, B, C, D 가 모두 펼쳐진다 |
| 닫기 | **하나씩** 닫는다 (D 를 닫아도 C 는 열린 채) |
| 목록 모드의 뒤로 가기 | 위로(`..`)는 한 단계씩 (D → C) |
| 안전장치 | 깊이 상한(예: 32)과 목록 실패 시 그 지점에서 멈춤 |
| 현재 코드 | `decideDoubleClick` (`fileRowInteraction.ts:58-64`), `expand`/`setRoot` (`fileTreeController.ts:152-180`) |

## 4. 목록 모드 경로 빵부스러기

| 항목 | 내용 |
|---|---|
| 표시 | `./{부모의 부모}/{부모}/{현재}` — 세션 루트 기준 상대 경로. 루트 세그먼트는 `.` 하나이고 구분자 `/` 가 뒤따른다(`./ /` 처럼 겹치지 않는다). 루트에 있을 때는 `./` 만 |
| 클릭 | 각 세그먼트를 누르면 그 경로로 이동 |
| 현재 세그먼트 | 누르면 **새로고침** |
| `./` | 누르면 **세션의 기본 디렉토리**(세션 루트)로 이동 |
| 긴 경로 | 가운데를 `…` 로 줄이고 전체 경로는 툴팁 |
| 현재 코드 | 경로가 평문 한 덩어리 (`FileExplorerPathBar.tsx:45-50`) |

## 5. 세션 루트에서 `..` 숨김 (목록 모드)

| 항목 | 내용 |
|---|---|
| 증상 | 세션 루트에서 `..` 를 누르면 "허용되지 않은 경로 이동입니다. (Path traversal detected; PATH_TRAVERSAL)" |
| 원인 | 서버가 파일시스템 루트가 아니면 항상 `..` 를 붙이고(`FileService.ts:218-226`), 세션 루트 위 목록은 거부(`pathValidator.ts:162`) |
| 결정 | 세션 루트에서는 `..` 행과 위로 버튼을 **숨긴다** |
| 수정 위치 | 서버: 세션 루트에서 `..` 를 만들지 않음(`hasParent=false`) — 클라이언트는 이미 `rootHasParent` 만 본다 |
