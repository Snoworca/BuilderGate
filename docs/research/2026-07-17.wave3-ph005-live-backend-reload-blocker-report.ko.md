## 현재까지 완료한 내용

Orca의 retained terminal authority 원칙을 BuilderGate의 WebSocket·다중 브라우저 환경에 맞게 생산 경로에 연결했다.

- 서버가 인증된 control connection의 구독, attached view, capability를 기준으로 canary를 선택한다.
- checkpoint start/chunk/commit/output, responder disable ACK, rollback drain/tail, query reply fence를 실제 서버·브라우저 경로에 연결했다.
- 서버 권위 retained state와 브라우저 writer lease를 연결하고 rollback 시 legacy writer를 복구한다.
- debug isolation은 실제 headless model, queue, source sequence, integrity failure, query reply exactly-once를 사용한다.
- 프런트의 WebSocketContext → TerminalView → TerminalContainer 생산 handoff와 cleanup/fencing을 연결했다.
- Wave2의 `requested split remains unified` RED 특성화 기대값을 Wave3 GREEN의 실제 split 협상으로 갱신했다.
- rollback output hold를 byte/chunk 상한으로 제한하고 overflow 시 기존 transaction을 폐기한 뒤 fresh compatibility recovery를 요청하도록 했다.
- 지속적인 transport 실패가 microtask 재귀로 CPU를 점유하지 않도록 세션별 요청을 합치고 10ms부터 최대 1초까지 지수 backoff하는 timer 기반 재시도로 전환했다.
- runtime dispose·replacement 시 recovery timer와 token을 정리하고 stale transaction이 새 rollback context를 변경하지 못하도록 identity fence를 추가했다.

## 차단 원인 증거

2026-07-18의 후속 재개 시도에서도 2222 listener는 동일한 PID 159036이었다. `authority-promotion-evidence.test.mjs --expect-green`은 다른 테스트를 실행하기 전에 `live backend process predates the current compiled authority build; reload is required`로 종료했고, 결정 산출물은 계속 존재하지 않았다. 따라서 구현 실패나 새 회귀가 아니라 동일한 적재 차단이 유지되고 있다.

`https://localhost:2222`의 실제 listener는 다음 프로세스다.

```text
PID 159036
node.exe C:\Work\git\_Snoworca\ProjectMaster\server\dist\index.js
시작 시각: 2026-07-15 21:32:44 KST
부모 프로세스: 없음
```

현재 프로세스는 `tsx watch`나 `nodemon`이 아니며 메모리에 7월 15일 빌드를 적재한 채 실행 중이다. daemon 상태 파일도 현재 PID를 소유하지 않고 `fatal` 상태의 과거 PID를 가리킨다. 따라서 소스 수정 및 새 `dist` 빌드는 성공했지만, 실행 중 프로세스에는 새 route와 authority attachment가 적재되지 않는다.

인증 전 요청은 공통 인증 middleware에서 401이지만, 인증 후 새 debug endpoint는 기존 session router까지 fall-through하여 404를 반환한다. 이는 새 route가 실행 중 프로세스에 등록되지 않았다는 직접 증거다.
