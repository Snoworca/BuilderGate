# MCP 키 입력: 방향키, Esc, 키 조합을 세션에 보내기

- 날짜: 2026-11-03
- 요청: "빌더게이트로 메시지 전달할 때 방향키는 지원이 안 되는 것 같아요." 이어서 "방향키와 ESC 그리고 키 조합(Shift + 방향키 등)을 모두 지원하는 방향으로 연구를 진행하시오."
- 결정된 것: 키 전송은 `buildergate.message.send` 에 `keys` 항목으로 넣는다(사용자 결정 2026-11-03).
- 관련 요구사항: FR-MCP-002(입력 게이트웨이), FR-MKB-001(모바일 키 변환기), IR-MKB-001(애플리케이션 커서 모드)

이 문서에서 "확인"은 원문이나 코드를 직접 읽은 것이다. "미확인"은 추론이거나 근거를 찾지 못한 것이다.

## 1. 지금 상태

| 항목 | 내용 | 근거 |
|---|---|---|
| 보낼 수 있는 것 | `prompt`(글)와 `deliveryMode`(`paste` / `submit`)뿐이다. 키를 지정하는 항목이 없다. | `server/src/services/McpToolService.ts` `buildergate.message.send` 스키마 |
| 글의 전달 방식 | 글을 가공하지 않고 PTY 입력으로 그대로 쓴다. submit 은 글을 쓴 뒤 Enter(`\r`)를 따로 쓴다. | `server/src/services/submitDelivery.ts` `submitWithSeparateEnter`, `server/src/index.ts` `createMcpGatewayDelivery` |
| 제어 문자 검사 | 게이트웨이는 Enter(`\r`, `\n`)만 검사한다. 글에 Enter 가 있으면 submit 요청이면서 `mcp:message.submit` 범위가 있어야 한다. ESC 같은 다른 제어 문자는 막지 않는다. | `server/src/services/SessionInputGateway.ts` `evaluateEnterPolicy` |
| `terminal.exec` | 명령줄을 입력하고 Enter 를 누른다. 키 항목이 없다. | `server/src/services/McpManagementTools.ts` |

결론: 글에 ESC 문자(`\u001b[A`)를 직접 넣으면 지금도 PTY 까지 간다. 하지만 도구 설명에 이 방법이 없고, 에이전트가 바이트를 정확히 만들어 보내기 어렵다. 그래서 사실상 키를 보낼 수 없다.

## 2. 이미 있는 것: 모바일 키 변환기

`frontend/src/utils/mobileKeyEncoder.ts` 는 DOM 과 xterm 에 의존하지 않는 순수 함수다(FR-MKB-001). 이미 처리하는 것은 다음과 같다(확인).

| 키 | 수식키 없음 | 수식키 있음 (m = 1 + Shift 1 + Alt 2 + Ctrl 4) |
|---|---|---|
| Up, Down, Right, Left, Home, End | `ESC [ A` 또는 애플리케이션 커서 모드에서 `ESC O A` | `ESC [ 1 ; m A` |
| Insert, Delete, PageUp, PageDown | `ESC [ n ~` | `ESC [ n ; m ~` |
| F1~F12 | xterm 기본값 | Alt 만 `ESC` 접두로 처리한다. Shift, Ctrl 은 무시한다. |
| Esc, Tab, Enter, Backspace | `ESC`, `\t`, `\r`, `\x7f` | Shift+Tab 은 `ESC [ Z` 다. Alt 는 `ESC` 접두로 처리한다. 나머지 조합은 무시한다. |
| 문자 1개 | 그대로 | Ctrl 은 C0 제어 문자, Alt 는 `ESC` 접두, Shift 는 대문자로 바꾼다. |

애플리케이션 커서 모드(DECCKM)는 브라우저의 xterm 에서 읽는다(IR-MKB-001).

빈 곳:

- 수식키가 붙은 F1~F12(`ESC [ 1 ; m P`, `ESC [ 15 ; m ~` 등)를 만들지 않는다.
- 수식키가 붙은 Enter, Backspace, Esc 는 수식키가 사라진다. 레거시 인코딩의 한계라 다른 터미널도 같다(4절).

## 3. 서버가 알 수 있는 것

- 서버는 세션마다 헤드리스 xterm(`@xterm/headless`)을 갖고 있고, `terminal.modes` 로 `applicationCursorKeysMode` 를 읽을 수 있다(확인: `server/src/utils/headlessTerminal.ts`, `server/src/services/retainedStateDigest.ts` 의 `RETAINED_STATE_MODE_NAMES`). 따라서 서버도 방향키를 `ESC [ A` 와 `ESC O A` 중 맞는 쪽으로 보낼 수 있다.
- 헤드리스 xterm 6.0 은 kitty 키보드 프로토콜(`CSI > flags u`)과 win32-input-mode(`CSI ? 9001 h`)를 추적하지 않는다. 이 두 모드를 쓰려면 서버가 PTY 출력에서 해당 순서열을 직접 찾아야 한다.

## 4. 외부 사실

### 4.1 xterm.js (브라우저 터미널)

- 확인(`src/common/input/Keyboard.ts`): Enter 는 `\r`, Alt+Enter 는 `ESC \r` 이다. **Shift+Enter 와 Ctrl+Enter 도 `\r`** 이다. Shift+Tab 은 `ESC [ Z` 다.
- 확인: kitty 키보드 프로토콜은 6.0 에 없다. 6.1(PR #5600)부터 `vtExtensions: { kittyKeyboard, win32InputMode }` 로 켤 수 있다. BuilderGate 는 6 계열이다.
- 귀결: 레거시 xterm 인코딩으로 보내면, 사용자가 브라우저에서 키를 누를 때와 같은 바이트가 간다. 이것이 가장 안전한 기준선이다.

### 4.2 Claude Code

- 확인(공식 문서 interactive-mode, terminal-config):
  - `Esc` 는 응답을 중단한다. `Esc Esc` 는 입력을 지우거나 되감기 메뉴를 연다.
  - `Ctrl+C` 는 실행 중이면 중단, 아니면 입력을 지운다. 두 번 누르면 종료한다.
  - `Shift+Tab` 은 권한 모드를 순환한다. Windows 에서 VT 입력 모드가 꺼져 있으면 `Alt+M` 을 쓴다.
  - 줄바꿈은 **`Ctrl+J`(0x0A)와 `\` 다음 Enter 가 모든 터미널에서 설정 없이 동작**한다. Option(Meta)+Enter 도 줄바꿈이다.
- 확인: Shift+Enter 는 kitty 키보드 프로토콜을 지원하는 터미널에서 동작한다(v2.1.269 이상). `/terminal-setup` 은 VS Code 계열에 `ESC CR` 을 보내는 바인딩을 설치한다.
- 확인: Windows 판은 `0x08`(`^H`)을 Ctrl+Backspace(단어 삭제)로 읽는다.
- 미확인: push 하는 kitty 플래그의 정확한 값, `CSI 27 ; 2 ; 13 ~`(modifyOtherKeys 형식)를 받는지.

### 4.3 Codex CLI (Rust, crossterm)

- 확인(crossterm `parse.rs`): `CSI 1 ; m A-D/H/F`, `ESC O A-D/H/F/P-S`, `CSI Z`, `CSI n ; m ~`, kitty `CSI … u` 를 파싱한다. `ESC` 뒤에 다른 바이트가 붙어 오면 Alt 로 읽는다. 따라서 `ESC CR` 은 Alt+Enter 다. `ESC` 하나만 오면 뒤를 잠시 기다린다.
- 확인(codex `keyboard_modes.rs`): 시작할 때 kitty 플래그(DISAMBIGUATE_ESCAPE_CODES, REPORT_ALTERNATE_KEYS)를 push 하고 modifyOtherKeys 를 끈다. `CODEX_TUI_DISABLE_KEYBOARD_ENHANCEMENT` 로 끌 수 있다. WSL+VS Code 에서는 기본으로 끈다.
- 확인: Shift+Enter 는 kitty 확장이 켜졌을 때만 Enter 와 구별된다.
- 확인(`windows_key_sequence.rs`): Windows 네이티브에서는 Win32 콘솔 API 를 쓴다. 그래서 `ESC [ 13 ; 2 u` 가 글자 키 이벤트로 낱낱이 도착하고, Codex 가 50ms 안의 7개 키를 모아 Shift+Enter 로 복원한다.

### 4.4 Windows ConPTY

- 확인(Microsoft 스펙 #4999): ConPTY 는 시작할 때 호스트에 `ESC [ ? 9001 h`(win32-input-mode)를 요청한다. 이 모드의 입력 형식은 `ESC [ Vk ; Sc ; Uc ; Kd ; Cs ; Rc _` 이다. ConPTY 는 이것을 수식키가 정확한 INPUT_RECORD 로 바꾼다.
- 확인(dormouse PR #117): 호스트가 9001 로 응답하면 Codex 같은 콘솔 API 앱에 Shift+Enter 가 손실 없이 간다. 하지만 이 모드가 켜진 채로는 kitty 가 무시되어, Claude Code 에서 Shift+Enter 가 제출로 바뀌는 회귀가 났다. 그래서 kitty push/pop 을 보고 9001 을 끄고 켜는 중재기가 필요했다.
- 미확인: ConPTY 가 레거시 VT(`ESC [ 1 ; 2 A`, `ESC [ Z`)를 수식키가 붙은 KEY_EVENT 로 바꾸는 세부. conhost 의 입력 상태 기계가 처리한다고 추정한다. 구현 단계에서 Windows 세션으로 실측해야 한다.

## 5. 레거시 인코딩으로 표현할 수 없는 조합

다음은 대상 프로그램의 확장 프로토콜(kitty, win32-input-mode) 없이는 안정적으로 보낼 수 없다.

- 바이트가 같아 구별되지 않는다: Shift+Enter, Ctrl+Enter, Ctrl+Shift+Enter, Shift+Backspace, Ctrl+Backspace, Shift+Esc, Shift+Space, Ctrl+Space(NUL 과 겹침).
- 다른 키와 바이트가 같다: Ctrl+I 는 Tab, Ctrl+M 은 Enter, Ctrl+[ 는 Esc, Ctrl+H 는 Backspace(Windows Claude Code 에서는 단어 삭제).
- 대응하는 C0 가 없거나 Shift 가 사라진다: Ctrl+숫자, Ctrl+구두점 일부, Ctrl+Shift+문자.
- Meta/Super 수식키, 키 뗌·반복 이벤트.

## 6. 설계안

### 6.1 API 모양 (결정됨: `message.send` 의 `keys`)

```json
{ "target": "worker-1", "keys": ["down", "down", "enter"] }
{ "target": "worker-1", "prompt": "git status", "keys": ["tab"] }
{ "target": "worker-1", "keys": ["shift+tab"] }
{ "target": "worker-1", "keys": ["ctrl+alt+left", "esc"] }
```

- 키 문자열: 수식키를 `+` 로 잇고 마지막이 키 이름이다. 대소문자를 구분하지 않는다. 수식키는 `shift`, `alt`(= `meta`, `option`), `ctrl`(= `control`)이다.
- 키 이름: `up`, `down`, `left`, `right`, `home`, `end`, `pageup`, `pagedown`, `insert`, `delete`, `f1`~`f12`, `esc`, `tab`, `enter`, `backspace`, `space`, 그리고 글자 1개(`a`, `1`, `/` 등).
- 의미 키 `newline`: 입력란 안 줄바꿈이다. `Ctrl+J`(0x0A)로 보낸다. Claude Code 문서가 모든 터미널에서 동작한다고 밝힌 유일한 형식이다. Codex 에서도 같은지는 미확인이다.
- 순서: `prompt` 가 있으면 먼저 보내고(`submit` 이면 Enter 까지), 그다음 `keys` 를 앞에서부터 보낸다.
- 거부: 모르는 키 이름, 5절의 표현 불가 조합(예: `shift+enter`)은 전송 전에 `VALIDATION_ERROR` 로 거부하고, 대신 쓸 키를 메시지에 적는다(예: `shift+enter` → `newline`). 조용히 다른 바이트로 바꾸지 않는다.

### 6.2 인코딩 단계

| 단계 | 내용 | 비고 |
|---|---|---|
| 1 (기본) | 레거시 xterm 인코딩. 2절의 변환기와 같은 규칙에 수식키 붙은 F1~F12 를 더한다. | 사용자가 브라우저에서 누르는 것과 같은 바이트다. |
| 1 | 방향키 형식은 서버 헤드리스 xterm 의 `applicationCursorKeysMode` 로 고른다. | 3절 |
| 1 | `esc` 는 단독으로 쓰고 뒤에 약 100ms 를 둔다. 다른 키 사이에는 짧은 간격(약 30ms)을 둔다. | 붙여 보내면 Alt+x 로 읽힌다(4.3). 간격 값은 미확인이라 실측으로 정한다. |
| 2 (선택) | 대상 앱이 kitty 플래그를 push 했으면 kitty `CSI … u` 형식으로 보낸다. 그러면 `shift+enter` 등 5절의 일부가 가능해진다. | PTY 출력에서 `CSI > flags u` / `CSI < u` 를 추적해야 한다. |
| 2 (선택) | Windows 세션에서 앱이 kitty 를 쓰지 않으면 win32-input-mode 형식으로 보낸다. | ConPTY 가 9001 을 요청한다(4.4). kitty 와 함께 켜면 회귀가 난다. |

1단계만으로 방향키, Esc, Tab, Shift+Tab, 수식키 붙은 방향키·Home·End·PageUp/Down·Delete, F1~F12, Ctrl+문자, Alt+문자, 줄바꿈(`newline`)이 모두 된다. 2단계는 `shift+enter` 처럼 레거시로 표현할 수 없는 조합이 실제로 필요할 때 연다.

### 6.3 변환기를 한 곳에 두기

같은 표를 서버와 브라우저에 따로 두면 한쪽만 고쳐지고 다른 쪽은 조용히 어긋난다. 지금 저장소에는 서버와 프런트가 함께 쓰는 소스 폴더가 없다. 서버는 `rootDir: ./src` 로 빌드하고, 프런트 파일을 주석으로만 가리킨 선례가 있다(`McpManagementTools.ts` 의 이미지 확장자 목록).

| 방법 | 장점 | 단점 |
|---|---|---|
| A. 공용 폴더(`shared/terminalKeys.ts`)를 만들어 두 빌드가 함께 가져온다 | 진짜 한 곳이다. | 서버 `rootDir`, `dist` 구조, 릴리즈 빌드(pkg), 봉인 도구를 함께 바꿔야 한다. 영향 범위가 크다. |
| B. 서버에 같은 변환기를 두고, 두 구현이 모든 키×수식키×커서 모드에서 같은 바이트를 내는지 비교하는 테스트를 둔다 | 빌드 구조를 건드리지 않는다. 어긋나면 테스트가 바로 빨개진다. | 코드가 두 벌이다. 비교 테스트가 행렬 전체를 덮어야 의미가 있다. |
| C. 서버 변환기가 원본이고, 프런트 빌드가 그 파일을 복사해 쓴다 | 소스는 한 벌이다. | 빌드 단계에 복사 스크립트가 생기고, 프런트 단위 테스트 실행 방식(`--experimental-strip-types`)과 맞춰야 한다. |

권장: B. 이 저장소의 작업 강도 방침(속도 우선)과 빌드 파이프라인의 위험도(릴리즈 빌드를 세 번 깨뜨린 이력)를 보면, 구조를 바꾸지 않고 비교 테스트로 묶는 것이 가장 싸고 안전하다. 프런트 단위 테스트는 서버 `.ts` 파일을 직접 가져올 수 있다(확장자 없는 import 가 없을 때).

### 6.4 권한과 안전

- `enter`, `newline`, `ctrl+m`, `ctrl+j` 처럼 `\r` 또는 `\n` 이 되는 키는 지금의 Enter 규칙을 그대로 따른다. `mcp:message.submit` 범위가 필요하다.
- `ctrl+c`, `ctrl+d`, `esc` 는 대상 프로그램을 중단하거나 종료할 수 있다. 범위를 따로 둘지(예: `mcp:message.keys`)는 결정이 필요하다. 기본안은 `mcp:message.paste` 범위로 키를 허용하고, Enter 계열만 submit 범위를 요구한다.
- 한 요청의 키 수는 상한을 둔다(예: 64개).
- 감사 기록에는 키 이름 목록을 남긴다. 바이트는 남기지 않는다.

## 7. 결정이 필요한 것

1. 변환기 공유 방법: A / B / C (권장 B).
2. 범위: 1단계만 먼저 할지, 2단계(kitty, win32-input-mode)까지 할지 (권장: 1단계 먼저, 2단계는 `shift+enter` 가 실제로 필요할 때).
3. `ctrl+c`, `esc` 등 중단 키에 별도 권한 범위를 둘지 (권장: 두지 않음, Enter 계열만 submit 범위).
