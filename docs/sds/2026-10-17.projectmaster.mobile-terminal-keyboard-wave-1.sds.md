### Files

- `frontend/src/utils/mobileKeyEncoder.ts` — pure key-to-bytes encoder, no DOM, no xterm import @req FR-MKB-001
  - `type MobileKeyName` — 'Up' 'Down' 'Left' 'Right' 'Home' 'End' 'Insert' 'Delete' 'PageUp' 'PageDown' 'F1'..'F12' 'Esc' 'Tab' 'Enter' 'Backspace'
  - `interface ModifierState` — { ctrl: boolean; alt: boolean; shift: boolean }
  - `encodeMobileKey(key: MobileKeyName | string, mods: ModifierState, applicationCursor: boolean): string` — named key or one character to PTY bytes ← mobileModifierLatch, keyboard components
- `frontend/src/utils/mobileModifierLatch.ts` — module-level latch store for Ctrl/Alt/Shift @req FR-MKB-002, FR-MKB-003
  - `type LatchState` — 'off' | 'once' | 'locked'
  - `const LATCH_HOLD_MS` — 1500
  - `const mobileModifierLatch` — store singleton ← TerminalView
    - `subscribe(listener: () => void): () => void` — useSyncExternalStore contract
    - `getSnapshot(): LatchSnapshot` — immutable { ctrl, alt, shift } of LatchState, new object only on change
    - `tap(mod: LatchModifier): void` — off→once, once→off, locked→off
    - `startPress(mod: LatchModifier): LatchPress` — arms a 1500 ms timer that sets locked and calls navigator.vibrate(25) when that function exists
    - `consumeOnce(): void` — every once → off; locked stays
    - `activeModifiers(): ModifierState` — true for once or locked
    - `resetForTests(): void` — all off, timers cleared
  - `interface LatchPress` — handle returned by startPress
    - `release(): void` — tap when the timer has not fired, nothing after lock
    - `cancel(): void` — clears the timer, no state change
  - `applyLatchToTypedData(data: string, applicationCursor: boolean): string` — re-encodes one printable ASCII char when any modifier is active, consumes once; otherwise returns data unchanged ← TerminalView
- `frontend/src/components/Terminal/TerminalView.tsx` — handle getter and onData latch hook @req IR-MKB-001, FR-MKB-003
  - `interface TerminalHandle` — adds getApplicationCursorKeysMode(): boolean
    - `getApplicationCursorKeysMode(): boolean` — xtermRef.current?.modes.applicationCursorKeysMode ?? false ← TerminalContainer
  - `onDataLatchStep(data: string): string` — inside term.onData after the provenance, replay and query-reply guards, only when programmaticPaste is null, whether or not user provenance is present (Android IME commits arrive after the microtask permit expires); calls applyLatchToTypedData with the live applicationCursorKeysMode
- `frontend/src/components/Terminal/TerminalContainer.tsx` — forwards the getter like getMouseTrackingActive @req IR-MKB-001
  - `getApplicationCursorKeysModeForward(): boolean` — handle field getApplicationCursorKeysMode: () => terminalRef.current?.getApplicationCursorKeysMode() ?? false
- `frontend/tsconfig.test.json` — registers the new unit test files @req FR-MKB-001
- `frontend/package.json` — adds test:unit:mobile-keyboard and appends the onData test to test:unit:terminal-view-behavior @req FR-MKB-003

## Acceptance Contracts

- SDS-AC-1 (FR-MKB-001 AC-1): WHEN an arrow is encoded without modifiers THE SYSTEM SHALL choose CSI or SS3 from the applicationCursor argument only → `encodeMobileKey`
- SDS-AC-2 (FR-MKB-001 AC-3): WHEN shift, alt and ctrl are all active on an arrow THE SYSTEM SHALL emit modifier parameter 8 → `encodeMobileKey`
- SDS-AC-3 (FR-MKB-001 AC-7): WHEN Ctrl is active on an uppercase letter or on a character outside the xterm table THE SYSTEM SHALL map the letter case-insensitively and pass any other character through unchanged → `encodeMobileKey`
- SDS-AC-4 (FR-MKB-001 AC-8): WHEN Alt is active on a key with a modifier parameter form THE SYSTEM SHALL emit the parameter form without an ESC prefix → `encodeMobileKey`
- SDS-AC-5 (FR-MKB-002 AC-2): WHEN a press is released 1499 ms after startPress THE SYSTEM SHALL treat it as a tap, and at 1500 ms SHALL set locked before release → `mobileModifierLatch.startPress`
- SDS-AC-6 (FR-MKB-002 AC-3): WHEN cancel() is called on a press THE SYSTEM SHALL leave every state unchanged and fire no timer → `LatchPress.cancel`
- SDS-AC-7 (FR-MKB-002 AC-5): WHEN the lock timer fires and navigator.vibrate is undefined THE SYSTEM SHALL lock without throwing → `mobileModifierLatch.startPress`
- SDS-AC-8 (FR-MKB-002 AC-4): WHEN consumeOnce runs with Ctrl once and Alt locked THE SYSTEM SHALL leave Ctrl off and Alt locked → `mobileModifierLatch.consumeOnce`
- SDS-AC-9 (FR-MKB-003 AC-3): WHEN typed data is non-ASCII, longer than one character or no modifier is active THE SYSTEM SHALL return the same string and leave once modifiers untouched → `applyLatchToTypedData`
- SDS-AC-10 (FR-MKB-003 AC-1): WHEN Ctrl is once and xterm onData delivers 'C' with user provenance THE SYSTEM SHALL submit 0x03 through submitCapturedInput and Ctrl SHALL be off → `onDataLatchStep`
- SDS-AC-11 (FR-MKB-003 AC-4): WHEN onData data comes from programmatic paste THE SYSTEM SHALL submit it unchanged, and WHEN one printable ASCII char arrives without user provenance with Ctrl once THE SYSTEM SHALL still re-encode it → `onDataLatchStep`
- SDS-AC-12 (IR-MKB-001 AC-1): WHEN xterm applicationCursorKeysMode is true THE SYSTEM SHALL return true from the handle and the container handle → `TerminalHandle.getApplicationCursorKeysMode`, `getApplicationCursorKeysModeForward`
