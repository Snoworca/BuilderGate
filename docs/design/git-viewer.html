BuilderGate · Git 보기 시안

v1 읽기 전용 · 세션 하단바 칩 → Git 창(그래프·상세·diff) · 3차 개정(기획·UI/UX 2차 리뷰 반영)

세션마다 하단바(MetadataRow)의 이름 오른쪽에 브랜치 칩이 붙습니다. 클릭하면 그 세션의 Git 창(변경이 있으면 작업 사본 행, 없으면 HEAD 커밋 선택). 우클릭·Shift+F10·터치 길게 누르기는 메뉴, 마우스를 올리거나 포커스하면 툴팁(Esc 로 닫힘). git 저장소가 아닌 세션(logs)은 지금과 똑같습니다. 배치를 바꾸면 칩이 ③ 의 단계표대로 줄어듭니다.

문서

Git 창은 편집기 창과 같은 모달리스 창입니다(오른쪽 아래 모서리로 크기 조절, 최소 760×420). 목록에 포커스를 두고 ↑↓ HomeEnd PgUpPgDn, 창 안 어디서나 [] 파일, np 덩어리, s 보기 전환, w 공백 무시, R 새로고침. Esc 는 편집기처럼 아무 일도 하지 않습니다. 창을 좁히면 작성자 → 커밋 열이 숨고, diff 머리 컨트롤이 "보기 ▾" 로 접힙니다.

단계는 하단바 폭 − 세션 이름의 실제 폭(= 남는 폭)으로 정합니다. 화면 폭이 아니라 그 하단바를 ResizeObserver 로 잽니다. 경계에서 깜빡이지 않게 ±8px 히스테리시스. 브랜치명은 단계별 최대 글자 수에 맞춰 JS 가 가운데를 줄이고, CSS 말줄임은 칩에 쓰지 않습니다. cwd 만 CSS 로 앞쪽이 줄어듭니다. 아래 표가 유일한 정본입니다. 맨 위 막대의 오른쪽 아래 모서리를 끌어 보십시오.

각 단계의 실제 모습

브랜치명 가운데 줄이기

최대 글자 n 이하면 그대로. 첫 / 가 8자 안이고 n ≥ 10 이면 접두사/…끝, 아니면 …끝. 전체 이름은 툴팁·aria-label 에 항상 있습니다.

cwd 와 공간 나누기

  • 칩은 이름 바로 오른쪽, 단계 안에서는 줄어들지 않음(flex-shrink 0). 남는 공간은 cwd 가 먼저 양보
  • cwd 는 30자 고정 대신 남은 폭에 맞춰 앞쪽을 CSS 로 줄임(…/ProjectMaster). 클릭 복사·우클릭/더블탭 경로 메뉴(FR-MDE-007·FR-UIDS-013)는 그대로
  • 단계 2부터 cwd 가 빠지면 경로 메뉴 전체가 칩 메뉴의 "경로" 묶음으로 옮겨 감
  • 저장소가 아닌 세션은 칩이 없으므로 cwd 를 끝까지 남김(지금과 같음)

누르는 영역·제스처

  • 칩 높이 22px, 행(28px) 밖으로 영역을 넓히지 않음 → 위 터미널을 가리지 않음
  • 최소 폭 데스크톱 28px, 터치(pointer: coarse) 44px. 이웃과 간격 8px
  • 터치: 탭 = 창, 500ms 길게 누르기 = 메뉴. iOS 콜아웃·텍스트 선택 끔, 길게 누르기 뒤 따라오는 contextmenu 이벤트 무시(메뉴 두 번 열림 방지)
  • cwd 의 더블탭과는 대상이 달라 겹치지 않음

창 폭 900px 미만이면 Git 창이 전체 화면이 되고 목록 → 커밋 → diff 세 단계로 쌓입니다. 단계마다 history.pushState 하므로 기기 뒤로 가기가 한 단계씩 돌아가고, 목록에서 뒤로 가면 창이 닫힙니다(앱을 떠나지 않음). diff 는 한 줄 보기 고정, 줄바꿈이 기본이며 이어지는 줄은 코드 시작 열에 맞춥니다.

모바일 규칙

  • 칩: 하단바가 대개 단계 3~4 → ⎇ feat/…graph ●3
  • 칩 탭 → 창. 길게 누르기 → 메뉴(아래에서 올라오는 시트)
  • 소프트 키보드·모바일 키바가 떠 있으면 키보드를 내린 뒤 창을 엶
  • 행 56px, 파일 행 52px, 버튼 44px 이상
  • diff 아래: 이전/다음 덩어리, 이전/다음 파일
  • 줄 번호 두 칸(이전·새로, 각 4자리)
  • 좌우 보기 없음. 줄바꿈 토글(↩)만

칩과 Git 창이 각 상태에서 어떻게 보이는지, 특수한 파일을 diff 자리에 어떻게 보여 주는지입니다. 서버 오류 코드는 apiError.<CODE> 로 번역합니다(⑦). 오류 칩(5번)은 눌러 볼 수 있습니다.

선택 유지

키커밋은 sha(작업 사본은 WORKTREE), 파일은 (영역, 경로). 행 번호를 쓰지 않음
새 커밋이 위에 생김같은 sha 를 계속 선택, 보이는 행이 움직이지 않도록 스크롤 보정
WORKTREE 가 사라짐새 HEAD 선택 + 토스트 "변경이 커밋되었습니다"
선택한 sha 가 사라짐목록 맨 위에 그 커밋의 "브랜치에 없음" 행을 남겨 선택 유지(activedescendant 가 실제 행을 가리킴) + 배너 [최신 HEAD 보기]. 내용은 sha 로 직접 조회(gc 전까지). 조회 실패 시 COMMIT_NOT_FOUND 3차
