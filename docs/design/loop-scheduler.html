② 루프 관리

등록한 루프를 한눈에 보는 창이다. 줄마다 켜기/끄기, 다음 실행 시각, 마지막 결과를 보여 준다. 줄을 누르면 최근 실행 기록이 펼쳐지고, 지금 실행으로 일정과 상관없이 한 번 돌려 볼 수 있다. 실행 중인 루프의 세션은 이름을 눌러 바로 그 탭으로 간다.

③ 루프 편집

위는 언제·어디서, 아래는 무엇을이다. 단계는 한 줄씩 위에서 아래로 실행된다. 세션 종료를 넣으면 그 뒤에는 단계를 더할 수 없다(더하기 버튼이 사라진다). 맨 아래 「한 줄로 입력」에 codex delay 2000 "금일 주식 시황 분석하시오" 처럼 적으면 단계 셋으로 풀어 준다(exit 는 평범한 명령으로 남는다). 이 시안의 버튼은 실제로 동작한다.

단계 종류

●명령한 줄을 셸에 입력하고 Enter. 예: codex, git pull. 앞 명령이 끝나기를 기다리지 않는다 — 기다려야 하면 대기를 넣는다.
●프롬프트앞에서 띄운 에이전트(codex, claude 등)에 보낼 글. 여러 줄을 쓸 수 있다. 글을 붙여 넣고, 잠시(600ms) 뒤 Enter 를 따로 보낸다 — 같이 보내면 에이전트가 Enter 를 글의 일부로 먹는다.
●대기사용자가 적은 시간만큼 그대로 기다린다(밀리초, 옆에 초로 환산해 보여 줌). 1초 · 2초 · 5초 · 10초 바로가기. 한 줄 입력의 delay 2000 이 이것이 된다. 에이전트가 떴는지 감지하지는 않는다.
●세션 종료서버가 세션을 닫는다(셸에 exit 를 치는 것이 아니다 — codex 가 앞에 떠 있으면 그 글은 프롬프트가 된다). 항상 마지막 단계다. 없으면 탭이 남아 결과를 볼 수 있고, 「남겨 둘 탭」 수만큼 유지된다.

④ 워크스페이스 배치

루프가 실행되면 @schedule-{n} 워크스페이스에 새 탭을 연다. n 은 0부터다. 워크스페이스가 없으면 만든다. 탭 수가 한도(maxTabsPerWorkspace, 기본 8)에 닿으면 마지막 번호 + 1 로 새 워크스페이스를 만든다. 탭 이름은 「루프 이름 #실행 회차」다.

세션 종료 단계가 있는 루프는 끝나면 탭을 닫으므로 칸이 비어 다시 쓰인다. 종료가 없는 루프는 탭이 쌓인다. 빈 칸을 찾을 때는 앞 번호 워크스페이스부터 본다. 종료가 없는 루프의 탭은 「남겨 둘 탭」 수를 넘으면 오래된 것부터 닫는다(⑤ 2·8번).

⑤ 정한 것

2026-10-29 사용자 결정: 권장안을 모두 따른다. 대기는 사용자가 적은 시간만큼만 기다린다.

1앞 실행이 돌고 있을 때 다음 시각이 오면건너뛰고 기록에 「건너뜀」을 남긴다. 「실행 중」은 마지막 단계를 보낼 때까지다. 그 뒤 남은 탭은 실행 중으로 치지 않는다.
2어느 워크스페이스에 여나앞 번호의 빈 칸부터. 모두 가득 차면 마지막 번호 + 1 로 만든다. 워크스페이스는 이름이 아니라 서버가 만든 id 로 기억한다. 지워졌으면 새로 만든다. 사용자가 옮겨 넣은 탭도 칸으로 센다.
3서버가 꺼져 있던 동안 지난 시각몰아서 실행하지 않는다. 다음 시각부터 돈다.
4시간대서버 기계의 현지 시각.
5명령 단계앞 명령이 끝나기를 기다리지 않는다. 기다림은 대기 단계로, 사용자가 적은 시간만큼만.
6빈 @schedule-{n}지우지 않는다.
7세션 종료서버가 세션을 닫는다. 한 줄 입력의 exit 는 평범한 명령이다.
8탭이 쌓이는 것루프마다 「남겨 둘 탭」(기본 1). 넘으면 그 루프의 가장 오래된 탭부터 닫는다. @schedule 탭 전체가 상한(기본 32)을 넘으면 실행을 건너뛰고 기록한다.
9세션 저장·복원@schedule-* 의 탭은 저장·복원 대상에서 뺀다.
10프롬프트 보내기붙여 넣기와 Enter 를 나눠 보내고 그 사이 600ms(restoreInputDelayMs).
11작은 규칙간격은 기준 시각부터 날짜를 넘어 이어 센다 · 같은 시각이 겹치면 한 번 · 지난 특정 날짜는 저장 거부 · 셸·디렉터리가 없으면 실패로 기록 · 실행 중 끄거나 지우면 남은 단계를 멈추고 탭은 둔다 · 기록은 루프마다 최근 50건 · 같은 분의 여러 루프는 세션을 차례로 만든다 · 저장은 server/data/loops.json · 화면 문자열은 i18n 카탈로그.
