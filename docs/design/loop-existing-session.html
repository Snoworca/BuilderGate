① 루프 편집 — 「어디서」에 탭 두 개

「언제」와 「무엇을」은 기존 시안 그대로다. 「어디서」만 「새 세션」 / 「기존 세션」 탭으로 나눈다. 탭을 눌러 보자 — 「새 세션」은 지금의 셸·디렉터리·남겨 둘 탭, 「기존 세션」은 세션 셀렉트와 바쁠 때 옵션이다. 기존 세션에서는 「세션 종료」 추가 버튼이 사라진다(사용자 세션을 닫지 않는다). 셀렉트를 바꾸면 아래 카드의 폴더·에이전트 상태가 바뀐다.

바뀐 곳

1탭 기본값새 루프는 「새 세션」. 탭을 바꿔도 다른 탭의 입력값은 저장 전까지 남는다. 저장되는 것은 보이는 탭 하나뿐.
2세션 셀렉트네이티브 <select> + 워크스페이스별 optgroup. 옵션 글자 「세션 — 상태」. @schedule-* 탭은 빼고, 셸이 끝난 탭은 고를 수 없게 보인다.
3저장 값탭 id(서버 재시작·탭 다시 시작에도 그대로) + 표시용 「워크스페이스 : 세션」 이름.
4보내는 방식지금 단계 규칙과 같다. 명령·프롬프트는 글을 쓰고 600ms 뒤 Enter 를 따로. 대기는 적힌 ms.

② 세션 셀렉트를 펼친 모습

OS 가 그리는 목록이라 모양은 브라우저마다 조금 다르다. 순서는 워크스페이스 화면 순서 → 그 안의 탭 순서. 맨 위 「세션을 고르세요」는 고를 수 없는 안내 줄이다. 에이전트 상태는 옵션 끝에 글로 붙이고, 고른 뒤에는 아래 카드에 칩으로 그린다(Messenger 세션 고르기와 같은 칩).

⑤ 저장한 세션이 없어졌을 때

사용자가 그 탭을 지웠다. 지운 탭의 id 는 돌아오지 않으므로 다음 실행 시각에 서버가 루프를 끄고 「세션이 없어 루프를 껐습니다」를 남긴다(권장안, ⑦ Q1). 편집 창을 열면 셀렉트는 「(없음) 워크스페이스 : 세션」을 고른 채 보이고, 노란 띠가 다음 할 일을 알려 준다. 다른 세션을 고르거나 새 세션으로 바꾸고 켜서 저장하면 다시 돈다.

⑦ 정할 것 — 권장안

아래는 제품 책임자 결정이 필요한 항목과 권장안이다. 실행 규칙 전체는 계획 문서 §4 에 있다.

Q1저장한 탭이 지워지면루프를 자동으로 끈다(기록 「세션이 없어 루프를 껐습니다」, 관리 창 「세션 없음」). 대안: 켜 둔 채 매번 건너뜀 — 지운 탭은 돌아오지 않으므로 기록만 쌓인다.
Q2에이전트가 작업 중이면기본은 건너뜀, 체크박스로 끌 수 있다. 「끝날 때까지 기다렸다 보내기」는 이번 범위 밖.
Q3같은 세션을 여러 루프가 고르면허용. 같은 순간이면 서버가 하나씩 차례로 보낸다. 편집 창에 「이 세션에 보내는 루프가 1개 더 있습니다」 안내.
Q4Enter 없이 붙여 넣기만넣지 않는다. 지금 단계 규칙(글 → 600ms → Enter)을 그대로 쓴다.
Q5저장하는 id탭 id. 서버 재시작(orphan recovery)과 탭 다시 시작에도 그대로이고 탭을 지울 때만 사라진다. sessionId 는 재시작마다 바뀌고, sessionKey 는 중복 감지 때 재발급될 수 있다. Messenger 와 맞추려면 sessionKey 도 가능.
Q6사용자가 그 탭에 치던 중이면감지하지 않고 보낸다(입력이 섞일 수 있음). 편집 창 힌트로 알린다.
