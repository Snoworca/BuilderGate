쟁점결론
모바일 폴더 업로드숨기지 않고 비활성 + 이유 한 줄. pointer:coarse 가 아니라 기능 감지로 판정합니다(Android Chrome은 지원).
모바일 바선택 상태별 두 세트 → 한 세트로 고정 [업로드][다운로드][붙여넣기][더보기]. 메뉴와 같은 판정 규칙을 씁니다.
충돌 체크박스"더 이상 묻지 않기"는 영구 설정처럼 읽힙니다 → "남은 n개에도 같은 선택 적용". 남은 충돌이 없으면 숨깁니다.
ZIP 준비사전 계산 1회 → 기준 이하이고 1초 안에 끝나면 바로 받기, 아니면 확인 바. 확인 바의 [받기]가 새 제스처라 iOS의 제스처 만료 문제가 풀립니다.
전송 중인 행목록 맨 아래에 고정(정렬이 바뀌어도 튀지 않음) → 완료 시 제자리로 옮기고 스크롤·강조. 그사이 사용자가 선택하거나 스크롤했다면 토스트만 띄웁니다.

1업로드 진입점

  • 경로 막대 버튼(강조 없음, 다운로드와 동등). 단축키는 두지 않습니다. Ctrl+U는 브라우저 소스 보기이고 셸에서는 줄 삭제입니다.
  • 우클릭 메뉴는 항목이든 빈 공간이든 같은 자리에 다운로드 · 업로드… · 폴더 업로드…를 둡니다. 적용되지 않으면 비활성(design 7).
  • 폴더 행 위 메뉴는 '{name}' 에 업로드…, 그 밖에는 현재 폴더로 올립니다.
  • OS 드롭: 빈 곳·파일 행 → 현재 폴더, 폴더 행 → 그 폴더. 하단 경로 칩이 대상을 알리고 aria-live 로 읽어 줍니다. 모달이 열려 있으면 드롭을 막습니다.
  • 트리 노드 드롭, 폴더 위 700ms 머물면 펼침, 탭 위 500ms 머물면 전환은 실제 구현 대상입니다(이 시안의 목록 보기에는 없음).

2전송·실패·이탈

  • 업로드 한 번 = 파일 작업 하나(FR-FEX-008 팝오버 재사용). 동시 전송은 3개(셀룰러에서는 2개).
  • 서버는 숨김 임시 파일에 쓰고 끝나면 이름을 바꿉니다. 취소·실패 시 임시 파일을 지웁니다.
  • 실패는 파일 단위로 처리합니다. 자동으로 1회 다시 시도하고, 그래도 실패하면 "완료 · n개 실패"와 함께 실패 목록과 [재시도]를 보여 줍니다.
  • 전송 중에만 beforeunload 를 등록하고, 창을 닫으면 확인 바를 띄웁니다. 모바일은 Wake Lock을 쓰고, 화면이 꺼져 끊기면 "중단됨 · 다시 시도"로 표시합니다.
  • 완료되면 같은 폴더를 보는 모든 탭을 새로 읽습니다. 창이 최소화되어 있으면 트레이에 배지를 답니다.

3다운로드

  • 파일 하나는 기존 일회용 토큰 방식을 그대로 씁니다(FR-FEX-021).
  • 여러 항목·폴더는 ZIP 하나로 받습니다. 이름은 항목 하나면 폴더명.zip, 여럿이면 {현재폴더}.zip 입니다.
  • 사전 계산으로 크기를 아니까 진행 막대는 확정형입니다. .git·node_modules 는 기본으로 빼고 그 사실을 보여 줍니다. 심볼릭 링크는 따라가지 않습니다.

4버그·접근성

  • 현재 fx-mobile-bar 의 aria-label이 작업 목록과 같은 "파일 작업"입니다. "파일 동작"으로 분리해야 합니다.
  • 비활성은 opacity만으로 표시하지 않고 disabled/aria-disabled 를 붙입니다. 진행은 role="progressbar", 시트는 포커스 트랩·뒤로가기·아래로 끌어 닫기를 갖춥니다.
  • 모바일 목록은 데스크톱과 같은 목록(같은 열, 28px 행)을 씁니다. 하단 바 레이블 12px, 하단 safe-area, 터미널 키보드가 열리면 바를 숨깁니다.

정해 주셔야 할 것 결정 필요

  • 업로드 최대 크기(설정값 여부, 기본값)
  • ZIP 확인 기준: 1GB / 1만 개가 적당한지
  • ZIP을 압축 없이 묶기만 할지(빠름), deflate로 압축할지
  • "건너뛰기"를 기존 복사 작업의 "복사하지 않기"에도 적용해 단어를 통일할지
