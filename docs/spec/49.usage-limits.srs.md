### FR-USAGE-001 — Codex 세션 기록에서 계정별 한도를 읽는다

| Field | Value |
| --- | --- |
| Type | functional |
| Target | usage-limits |
| Status | implemented |
| Priority | high |
| Tags | - |
| Risk | medium |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | #213 |
| Related Docs | [usage-limits.html](../design/usage-limits.html), [research](../research/2026-10-31.usage-limits-per-account.md) |

#### Requirement

When the server refreshes usage, it shall read the newest rollout per Codex account from each known CODEX_HOME and report each limit window found.

#### Rationale

Issue #213; research F-items in docs/research/2026-10-31.usage-limits-per-account.md.

#### Acceptance Criteria

- [x] AC-1: 각 Codex 홈(Windows 홈과 WSL 사용자 홈의 .codex, CODEX_HOME)의 sessions 아래 rollout 에서 첫 줄 session_meta.creator_account_id 로 계정을, 마지막 rate_limits 로 사용률을 읽는다. auth.json 은 읽지 않는다.
- [x] AC-2: 창은 window_minutes 로 가른다: 300 은 5시간, 10080 은 주간. primary/secondary 순서에 기대지 않는다. 그 밖의 창은 무시한다. rate_limits.limit_id 가 codex 가 아닌 기록(예: premium)은 다른 한도이므로 읽지 않는다. limit_id 가 없는 옛 기록은 받아들인다.
- [x] AC-3: 계정마다 가장 최근 rollout 의 마지막 값을 쓴다. creator_account_id 가 없는 rollout 은 계정 미상으로 묶는다. 8일보다 오래된 날짜 폴더와 파일은 읽지 않고, 바뀌지 않은 파일은 다시 읽지 않는다.
- [x] AC-4: 읽은 값은 사용률(0~100), 초기화 시각, 기록 시각, 요금제, 출처(Windows/WSL)다.

### FR-USAGE-002 — Claude 상태줄 중계는 한도와 계정만 기록하고 원래 상태줄을 그대로 보인다

| Field | Value |
| --- | --- |
| Type | functional |
| Target | usage-limits |
| Status | implemented |
| Priority | high |
| Tags | - |
| Risk | high |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | #213 |
| Related Docs | [usage-limits.html](../design/usage-limits.html), [research](../research/2026-10-31.usage-limits-per-account.md) |

#### Requirement

When Claude Code runs the statusline command, the relay shall write rate_limits and the account key to a file in that Claude config folder and then run the original command with the same input and print its output.

#### Rationale

Issue #213. Claude Code passes rate_limits only to the statusline stdin; it carries no account identity (verified in the 2.1.314 bundle).

#### Acceptance Criteria

- [x] AC-1: 입력 JSON 의 rate_limits.five_hour / seven_day 에서 used_percentage 와 resets_at 만 꺼내 기록한다. 다른 입력값은 기록하지 않는다.
- [x] AC-2: 계정은 같은 설정 폴더(CLAUDE_CONFIG_DIR 또는 홈)의 .claude.json oauthAccount 의 accountUuid 와 organizationUuid 로 정하고, 기록에는 그 해시와 이메일 전체·요금제만 남긴다. .credentials.json 은 읽지 않는다.
- [x] AC-3: 기록은 설정 폴더 안 buildergate-usage.json 에 계정별 최신값으로 원자적으로 쓴다.
- [x] AC-4: 기록에 실패해도 원래 상태줄 명령은 같은 입력으로 실행되고 그 출력과 종료 코드가 그대로 나간다. Windows 에서는 Claude Code 처럼 Git Bash 로 실행한다(CLAUDE_CODE_GIT_BASH_PATH, PATH 의 git 옆 bin\\bash.exe, 기본 설치 위치 순; 없으면 기본 셸). 원래 명령이 없으면 아무것도 출력하지 않는다.

#### Requirement

When the user turns Claude usage collection on, the system shall wrap the statusLine command of each Claude settings.json (Windows and WSL) with the relay, and when turned off, restore each original statusLine.

#### Rationale

Issue #213; user approved the on/off approach on 2026-10-31.

#### Acceptance Criteria

- [x] AC-1: 켜면 각 settings.json 의 statusLine.command 를 중계 명령으로 바꾸고, 원래 statusLine 값(없으면 없음)을 그 설정 폴더의 buildergate-statusline.json 에 보관한다. 중계가 실행할 때 이 파일을 읽는다. 다른 설정 키는 바꾸지 않는다. 그 Claude 가 중계를 실행할 node 를 찾을 수 없으면 그 폴더는 바꾸지 않고 실패로 남긴다.
- [x] AC-2: 끄면 보관한 원래 값으로 되돌린다. 원래 statusLine 이 없었으면 키를 지운다. 중계 파일과 기록 파일(buildergate-usage.json)도 지운다.
- [x] AC-3: 이미 중계로 감싼 상태에서 다시 켜도 두 번 감싸지 않는다.
- [x] AC-4: 켠 뒤 사용자가 statusLine 을 바꿔 중계가 빠지면 상태 조회가 그 사실을 알리고, 켠 채로 저장하면 다시 넣는다. 모든 폴더에서 실패하면 켜지 않고, 폴더별 실패 사유를 상태로 돌려준다.

### FR-USAGE-004 — 계정별로 합치고 표시할 값을 정한다

| Field | Value |
| --- | --- |
| Type | functional |
| Target | usage-limits |
| Status | implemented |
| Priority | high |
| Tags | - |
| Risk | medium |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | #213 |
| Related Docs | [usage-limits.html](../design/usage-limits.html), [research](../research/2026-10-31.usage-limits-per-account.md) |

#### Requirement

When the server reports usage, it shall merge readings of the same agent account from Windows and WSL and attach the display fields each bar needs.

#### Rationale

Issue #213; design docs/design/usage-limits.html §④.

#### Acceptance Criteria

- [x] AC-1: 같은 에이전트·같은 계정 키의 기록은 하나로 합치고 기록 시각이 더 최근인 값을 쓴다. 계정 키가 달라도 모든 창의 초기화 시각 차이가 5초 이내이면 같은 한도로 보고 한 막대로 합친다(가장 작은 키를 남기고 값은 가장 최근 기록을 쓴다).
- [x] AC-2: 초기화 시각이 지난 창은 사용률 0 과 reset 표시로 보고한다. 계정을 알 수 없는 기록은 모든 창의 초기화 시각이 지났으면 보고하지 않는다.
- [x] AC-3: 남은 양(100 - 사용률)에 따라 수준을 정한다: 40 이상 plenty, 15 이상 40 미만 low, 15 미만 critical.
- [x] AC-4: 계정 이름은 사용자 별명, 이메일 전체와 요금제, 짧은 해시 순으로 정한다. 사용자가 숨긴 계정은 보고하지 않는다. 별명과 숨김은 계정별로 병합해 저장하므로 이번에 읽히지 않은 계정의 값은 유지된다. 창 기록이 없는 계정은 설정 목록에도 나오지 않는다.
- [x] AC-5: 기록 시각이 1시간보다 오래되면 stale 로 표시한다. stale 표시는 그 계정 줄에만 붙는다.

### FR-USAGE-005 — 사용량은 정한 주기로 갱신하고 바로 다시 읽을 수 있다

| Type | functional |

#### Requirement

While the server runs, it shall reread the usage sources every refresh interval (15 to 3600 seconds, default 60) and immediately when asked.

### FR-USAGE-006 — 남은 양이 기준 미만이면 Google Chat 과 텔레그램으로 알린다

| Field | Value |
| --- | --- |
| Type | functional |
| Target | usage-limits |
| Status | implemented |
| Priority | critical |
| Tags | - |
| Risk | high |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | #213 |
| Related Docs | [usage-limits.html](../design/usage-limits.html), [research](../research/2026-10-31.usage-limits-per-account.md) |

#### Requirement

When a refresh produces a reading whose remaining capacity is below the threshold and whose used percentage differs from the previous reading of the same agent, account and window, the server shall send an alert to every enabled channel.

#### Rationale

Issue #213; user decisions 2026-10-31: threshold is remaining capacity; alert on every update unless the value equals the previous update.

#### Acceptance Criteria

- [x] AC-1: 기준은 1~99 정수 %(기본 20)이고 남은 양(100 - 사용률)과 비교한다. 대상 에이전트(Claude·Codex)와 창(5시간·주간)을 고를 수 있다. 숨긴 계정은 알리지 않는다.
- [x] AC-2: 남은 양이 기준 미만이면 갱신될 때마다 보낸다. 같은 에이전트·계정·창의 직전 갱신 사용률과 이번 사용률이 같으면 보내지 않는다. 기준 이상이면 보내지 않는다. 설정 저장과 갱신이 겹쳐도 직전 값은 되돌아가지 않는다.
- [x] AC-3: Google Chat 은 https://chat.googleapis.com 웹훅 URL 로 {text} 를 POST 한다(다른 호스트는 거부). 텔레그램은 봇 토큰과 chat id 로 sendMessage 를 부른다. 메시지에는 에이전트, 계정 이름, 창, 남은 양, 기준, 초기화까지 남은 시간, 기계 이름이 들어간다.
- [x] AC-4: 웹훅 URL 과 봇 토큰은 암호화해 저장하고, API 응답과 로그에는 끝 4자리만 남긴다(오류 문구에서는 URL 과 그 쿼리 값을 가린다). 빈 값으로 저장하면 기존 값을 유지하고, 지우기는 따로 요청한다.
- [x] AC-5: 테스트 요청은 넘겨받은 값(저장 전 값 포함, 없으면 저장된 값)으로 실제 메시지를 보내고 성공 여부, HTTP 상태와 오류 문구를 돌려준다.
- [x] AC-6: 한 채널의 실패는 다른 채널 전송과 갱신을 막지 않는다.
