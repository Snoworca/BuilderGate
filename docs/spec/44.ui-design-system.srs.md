## 1. Scope Overview

BuilderGate 화면 전체가 따르는 시각 규칙과 문구 규칙, 그리고 그 규칙을 담은 공용 부품이다. CON-ARCH-001 이 정한 색·모서리·행 높이 토큰 위에 글자·간격·컨트롤·아이콘 크기 토큰, 선 아이콘 세트, 공용 부품, 한국어 문구 규칙, 접근성 대비 기준을 더하고, 기존 화면을 단계적으로 옮긴다. 기준 화면은 [디자인 시스템 견본](../research/2026-09-26.ui-design-system.html)이다.

## 2. Scope Boundaries

### In Scope

- 글자 크기·굵기·간격·컨트롤 높이·아이콘 크기·글꼴 토큰
- 하나의 선 아이콘 세트와 아이콘 전용 버튼의 접근 가능한 이름·툴팁
- 공용 부품: 버튼, 칩, 배지, 창 틀, 선택 목록 행, 진행 막대, 배너, 툴팁, 폼 입력
- 사용자에게 보이는 UI 문구의 한국어 통일과 문구 규칙
- 글자 대비·초점 표시·터치 영역 기준
- 기존 화면 이전: 창 → 헤더·사이드바·탭 막대 → 편집기·파일 탐색기

### Out of Scope

- 세션 터미널 영역의 레이아웃과 모양: 타일 사이의 가는 구분선, 각 세션 아래쪽의 상태 표시줄(MetadataRow). 영어 문구의 한국어 변경만 한다(FR-UIDS-004 AC-6)
- 터미널 내용(xterm 렌더링과 터미널 색 테마)
- 벤더링한 편집기(atomic-editor) 내부 스타일
- i18n: 문자열 추출 도구와 다국어 사전 (추후 별도 작업)
- 새 기능 추가, 밝은 테마 전면 도입 (현재 paper 표면은 유지)

## 3. Assumptions and Constraints

- CON-ARCH-001 의 색·모서리·행 높이 토큰과 강조색 #0078d4 를 그대로 쓴다.
- 글꼴은 시스템 글꼴(Segoe UI 계열)과 고정폭 Cascadia Code 계열이다. 웹 폰트를 새로 들이지 않는다.
- 모바일 레이아웃과 기존 동작은 바꾸지 않는다. 바뀌는 것은 모양과 문구다.
- E2E 테스트가 문구·클래스로 요소를 찾는 곳은 이전 작업과 함께 고친다.

#### Requirement

시스템은 글자 크기·굵기·간격·컨트롤 높이·아이콘 크기·글꼴을 이름이 고정된 CSS 토큰으로 정의하고, UI 컴포넌트는 그 토큰만 참조해야 한다.

#### Rationale

2026-09-26 측정: frontend/src 에서 글자 크기 21가지(px·rem·em 혼용), 모서리 12가지, TSX 인라인 hex 57곳이 쓰였다. 목업이 기존 색 토큰만 쓰고도 더 정돈돼 보인 이유가 이 단계의 통일이다.

#### Acceptance Criteria

- [x] AC-1: 글자 크기 토큰 6단계를 정의한다: --fs-2xs 11px, --fs-xs 12px, --fs-sm 13px(본문 기본), --fs-md 14px, --fs-lg 16px, --fs-xl 18px. 반 픽셀 값은 쓰지 않는다
- [x] AC-2: 굵기 토큰 3단계를 정의한다: --fw-regular 400, --fw-semibold 600, --fw-bold 700
- [x] AC-3: 간격 토큰을 4px 단위로 정의한다: --sp-1 4px, --sp-2 8px, --sp-3 12px, --sp-4 16px, --sp-5 20px, --sp-6 24px, --sp-8 32px
- [x] AC-4: 컨트롤 높이 토큰을 정의한다: --ctl-sm 28px, --ctl-md 32px, --ctl-lg 36px, --ctl-touch 44px(모바일 최소)
- [x] AC-5: 아이콘 크기 토큰을 정의한다: --icon-sm 16px, --icon-md 18px, --icon-lg 20px. 선 두께는 2px 하나다
- [x] AC-6: 모서리는 CON-ARCH-001 의 --r-sm/--r-md/--r-lg 에 알약용 --r-pill 999px 하나만 더한다
- [x] AC-7: 글꼴 토큰 --font-sans(Segoe UI 계열 시스템 글꼴)와 --font-mono(Cascadia Code 계열)를 정의하고 웹 폰트를 새로 들이지 않는다
- [x] AC-8: 가드 테스트가 이전을 마친 컴포넌트 파일에 hex 색 리터럴과 토큰 밖 font-size·border-radius 값이 없음을 확인한다. 예외는 벤더링 편집기와 xterm 테마뿐이며 목록으로 명시한다

#### Requirement

시스템은 UI 아이콘을 하나의 선 아이콘 세트로 그리고, 아이콘만 있는 버튼마다 접근 가능한 이름과 툴팁을 제공해야 한다.

#### Rationale

공용 Icon 은 8개뿐이고 헤더 보기 전환은 ⊞/☰ 글자, 나머지는 제각각의 인라인 SVG 다. 크기와 선 두께가 섞여 한 화면에서 무게가 달라 보인다.

#### Acceptance Criteria

- [x] AC-1: 모든 UI 아이콘은 공용 Icon 컴포넌트의 이름으로 그린다: 24 viewBox, 선 두께 2, currentColor
- [x] AC-2: 유니코드 글자(⊞ ☰ ▶ 등)와 이모지를 아이콘으로 쓰지 않는다 — 가드 테스트로 확인한다
- [x] AC-3: 아이콘 전용 버튼은 aria-label 과 같은 뜻의 title(툴팁)을 가진다 — 가드 테스트로 확인한다
- [ ] AC-4: 크기 규칙: 헤더·툴바 --icon-md, 목록·칩 --icon-sm, 창 머리 아이콘 타일 --icon-lg

#### Requirement

시스템은 버튼·칩·배지·창 틀·선택 목록 행·진행 막대·배너·툴팁을 공용 부품으로 제공하고, 화면은 같은 역할에 같은 부품을 써야 한다.

#### Rationale

같은 역할(예: 창의 확인 버튼, 상태 칩)이 화면마다 다른 크기·색·모서리로 그려져 있다. 부품으로 묶어야 이후 화면이 같은 모양으로 유지된다.

#### Acceptance Criteria

- [x] AC-1: 버튼: 주(primary)·보조(secondary)·위험(danger)·아이콘 네 종류와 --ctl-sm/md/lg 세 크기, 비활성·마우스 올림·초점 상태를 가진다
- [x] AC-2: 칩과 배지: 중립·강조·성공·경고·위험 다섯 톤을 가지며, 톤을 색만으로 구분하지 않도록 글자나 아이콘을 함께 쓴다
- [x] AC-3: 창 틀: 아이콘 타일·제목·설명의 머리, 본문, 안내 문구와 동작 버튼을 담는 하단 바로 구성하고 기존 WindowDialog 위에 얹는다
- [x] AC-4: 선택 목록 행: 체크박스·제목·보조 정보(경로 등 고정폭)·오른쪽 상태를 가지며 행 전체가 체크 영역이다
- [x] AC-5: 진행 막대·배너·툴팁을 제공한다. 배너는 화면을 막지 않고 주 동작과 나중에 동작을 가진다
- [x] AC-6: 모든 대화형 부품은 초점 표시(2px 강조색 링)를 가진다
- [x] AC-7: 폼 입력: 라벨·도움말·오류 문구를 가진 필드 틀과 텍스트 입력, 숫자 입력(단위 표시), 선택 상자, 스위치, 체크박스를 제공한다. 라벨은 입력과 연결된다(label for / aria-labelledby)

#### Requirement

시스템은 사용자에게 보이는 모든 UI 문구를 한국어로 쓰고, 버튼은 동작을, 설명은 결과를 먼저 말하는 문구 규칙을 따라야 한다.

#### Rationale

지금 UI 는 Tools·Settings·Switch to Grid 같은 영어와 복구 옵션·명령줄 관리 같은 한국어가 섞여 있다. 2026-09-26 사용자 결정: 지금은 한국어로 통일하고 i18n 은 나중에 한다.

#### Acceptance Criteria

- [x] AC-1: 헤더·메뉴·창·툴팁·aria-label 의 영어 문구를 한국어로 바꾼다(예: Tools→도구, Settings→설정, Switch to Grid→그리드 보기로 전환). 고유명사(BuilderGate, Claude, Codex, Hermes, OpenCode, MCP)와 경로·명령은 그대로 둔다. 제품 용어 Workspace 는 음역하지 않고 영어로 쓴다(목록 제목 Workspaces, 문장 안에서는 Workspace)
- [ ] AC-2: 버튼 문구는 누르면 일어나는 동작을 말한다(예: 세션 저장, 워크스페이스 삭제, 선택한 5개 이어하기). 확인만 쓰는 버튼은 결과가 이미 화면에 적혀 있을 때만 쓴다
- [ ] AC-3: 중단·삭제처럼 되돌릴 수 없는 동작의 설명은 무엇이 사라지고 무엇이 남는지를 먼저 말한다
- [ ] AC-4: i18n(문자열 추출 도구·다국어 사전)은 만들지 않는다

#### Requirement

시스템은 UI 글자 대비, 키보드 초점 표시, 모바일 터치 영역을 일정 기준 이상으로 유지해야 한다.

#### Rationale

작은 회색 글씨(#767676 on #2b2b2b ≈ 3.3:1)가 기준에 못 미친다. 원격으로 휴대폰에서 쓰는 경우가 제품 목적에 들어 있다.

#### Acceptance Criteria

- [ ] AC-1: 본문 글자 대비 4.5:1 이상, 16px 이상 굵은 글자는 3:1 이상이다. --fg-faint(#767676)는 chrome 표면의 14px 미만 글자에 쓰지 않는다
- [x] AC-2: 모든 대화형 요소는 :focus-visible 에서 보이는 초점 링을 가진다
- [ ] AC-3: 모바일 레이아웃의 누르는 영역은 --ctl-touch(44px) 이상이다
- [ ] AC-4: 의미를 가진 색(성공·경고·위험)은 색 말고도 글자나 아이콘으로 구분된다
- [x] AC-5: 어두운 표면의 글자용 의미 색 토큰을 둔다: --accent-text #6cb6ff(6.6:1), --ok-text #4cc38a(6.4:1), --warn-text #e2b451(7.3:1), --danger-text #ec8f8f(6.0:1). --danger(#e05c5c, 3.95:1)는 작은 글자에 쓰지 않고, 흰 글자를 얹는 위험 버튼은 --danger-fill #c94a4a(4.6:1)를 쓴다

#### Requirement

시스템은 기존 화면을 디자인 시스템으로 단계적으로 옮겨야 한다: 창 → 헤더·사이드바·탭·세션 메타데이터 줄 → 편집기·파일 탐색기. 터미널 내용은 바꾸지 않는다.

#### Rationale

한 번에 바꾸면 E2E 수십 개가 동시에 깨진다. 독립적인 창부터 옮기면 단계마다 되돌리기 쉽다. CON-ARCH-001 AC-8 이 미뤄 둔 기존 CSS 색(#1e1e1e, #252526)의 토큰 이전은 이 요구사항이 맡는다.

#### Acceptance Criteria

- [x] AC-1: 1단계: WindowDialog 를 쓰는 창(설정, 복구 옵션, 명령줄 관리, MCP 설정, 터미널 키보드 등)을 창 틀·버튼·목록 행 부품으로 옮긴다
- [x] AC-2: 2단계: 헤더, 워크스페이스 사이드바, 탭 막대를 옮긴다. 헤더 보기 전환의 ⊞/☰ 글자를 아이콘으로 바꾼다
- [x] AC-3: 3단계: 편집기 창과 파일 탐색기의 남은 하드코딩 값을 토큰으로 옮긴다
- [ ] AC-4: 단계마다 옮긴 파일에 hex 색 리터럴과 토큰 밖 크기 값이 0 이고, 영향받는 E2E 는 새 문구·선택자로 고쳐 통과한다
- [ ] AC-5: 기존 동작(단축키, 드래그, 창 배치, 모바일 레이아웃)은 바뀌지 않는다
- [x] AC-6: 세션 터미널 영역의 레이아웃과 모양은 바꾸지 않는다: 타일 사이의 가는 구분선(react-mosaic split line)과 각 세션 아래쪽의 28px 상태 표시줄(MetadataRow: 색 막대·이름·경로·경과 시간)의 위치·높이·배치·색·글자 크기가 그대로다. 이 영역에서 허용하는 변경은 영어 문구의 한국어 변경뿐이며, 이 영역의 파일(Grid/MosaicTile.tsx, Grid/MosaicOverrides.css, MetadataBar/MetadataRow.tsx, Terminal/)은 AC-4 와 CON-UIDS-001 AC-8 의 하드코딩 값 기준에서 예외다

#### Requirement

The system shall draw every item of the session terminal's context menu with an icon from the shared icon set, and shall mark each workspace row with a dot that shows whether any of its sessions is running.

#### Rationale

사용자 요청(2026-09-26): 터미널 메뉴의 파일 탐색기에도 아이콘을 보이고, 시안처럼 워크스페이스 항목 왼쪽에 회색·초록 원을 붙인다

#### Acceptance Criteria

- [x] AC-1: 세션 터미널 우클릭 메뉴의 새 세션·세션 닫기·Workspace 이동·파일 탐색기 열기·복사·붙여넣기 항목은 공용 아이콘 세트의 이름으로 그린다(유니코드 글자 아이콘 없음). 서버가 보내는 셸 아이콘은 그대로 둔다
- [x] AC-2: 워크스페이스 목록의 각 행은 이름 왼쪽에 8px 원을 둔다. 탭 가운데 하나라도 상태가 running 이면 초록(--ok), 아니면 회색이다
- [x] AC-3: 원은 색만으로 뜻을 전하지 않도록 행에 상태 이름(실행 중·대기)을 접근 가능한 이름으로 함께 준다
