### FR-LOOP-001 — 루프 정의를 검증해 저장한다

| Field | Value |
| --- | --- |
| Type | functional |
| Target | loop-scheduler |
| Status | implemented |
| Priority | high |
| Tags | - |
| Risk | medium |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | #206 |
| Related Docs | [loop-scheduler.html](../design/loop-scheduler.html) |

#### Requirement

When a user saves a loop, the system shall validate it and keep it in server/data/loops.json so that it survives a server restart.

#### Rationale

Issue #206; design docs/design/loop-scheduler.html §③ and §⑤ 7, 11.

#### Acceptance Criteria

- [x] AC-1: 루프는 이름, 켜짐 여부, 일정, 셸, 디렉터리, 남겨 둘 탭 수(1~16, 기본 1), 단계 목록을 가지며 서버를 다시 켜도 그대로 남는다.
- [x] AC-2: 단계는 명령(한 줄) · 프롬프트(여러 줄 가능) · 대기(0 이상 3,600,000 이하의 정수 ms) · 세션 종료 네 가지다. 세션 종료가 마지막이 아닌 곳에 있으면 저장을 거부한다.
- [x] AC-3: 단계가 하나도 없거나, 일정에 고른 요일·날짜·시각이 하나도 없거나, 빈 명령·프롬프트가 있으면 저장을 거부한다.
- [x] AC-4: 특정 날짜 일정의 모든 시각이 이미 지났으면 저장을 거부한다.
- [x] AC-5: REST API 는 GET/POST /api/loops, PUT/DELETE /api/loops/:id, POST /api/loops/:id/run(지금 한 번 실행)을 인증 뒤에 제공한다.

### FR-LOOP-002 — 루프의 다음 실행 시각을 서버 현지 시각으로 계산한다

| Field | Value |
| --- | --- |
| Type | functional |
| Target | loop-scheduler |
| Status | implemented |
| Priority | high |
| Tags | - |
| Risk | medium |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | #206 |
| Related Docs | [loop-scheduler.html](../design/loop-scheduler.html) |

#### Requirement

While a loop is enabled, the system shall run it at every time its schedule names and at no other time.

#### Rationale

Issue #206; design §⑤ 3, 4, 11.

#### Acceptance Criteria

- [x] AC-1: 요일마다: 고른 요일마다 고른 각 시각에 실행한다.
- [x] AC-2: 매월: 고른 날짜마다 고른 각 시각에 실행한다. 그 달에 없는 날짜(예: 2월 30일)는 건너뛰고, 말일은 그 달의 마지막 날이다. 같은 순간이 두 번 나오면(31일과 말일) 한 번만 실행한다.
- [x] AC-3: 특정 날짜: 그 날짜의 각 시각에 실행하고, 마지막 시각을 실행한 뒤 루프를 끈다.
- [x] AC-4: 간격: 기준 시각부터 간격(1분 이상)마다 실행하며, 날짜를 넘어 이어서 센다.
- [x] AC-5: 시각은 서버 기계의 현지 시간대로 해석한다.
- [x] AC-6: 서버가 꺼져 있던 동안 지나간 시각은 실행하지 않고, 서버가 켜진 뒤의 다음 시각부터 실행한다.

### FR-LOOP-003 — 루프 실행은 단계를 위에서 아래로 차례로 보낸다

| Field | Value |
| --- | --- |
| Type | functional |
| Target | loop-scheduler |
| Status | implemented |
| Priority | high |
| Tags | - |
| Risk | high |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | #206 |
| Related Docs | [loop-scheduler.html](../design/loop-scheduler.html) |

#### Requirement

When a loop runs, the system shall open a new tab with the loop's shell in the loop's directory and send each step in order.

#### Rationale

Issue #206; design §③ step kinds, §⑤ 5, 7, 10. The separate Enter reuses FR-MCP-002 AC-7 so the two paths do not drift.

#### Acceptance Criteria

- [x] AC-1: 명령과 프롬프트 단계는 글을 쓰고, 잠시 뒤 Enter 를 따로 쓴다(MCP 와 같은 submitWithSeparateEnter, 같은 대기 설정). 앞 명령이 끝나기를 기다리지 않고 다음 단계로 간다.
- [x] AC-2: 대기 단계는 적힌 ms 만큼 기다린다. 에이전트가 떴는지 감지하지 않는다.
- [x] AC-3: 세션 종료 단계는 셸에 글을 쓰지 않고 서버가 그 탭을 닫는다.
- [x] AC-4: 실행 중에 루프를 끄거나 지우거나 그 탭이 닫히면 남은 단계를 보내지 않는다. 탭은 그대로 둔다.
- [x] AC-5: 셸을 열 수 없거나 디렉터리가 없으면 탭을 만들지 않고 그 실행을 실패로 기록한다.

### FR-LOOP-004 — 루프 탭은 @schedule-{n} 워크스페이스에 연다

| Field | Value |
| --- | --- |
| Type | functional |
| Target | loop-scheduler |
| Status | implemented |
| Priority | high |
| Tags | - |
| Risk | medium |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | #206 |
| Related Docs | [loop-scheduler.html](../design/loop-scheduler.html) |

#### Requirement

When a loop runs, the system shall place its tab in the lowest-numbered @schedule-{n} workspace with room, and create @schedule-{max+1} (or @schedule-0) when none has room.

#### Rationale

Issue #206; design §④ and §⑤ 1, 2, 6, 8, 9.

#### Acceptance Criteria

- [x] AC-1: @schedule-{n} 워크스페이스는 서버가 만든 id 로 기억한다. 탭 수가 maxTabsPerWorkspace 보다 적은 것 가운데 번호가 가장 작은 곳에 연다.
- [x] AC-2: 모두 가득 찼거나 하나도 없으면 가장 큰 번호 + 1(없으면 0)로 새로 만든다. 사용자가 지운 워크스페이스는 잊는다.
- [x] AC-3: 탭 이름은 「루프 이름 #회차」다.
- [x] AC-4: 세션 종료가 없는 실행의 탭이 그 루프의 남겨 둘 탭 수를 넘으면, 그 루프의 가장 오래된 탭부터 닫는다.
- [x] AC-5: 모든 @schedule 워크스페이스의 탭 합계가 32 이상이면 탭을 열지 않고 그 실행을 건너뜀으로 기록한다.
- [x] AC-6: 탭이 모두 닫힌 @schedule 워크스페이스는 지우지 않는다.
- [x] AC-7: @schedule 워크스페이스의 탭은 세션 저장·복원(FR-AITUI-007) 대상에서 뺀다.
- [ ] AC-8: 워크스페이스와 탭을 만들고 닫을 때 REST 경로와 같은 WebSocket 이벤트를 보내 열린 브라우저가 따라온다.

### FR-LOOP-005 — 루프는 겹쳐 돌지 않고 실행 기록을 남긴다

| Field | Value |
| --- | --- |
| Type | functional |
| Target | loop-scheduler |
| Status | implemented |
| Priority | medium |
| Tags | - |
| Risk | low |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | #206 |
| Related Docs | [loop-scheduler.html](../design/loop-scheduler.html) |

#### Requirement

When a loop's time comes while its previous run is still sending steps, the system shall skip the new run and record it as skipped.

#### Rationale

Issue #206; design §② history and §⑤ 1, 11.

#### Acceptance Criteria

- [x] AC-1: 「실행 중」은 마지막 단계를 보낼 때까지다. 그 뒤 남아 있는 탭은 실행 중으로 치지 않는다.
- [x] AC-2: 기록 한 건은 시작 시각, 결과(성공 · 실패 · 건너뜀 · 중단), 보낸 단계 수, 워크스페이스와 탭, 실패 사유를 담는다. 루프마다 최근 50건만 남긴다.
- [x] AC-3: 같은 순간에 여러 루프가 돌면 세션을 하나씩 차례로 만든다.

### FR-LOOP-006 — 도구 메뉴의 루프 창에서 루프를 관리한다

| Field | Value |
| --- | --- |
| Type | functional |
| Target | loop-scheduler |
| Status | implemented |
| Priority | high |
| Tags | - |
| Risk | low |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | #206 |
| Related Docs | [loop-scheduler.html](../design/loop-scheduler.html) |

#### Requirement

When the user chooses Tools > Loop, the system shall show the loop manager, and the loop editor shall build the schedule and steps defined in FR-LOOP-001.

#### Rationale

Issue #206; design §① §② §③.

#### Acceptance Criteria

- [ ] AC-1: 도구 메뉴 아래쪽에 구분선과 「루프」 항목이 있고, 켜진 루프가 있으면 그 개수를 보여 준다.
- [ ] AC-2: 관리 창은 루프마다 켜기/끄기, 이름과 일정 요약, 다음 실행 시각, 마지막 결과를 보이고, 새 루프 · 지금 실행 · 편집 · 삭제와 최근 기록 펼치기를 제공한다.
- [x] AC-3: 편집 창은 반복(요일마다 · 매월 · 특정 날짜 · 간격), 시각, 셸(새 탭과 같은 목록), 디렉터리, 남겨 둘 탭, 단계 목록을 편집한다. 세션 종료 단계가 있으면 단계를 더 추가할 수 없다.
- [x] AC-4: 한 줄 입력 codex delay 2000 "금일 주식 시황 분석하시오" 는 명령 codex, 대기 2000, 프롬프트 세 단계로 풀린다. exit 는 평범한 명령이다.
- [x] AC-5: 화면 문자열은 i18n 카탈로그(en · ko)를 거친다.
