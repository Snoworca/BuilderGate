### FR-MSG-001 — 방을 만들고 참여자를 관리한다

| Field | Value |
| --- | --- |
| Type | functional |
| Target | messenger |
| Status | implemented |
| Priority | high |
| Tags | - |
| Risk | medium |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | - |
| Related Docs | [messenger.html](../design/messenger.html) |

#### Requirement

When a user creates a room, the system shall store the room on the creator's server as its storage PC, add the selected local sessions and invite the selected contacts, and let members be removed or leave.

#### Rationale

-

#### Acceptance Criteria

- [x] AC-1: AC-1: 방 이름(1~60자)과 내 세션 0개 이상, 연락처 0명 이상으로 방을 만든다. 세션마다 '받은 메시지를 바로 입력(Enter)' 을 고른다(기본 켜짐). 만든 사람의 서버가 그 방의 보관 PC 가 되고, 방 정보는 'X PC에 보관됩니다' 로 보인다.
- [x] AC-2: AC-2: 방 목록은 마지막 메시지 시각 순이고 방마다 읽지 않은 수를 보인다. 나나 내 세션을 지정한 메시지가 있으면 수가 빨간색이다.
- [x] AC-3: AC-3: 방 머리의 초대로 내 세션과 연락처를 더한다. 참여자 목록은 사람 아래에 그 사람의 세션을 들여 쓴다.
- [x] AC-4: AC-4: 방을 만든 사람과 세션 주인은 그 세션을 뺄 수 있고, 방을 만든 사람은 사람을 내보낼 수 있다. 내보내면 그 사람의 세션도 빠지고, 내보내진 사람의 메신저 창은 그 방에 더 이상 참여하지 않는다고 알린다. 누구나 방을 나갈 수 있다.
- [x] AC-5: AC-5: 세션이 닫히면 방에서 빠지고 시스템 메시지가 남는다.
- [x] AC-6: AC-6: 방과 메시지를 이름·본문으로 검색한다.

### FR-MSG-002 — 메시지를 보내고 기록을 남긴다

| Field | Value |
| --- | --- |
| Type | functional |
| Target | messenger |
| Status | implemented |
| Priority | high |
| Tags | - |
| Risk | medium |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | - |
| Related Docs | [messenger.html](../design/messenger.html) |

#### Requirement

When a person or an agent posts to a room, the storage PC shall give the message the next sequence number of the room, append it to the room log, and send it to every member server, which keeps a copy of the log.

#### Rationale

-

#### Acceptance Criteria

- [x] AC-1: AC-1: 사람은 메신저 화면에서, 에이전트는 room.send 로 보낸다. 메시지는 보낸 이, 종류(사람/에이전트), 시각, 본문, 지정 대상을 가진다.
- [x] AC-2: AC-2: 순번은 보관 PC 만 매긴다. 참여 PC 는 clientMsgId 로 중복을 거르고, 순번 순서로만 기록과 붙여넣기를 한다.
- [x] AC-3: AC-3: 기록은 방마다 data/messenger/rooms 아래 파일 하나에 남고, 서버를 다시 시작해도 남는다. 참여 PC 는 받은 마지막 순번을 기억하고 다시 연결되면 빠진 것을 받아 온다. 참여할 때는 기록 전체를 받는다.
- [x] AC-4: AC-4: 메시지마다 상태를 보내는 중, 전달됨, 붙여넣음(세션 수) 세 단계로 보인다.
- [x] AC-5: AC-5: 본문은 코드와 코드 블록만 렌더한다. 에이전트 메시지가 연속으로 여럿이면 접어서 보인다.

### FR-MSG-003 — @ 로 받을 사람과 세션을 지정한다

| Field | Value |
| --- | --- |
| Type | functional |
| Target | messenger |
| Status | implemented |
| Priority | high |
| Tags | - |
| Risk | medium |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | - |
| Related Docs | [messenger.html](../design/messenger.html) |

#### Requirement

When a message names members with @, the system shall resolve each name to a room member at send time and paste the message only to the named sessions.

#### Rationale

-

#### Acceptance Criteria

- [x] AC-1: AC-1: @세션 은 내 PC 의 세션, @사람::세션 은 그 사람 PC 의 세션이다. 첫 :: 만 경계로 본다. 공백이 있는 세션 이름은 따옴표로 감싼다.
- [x] AC-2: AC-2: 지정이 없으면 보낸 세션을 뺀 방의 모든 세션이 받는다. 지정이 하나면 1:1, 여럿이면 1:n 이다.
- [x] AC-3: AC-3: 같은 이름이 방에 둘이면 보내지 않고 AMBIGUOUS_TARGET 과 후보를 돌려준다. 방에 없는 이름이면 TARGET_NOT_FOUND 다.
- [x] AC-4: AC-4: @사람 만 지정하면 붙여넣지 않고 그 사람의 읽지 않은 수만 빨간색으로 만든다.
- [x] AC-5: AC-5: 지정은 보내는 순간 멤버 ID 로 저장한다. 세션 이름이 바뀌어도 지난 지정이 유지되고 화면은 현재 이름으로 보인다.
- [x] AC-6: AC-6: 입력창에서 @ 를 치면 이 방의 사용자(연결된 사람 먼저)와 내 세션 목록이 뜨고, 사용자를 고르거나 사람::까지 치면 그 사람의 세션 목록이 뜬다. 사용자 줄에서 '사람만 지정' 을 고르면 @사람 만 넣는다. 화살표, Enter/Tab, Esc 로 조작한다.

### FR-MSG-004 — 방 메시지를 프리픽스와 함께 세션에 붙여넣는다

| Field | Value |
| --- | --- |
| Type | functional |
| Target | messenger |
| Status | implemented |
| Priority | high |
| Tags | - |
| Risk | medium |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | - |
| Related Docs | [messenger.html](../design/messenger.html) |

#### Requirement

When a room message reaches a member server, the server shall paste it into each receiving local session with the prefix [BG-ROOM:<room> | <sender>( → <targets>)], using the existing message paste path.

#### Rationale

-

#### Acceptance Criteria

- [x] AC-1: AC-1: 보낸 세션에는 붙여넣지 않는다. 붙여넣을지는 그 세션의 주인 서버만 정한다. 전달하는 순간 AI 에이전트(Claude Code, Codex 등)가 감지된 세션에만 붙여넣고, 일반 셸 세션에는 붙여넣지 않는다(다른 사람의 글이 셸 명령으로 실행되지 않게 한다). 붙여넣지 않은 세션은 수신 확인에서 skipped(NO_AGENT)로 세고 화면에 '에이전트 없음 · 붙여넣지 않음' 으로 보인다.
- [x] AC-2: AC-2: 세션마다 받은 메시지를 바로 입력(Enter)할지 고른다. 기본은 켜짐이다. 붙여넣는 순간 그 화면이 bracketed paste(DECSET 2004)를 켜 두지 않았으면 에이전트 화면이 준비되지 않은 것으로 보고 아무것도 쓰지 않는다(AGENT_NOT_READY). 에이전트 TUI 는 이 모드를 켜고, ex·vim·less 같은 프로그램은 켜지 않는다.
- [x] AC-3: AC-3: 2,000자를 넘는 본문은 앞부분만 붙여넣고 room.history 로 전문을 읽으라고 적는다. 한 세션에 붙여넣기가 진행 중일 때 그 세션 앞으로 온 메시지들은, 진행 중인 붙여넣기가 끝나는 즉시 한 번에 묶어 붙여넣고 메시지마다 줄 앞에 프리픽스를 단다(그 세션이 bracketed paste 를 켰을 때). 첫 메시지는 기다리지 않는다. 켜지 않았으면 하나씩 붙여넣는다.
- [x] AC-4: AC-4: 세션이 방에 들어오면 방 이름, 참여자, 답하는 방법, 사람의 메시지는 지시이고 에이전트의 메시지는 참고 정보라는 안내를 한 번 붙여넣는다.
- [x] AC-5: AC-5: 보낸 이는 받는 쪽이 인증된 연결로 확인한 이름으로 쓴다. 다른 PC 의 세션은 사람::세션 으로 쓴다.

### FR-MSG-005 — 에이전트끼리 연속으로 주고받으면 붙여넣기를 멈춘다

| Field | Value |
| --- | --- |
| Type | functional |
| Target | messenger |
| Status | implemented |
| Priority | high |
| Tags | - |
| Risk | medium |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | - |
| Related Docs | [messenger.html](../design/messenger.html) |

#### Requirement

When a room has 20 consecutive agent messages without a human message, the storage PC shall mark further messages as held, which are recorded but not pasted, until a human posts or resumes the room.

#### Rationale

-

#### Acceptance Criteria

- [x] AC-1: AC-1: 보관 PC 가 방마다 사람 메시지 없이 이어진 에이전트 메시지 수를 센다. 상한 기본값은 20 이다.
- [x] AC-2: AC-2: 사람 메시지 없이 이어진 에이전트 메시지가 상한(기본 20)에 이르면, 그 상한째 메시지부터 기록에만 남고 붙여넣지 않는다. room.send 는 held: true 를 받는다. 에이전트 메시지마다 그때의 연속 수를 '연속 n/상한' 으로 보인다.
- [x] AC-3: AC-3: 방에 노란 띠와 목록의 ! 표시가 보인다. 사람이 메시지를 쓰거나 '기록만 두고 이어서 붙여넣기' 를 누르면 수가 0 이 된다.
