## 1. Scope Overview

모바일 모드에서 시스템 키보드에 없는 방향키·Esc·Ctrl·F 키를 터미널로 보내는 기능이다. 시스템 키보드 위에 붙는 키 줄, 시스템 키보드 대신 쓰는 특수 키보드와 숫자패드, 그리고 Ctrl·Alt·Shift 수식키 래치(한 번 적용·잠금)를 다룬다. 디자인 기준은 `docs/design/mobile-terminal-keyboard.html` 이며 에픽은 GitHub #133 이다.

## 2. Scope Boundaries

### In Scope

- 키 이름과 수식키 상태를 터미널 바이트로 바꾸는 변환기
- Ctrl·Alt·Shift 수식키 래치와 시스템 키보드 입력에 대한 적용
- 모바일 키 줄, 특수 키보드, 숫자패드 UI

### Out of Scope

- 데스크톱 레이아웃의 키보드 동작 변경
- RD Client 의 Win · AltGr · 마우스 · 스크린샷 키

## 3. Assumptions and Constraints

- 키 입력은 기존 `TerminalHandle.sendInput` → `submitCapturedInput` 경로로만 보낸다. 새 전송 경로를 만들지 않는다.
- 진동은 Vibration API 가 있는 브라우저(안드로이드 Chrome)에서만 일어난다.
- UI 문장은 i18n 카탈로그를 거치고, 키 이름(Ctrl, Esc, F1 등)은 ASCII 상수로 둔다.

### FR-MKB-001 — 모바일 키 변환기는 키 이름과 수식키 상태를 xterm 호환 바이트로 바꾼다

#### Requirement

시스템은 키 이름, 수식키 상태 {ctrl, alt, shift}, applicationCursor 플래그를 받아 터미널로 보낼 바이트 문자열을 돌려주는 순수 함수 변환기를 제공해야 한다.

#### Rationale

모바일 시스템 키보드에는 방향키·Esc·F 키가 없다. 키 줄과 특수 키보드가 같은 변환 규칙을 쓰도록 순수 모듈 하나로 둔다 (epic #133, 디자인 시안 encode()).

#### Acceptance Criteria

- [x] AC-1: 방향키는 수식키가 없을 때 applicationCursor 가 거짓이면 ESC [ A..D, 참이면 ESC O A..D 로 바뀐다
- [x] AC-2: Home/End 는 수식키가 없을 때 ESC [ H / ESC [ F 로, applicationCursor 가 참이면 ESC O H / ESC O F 로 바뀐다
- [x] AC-3: 방향키·Home·End 에 수식키가 있으면 ESC [ 1 ; m X 로 바뀌고 m = 1 + shift(1) + alt(2) + ctrl(4) 이다
- [x] AC-4: Insert·Delete·PageUp·PageDown 은 ESC [ 2~ · 3~ · 5~ · 6~ 로, 수식키가 있으면 ESC [ n ; m ~ 로 바뀐다
- [x] AC-5: F1~F4 는 ESC O P..S 로, F5~F12 는 ESC [ 15~ 17~ 18~ 19~ 20~ 21~ 23~ 24~ 로 바뀐다
- [x] AC-6: Esc·Tab·Enter·Backspace 는 ESC · \t · \r · 0x7f 로, Shift+Tab 은 ESC [ Z 로 바뀐다
- [x] AC-7: Ctrl+한 글자는 xterm 표대로 바뀐다: a..z 와 A..Z → 0x01..0x1a(대소문자 무관), @·2·Space → 0x00, [·3 → 0x1b, \·4 → 0x1c, ]·5 → 0x1d, ^·6 → 0x1e, _·-·7 → 0x1f, ?·8 → 0x7f, 그 밖의 글자는 그대로이며, 수식키가 붙은 F1~F12 와 영문자가 아닌 글자의 Shift 는 수식키 없이 같은 바이트를 낸다
- [x] AC-8: Alt 는 수식키 매개변수 형식(ESC [ 1 ; m X, ESC [ n ; m ~)이 없는 키, 곧 한 글자·Esc·Tab·Enter·Backspace·F1~F12 의 결과 앞에 ESC 하나를 붙이고, 매개변수 형식이 있는 키에는 붙이지 않는다. Shift+영문자는 Ctrl/Alt 를 적용하기 전에 대문자로 바꾼다

### FR-MKB-002 — Ctrl·Alt·Shift 수식키 래치는 한 번 적용과 0.75초 잠금 상태를 가진다

| Field | Value |
| --- | --- |
| Type | functional |
| Target | mtk-wave-1 |
| Status | implemented |
| Priority | high |
| Tags | - |
| Risk | medium |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | https://github.com/Snoworca/BuilderGate/issues/135 |
| Related Docs | [mobile-terminal-keyboard design](../design/mobile-terminal-keyboard.html) |

#### Requirement

시스템은 Ctrl·Alt·Shift 각각에 off·once·locked 세 상태를 갖는 모듈 전역 래치 저장소를 subscribe/getSnapshot 인터페이스로 제공해야 하며, 탭·0.75초 누름·키 전송에 따라 상태를 바꿔야 한다.

#### Rationale

모바일에서는 Ctrl 을 누른 채 시스템 키보드 글자를 칠 수 없어서 먼저 눌러 켜 두는 래치가 필요하다. 사용자가 2026-10-17 대화에서 한 번 적용 + 1.5초 잠금 모델을 확정했다.

#### Acceptance Criteria

- [x] AC-1: 탭은 off → once, once → off, locked → off 로 바꾼다
- [x] AC-2: fake timer 기준으로 누른 뒤 749 ms 에는 상태가 바뀌지 않고 750 ms 시점에 손을 떼기 전에 locked 가 된다
- [x] AC-3: 750 ms 전에 떼면 탭으로 처리하고, pointercancel 은 어떤 상태도 바꾸지 않는다
- [x] AC-4: 변환기로 인코딩된 키 하나를 보내면 once 인 수식키는 모두 off 가 되고 locked 인 수식키는 그대로 locked 이다
- [x] AC-5: locked 가 될 때 navigator.vibrate 가 있으면 vibrate(25) 를 부르고, 없으면 오류 없이 잠긴다
- [x] AC-6: 래치 저장소는 subscribe/getSnapshot 계약을 제공하고 TerminalView 가 같은 저장소의 상태를 읽는다

#### Rationale

- [x] AC-5: 모든 수식키가 off 이면 submitCapturedInput 에 넘어가는 (data, source) 인자가 변경 전과 바이트 단위로 같다

#### Requirement

- [x] AC-3: 키를 누르면 활성 터미널의 getApplicationCursorKeysMode 로 encodeMobileKey 를 부른 결과를 sendInput 으로 보내고, 보낸 뒤 once 수식키를 소모한다

- [x] AC-5: 화면보다 길면 가로로 스크롤되고 스크롤바는 보이지 않는다. 버튼 높이는 36 px 이상이다
- [x] AC-6: 버튼의 aria-label 과 title 문장은 i18n 카탈로그(messages.en/ko.json)를 거치고 키 이름은 ASCII 상수로 둔다
- [x] AC-7: isMobile 이 거짓이 되면 래치 저장소의 운영용 reset() 을 불러 모든 수식키를 off 로 되돌리고 누르고 있는 중인 1500 ms 잠금 타이머도 취소한다. 모바일에서 시스템 키보드가 내려가 키 줄이 숨어도 잠금은 유지된다. reset() 이후에는 이전에 시작한 press 가 locked 를 만들지 않는다

### FR-MKB-008 — 키보드 전환 버튼은 시스템 키보드와 특수 키보드를 같은 자리에서 바꾼다

#### Requirement

시스템은 키 줄의 전환 버튼으로 시스템 키보드를 내리고 같은 자리에 특수 키보드 패널을 띄우거나, 패널을 닫고 시스템 키보드를 다시 올려야 하며, 패널이 열린 동안 터미널 입력이 다시 포커스를 받지 않게 해야 한다.

#### Rationale

RD Client 의 Special Keys 화면처럼 F 키·방향키·편집 키를 한 화면에서 쓰려면 시스템 키보드를 내리고 그 자리를 써야 한다 (epic #133, #137).

#### Acceptance Criteria

- [x] AC-1: 시스템 키보드가 떠 있을 때 전환 버튼을 누르면 새 TerminalHandle.blurInput() 으로 helper textarea 의 포커스를 풀고 pendingFocusRestoreRef 를 비운 뒤 특수 키보드 패널을 연다
- [x] AC-2: 패널 높이는 마지막으로 잰 시스템 키보드 inset(getLastKeyboardInset) 과 260 px 중 큰 값이고, 잰 값이 없으면 280 px 이다. 260 px 는 44 px 키 다섯 줄과 간격의 최소 높이라서 가로 화면처럼 inset 이 작아도 패널 키가 잘리지 않는다
- [x] AC-3: 패널이 열린 동안 전환 버튼을 누르면 같은 탭 처리기 안에서 동기적으로 setFocusSuppressed(false) 로 억제를 풀고 이어서 TerminalHandle.focus() 를 불러 시스템 키보드를 다시 올린 뒤 패널을 닫는다. 억제 플래그는 React 상태가 아니라 TerminalView 안의 ref 로 들고 있고, 억제를 푸는 것은 전환 버튼과 패널이 저절로 닫히는 경우(isMobile 이 거짓이 될 때, 작업공간 화면을 떠날 때, 활성 탭이 없어질 때)뿐이다

시스템은 모바일에서 시스템 키보드가 내려간 뒤 키보드가 차지했던 자리를 빈 공간으로 남기지 않고, 새로고침 없이 앱 화면을 화면 아래 끝까지 다시 채워야 한다.

#143: 키보드가 올라올 때 브라우저가 문서를 스크롤하고, 키보드를 내리면 잠금이 풀린 .app 이 그 스크롤만큼 위로 밀려 아래가 빈다. 마지막 visualViewport 이벤트가 애니메이션 중간 값일 때도 줄어든 높이가 남는다.

- [x] AC-4: 키보드가 열려 있는 동안(inset > 0)에는 문서 스크롤을 건드리지 않는다

### FR-MKB-013 — 모바일 키 줄은 시스템 키보드가 올라와 있을 때만 보인다

| Field | Value |
| --- | --- |
| Type | functional |
| Target | mtk-wave-2 |
| Status | implemented |
| Priority | medium |
| Tags | - |
| Risk | low |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | https://github.com/Snoworca/BuilderGate/issues/147 |

#### Requirement

시스템은 모바일 키 줄을 활성 터미널 입력에 포커스가 있고 시스템 키보드가 실제로 올라와 있을 때, 또는 특수 키보드 패널이 열려 있을 때만 보여야 한다.

#### Rationale

#147: 안드로이드에서 뒤로 버튼으로 키보드를 닫으면 포커스가 남아 키 줄만 하단에 남았다. 사용자가 키보드가 올라왔을 때만 보이기를 요청했고 패널 유지·늦은 등장·하드웨어 키보드 태블릿 동작을 수용했다.

#### Acceptance Criteria

- [x] AC-1: 시스템 키보드 높이는 현재 화면 너비에서 본 가장 큰 화면 높이(max(innerHeight, visualViewport.height + offsetTop))에서 visualViewport.height 를 뺀 값과 FR-MKB-007 의 inset 중 큰 값이며, 이것이 120 px 이상이면 키보드가 올라온 것이다. 화면 너비가 바뀌면 기준 높이를 다시 잡는다. 그래서 키보드와 함께 innerHeight 가 줄어드는 브라우저(삼성 인터넷 등)에서도 판정된다. visualViewport 가 없으면 올라온 것으로 본다
- [x] AC-2: 키 줄은 isMobile·작업공간 화면·활성 탭 조건에 더해 (입력 포커스 그리고 키보드 올라옴) 또는 특수 키보드 패널 열림일 때 보인다
- [x] AC-3: 포커스는 남았는데 키보드가 내려가 있는 상태가 되면 키 줄은 바로 숨지 않고 400 ms 를 기다려 그동안 키보드가 올라오지 않을 때 숨는다. 포커스를 잃거나 다른 조건이 깨지면 바로 숨는다
- [x] AC-4: 키보드 판정은 inset 이 기준을 넘거나 내려올 때만 다시 렌더하고, 데스크톱에서는 visualViewport 를 구독하지 않는다

### FR-MKB-014 — Ctrl 래치가 켜진 상태의 v 는 클립보드를 붙여넣는다

| Field | Value |
| --- | --- |
| Type | functional |
| Target | file-transfer |
| Status | implemented |
| Priority | high |
| Tags | mobile, keyboard, clipboard |
| Risk | low |
| Stability | evolving |
| Verification Method | unit tests of takeLatchedPaste and its TerminalView wiring; phone E2E pasting a written clipboard text on 2222. |

#### Requirement

When Ctrl is latched and Alt is not, the system shall treat a v or V typed on the system keyboard as the paste shortcut, pasting the clipboard through the terminal's clipboard coordinator instead of sending the ^V control character, and shall spend a once Ctrl.

#### Rationale

2026-10-21 user report: with something on the clipboard, Ctrl (latched) + v did not paste on a phone; it sent ^V.

#### Acceptance Criteria

- [x] AC-1: AC-1: With Ctrl once or locked and Alt off, typing v or V pastes the clipboard text into the terminal and sends no 0x16.
- [x] AC-2: AC-2: A once Ctrl turns off after the paste; a locked Ctrl stays locked.
- [x] AC-3: AC-3: Any other character, two or more characters, or Ctrl together with Alt is not a paste and keeps the FR-MKB-003 re-encoding.
