## 1. Scope Overview

브라우저에서 세션의 파일 시스템을 탐색하고 조작하는 화면. 같은 트리 컴포넌트가 두 자리에 놓인다 — 워크스페이스당 하나인 모달리스 탐색기 창과, 편집기 창의 좌측 패널이다. 두 자리는 컴포넌트와 훅을 공유하되 인스턴스는 나누고, 클립보드와 작업 목록만 애플리케이션 전체에서 하나다.

서버 쪽 파일 조작 작업 모델은 `FOP` 스코프가 맡는다. 이 스코프는 그 작업을 일으키고 진행을 보여 주는 화면까지다.

## 2. Scope Boundaries

### In Scope

- 트리 자료 구조와 가변 뿌리, `..` 상위 이동
- 트리 모드와 목록 모드, 모드 전환
- 탐색기 모달리스 창과 탭, 최소화와 헤더 트레이
- 탐색기 전용 클립보드와 단축키, 모바일 버튼 줄
- 컨텍스트 메뉴와 우클릭이 선택을 다루는 방식
- 창 범위 모달 (오류 · 이름 충돌 · 삭제 확인)
- 진행 표시 세 자리 (창 안 진행 줄 · 하단 상태바 · 알림창)
- 탐색기를 여는 세 진입점

### Out of Scope

- 서버의 파일 조작 작업 모델과 진행 보고 형식 — `FOP` 스코프
- 편집기 창이 좌측 패널을 호스팅하는 규칙 — `FR-MDE-012`
- 디자인 토큰 계약 — `CON-ARCH-001`
- 파일 시스템 변경 감시와 트리 자동 갱신
- 끌어다 놓기로 파일 옮기기 (탭 사이 이동은 클립보드로 한다)
- 파일 검색과 이름으로 거르기
- 휴지통 또는 삭제 취소
- 탐색기 창의 좌우 분할 (이중 패널)
- 압축 파일 열기, 파일 속성 보기, 권한 변경

## 3. Assumptions and Constraints

- 파일 REST API 와 경로 검증은 이미 가동 중이며 그대로 쓴다. 그 계약은 **레거시 SRS** `docs/srs/buildergate.srs.md` §4.7 의 `FR-FILE-001`~`004` 와 `NFR-SEC-004` 에 있다 — 그 문서는 SpecKiwi 가 추적하지 않으므로 `docs/spec/` 안에서 찾으면 나오지 않는다.
- 모달리스 창 프레임과 z-순서 스택(`WindowDialog`, `dialogStack`), 컨텍스트 메뉴 컴포넌트, 길게 누르기 훅은 이미 있다.
- 쌓임 순서는 `CON-MDE-001` 의 3000번대 대역과 `FR-MDE-003` 규칙을 그대로 따른다.
- 하단 상태바는 새로 만든다. 기존 `StatusBar.tsx` 는 렌더 트리에 연결되어 있지 않고 담고 있는 개념도 지금 쓰이지 않으므로 건드리지 않는다.
- Mdir 이중 패널 코드(`components/FileManager/`, 785행)는 출발점이 아니다. 그대로 두고 새로 만든다.

#### Requirement

시스템은 파일 트리 상태를 expandedPaths, childrenByPath, selectedPaths, root, mode 로 갖고 goUp() 과 setRoot() 로 뿌리를 옮길 수 있어야 하며, 트리 모드와 목록 모드가 같은 상태의 두 뷰여야 한다.

#### Rationale

뿌리를 고정으로 받으면 상위 디렉터리로 갈 수 없다. 두 모드를 별개 기능으로 만들면 같은 상태가 두 벌이 되고 전환할 때마다 서버를 다시 읽게 된다.

#### Acceptance Criteria

- [x] AC-1: 훅은 root 를 가변으로 갖고 goUp() 과 setRoot(path) 를 제공한다
- [x] AC-2: 트리 모드는 뿌리와 펼쳐 둔 자손을 그리고, 목록 모드는 뿌리의 직계만 그린다
- [x] AC-3: 두 모드가 childrenByPath 를 공유하여 모드 전환에 서버 요청이 발생하지 않는다
- [x] AC-4: 뿌리가 바뀌어도 expandedPaths 를 버리지 않고, 되돌아오면 펼쳐 둔 상태가 그대로 살아 있다
- [x] AC-5: 디렉터리를 처음 펼칠 때만 조회하고, 다시 읽으려면 refresh(path) 를 명시적으로 호출해야 한다
- [x] AC-6: 파일 작업이 끝나면 영향을 받은 디렉터리만 다시 읽는다

### CON-FEX-001 — '..' 는 트리 노드가 아니라 창의 크롬이다

| Field | Value |
| --- | --- |
| Type | constraint |
| Target | file-explorer |
| Status | verified |
| Priority | medium |
| Tags | - |
| Risk | medium |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | - |
| Related Docs | [파일 탐색기 설계](../plan/2026-09-12.file-explorer.design.md) |

#### Requirement

시스템은 상위 디렉터리로 가는 '..' 를 노드 목록에 넣지 않고 창의 크롬으로 그려, 선택·클립보드·삭제 같은 파일 조작이 그 항목에 닿을 수 없게 해야 한다.

#### Rationale

부모로 가는 일은 뿌리를 바꾸는 조작이지 자식 노드가 아니다. 노드로 두면 선택·Ctrl+A·Shift 범위 선택·컨텍스트 메뉴·클립보드·Delete 여섯 곳 전부에 예외를 심어야 하고, 하나만 빠지면 '..' 를 복사하거나 지우려 드는 버그가 된다. 그런 예외는 나중에 조작이 하나 늘 때 함께 늘지 않는다.

#### Acceptance Criteria

- [x] AC-1: '..' 행은 노드 목록에 들어가지 않는다
- [x] AC-2: '..' 는 선택 집합에 들어갈 수 없다
- [x] AC-3: '..' 에는 컨텍스트 메뉴가 붙지 않는다
- [x] AC-4: Ctrl+A 와 Shift 범위 선택이 '..' 를 포함하지 않는다
- [x] AC-5: 클립보드 담기와 Delete 가 '..' 를 대상으로 삼을 수 없다
- [x] AC-6: 서버 listDirectory 가 돌려주는 '..' 항목은 노드로 만들지 않고, '상위가 존재하는가' 판정에만 쓴다 (경계 판정은 SEC-FOP-001 참조)

#### Requirement

#### Rationale

큰 디렉터리를 훑는 일과 구조를 보는 일은 다른 작업이다. 유형 컬럼을 두지 않는 것은 확장자가 이름에 이미 보이고 좁은 창에서 가장 먼저 잘리는 자리이기 때문이다.

- [x] AC-6: 최소화해도 배치는 유지되어 최대화 상태였으면 복귀 후에도 최대화다

| Field | Value |
| --- | --- |
| Type | functional |
| Target | file-explorer |
| Status | verified |
| Priority | medium |
| Tags | - |
| Risk | medium |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | - |
| Related Docs | [파일 탐색기 설계](../plan/2026-09-12.file-explorer.design.md) |

#### Requirement

시스템은 { mode: 'copy' | 'cut', entries: [{ sessionId, path }] } 형태의 탐색기 전용 클립보드를 두고, Ctrl+C·Ctrl+X·Ctrl+V·Delete·F2 를 트리 표면에 포커스가 있을 때만 가로채야 한다.

#### Rationale

웹 페이지는 시스템 클립보드에서 파일 핸들을 얻을 수 없다. 포커스 판정이 빠지면 터미널에서 누른 Ctrl+C 가 인터럽트로 가지 못하고 탐색기에 먹히는데, 그것은 에이전트를 멈출 수 없게 되는 심각한 고장이다.

#### Acceptance Criteria

- [x] AC-1: 클립보드는 탭과 창을 가리지 않는 하나의 값이라 탭 사이 복사·이동이 저절로 된다
- [x] AC-2: 잘라내기로 담긴 항목은 트리에서 흐리게 그려 아직 옮겨지지 않았음을 보인다
- [x] AC-3: Ctrl+C·Ctrl+X 는 선택을 각각 복사·잘라내기 모드로 담는다
- [x] AC-4: Ctrl+V 는 현재 탭의 디렉터리에 붙여넣는다
- [x] AC-5: Delete 는 확인 모달을 거쳐 선택을 지우고 F2 는 이름을 바꾼다
- [x] AC-6: 탐색기 창에서는 창 표면 안에 포커스가 있을 때 가로챈다
- [x] AC-7: 편집기 좌측 패널에서는 트리 패널 표면 안에 포커스가 있을 때만 가로채고 문서 영역은 제외한다
- [x] AC-8: 모바일에서는 단축키 대신 복사·잘라내기·붙여넣기·삭제·이름 바꾸기·새 폴더 버튼 줄을 두고 할 수 없는 동작은 흐리게 처리한다

| Field | Value |
| --- | --- |
| Type | functional |

| Risk | medium |

#### Requirement

시스템은 이름 충돌·오류·삭제 확인을 탐색기 창 표면 안에만 겹치는 모달로 띄우고 전역 모달 대역에 등록하지 않아야 한다.

#### Rationale

결정 모달을 전역 대역에 넣으면 파일 하나를 덮어쓸지 묻는 동안 터미널까지 멈춘다. 에이전트를 지켜보지 못하게 되는 것은 이 제품에서 받아들일 수 없는 비용이다. 삭제 확인에 '묻지 않기' 를 달지 않는 것은 삭제가 되돌릴 수 없고, 묻지 않기로 한 사실 자체를 사용자가 잊었을 때 잃는 것이 너무 크기 때문이다.

#### Acceptance Criteria

- [x] AC-1: 모달은 탐색기 창 표면 안에만 겹치고 창 바깥을 덮지 않는다
- [x] AC-2: 포커스를 그 창 표면 안에 가둔다 — 서버가 보낸 결정 모달은 포커스가 이미 그 창 안에 있을 때만 가져가고, 창 밖(터미널)의 포커스를 빼앗지 않는다. 삭제 확인은 사용자가 요청한 것이라 항상 가져간다
- [x] AC-3: Escape 는 그 질문을 취소한 것으로 처리한다
- [x] AC-4: 전역 모달 대역에 등록하지 않아 터미널과 편집기를 계속 쓸 수 있다
- [x] AC-5: 오류 모달의 선택지는 무시·재시도·취소다
- [x] AC-6: 이름 충돌 모달의 선택지는 덮어쓰기·이름 바꾸기·복사하지 않기다
- [x] AC-7: 위 두 모달 하단에 '더 이상 묻지 않기' 체크박스를 둔다
- [x] AC-8: 삭제 확인 모달에는 '더 이상 묻지 않기' 를 두지 않는다

### FR-FEX-008 — 진행 표시는 창 안 진행 줄·하단 상태바·알림창 세 자리에 뜬다

| Field | Value |
| --- | --- |
| Type | functional |
| Target | file-explorer |
| Status | verified |
| Priority | medium |
| Tags | - |
| Risk | medium |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | - |
| Related Docs | [파일 탐색기 설계](../plan/2026-09-12.file-explorer.design.md) |

#### Requirement

시스템은 파일 조작의 진행을 탐색기 창 하단 진행 줄, 앱 하단 상태바, 상태바를 눌러 여는 우하단 알림창 세 자리에 보여야 하며, 작업이 없을 때는 셋 다 자리를 차지하지 않아야 한다.

#### Rationale

상태바만으로는 시선과 피드백이 멀다. Ctrl+V 를 누르는 순간 시선은 화면 가운데 창에 있는데 피드백은 앱 맨 아래 가장자리에 뜨고, 긴 복사가 도는 동안 탐색기 창은 완전히 가만히 있다. 진행이 앱 전역이고 질문이 창 안인 이유는 작업이 창보다 오래 살기 때문이다.

#### Acceptance Criteria

- [x] AC-1: 탐색기 창 하단 진행 줄은 그 창에서 시작한 작업만 보여 준다
- [x] AC-2: 창 안 진행 줄에 막대·작업 종류·처리량·취소 버튼이 들어간다
- [x] AC-3: 작업이 여럿이면 창 안 진행 줄이 가장 최근 것과 '외 N개' 를 보이고 누르면 알림창이 열린다
- [x] AC-4: 하단 상태바는 작업 1개일 때 막대와 현재 파일 이름을, 2개 이상일 때 개수와 회전 프로그레스를 보여 준다
- [x] AC-5: scanning 단계에서는 막대가 아니라 회전 프로그레스를 보여 준다
- [x] AC-6: 상태바를 누르면 우하단 알림창이 열리고 작업마다 진행 막대와 취소 버튼이 한 줄씩 놓인다
- [x] AC-7: 알림창은 팝오버이므로 dialogStack 에 등록하지 않고 끌거나 크기를 바꿀 수 없으며 바깥을 누르면 닫힌다
- [x] AC-8: 작업이 없으면 세 자리 모두 자리를 차지하지 않는다
- [x] AC-9: 탐색기 창을 닫거나 최소화해도 작업은 계속 돌고 상태바가 이어받는다

#### Requirement

시스템은 단일 클릭을 선택으로, 파일 더블클릭을 편집기 열기로 다루어야 하며, 열 수 없는 파일은 흐리게 그려 더블클릭을 받지 않아야 한다.

#### Rationale

단일 클릭이 파일을 열어 버리면 여러 항목을 고를 방법이 없어진다. 파일 조작에는 다중 선택이 필요하므로 앞선 설계의 '단일 클릭으로 연다' 를 취소한다. 편집기는 텍스트 편집기이므로 바이너리 파일을 열면 내용이 깨진다.

#### Acceptance Criteria

- [x] AC-1: 단일 클릭은 선택이고 Ctrl 은 추가 선택, Shift 는 범위 선택이다
- [x] AC-2: 파일 더블클릭은 편집기 창에서 연다
- [x] AC-3: 트리 모드에서 디렉터리 더블클릭은 펼치거나 접는다
- [x] AC-4: 삼각형 아이콘 클릭은 선택을 바꾸지 않고 펼치거나 접는다
- [x] AC-5: 열 수 없는 파일은 흐리게 그리고 더블클릭을 받지 않는다
- [x] AC-6: 열 수 있는지의 판정은 viewableExtensions.ts 의 확장자 집합을 재사용한다 — FR-MDE-013(target code-editor)이 구현되면 판정 출처가 그 판정표로 바뀌며, 그때 이 AC 를 그 표를 가리키도록 고친다
- [x] AC-7: 열 수 없는 파일도 복사·이동·삭제는 되며 판정이 막는 것은 여는 일뿐이다

- [x] AC-4: 같은 이름이 이미 있으면 덮어쓰지 않고 새 이름으로 둘 다 보관한다
- [x] AC-5: 터치 기기·모바일 폭에서는 오버레이를 띄우지 않고 놓아도 업로드하지 않는다. 파일 탐색기 안에서 끌어 온 항목도 업로드로 취급하지 않는다

- [x] AC-4: AC-4: While entries are picked up, holding the pointer near the top or bottom edge of the list scrolls it, and a touch does not scroll the page.
- [x] AC-5: AC-5: On touch, releasing a picked-up row without moving more than 10 px opens the row's context menu; with a mouse the same release puts it back.
- [x] AC-6: AC-6: On touch, two taps on a row within 300 ms and 24 px open it as a mouse double click does (editor, expand or enter); the 1.5 s hold to open is removed. Explorer tabs and other elements keep opening their menu on a double tap (FR-UIDS-013).
