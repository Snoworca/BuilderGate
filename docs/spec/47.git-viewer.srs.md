| Field | Value |

## 1. Scope Overview

세션의 작업 폴더가 git 저장소일 때, 세션 하단바에 브랜치 칩을 보여 주고, 칩에서 Git 그래프 창과 diff 를 연다. IDE 없이 코딩 에이전트로 작업할 때 무엇이 바뀌었는지 보기 위한 읽기 전용 기능이다.

- 설계 시안: [docs/design/git-viewer.html](../design/git-viewer.html)
- 구현 계획: [docs/plan/2026-10-23.git-viewer.plan.md](../plan/2026-10-23.git-viewer.plan.md) (설계에서 바꾼 것 D1~D6 포함)
- 에픽: #164

## 2. Scope Boundaries

### In Scope

- 세션 하단바의 브랜치 칩(브랜치, 변경 수, ahead/behind, 진행 중 작업)
- Git 창: 커밋 그래프(현재·전체·기준 비교), 커밋 상세, 파일 목록, diff
- 서버의 읽기 전용 git API(summary·status·log·commit·diff·compare)

### Out of Scope

- 쓰기 작업: stage, commit, discard, checkout, branch 생성, fetch
- 구문 강조, 이미지 전후 비교, 비 UTF-8 내용 표시(v1.1 이후)
- WS push 와 `.git` 감시(v1.1. v1 은 보이는 동안만 REST 폴링)
- 서브모듈 내부, 중첩 저장소

## 3. Assumptions and Constraints

- 서버 PC 에 git 2.30 이상이 있다. WSL 세션은 WSL 안의 git 을 쓴다.
- `server/src/ws/WsRouter.ts` 는 봉인된 소스라 v1 에서 고치지 않는다.

#### Requirement

The system shall show, in the bottom bar of each terminal session whose working directory is inside a git repository, a branch chip with the branch name, the number of changed paths and the ahead/behind counts.

#### Rationale

-

#### Acceptance Criteria

- [ ] AC-1: 저장소 세션은 첫 summary 응답 즉시 칩을 표시한다. 저장소가 아닌 세션은 하단바 DOM 이 지금과 같다(스냅샷 테스트).
- [ ] AC-2: 분리 HEAD 는 7자 sha 와 경고색, 진행 중 작업은 번역된 이름(병합 중, 리베이스 i/n 등)을 표시한다.
- [ ] AC-3: ●n 의 n 은 서로 다른 경로 수다(같은 파일의 스테이징·미스테이징을 한 번만 센다).
- [ ] AC-4: upstream 이 없으면 ↑ 를 기준 브랜치 대비로 ≈↑ 형식으로 표시하고 툴팁에 밝힌다.
- [ ] AC-5: 칩 aria-label 에 브랜치 전체 이름·변경 수·앞섬/뒤처짐이 폭 단계와 무관하게 들어간다.
- [ ] AC-6: 저장소 여부를 모르는 첫 summary 응답 전에는 칩 자리에 확인 중 표시를 둔다. 응답이 저장소가 아니면 이 표시를 지우고 하단바는 원래 모습으로 돌아간다.

The system shall show a modeless Git window per session with the same window behaviour as the editor window.

-

- [ ] AC-5: Esc 는 아무 일도 하지 않고 전역 단축키는 없다. cwd 가 다른 저장소로 바뀌면 배너, 세션이 끝나면 배너를 띄운다.

The system shall compare the current branch with an automatically detected base branch without fetching.

- [ ] AC-4: 라벨에 감지한 ref 이름을 쓰고 fetch 하지 않는다.

### PERF-GIT-001 — 성능

| Field | Value |
| --- | --- |
| Type | performance |
| Target | git-viewer |

#### Requirement

The system shall keep git status queries fast and asynchronous.

#### Rationale

-

#### Acceptance Criteria

- [ ] AC-1: 로컬 벤치마크(커밋 50,000·파일 10,000 저장소): 칩 클릭 → 첫 diff p95 ≤ 1초, summary p95 ≤ 300ms(Windows) / ≤ 600ms(WSL).
- [x] AC-2: wsl.exe 호출 1회 비용을 실측해 기록한다(목표 ≤ 250ms, 넘으면 WSL 작업 중 폴링 5초).
- [x] AC-3: 세션 6개가 작업 중이고 클라이언트가 2개일 때 git 으로 인한 서버 CPU < 한 코어의 5%, 이벤트 루프 지연 p99 < 50ms.
- [x] AC-4: asyncFileProcessing 가드에 git 서버 파일이 포함되고 동기 호출이 0 이다. git 동시 실행은 서버 4·저장소 2.
- [x] AC-5: summary 의 status 가 150ms 를 넘은 저장소는 git update-index -q --refresh 를 한 번 실행해 index 의 파일 상태 정보를 갱신한다(다른 git 이 index 를 쓴 직후 status 가 모든 파일을 다시 읽는 상태를 없앤다). 다른 git 이 index.lock 을 잡고 있으면 건너뛰고, 실패해도 summary 는 그대로 응답하며, 갱신은 저장소당 60초에 한 번까지다.
- [x] AC-6: 저장소와 기준 브랜치를 이미 아는 summary 는 git 프로세스를 하나(status)만 띄운다. 기준 브랜치와 HEAD 는 .git 의 ref 파일(루즈 ref, packed-refs, origin/HEAD)을 직접 읽어 정하고, reftable 저장소이거나 읽기에 실패하면 git 으로 대신한다.
- [x] AC-7: 작업 사본 파일의 첫 diff(칩 클릭 → 창 → diff)는 git 프로세스를 최대 4개, 2단계로 쓴다: 파일 목록은 summary 의 status 결과(HEAD·index blob id 포함)를 다시 쓰고, numstat 은 바뀐 경로로 한정하며, log 의 shallow·HEAD 확인은 파일과 summary 로 대신하고, diff 의 입력 id 는 status 결과에서 가져온다.
- [x] AC-8: git 프로세스는 메인 스레드가 아닌 worker thread 에서 띄운다. 프로세스 생성(Windows CreateProcess, 백신 검사 포함)이 이벤트 루프를 막지 않는다.
- [x] AC-9: WSL 세션의 git 명령은 배포판마다 상주하는 헬퍼 하나를 거친다. 헬퍼는 wsl.exe 를 한 번만 띄우고 인자를 셸 해석 없이 git 에 그대로 넘기며, 시간 제한·오류·종료 시 다시 띄운다. 헬퍼를 쓸 수 없으면 명령마다 wsl.exe 를 띄우는 방식으로 돌아간다.
- [x] AC-10: Windows 저장소는 파일 감시로 바뀐 것이 없음을 확인하면 git 을 띄우지 않고 직전 summary 를 돌려준다. 감시가 실패하거나 일정 시간(30초)이 지나면 git 으로 다시 확인한다.
