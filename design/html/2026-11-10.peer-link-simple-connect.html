원격 연결 간소화

지금은 원격 하나를 잇는 데 wss:// 주소, 인증서 지문, 한 번만 보이는 키까지 세 가지를 맞춰야 합니다. 앞으로는 상대의 MCP 주소와 MCP 키 두 가지만 붙여 넣으면 연결되게 합니다.

전후

사용자가 하는 일

지금 · 5단계
  1. 상대 서버에서 고정 인증키를 생성하고, 한 번만 보일 때 바로 복사
  2. 상대 MCP 포트를 알아내 wss://IP:3333 로 직접 조립
  3. openssl 로 상대 인증서 지문 추출
  4. 지문을 붙여 넣기 (빠뜨리면 DEPTH_ZERO_SELF_SIGNED_CERT)
  5. 키를 잃어버리면 재생성 → 기존 연결이 모두 끊김
제안 · 2단계
  1. 상대 서버의 MCP 설정 창에서 MCP 주소와 MCP 키를 복사 (키는 「보기」로 언제든 다시 확인)
  2. 이 서버의 「원격 추가」에 붙여 넣고 저장. 주소 변환과 인증서 기억은 서버가 처리
1

MCP 키 하나로 연결

요청: 그냥 MCP 키로 다 되게 하자.

인증서 지문 칸을 없앱니다. 처음 연결에 성공하면 상대 인증서를 서버가 스스로 기억하고, 이후에는 같은 인증서인지만 확인합니다. 자체 서명 인증서도 그대로 연결됩니다. 메신저의 「연결 코드」가 이미 같은 방식으로 동작합니다(contactHttp.ts).

지문 칸 없음. 사용자가 입력할 것이 없습니다.

상대 인증서가 바뀌었을 때 (예: 상대가 인증서를 다시 만든 경우)
상태
확인 필요 상대 서버의 인증서가 처음 연결할 때와 다릅니다. 상대가 인증서를 다시 만들었다면 「새 인증서 신뢰」를 누르세요.
누르면 새 인증서를 기억하고 다시 연결합니다.

결정 필요 · 인증서를 얼마나 믿을까

A. 처음 연결 때 기억 (권장)
  • 사용자 입력은 B 와 같습니다 (지문 칸 없음)
  • 누군가 중간에서 가로채면 그 연결을 막아, MCP 키가 새지 않습니다
  • 인증서가 바뀌면 버튼 한 번으로 다시 신뢰합니다
B. 인증서를 전혀 검사하지 않음
  • 가장 단순합니다
  • 같은 망의 누군가가 중간에서 가로채면 MCP 키를 그대로 얻습니다. 그 키로 내 세션에 명령을 보낼 수 있습니다

결정 필요 · 상대 MCP 가 HTTP(암호화 없음)일 때

MCP 리스너는 기본값이 HTTP 입니다. 지금은 HTTP 리스너가 다른 PC에서 온 원격 연결을 거부합니다. 이 경우 키가 평문으로 오가기 때문입니다.

A. 지금처럼 거부하고 이유를 안내 (권장)「상대 MCP 설정에서 HTTPS 를 켜세요」라고 알려 줍니다. HTTPS 를 켜는 것도 클릭 한 번이면 됩니다.
B. HTTP 도 허용키가 망에 평문으로 흐릅니다. 사내망 안에서만 쓰더라도 패킷을 볼 수 있는 사람은 누구나 키를 얻습니다.
2

MCP 키 「보기」 버튼

요청: MCP 키는 보이기 버튼을 눌러서 볼 수 있도록 하자.

지금은 키를 해시로만 저장하므로 서버도 원래 키를 모릅니다. 그래서 생성할 때 한 번만 보여 줄 수 있습니다. 앞으로는 원격 링크 키와 같은 방식으로 이 PC 키로 암호화해 저장하고, 로그인한 사용자가 「보기」를 누르면 풀어서 보여 줍니다.

지금

고정 인증키

외부 MCP 클라이언트의 Bearer 인증에 사용합니다.

이 창을 닫거나 다른 탭으로 옮기면 다시 볼 수 없습니다.

제안

MCP 키

다른 BuilderGate 나 MCP 클라이언트가 이 서버에 연결할 때 씁니다.

••••••••••••••••••••••••••••
재생성하면 이전 키로 연결된 원격이 끊깁니다.
  • 이미 해시로만 저장된 키는 원래 값을 알 수 없으므로 보여 줄 수 없습니다. 그 경우 「보기」 대신 「이 키는 볼 수 없습니다. 재생성하면 볼 수 있습니다」라고 안내합니다. 기존 연결은 재생성 전까지 그대로 동작합니다.
  • 키는 어떤 로그에도 남기지 않으며, 「보기」 요청에도 로그인이 필요합니다.
  • 「고정 인증키」라는 이름을 「MCP 키」로 바꿉니다. 원격 연결 화면의 「인증키」 칸도 같은 이름을 씁니다.
3

MCP 주소를 그대로 붙여 넣기

요청: wss:// 주소가 아니라 MCP 주소를 넣어서 연결되게 하자. 등록하는 쪽에서 알아서 wss 로 변환.

주소 칸에 상대 MCP 설정 창 위쪽에 보이는 연결 주소를 그대로 붙여 넣습니다. 입력하는 대로 아래에 실제 연결 주소를 보여 주므로, 저장하기 전에 확인할 수 있습니다.

제안 · 원격 추가

위 주소 칸에 아래 표의 예시를 넣어 보세요.

입력실제 연결 주소규칙
https://10.0.1.13:3333/mcpwss://10.0.1.13:3333/mcp/peerhttps → wss, 경로 /mcp → /mcp/peer
10.0.1.13:3333wss://10.0.1.13:3333/mcp/peer방식이 없으면 wss
10.0.1.13wss://10.0.1.13:3333/mcp/peer포트가 없으면 MCP 기본 포트 3333
wss://10.0.1.13:3333wss://10.0.1.13:3333/mcp/peer지금 저장된 주소도 그대로 동작
http://127.0.0.1:3333/mcpws://127.0.0.1:3333/mcp/peer같은 PC(루프백)만 http 허용
http://10.0.1.13:3333/mcp연결 안 함「상대 MCP 가 HTTP 입니다. 상대 MCP 설정에서 HTTPS 를 켜세요」 (위 결정 B 를 고르면 허용)

변환은 저장할 때 서버에서 한 번 더 같은 규칙으로 합니다. 화면 미리보기와 서버 결과가 어긋나지 않도록 규칙을 한 곳에 둡니다.
