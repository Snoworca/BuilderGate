세션 입력창 (Composer) 기획

총괄 세션에 메시지가 쏟아져 사용자 입력이 끊기는 문제를 해결하기 위해, 각 세션 창 하단에 별도 입력창을 둔다 · 2026-11-19 · 소스 변경 없음(기획 시안)

한눈에 보기
  • 입력이 끊기는 근본 원인은 사용자 타이핑과 외부 붙여넣기가 같은 PTY 입력 줄을 공유한다는 점이다. 메신저·MCP 붙여넣기는 사용자가 쓰다 만 줄 한가운데로 들어가고, 약 1초 뒤 서버가 보내는 Enter 가 사용자의 미완성 문장까지 함께 제출한다.
  • 해결: 세션마다 터미널 아래에 입력창을 둔다. 사용자는 여기서 안전하게 쓰고, 보내는 순간에만 한 번에(bracketed paste + Enter) PTY 로 들어간다.
  • 열고 닫기는 세 가지다: 세션 하단 상태 줄(MetadataRow) 맨 오른쪽 토글 버튼, Alt+N, 모바일 컨텍스트 메뉴의 「입력창 표시」.
  • 기본값: Enter 전송 · Shift+Enter 줄바꿈, 높이는 위로 드래그해 조절(전역 1개 값), 열림 상태와 초안은 세션별로 저장한다. 설정 화면에 새 항목을 추가하지 않는다.

1. 문제 분석 — 입력이 왜 끊기는가

1.1 외부 메시지가 PTY 에 들어가는 경로

단계코드 위치동작
계획server/src/services/messenger/delivery.ts planDelivery받는 세션마다 [BG-ROOM:방 | 보낸이 → @대상] 본문 형태의 PasteJob 을 만든다. submit 은 세션의 enter 설정을 따른다.
직렬화roomService.ts enqueuePaste · drainPastes · pasteBatch세션별 큐. 붙여넣기 하나가 진행 중일 때 들어온 것들은 끝난 직후 한 덩어리로 붙여 넣는다(FR-MSG-004 AC-3). 사용자가 타이핑 중인지는 보지 않는다.
프레이밍pasteFrame.ts buildRoomPastebracketed paste 모드면 ESC[200~ … ESC[201~ 로 감싼다.
쓰기server/src/index.ts createMessengerPaster → submitWithSeparateEnter본문을 먼저 쓰고, 설정된 지연(submitEnterDelay, 기본 약 1초) 뒤에 Enter(\r)를 따로 쓴다. MCP message.send · reply-to-leader · 웹훅도 같은 게이트웨이(SessionInputGateway)를 탄다.

1.2 사용자가 xterm 에 직접 칠 때 일어나는 일

  1. 사용자가 Claude Code 입력란에 리팩터 범위를 server/ 로 한정하고 까지 친다(커서는 줄 끝).
  2. 메신저 메시지가 도착한다. 서버는 그 줄의 커서 위치에 [BG-ROOM:…] 빌드 끝났습니다 를 붙여 넣는다 — 에이전트 TUI 는 이것을 사용자 입력과 구분하지 못한다.
  3. 약 1초 뒤 서버가 Enter 를 보낸다. 사용자의 미완성 문장 + 메시지가 한 프롬프트로 제출된다.
  4. 사용자가 이어서 친 글자는 이미 다음 입력란으로 넘어가 있거나, 붙여넣기와 Enter 사이 1초 틈에 끼어 메시지 중간에 섞인다.

원인 정리: ① 입력 줄이 하나뿐이다(사용자와 외부 송신자가 공유). ② 서버는 사용자의 타이핑 상태를 모른다. ③ 본문과 Enter 가 분리돼 있어 그 틈에 사용자 키 입력이 들어갈 수 있다. 총괄 세션은 받는 메시지 수가 가장 많아 세 가지가 모두 자주 겹친다.

1.3 입력창이 해결하는 것과 해결하지 못하는 것

해결한다
  • 쓰는 동안의 초안이 PTY 밖(브라우저 textarea)에 있으므로 외부 붙여넣기와 섞이지 않는다.
  • 보내기는 단일 bracketed paste + Enter 이므로 다른 붙여넣기와 원자적으로 순서가 정해진다(아래 7.3 의 같은 큐 사용 시).
  • 한글 IME 조합이 xterm 의 숨은 textarea 가 아니라 일반 textarea 에서 일어나 조합 깨짐이 줄어든다.
해결하지 못한다 (보완 필요)
  • 사용자가 입력창을 쓰지 않고 여전히 xterm 에 직접 칠 때 → 6장 D-1 의 「타이핑 중 배달 보류」로 보완한다.
  • 에이전트 TUI 입력란에 이미 남아 있던 글자 → 보내기 직전에 그 내용이 있는지 알 수 없다(7.4 참고).

4. 상호작용 설계

4.1 표시·숨김

수단동작
상태 줄 토글세션 하단 MetadataRow 맨 오른쪽(경과 시간 뒤)에 둔다. 앱 전체 하단의 FileJobStatusBar 는 파일 작업 중에만 나타나는 줄이라 상시 토글을 둘 수 없다. 따라서 요청의 「가장 우측 하단 상태표시줄」은 각 세션의 하단 상태 줄 오른쪽 끝으로 해석한다. 누르면 열림/닫힘이 바뀌고, 열 때 입력창에 포커스를 준다.
Alt+N포커스가 있는 세션 기준 3단 동작:
① 닫혀 있으면 → 열고 입력창에 포커스
② 열려 있고 터미널에 포커스 → 입력창으로 포커스만 이동
③ 입력창에 포커스 → 닫고 터미널로 포커스 복귀
한 키로 「쓰러 가기」와 「치우기」를 모두 한다. IME 조합 중(isComposing)에는 무시한다.
모바일 컨텍스트 메뉴「입력창 표시」 / 「입력창 숨기기」. 터치 화면에서만 노출하지 않고 모든 환경에 같은 항목을 두어도 무방하다(데스크톱에서 단축키를 모르는 사용자도 찾을 수 있다). 권장: 모든 환경에 노출.

4.2 크기 조절

  • 입력창 위쪽 7px 손잡이를 위로 끌면 커지고, 아래로 끌면 작아진다. 더블클릭하면 기본 높이로 돌아간다.
  • 최소: 한 줄(약 44px). 최대: 타일 높이의 50%, 단 터미널이 최소 6줄을 유지하는 범위까지.
  • 자동 늘림: 사용자가 정한 높이를 「최대치」로 보고, 내용이 짧으면 그보다 작게, 길어지면 그 높이까지 자란 뒤 스크롤한다. 따라서 대부분의 사용자는 한 번도 드래그할 필요가 없다.
  • 터미널 재맞춤 시점: 드래그 중에는 입력창만 그리고, 손을 뗄 때 한 번만 xterm fit → PTY resize 를 보낸다. 드래그마다 SIGWINCH 를 보내면 에이전트 TUI 가 화면을 계속 다시 그린다. 자동 늘림도 같은 이유로 줄 수가 바뀔 때만, 150ms 디바운스로 반영한다.
  • 저장: 높이는 전역 하나(브라우저 저장소), 열림 상태는 세션별. 권장 이유: 높이는 취향이고 세션마다 다를 이유가 없지만, 어느 세션에 입력창이 필요한지는 세션의 역할(총괄 여부)에 따라 다르다.

4.4 보내기 동작

  1. 초안을 기존 붙여넣기 정제 경로(sanitizeTerminalPasteText, 크기 상한 TERMINAL_PASTE_MAX_BYTES)에 통과시킨다.
  2. bracketed paste 로 본문을 쓰고, 서버의 submitEnterDelay 와 같은 규칙으로 Enter 를 따로 쓴다. 에이전트 TUI 가 긴 붙여넣기를 처리하기 전에 Enter 가 도착해 줄바꿈으로 먹히는 문제를 서버가 이미 이렇게 풀고 있기 때문이다.
  3. 성공하면 입력창을 비우고 그 내용을 세션별 보낸 기록에 넣는다. 포커스는 입력창에 남긴다(연속 지시가 흔하다).
  4. 실패하면(세션 종료, 크기 초과, 여러 줄 미지원 등) 초안을 그대로 두고 입력창 바로 위에 한 줄 오류를 띄운다. 초안이 사라지는 일은 없어야 한다.

4.5 포커스 규칙

  • 입력창을 열면 입력창에 포커스. 닫으면 그 세션의 터미널로 포커스.
  • Esc 는 입력창에서 터미널로 포커스만 옮긴다(입력창은 열린 채). PTY 에 ESC 를 보내지 않는다. 에이전트를 중단하려면 터미널에서 Esc 를 한 번 더 누른다.
  • 입력창 포커스 중에는 xterm 의 키 처리·터미널 단축키(TerminalShortcutManager)가 동작하지 않는다. 일반 textarea 이므로 Ctrl+C/V/A, 단어 이동 등 OS 편집 동작이 그대로 동작한다.
  • 터미널을 클릭하면 터미널로 포커스가 간다(기존 동작 유지). 입력창이 열려 있는 세션에서 터미널에 직접 쳐도 막지 않는다.

4.6 초안과 기록

  • 초안 저장: 세션별로 입력할 때마다(300ms 디바운스) 브라우저 저장소에 저장한다. 새로고침·탭 전환·창 닫기 뒤에도 남는다. 세션을 닫으면 그 세션의 초안과 기록을 지운다.
  • ↑ / ↓ 기록: 커서가 첫 줄에 있고 초안이 비었거나 기록 탐색 중일 때만 ↑ 가 이전 항목을 채운다. 그 외에는 평범한 커서 이동이다(여러 줄 편집을 방해하지 않기 위해). 세션당 최근 50개.
  • 기록 탐색 중 수정하던 초안은 ↓ 로 맨 끝까지 내려가면 다시 나타난다(셸의 관례).

5. 예외 상황

상황처리
bracketed paste 를 켜지 않은 프로그램(일반 셸 등)에 여러 줄 보내기기존 경로가 unsupported-multiline-paste 로 거부한다. 입력창은 보내기 버튼 옆에 「이 세션은 여러 줄을 받지 못합니다」를 띄우고 초안을 유지한다. 한 줄 초안은 그대로 보낸다.
세션이 끊김(disconnected) / 재연결 중입력창은 계속 쓸 수 있고 전송 버튼만 비활성. 재연결되면 다시 활성화. 자동 재전송은 하지 않는다(의도치 않은 지시 방지).
세션 종료입력창을 닫고 초안을 지운다. 단, 닫기 직전 초안이 있으면 세션 닫기 확인창에 「보내지 않은 입력이 있습니다」를 한 줄 덧붙인다.
매우 큰 붙여넣기(입력창에 MB 단위)입력은 받되 전송 시 크기 상한으로 거부하고 바이트 수를 알려 준다(기존 paste-too-large 메시지 재사용).
모바일 가상 키보드가 올라와 화면이 줄어듦입력창 최대 높이를 visualViewport 기준 35% 로 다시 계산한다. 터미널이 6줄 아래로 줄면 입력창을 먼저 줄인다.
타일을 최대화/복원, 탭 모드 ↔ 그리드 모드 전환열림 상태·초안은 세션 키 기준이라 그대로 따라간다.
보내는 순간 메신저 붙여넣기가 진행 중7.3 의 같은 큐를 쓰면 붙여넣기 + Enter 가 끝난 뒤 입력창 내용이 들어간다. 같은 큐를 쓰지 않으면 1초 틈에 끼어들 수 있다 — 그래서 같은 큐를 권장한다.
macOS 의 Option+NmacOS 에서 Option+N 은 데드 키(˜, ñ 입력)다. event.key 가 아니라 event.code === 'KeyN' 로 판정하고 preventDefault 한다. 다만 스페인어 등 ñ 를 쓰는 사용자는 입력이 막힌다 — 6장 D-3 참고.

7.3 보내기 경로 — 두 가지 안

안 1. 클라이언트 조합 (빠름)

핸들의 pasteText(draft, 'composer') 뒤에 sendInput('\r') 를 지연을 두고 보낸다. 기존 정제·크기 상한·여러 줄 가드를 그대로 쓴다.

단점: 서버의 메신저 큐와 별개라, 메신저 붙여넣기의 「본문 → 1초 → Enter」 틈에 끼어들 수 있다.

안 2. 서버의 같은 세션 큐 사용 (권장)

WS 에 composer:submit(세션 ID, 본문) 메시지를 더하고, 서버는 메신저와 같은 세션별 직렬화 지점을 통해 buildRoomPaste + submitWithSeparateEnter 로 쓴다. 감사 출처는 SessionInputGateway 의 새 ingress composer.

장점: 붙여넣기 두 개가 서로의 본문과 Enter 사이에 끼는 일이 구조적으로 없어진다. D-1 B(타이핑 임대)도 같은 지점에 붙일 수 있다.

현재 직렬화 큐는 roomService 안(메신저 전용)에 있고 MCP message.send 는 따로 쓴다. 안 2 를 하려면 이 큐를 세션별 「제출 차선」 하나로 끌어내 메신저·입력창·(필요하면) MCP 가 함께 쓰게 하는 것이 깔끔하다. 범위가 커지면 1차는 안 1 로 내고, 2차에서 차선 통합과 D-1 B 를 함께 한다.

7.4 알아 둘 제약

  • 입력창이 열리고 닫힐 때마다 터미널 줄 수가 바뀌어 PTY resize 가 나간다. 이 저장소에는 리사이즈 임대·재그리기 관련 장치(terminalResizeSendLedger.ts, terminalRedrawNudge.ts)가 있으므로 기존 fit 경로를 그대로 타게 하고 별도 resize 를 만들지 않는다.
  • 정책 자원(resourceLimits.*)을 새로 읽게 되면 server/src/services/TerminalResourcePolicy.test.ts 를 직접 돌려야 한다(저장소 전역 감시 테스트).
  • 현재 이 기능에 해당하는 SRS 요구사항이 없다. 구현 전에 요구사항(입력창 표시·크기·보내기·초안, 그리고 D-1 B 를 한다면 배달 보류)을 먼저 등록해야 한다.
